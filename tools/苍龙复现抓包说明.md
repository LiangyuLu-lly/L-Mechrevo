# 苍龙复现抓包说明（调自定义档会不会被弹回）

**一句话**：点【自定义】后，用拔插电 / 睡眠唤醒 / 切显卡模式各试一次，**每次一出现异常就立刻抓包**回传。

---

## ① 触发步骤

1. 打开 **L-Mechrevo**，确认它正在运行（日志才会写）。
2. 点【自定义】档，选好你要的自定义档位，确认 UI 显示的是「自定义」（不是静音/平衡）。
3. 依次做下面**三个场景**，每个场景各试一次；**每次做完先看 UI 有没有被弹回静音/平衡**。

## ② 该看什么（日志里应出现的"修好了"的行）

日志文件：`%APPDATA%\MechrevoLite\log.txt`（即 `C:\Users\<你的用户名>\AppData\Roaming\MechrevoLite\log.txt`）

**正常（保住了自定义档）** 应出现：

```
AutoPerformance: powerChanged=... customActive=True -> 保留自定义档
Reapplying custom profile N (power source changed).
Custom profile N reapplied.
```

- 第一行是**决策行**：`customActive=True -> 保留自定义档` ⇒ 判定对了，走保留分支。
- 第二行括号里也可能是 `custom mode preserved on init/wake`（唤醒/开机时）。
- 第三行是**结果行**：自定义档被重放成功。

**失败（还是被弹回）** 会长这样：

```
SwitchCustomProfile(n) confirmed=False actualMode=... actualProfile=... 
PerfModes: ... 未切换成功（reason=... route=...）→ ActiveModeId 仍为 ...
```

- `confirmed=False` ⇒ 硬件回读没确认。
- `未切换成功` ⇒ 这次档位没落地（会等下一次重试）。
- 若还有 `SwitchCustomProfile: GCU 未连接`，说明是 GCU 掉线导致，不是本修复的问题。

## ③ 三个场景（每个都要试一次）

| # | 场景 | 怎么做 | 期望看到的行 |
|---|------|--------|--------------|
| 1 | **拔插电** | 拔掉电源适配器，等 10 秒；再插回去，等 10 秒 | `powerChanged=True` + `保留自定义档` |
| 2 | **睡眠唤醒** | 合盖或开始菜单 → 睡眠；唤醒后等 20 秒 | `保留自定义档` + `custom mode preserved on init/wake` |
| 3 | **切换显卡模式** | 在 L-Mechrevo 里切一次显卡模式（独显直连 ↔ 混合），等它切完 | `保留自定义档` + `Custom profile N reapplied.` |

> 每个场景之后都**先看 UI 档位**再往下做，别连着做完三个才看——连着做就分不清是哪一个场景弹回的。

## ④ 复现后立刻抓包

**每次场景一异常，立刻**（30 秒内最好）跑一次抓包，把 zip 发回来：

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\GCU抓包.ps1"
```

- 脚本就在桌面的话，直接双击 `GCU抓包.ps1` 也行（普通用户就能跑，抓包部分才需要管理员）。
- 生成的 `LM-GCU抓包-<时间戳>.zip` 就在桌面上，**把 zip 整包发回来**即可。

## ⑤ ⚠️ 如果仍被切回，请顺手圈出来

回传时请把**抓包那一刻前后的那几行原文**贴出来（或截图圈出来）：

1. `AutoPerformance:` 那一行 —— 看 `customActive=` 是 True 还是 False。
2. 紧跟的 `Reapplying custom profile ...` 或 `... Performance Mode: ...` 那一行 —— 看走了哪条分支。
3. `SwitchCustomProfile(...) confirmed=` 或 `Custom profile N reapplied.` —— 看结果。
4. 若有 `PerfModes: ... 未切换成功` —— 把整行贴上（含 `reason=` / `route=`）。

> 有这几行就能确定是「判定错了」「重放失败」还是「GCU 未连接」，不用再猜。
