# GCU 独显热切 / 静默 项目报告

日期：2026-10-08
范围：机械革命 翼龙15PRO(4060)、翼龙16Pro(R7 255 + 5060)、极光X Pro(255HX + 5070Ti)、AARU(8945HX + 5070Ti)
交付物：`GCU显卡工具箱.zip`（中文界面 + 4 个引擎，全部只读为默认、写入需显式确认）

---

## 一、目标

控制中心（GCU）切「核显省电模式」的两大痛点：

1. 提示 **「显卡使用中，暂不支持切换」** —— 只要有用独显的程序就切不了；
2. 切换到底做了什么、有没有成功，完全看不到；
3. 想"不重启就让独显下线"，到底可不可行、靠哪一层，没有依据。

目标：**不依赖控制中心**，做出可验证、可回滚的独显"静默/恢复"工具，并说清各机型的真实能力边界。

---

## 二、结论摘要

1. **热切的写入目标在所有机型上完全一致**（厂商只有一份二进制、选择子是编译期常量）：
   `root\WMI` → `AcpiTest_MULong`（优先实例 `ACPI\PNP0C14\1_1`）→ 方法 `GetSetULong(Data)`：

   | 用途 | Data |
   |---|---|
   | 切走（iGPU-only ON） | `0x3_0000_0000_01` |
   | 切回（OFF） | `0x3_0000_0000_00` |
   | 读状态 | `0x3_0000_0000_02` → **85 = 已生效，170 = 未生效** |
   | 读支持 | `0x3_0000_0000_03` → **85 = 支持，170 = 不支持** |

2. **跨机型能否热切，只取决于"支持位"这一个人门**：`support=85` 可用，`170` 直接没有这条路（翼龙15PRO 4060 就是 170）。
3. **在 3 台 `support=85` 的机器上，热切实测都成功**：`nvidia-smi` 失联（exit 9）、Windows 里设备**不在场**、固件状态位变 85；且**双向都不需要重启**（AARU 实测 49 秒内 off→on 来回）。
4. **"设备管理器里看不到"≠设备被删**：切换成功后设备是"**不在场**"（枚举里只剩幽灵节点，`present=False / phantom≥1`），设备管理器默认不显示不在场设备，所以那一行"直接没了"。
5. **强制静默（即使有程序占用）用软件层（PnP）实现**：`Disable-PnpDevice` + 可选 `pnputil /remove-device /force` —— 不经过控制中心，**不受"显卡使用中"限制**，任何机型可用。
6. **"写入被接受"不等于"已生效"**：必须回读验证。本工具用三项判据（固件状态 85 + 驱动失联 + 设备不在场）判定，**超时自动回滚**（厂商自己也是这么做的）。
7. **实时观察会干扰切换**：机主实测"挂着抓取工具时经常切换失败"。原因是抓取时每 3 秒要读 3 次 ACPI/EC，与厂商"靠轮询 EC 确认成功"的流程抢那条通路 → 厂商误判失败并回滚。**正确做法：拍完快照 → 关掉工具 → 去控制中心切换 → 再打开对比**。

## 三、四台机器实测对照

| 机器 | CPU | GPU | `support` | `OemDisplayMode@98` | `EC[2002]`低5位 | 热切实测 |
|---|---|---|---|---|---|---|
| 翼龙15PRO | AMD | RTX 4060 | **170（不支持）** | 1（独显直连） | 17 | 无此路径（只能 PnP / 冷切） |
| 翼龙16Pro | AMD R7 255 | RTX 5060 | 85 | 0（混合） | 23 | ✅ 成功：驱动失联 + 设备不在场 |
| 极光X Pro | Intel 255HX | RTX 5070Ti | 85 | 4（Intel 编码=关） | 25 | ✅ 成功（12:46 报告） |
| AARU | AMD 8945HX | RTX 5070Ti | 85 | 0（混合） | 25 | ✅ 成功，且 49 秒内可双向切换 |

配套发现：

* **`EC[2002]` 低 5 位是"显卡模块 ID"**（同 GPU 同值：5070Ti=25，与 CPU 平台无关）→ 可作跨机型自校验。
* **固件结构体（180 字节）偏移跨机型一致**：`OemBoardSsid@0`（= 某 PCI 设备的 SUBSYS）、`PowerMode@47`、`APVersionCheck@67`、`OemDisplayMode@98`、`AudioCodecID@104`（自然对齐，@103 为填充）。
* **blob 变量名按代际不同**：40 系在 `UniWillVariable`，50 系在 `OemMagicVariable`（工具已自适应）。
* `OemMagicDoor` 仅 50 系固件存在；`OemDgpuPresent` 四台固件里都没有。

## 四、工具与用法

`GCU显卡工具箱.zip`（双击 `双击运行-显卡工具箱.cmd`，UTF-8 带 BOM 的中文界面）：

| 菜单 | 作用 | 依赖 |
|---|---|---|
| 1 | 体检并生成报告到桌面 | 只读 |
| 2 / 3 | 切换前拍快照 / 切换后对比（**推荐路径**：拍完关掉工具再去切换） | 只读 |
| 4 | 实时抓取切换过程（**会干扰厂商切换，成功率低**） | 只读 |
| 5 | 释放独显占用（列出→确认→结束占用进程；分"主要/轻微"两档） | 只读 + 结束进程 |
| 6 | 只看一下状态 | 只读 |
| 7 / 8 | **静默 / 还原独显**（PnP 禁用 / 启用，全机型可用） | 写设备状态 |
| 9 / 10 | **热切静默 / 热切还原**（写 ACPI 选择子，仅 `support=85`） | 写固件接口 |
| 11 | **强制静默（彻底）**：清占用 → 硬件层切走 → 软件层禁用(+移除节点) | 全部 |
| 12 | **报告开关**：关掉后不再往桌面生成报告文件（快照不受影响） | — |

引擎（全部可单独调用）：

* `Get-GcuNvramState.ps1` —— 只读体检 / 快照 / 前后对比 / `-CompareTo last`（自动用上次标记的基线）；
* `Invoke-GpuHotSwitch.ps1` —— ACPI 热切：`-Action Status|Silence|Restore`，写入后三项判据轮询（默认 120 秒），失败自动回滚；`-DryRun` 可空跑；
* `Clear-DgpuOccupants.ps1` —— 占用释放：默认只读，`-Kill` 才动手；按"是否真正使用独显"分档，保护系统/桌面/安全软件/控制中心；
* `Invoke-DgpuSilence.ps1` —— PnP 禁用/启用（`-Force` 先清占用、`-RemoveDevice` 彻底移除），自带安全门控（内屏由独显驱动时拒绝，防黑屏）与自动回滚。

退出码约定（热切引擎）：`0` 成功 / `1` 出错 / `2` 前置条件拒绝 / `3` 未确认 / `4` 写入后验证超时已回滚 / `5` 还原未确认。

## 五、关键实测证据

**成功的一次（AARU，间隔 49 秒的两份只读体检）**

| 项 | 12:51:58 | 12:52:47 |
|---|---|---|
| `reg_igpu_only` | 1（已切走） | 0（正常） |
| 固件状态位 | **85** | **170** |
| `nvidia-smi` | **exit 9**（联系不上驱动） | exit 0，16.26 W / P4 |
| 设备 | `Unknown`、**不在场** | `OK/code 0`、在场 |

→ 证明热切**双向、秒级、不需要重启**。

**三种失败模式与处置**

| 现象 | 原因 | 处置 |
|---|---|---|
| 写入被接受但状态 120 秒不动 → 自动回滚 | ① 刚还原后又立刻切换（节奏问题）；② 前置条件未满足 | 工具已自动回滚；建议还原后等 ≥1 分钟再切 |
| 还原"怎么等都回不来"，`present=False / phantom=0`、设备行为空 | 之前用过**强制静默·彻底模式**：`pnputil /remove-device /force` **删掉了设备节点**，ACPI 写入无法重建 | 菜单 **8**（重新扫描+启用）或 `pnputil /scan-devices`；必要时重启（一定能回来）。**菜单 10 现已自动先 rescan** |
| 报告显示 `nvidia_present=True` 但机主说设备管理器里没有 | `Get-PnpDevice` 默认包含**非在场（幽灵）设备**（本机 539 个设备里 271 个非在场） | 工具已改为"只算真正在场"，并单独输出 `phantom=N` 与 `PHANTOM/not present` 标注 |

**已修的其他判读缺陷（部分来自真实报告）**

* 概括摘要把"OFF 写入返回 170"误判为"未被接受"→ 已按方向给期望值（ON→85 / OFF→170）；
* 对比表把演示字段（`Count/Keys/Values`）当数据行；摘要正则跨行吃到下一字段名（出现 `True -> nvidia_count`）；
* 英特尔机型显示模式显示"未知"→ 改为按平台套用编码表（AMD 1/0/2，Intel 2/4/1）；
* "检测时间"把 120 秒观察窗算进去（写成 `~123s`）→ 已拆分为"首次检出"与"快照时刻"；
* 时间线在有变化时仍打印"没有任何信号变化"；
* 假管理员提示（日志里第一次读固件变量必然先失败再重试成功）；
* 中文界面需要 UTF-8 **带 BOM**（Windows PowerShell 5.1 才能正确读取）。

## 六、已知限制与未解问题

1. **翼龙15PRO(4060) 无热切**：`support=170`，固件不提供该接口，任何软件都无法让固件给它断电；可用的是 PnP 层与冷切。
2. **需要重启才生效的冷切层（`OemDisplayMode` 写入）本次未实现**（按需求不做），持久性验证存档：
   曾观察到 `IGPUonly` 被重置（怀疑与控制中心改电源模式有关），因此"重启后是否保持"仍未有定论。
3. **"刚还原后立即再切"偶发不生效**：返回值语义还需更多样本（已知 OFF 写入返回 170 = 写后状态）。
4. **实时抓取（菜单 4）与厂商切换互相干扰**：机制已定位为"抢读 EC/ACPI"，建议默认用两步法。
5. 热切生效**速度因机而异**（AARU 秒级；英特尔某次"半应用"后自行完成）→ 默认 120 秒等待，必要时可调大。

## 七、机主操作手册（非技术用户）

**日常（推荐）**

```
① 想切走独显：菜单 9  → 成功会在 1~2 秒内提示（最多等 120 秒）
② 想切回来：  菜单 10
```

**如果控制中心切不动**（提示"显卡使用中"）

```
菜单 5（释放占用）→ 菜单 9 或菜单 11
```

**如果独显"消失"后想恢复**

```
菜单 10（热切还原）→ 若还不行：菜单 8（重新扫描）→ 仍不行：重启（一定恢复）
```

**注意**

* 菜单 11 的"彻底模式"会**移除设备节点**：最彻底，但恢复必须走菜单 8 或重启；**日常不要用它**。
* 菜单 5 与菜单 11 会**强制关闭占用独显的程序**，未保存内容会丢失。
* 菜单 12 可关掉"生成报告文件"（关掉后结果只显示在屏幕上）。
* 切换时屏幕可能闪一下；若黑屏不恢复：等 30 秒，仍黑则长按电源键 10 秒强制关机再开机（不损硬件）。
* **不要运行**厂商目录里的 `GetGpuUsage.ps1`：名字像"查看占用"，内容其实是"禁用 NVIDIA 设备"。
