# 交接：同方 EC「显卡功耗 / Dynamic Boost」控制脚本与实测结论

> 日期：2026-10-19 · 机型：机械革命 翼龙15Pro（同方模具 **GM5HG0A**，Ryzen 7 8745H + RTX 4060 Laptop 115W/140W）
> 目的：把这轮「GPU 功耗上限（DB）控制」的脚本、通道、字节语义、踩坑和结论一次性交接，**供另一个会直接接手**。
> 相关背景文档：`docs/notes/显卡功耗与DB-调研-20261017.md`（§7 同方实测、§8 2026-10-19 补充）。

## 0. 一句话结论

- EC 里 **`0x743` 是 Dynamic Boost 使能位**（bit1=DB enable，bit2=CTGP，bit0=DB Func）；
- **`0x746` / `0x7D5` 是 DB 最大 TGP（W）**（0x19=25W → 140W；0x05=5W → 120W；0x00 → 115W）；
- **`0x745` / `0x7D4` 是 DB 目标字节**（开 DB 时官方写 `0xFF`）；
- 官方 GCU 切狂暴会写全套；**OpenRevo 只写 `0x746/0x7D5`，不写 `0x743/0x745/0x7D4` ⇒ DB 不开、上限停 115W**（详见 §7）；
- 通过 `\\.\ACPIDriver` 的写 IOCTL **可以写这些字节**（已实测：写全套后 enforced 115→140W）；
- **DB 是动态的**：只有 GPU 有负载时才维持 140W；负载一停固件会把值收回 115W。

## 1. 两条 EC 通道（同方机型）

| 通道 | 用途 | 现状 |
|---|---|---|
| `root\WMI:AcpiTest_MULong`（免驱 WMI） | 读 EC | ✅ 读可用；写**不可用**（见 §5） |
| `\\.\ACPIDriver`（UWACPIDriver / ACPIDriver 驱动） | 读+写 EC（H2RAM） | ✅ 读、写都可用（LM 限充用的就是它） |

`\\.\ACPIDriver` IOCTL（与 `source/MechrevoLite.Hardware/EcChargeLimit.cs` 完全一致）：

```
读：IOCTL = 2621482120 (0x9C402008)
    in  : int32 address（4 字节）
    out : 首字节 = 值（读返回 0 长度/失败 ⇒ 读不到）
写：IOCTL = 2621482124 (0x9C40200C)
    in  : int32 address（4 字节）+ 1 字节 value（共 5 字节）
```

- 地址是 EC 16 位地址；**同方可用窗口 = H2RAM `0x700–0x7FF`**；
- 打不开设备 ⇒ 驱动未装/未加载（LM 安装目录里带 `ACPIDriver` / `UWACPIDriver`）。

## 2. 字节语义（同方 · 已实测 + 源码常量）

源码里已有定义但**未接线**：`source/MechrevoLite.Fan/GpuPowerControlEncoding.cs`

```
0x743 (1859) ControlAddress        = 控制字节
        bit0 DynamicBoostFunCtrl
        bit1 DynamicBoostEnabled    ← DB 使能
        bit2 CtgpEnabled
0x744 (1860) ConfigurableTgpAddress
0x745 (1861) DynamicBoostAddress   ← DB 目标
0x746 (1862) MaximumTgpAddress     ← DB 最大 TGP（W）
```

官方 GCU「狂暴」档实测会写（模式切换瞬间同时变）：

| 地址 | 平衡/静音 | 狂暴 | 说明 |
|---|---|---|---|
| 0x743 | 0x01 | **0x07** | DB 使能（bit0+1+2） |
| 0x745 | 0x00 | **0xFF** | DB 目标 |
| 0x746 | 0x00 | **0x19 = 25W** | DB 最大 TGP |
| 0x7D4 | 0x00 | **0xFF** | 第二份 DB 目标（未定语义，与 0x745 同步） |
| 0x7D5 | 0x00 | **0x19 = 25W** | 第二份 DB max（与 0x746 同步） |
| 0x751 | 0x00 | 0x10 | 未知（与 0x787/0x7AB 成对翻转） |
| 0x7C4 | 0x20/0x28 | 0x30/0x38 | 未知（功耗预算？） |
| 0x7C6 | 0x04 | 0x00 | 未知 |

⇒ `enforced = 115W + DB max TGP`：+5→120W、+15→130W、+25→140W。

## 3. 脚本清单（都在 `tools/dev/ec-tgp-probe/`）

> 所有 `.ps1` 都**必须带 UTF-8 BOM**（PS 5.1 否则会把中文按 ANSI 解析 ⇒ 直接语法错误，见 §6）。
> 全部需要**管理员** PowerShell。

### 3.1 `ec-tgp-probe.ps1` —— 只读（ACPI WMI 通道）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ec-tgp-probe.ps1
powershell ... ec-tgp-probe.ps1 -Seconds 60 -IntervalSec 1 -PrintAll   # 连续采样
```

- 读 `0x740..0x74F` + `nvidia-smi`，打印变化；
- 走 `AcpiTest_MULong.GetSetULong`（Data = `0x1_0000_0000 + addr`）；
- 历史产物，保留作对照。

### 3.2 `ec-acpidriver-watch.ps1` —— 只读（ACPIDriver，小集合）

读 `0x740..0x747` + `nvidia-smi`，每秒打印变化。用于早期模式对比。

### 3.3 `ec-acpidriver-watch2.ps1` —— ⭐ 只读全窗口扫描（推荐）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ec-acpidriver-watch2.ps1 -Seconds 120
```

- 扫 `0x700–0x7FF` 全窗口，每秒 diff，**只打印变化的地址**（`0x743:01→07` 这种）；
- 起点会 dump 256 字节 hex 快照（16 字节一行）；
- 日志：`%TEMP%\ec-db-watch2.txt`；
- 用途：切模式时看**到底哪些字节变了**（区分 DB/TGP/其它）。

### 3.4 `ec-acpidriver-db-unlock.ps1` —— 写（只写 `0x743`，早期版本）

```powershell
powershell ... ec-acpidriver-db-unlock.ps1            # 写 0x743=0x07
powershell ... ec-acpidriver-db-unlock.ps1 -SameValueTest   # 写回原值（验证写通道）
powershell ... ec-acpidriver-db-unlock.ps1 -Restore        # 回滚
```

- 日志：`%TEMP%\ec-db-log.txt`；
- ⚠️ 只写使能位、不改 `0x746/0x745`，所以 DB 上限仍是原值（要 140W 需 §3.5 全套）。

### 3.5 `ec-acpidriver-db-enable.ps1` —— ⭐ 写（完整版，推荐）

```powershell
# 写官方 GCU 狂暴那套（0x743=07 / 0x745=FF / 0x746=19 / 0x7D4=FF / 0x7D5=19）
powershell ... ec-acpidriver-db-enable.ps1

# 只读（看当前值，不写）
powershell ... ec-acpidriver-db-enable.ps1 -WhatIf

# 只改单个字节（验证固件会不会自己接管）
powershell ... ec-acpidriver-db-enable.ps1 -SetAddr 0x746 -SetValue 0x19 -MonitorSeconds 20

# 回滚到进入时的原值
powershell ... ec-acpidriver-db-enable.ps1 -Restore
```

- 日志：`%TEMP%\ec-db-enable.txt`；
- 流程：记录原值 → 逐字节写 → 回读 → 监视 20s（enforced/draw/temp/clock）。
- **写入成功判据**：回读 `0x743=0x07`、`0x746=0x19`、`0x7D4=0xFF`、`0x7D5=0x19`，且 `enforced=140W`。

## 4. 关键实测证据（2026-10-19）

| 场景 | 0x743 | 0x746/0x7D5 | enforced |
|---|---|---|---|
| 官方 GCU 切狂暴 | 0x07 | 0x19 / 0x19 | **140W** |
| 官方 GCU 切平衡/静音 | 0x01 | 0x00/0x05/0x0F 随档位 | 115/120/130W |
| **OpenRevo 切狂暴** | **0x01（从未写 07）** | 0x19↔0x05 变化 | **115W（FurMark 满载也只有 115W）** |
| 手动写全套（脚本 3.5） | 0x07 | 0x19 / 0x19 | **140W**（回读一致） |
| 手动开 DB 后切办公 | 0x07（没被关） | 0x05 | 120W |

补充：
- **DB 是动态的**：只有 GPU 有负载（如 FurMark 前台）时才维持 140W；负载一停，固件回写数值、`enforced` 掉回 115W；
- **物理模式按钮不能单独切模式**：无 GCU/接管软件时不响应，模式切换由 GCU（或接管软件）写 EC 完成。

## 5. 踩坑记录（重要，接手前必看）

1. **`AcpiTest_MULong` 写不了**：
   - 方法签名：`GetULong(Data:UInt32)` / `SetULong(Data:UInt32)` / `FireULong(Hack:UInt32)` /
     `GetSetULong(Data:UInt64, Return:UInt32)` / `GetButton(Data:UInt64, Return:UInt32)`；
   - 读用 `GetSetULong`（Data = `(1<<40) + addr`）可用；
   - `SetULong` 传入“地址+值”各种 32 位编码、`FireULong(Hack=…)` 各种组合 **全部不生效**（回读不变）；
   - ⇒ 结论：这条路写不能，改用 ACPIDriver。
2. **PowerShell `[ordered]@{}` 的整数键索引坑**：
   - `$d = [ordered]@{ 0x743 = 0x07 }`，`$d[1859]` 会绑到**索引（序号）重载** ⇒ 返回 `$null`（即使 `Contains(1859)` 为 True）；
   - 结果：脚本把 `[byte]$null = 0` 写进去 ⇒ **5 个字节全被写成 0x00**（本项目真实踩过）；
   - 正确取值：`$d.Item([object]1859)`；或者干脆用数组/`pscustomobject`。
3. **`.ps1` 必须 UTF-8 BOM**：PS 5.1 无 BOM 时把中文按 ANSI 解码 ⇒ 解析报 `Missing closing '}'`，且**退出码 1、什么日志都不写**。
4. **写 `0x743` 之前先写回同值测试**（脚本 `-SameValueTest` / `-WhatIf` 先看值），确认写通道和回读都正常再动真值。
5. **H2RAM 窗口是 `0x700–0x7FF`**：写窗口外地址不保证生效（`\\.\ACPIDriver` 是 H2RAM 通道）。
6. **写坏/写错后的回滚**：切一次 LM 的性能模式（固件会重写）或重启；脚本也有 `-Restore`。
7. **读 ≠ 可达**：ACPIDriver 对不可达地址可能返回填充值（历史教训），判据要结合回读与 nvidia-smi。

## 7. OpenRevo issue 结论（可直接引用）

> **Bug**：OpenRevo 控制台切「狂暴」不写 DB 使能位 `0x743`（恒 `0x01`），只改 `0x746/0x7D5`（DB 最大 TGP），
> 导致 Dynamic Boost 不启用、GPU 功耗上限停在 **115W**（FurMark 满载也只有 115W）；
> 官方 GCU 同场景写 `0x743=0x07 / 0x745=0xFF / 0x7D4=0xFF` ⇒ **140W**；
> 手动写全套后回读一致、enforced 变 140W，证明 EC 可控、缺的是控制台未写。

## 9. 2026-10-19 晚：工具化与补充实测

### 9.1 已验证的换算关系

- `enforced（驱动实际上限） = 显卡默认 TGP + DB 字节值`
- 本机 4060：默认 115W / 最小 5W / 最大 140W，DB 可调 0..25W
- 实测：`0x746=0x05 -> 120W`、`0x0A -> 125W`、`0x13 -> 134W`、`0x00 -> 115W`
- 因此：**只写已确认的 5 个字节，最低只能到 115W**，压不到 35W

### 9.2 动态读取（不写死机型）

```powershell
nvidia-smi --query-gpu=power.default_limit,power.min_limit,power.max_limit --format=csv
```
工具据此计算 DB 可调范围与期望值；读不到时**拒绝写入**。

### 9.3 官方控制台的写入时序（抓取自 Watch 日志）

- 切档时只写 `0x746` 与 `0x7D5`，两份**分开写**（间隔约 1 秒）
- `0x743/0x745/0x7D4` 在该次切换中未变
- 写入后 enforced 约 1 秒内跟随

### 9.4 离电时的完整变化（只读观察，未复刻）

| 地址 | 插电 | 离电 |
|---|---|---|
| `0x7CC` | `0x01` | `0x00`（最先变，疑似供电标志） |
| `0x7C4` | `0x38` | `0x20` |
| `0x751` | `0x00` | `0xA0` |
| `0x746/0x7D5` | 当前 DB 值 | `0x00` |
| `0x745/0x7D4` | `0xFF` | `0x00` |
| `0x743` | `0x07` | `0x05`→`0x01` |

离电后 enforced 掉到约 35W。**未做复刻**：伪造 `0x7CC` 等未确认地址可能影响充电与功耗策略，风险过高，已放弃该实验方向。

### 9.5 工具侧当前的封禁策略

- 可写白名单：`0x743 / 0x745 / 0x746 / 0x7D4 / 0x7D5`
- 未确认地址（`0x7C4 / 0x751 / 0x7CC`）：**只读展示，任何代码路径都不写**
- 写入流程：只读预演 → 原值记录 → 同值回写自检 → 写入（两份间隔 1s）→ 回读校验 + `nvidia-smi` 交叉验证 → 可选回滚
- 回滚只回写已确认地址；遇到未确认地址直接跳过

### 9.6 仍未解决 / 可继续

- [ ] 为什么"写 0x746/0x7D5 后驱动有时不跟随"：疑似需要驱动侧通知（NVAPI/ACPI 事件）或下一次模式切换；`nvidia-smi -pl` 在本机不支持，NVAPI 路线未验证
- [ ] 目标：稳定地把上限压到 115W 以下（例如 50W/35W），目前只有离电可达到，软件路径未找到安全开关
