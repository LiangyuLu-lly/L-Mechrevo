## 一、为什么动这三处（都是静态可证的缺陷，不靠猜）

### ① `efb652c` 的脚本化编辑插错了位置（2 处误插）

`efb652c`（"回读主体接线"）要加的是**启动时打一次**「宝龙达状态支持清单」。
它把整段插到了**每一个** `RestoreBaolongdaFanFirmwareControl();` 前面 —— 而那个调用点有 **3 处**：

| 位置 | 本意 | 实际 |
|---|---|---|
| `ApplyBaolongdaBackendAsync`（启动） | ✅ 打一次清单 ＋ 交回固件 | ✅ 正确 |
| `SaveBaolongdaFanCurve`（关曲线时） | ❌ 只该交回固件 | ⚠️ **每次关曲线都同步跑 14 个功能号的只读快照**（卡 UI、日志突然刷一大段） |
| `Dispose`（退出） | ❌ 只该交回固件 | ⚠️ 关机路径白跑一遍 WMI（退出变慢、日志噪音） |

⭐ 旁证：三处的收尾都是同一行 `}RestoreBaolongdaFanFirmwareControl();`（`}` 和语句粘在一行），
这正是"按字面插入到每一处匹配点"留下的痕迹。

### ② `FanCurveDecider` 写好了却**没人用**

`FanCurveEngine.cs` 里的 `FanCurveDecider`（回差 3℃：升温立刻写 / 降温过回差 / 不变不写）
有整套自检（`tools\dev\fancurve-selftest` 里 "回差防抖" 那一节），但生产代码里**零调用点**：

```
grep -rn "FanCurveDecider" source\      ⇒ 只有定义，没有 new / Decide
```

而 `ApplyBaolongdaFanCurveStep` 直接调 `FanCurveEngine.ResolveRpm(...)` 然后**每 3 s 无条件重写**
两通道 ＋ 手动开关（`TrySetFanManualViaBackend` 每 call 打一行日志）⇒ 约 **1200 行/小时**的日志，
以及每 3 s 一次 `PrepareFanManualControl()` ＋ 2 次转速写 ＋ 开关写 ＋ 回读。

### ③ 曲线没有「关掉」的入口（交接文档待办 #1）

`FanCurveForm.FlushPendingAsync` 里保存时硬编码 `Enabled = true`，界面上**没有任何开关**。
⇒ 机主一旦拖过曲线，软件闭环**永久生效**，想停只能手改
`%APPDATA%\MechrevoLite\fan_curve_bd.cfg`。

## 七、追加（同日）· 转速百分比按**原厂口径**修正

> 用户反馈：「40 系控制台可以显示转速百分比，LM 不行」。
> 查实：**不是没显示，是分母不同** —— LM 40% vs 官方 33%（同一时刻、同一台 4070）。

### 7.1 原厂 40 系的真实算法（反编译级）

材料：`_upstream\JiaoLongControl-Official\蛟龙游戏控制中心Setup.exe`（v0.3.15）
→ `innounp -x` → `{app}\蛟龙游戏控制中心.dll` → `ilspycmd`。

```csharp
Tuple<int, int> _CPUGPUFanSpeed = WMIMethodServices.GetValue<Tuple<int, int>>(WMIMethodName.CPUGPUFanSpeed); // 功能号 13
FanSpeed.Text = _CPUGPUFanSpeed.Item1 + " RPM";        // [4..5] 小端 = RPM
float num = (float)_CPUGPUFanSpeed.Item1 / 60f;        // ⭐⭐ 分母 = 60 ⇒ 100% = 6000 RPM
FANProgressBar.Value = (int)Math.Round(num);
FANTextBlock.Text = num.ToString("F0") + "%";          // ⭐ 整数百分比
```

真机对照（`MRID6-23` / 4070）：官方 **1965 RPM ⇒ 33%**（1965 ÷ 6000 = 32.75）
vs LM **1996 RPM ⇒ 40%**（旧分母 5000）。

### 7.2 LM 为什么是 40%（旧实现的错）

`MechrevoHw.FanRpmMaxForPercent` 旧逻辑：**读功能号 21 当"最大转速"**
（候选 50 或 50×100=5000，落在 1000~12000 就采信）⇒ 真机读到 50 ⇒ 分母 5000。

⇒ 而原厂对功能号 21 的用法是**手动转速设定值**：
```csharp
private void Set_FanSpeed(byte speedValue) {
    MaxFanSpeed.Text = speedValue.ToString();          // 显示"58"这类数字
    MaxFanSpeedSlider.Value = Set_MaxFanSpeedSlider(); // 22~58 映射到 0~100
    Task.Run(() => SetValue(WMIMethodName.MaxFanSpeed, speedValue));
}
WMISystemPerMode value = GetValue<WMISystemPerMode>(WMIMethodName.MaxFanSpeed);  // 读回来就是上次写的值
```
⇒ ⛔ **它不是 max**；我们拿它当分母，分母就随"上次手动设过多少"漂移（今天 50 → 5000，明天 58 → 5800）。

### 7.3 改法（一处常量）

| 位置 | 改动 |
|---|---|
| `MechrevoHw.BaolongdaFanRpmAtFullPercent`（新增常量） | `= 6000`（原厂 40 系口径；6000 = 协议满刻度 60×100） |
| `MechrevoHw.FanRpmMaxForPercent` | `=> UsesBaolongda ? 6000 : 0`；删掉读功能号 21 的整套逻辑、删 `FanRpmMaxIsReference` |
| `SettingsForm`（duty 计算） | 去掉 `!hw.FanRpmMaxIsReference` 判据 ⇒ 宝龙达恒按 `RPM ÷ 6000` 算；GCU 分支一字未改 |
| `DiagnosticBaolongdaInfo` | 功能号 21 标签改为「风扇手动转速设定值（读=上次设的转速，不是最大转速）」 |

预期：40 系上 LM 与官方**逐项一致**（1996 RPM ⇒ 33%）。
⚠️ 30 系**未**采用旧版 30 系控制台（v0.2.35）的 `rpm / 35f`（⇒ 3500）——
那是另一套年代／可能不同模具的包。30 系真机请对照官方控制台百分比；
若不一致，只改 `BaolongdaFanRpmAtFullPercent` 一处（需要时按代数拆开）。

⚠️ 风扇曲线窗口里的百分比**不动**：那是"曲线自己区间 1200~4200"的编辑刻度，不是转速百分比。
