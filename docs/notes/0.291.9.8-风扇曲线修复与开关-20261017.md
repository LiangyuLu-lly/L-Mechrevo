## 一、为什么动这三处（都是静态可证的缺陷，不靠猜）

### ① `efb652c` 的脚本化编辑插错了位置（2 处误插）

`efb652c`（"回读主体接线"）要加的是**启动时打一次**「宝龙达状态支持清单」。
它把整段插到了**每一个** `RestoreBaolongdaFanFirmwareControl();` 前面 —— 而那个调用点有 **3 处**：

| 位置 | 本意 | 实际 |
|---|---|---|
| `ApplyBaolongdaBackendAsync`（启动） | ✅ 打一次清单 ＋ 交回固件 | ✅ 正确 |
| `SaveBaolongdaFanCurve`（关曲线时） | ❌ 只该交回固件 | ⚠️ **每次关曲线都同步跑 14 个功能号的只读快照**（卡 UI、日志突然刷一大段） |
| `Dispose`（退出） | ❌ 只该交回固件 | ⚠️ 关机路径白跑一遍 WMI（退出变慢、日志噪音） |

⭐ 旁证：三处的收尾都是同一行 `}RestoreBaolongdaFanFirmwareControl();`（`}` 和语句粘在一行），
这正是"按字面插入到每一处匹配点"留下的痕迹。

### ② `FanCurveDecider` 写好了却**没人用**

`FanCurveEngine.cs` 里的 `FanCurveDecider`（回差 3℃：升温立刻写 / 降温过回差 / 不变不写）
有整套自检（`tools\dev\fancurve-selftest` 里 "回差防抖" 那一节），但生产代码里**零调用点**：

```
grep -rn "FanCurveDecider" source\      ⇒ 只有定义，没有 new / Decide
```

而 `ApplyBaolongdaFanCurveStep` 直接调 `FanCurveEngine.ResolveRpm(...)` 然后**每 3 s 无条件重写**
两通道 ＋ 手动开关（`TrySetFanManualViaBackend` 每 call 打一行日志）⇒ 约 **1200 行/小时**的日志，
以及每 3 s 一次 `PrepareFanManualControl()` ＋ 2 次转速写 ＋ 开关写 ＋ 回读。

### ③ 曲线没有「关掉」的入口（交接文档待办 #1）

`FanCurveForm.FlushPendingAsync` 里保存时硬编码 `Enabled = true`，界面上**没有任何开关**。
⇒ 机主一旦拖过曲线，软件闭环**永久生效**，想停只能手改
`%APPDATA%\MechrevoLite\fan_curve_bd.cfg`。

### 日志（机主看这个判断有没有生效）

```
宝龙达风扇曲线（⭐ 软件闭环 · ⭐ 单位 RPM ✅）：⭐ ch0 温度 62℃ → ⭐ 1500 RPM（⭐ 档位 15）
            · ⭐ ch1 温度 71℃ → ⭐ 2200 RPM（⭐ 档位 22） · ⭐ 确认=True · ⭐ 本轮有变化（...）
```

- 「本轮**有变化**」= 目标真的变了才写；「本轮**仅重申**」= 30 s 到点、值没变（重申控制权）。
- **不再**每 3 s 一条。若日志里 3 s 一条且全是一模一样的数值 ⇒ 说明用的不是 .8。

### 必须机主在真机验的（本机验不了）

1. **勾选后风扇是否跟随**：拖一条明显的曲线（如 60℃→1000 RPM、85℃→4000 RPM），跑压力测试，
   看转速是否随温度走；日志里应出现「本轮有变化」。
2. **通道没搞反**：CPU 单烤（如 AIDA64 FPU）时应是 **CPU 那路**转速上去，GPU 那路不该猛转。
3. **取消勾选是否交回固件**：转速回到固件自己的曲线（通常会降下来），日志出现
   「已交回固件自动控制并回读确认（两通道归零 ＋ 手动开关=关）」。
4. **退出程序后是否交回**（原来就有，回归确认）。
5. 复选框文字/位置在你机器上是否被挤压（`FlowLayoutPanel` 自动换行，理论上不会）。

## 四、给机主的一次性测试清单（0.291.9.8）

> ⚠️ 一次装完、一次测完，别分几轮问。**每项只要"是/否 + 现象"**。

**A. 键盘灯（30 系 / 40 系各自）**
1. 亮度 4 档（30 系）/ 5 档（40 系）能否区分？最高档是不是明显更亮？
2. 固定色（模式 2）选红/绿/蓝，颜色对不对？（40 系这一版有 500 ms 延迟）
3. 彩虹（模式 1）/ 轮播（模式 3）出不出颜色？（30 系模式 3 是"定义了但官方从不写"，可能无效 ⇒ 无效就回退）

**B. LOGO 灯**
4. 开/关是否联动尾部灯带？有没有出现颜色/效果下拉（应该**没有**）。

**C. 温度**
5. CPU 温度有显示吗（30 系靠 ACPI 热区 / 40 系靠 LHM→NVML）？
6. GPU 温度有显示吗（40 系）？日志里搜「GPU 温度探路」应该能看到走到哪一环。

**D. 风扇曲线（本版重点）**
7. 先用 `--fan-watch 30` 记下两通道的实际转速区间（空闲 / 单烤 CPU / 单烤 GPU），
   把曲线 band 与 16 个点调成"不比固件更保守"，**再**勾选「启用软件闭环」。
8. 见上面第三节 1~5。

**E. 其它**
9. 退出程序后风扇有没有"卡在高速"？（这是 `Restore` 的验收点）
