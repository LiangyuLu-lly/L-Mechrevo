# 无界 14XA 风扇曲线：fanctl 参考实现 vs LM 现状（2026-10-22）

- 参考来源：`D:\Downloads\fanctl.rar`（无界14XA / Uniwill EC 风扇控制小工具，Python + inpoutx64）
- 现象：**强冷能用，风扇曲线总是错乱**（机主 2026-10-22）
- 结论：强冷与风扇曲线在 LM 里走的是**两条完全不同的通路**；参考工具证明无界 EC 的风扇调速必须走「EC 占空比直写 + 高频维持」，而 LM 的风扇曲线走的是 GCU 固件曲线上传 —— 这就是错乱的根因方向。

---

## 1. fanctl 验证过的无界 EC 事实（WUJIE14XA，BIOS N.1.14MRO26）

| 用途 | EC 地址 | 说明 |
|---|---|---|
| I2EC 模式校验 | `0x200D` | bit0/1 必须为 1 才是读写模式 |
| CPU 温度 | `0x043E` | 1 字节，摄氏度 |
| GPU 温度 | `0x044F` | 纯核显机型恒 0 |
| 风扇1 转速 | `0x0464/0x0465` | 大端 16 位，RPM |
| 风扇2 转速 | `0x046C/0x046D` | 大端 16 位，RPM |
| **主扇占空比目标** | `0x1804` | 0~200 → 0~100% |
| **副扇占空比目标** | `0x1809` | 0~200 → 0~100%，**必须和主扇一起写** |

`0x1800-0x1809` 是两条对称 5 字节记录：A 上限 `0x1801=0xC8`、目标 `0x1804`（主扇）；B 上限 `0x1806=0xC8`、目标 `0x1809`（副扇）。两路独立，只写主扇时 EC 会把副扇目标沿斜坡挪到 0（几十秒后副扇停转）。

### 关键机制（fanctl 实测）

1. **必须高频持续写**：EC 热管理任务会周期性把目标寄存器覆盖回自己的值。
   - 2 Hz：被 EC 压制（副扇 2318→3433 缓慢爬行，不收敛）
   - 10 Hz：拉锯（2573↔5417 剧烈摆动，最差）
   - **25 Hz：完全压制，稳定达到目标**
   - 状态采样保持 2 Hz 即可（读端口不用跟着涨）。
2. **两条记录都要写**（`0x1804` + `0x1809`），只写一条 = 另一把扇失控。
3. **副扇下限 20%**：低于约 20% 副扇转不起来，EC 判堵转并闭锁该路（15% 时 341~937 RPM 挣扎）。
4. **释放策略：停就干脆停**——直接停止写入，EC 6~8 秒内接管；⛔ 不要“缓慢斜降到 30% 再松手”（会把 `0x1809` 锁在 0，副扇长时间停转）。
5. **不要长期把主扇压到极低**：强行 `0x0F`（约 7%）约 75 秒后 EC 会把副扇也降到 `0x06`，两把扇近乎停转、CPU 温度冲高。
6. **安全护栏**（fanctl 的做法）：保护阈值 85°C 强制 100%；临界 95°C 切回 EC 自动；手动下限 20%；副扇连续 12 秒 0 RPM ⇒ 停止写入交还 EC；异常即停写。
7. 端口访问：`\\.\inpoutx64` IOCTL（READ/WRITE_PORT），I2EC 窗口端口 `0x681/0x682/0x683`（先写地址高、地址低、再读写数据）。

## 2. LM 现在是怎么做的（两条路）

### 2.1 强冷（能用）

`MechrevoService.SwitchFanBoost` → GCU MQTT `Fan/Control` 的 `FAN_BOOST_ON/OFF`，回读 `FanBoost` 状态。
无界（`WujieSmuApu`）即使能力位未刷新也允许走 GCU 话题 ⇒ 所以强冷能用。

### 2.2 风扇曲线（错乱）

`FanCurveForm` → `MechrevoHw.SetFanCurve(type, duties)` → GCU `Fan/Control` 的
`SET_FAN_SPEED_CURVE_SETTING`（16 点 duty + `Name`/`Type`），再用
`GET_FAN_SPEED_CURVE_SETTING` 回读确认；`FanCurveSeen` 才显示曲线行。

⇒ 这是「GCU 固件曲线表」路线，与强冷的 `FAN_BOOST` 不是同一条路。
无界的 WJXY 载荷/EC 固件并不保证按这套 16 点表执行（EC 自己的热管理任务会覆写占空比），
所以保存后回读可能“看起来成功”，实际风扇行为却错乱。

## 3. 结论与建议实现

### 3.1 结论

- 无界风扇**实际可控的是 EC 占空比**（`0x1804/0x1809`），不是 GCU 的 16 点固件曲线；
- fanctl 的 25 Hz 双寄存器直写是被实测验证过的唯一稳定方式；
- 强冷走 GCU `FAN_BOOST`，与曲线不冲突，可以继续保留。

### 3.2 建议实现（Wujie EC 风扇曲线后端）

1. 新增 `WujieFanEc`（`source/MechrevoLite.Hardware/`）：
   - 复用 `I2ecInpOut` 的 inpoutx64 通道（同驱动、同 0x681-683 I2EC 窗口，本机已具备）或抽一个通用 I2EC 读写；
   - 校验 `0x200D` bit0/1；
   - **25 Hz 定时器**同时写 `0x1804` + `0x1809`（raw=`percent*2`，clamp 到 0..200）；
   - 读温度 `0x043E`、风扇转速 `0x0464/0x046C`（或复用 LM 现有 EC 转速读取做交叉校验）；
   - 安全：下限 20%、≥85°C 强制 100%、≥95°C 停止写入、副扇 0 RPM 看门狗、关闭窗口/异常立即停写交还 EC；
   - ⛔ 不做缓慢释放，直接停写。
2. UI：无界机型的 `FanCurveForm` 改为「温度 → 占空比 %」曲线（不再假装是 16 点 RPM 固件表），保存即启用 EC 直写；提供「交还 EC」按钮。
3. 与 GCU 曲线互斥：无界机型不再发 `SET_FAN_SPEED_CURVE_SETTING`（或仅保留能力探测），避免两条路抢风扇。
4. 验收：真机上对比 20%/60%/100% 的实际 RPM（fanctl 实测：20%≈1786-1807/1592-1631；60%≈4236-4269/3843-3993；100%≈5875-5891/5220-5486），确认曲线点与目标一致、不再错乱。

### 3.3 风险

- 需要本机已安装 **inpoutx64**（LM 不分发；无界电池电压修复已依赖它）；
- 25 Hz 写是“与 EC 抢寄存器”，必须有安全停写与看门狗；
- 不同 BIOS/EC 版本地址可能不同 ⇒ 先只读探测 `0x200D/0x1800-0x1809/0x0464` 确认再写；
- 与官方 GCU/控制台同时运行时可能互相覆盖 ⇒ 单写者原则。
