- `source\MechrevoLite.Hardware\MechrevoHw.cs:3805-3880` `RefreshRefreshRateFromActiveDisplay()`
  - 注释（:3806-3819）记录了**机主 2026-10-09 的原始反馈**：
    「针对多显示屏切换刷新率的处理不太行」「从外接显示器切回电脑内屏的时候刷新率不可用」
    「没有我电脑内屏那一档的刷新率()」「外接屏幕300 极光x内屏是180的」
  - 根因：`currentHZList`/`currentHZ` 是「GCU 报什么就是什么」的**单一列表**，不区分当前活动显示器

    ① 用内屏实测最大刷新率**过滤**物理不可能的档位 ② 把内屏实测档位**并入**列表（±2Hz 视为同档）
    ③ 当前值以内屏 `EnumDisplaySettings` 实测为准
  - **取屏口径极严**（:3814-3819）：只接受 `InternalScreenConfidence.Embedded`
    （输出技术 = `INTERNAL` 或 `DISPLAYPORT_EMBEDDED`（eDP））；
    **认不出 / 退化为 primary 时一律不校正**（否则会把外接屏档位塞进内屏那一行 = 回归）
  - `ScreenNative.cs:17-22` `InternalScreenConfidence { None, UniqueName, Embedded }`；
    `:35-39` `IsEmbeddedOutput`；`:124-230` `FindLaptopScreen` 用 **`QDC_ONLY_ACTIVE_PATHS`（只查活动路径）**

## 三、⭐ 待修的三处（⭐ 有用户报告时直接开工）

### 待修 ① —— GCU 不可用时，从 Win32 重建 `hzList`（⭐ 优先）
- **现象**：GCU 不可用 ⇒ `HzList` 空 ⇒ `SupportsDisplayRefresh=false` ⇒
  `SettingsForm.cs:10217-10224` 的 `maxFrequency <= MIN_RATE` ⇒ **`tableScreen.Visible=false`** ⇒
  **整个刷新率区（含两个本来就能用的按钮）被隐藏** ❌
- **改法**：在 `MechrevoHw` 里加一条降级：**GCU 不可用 / `HzList` 为空时，用
  `ScreenNative.GetAvailableRefreshRates(内屏)` + `GetMaxRefreshRate` 重建列表**（仅在内屏可识别时）。
- **依据**：`ScreenControl.cs:24` `GetMaxRate` 已经是 Win32 读的；`ScreenNative.cs:296/364/399` 三个读接口都在。

### 待修 ② —— `service.SwitchRefreshRate` 降级到 Win32
- **位置**：`MechrevoService.cs:2660`
- **改法**：门槛不满足（`SupportsDisplayRefresh==false` 或 `HzList` 不含该档）**且**目标屏是内屏时，
  改走 `ScreenNative.SetRefreshRate(内屏, hz)`（并回读确认）。
- **注意**：`PerfModeBackend.cs:99` 与 `FunctionVerifier.cs:408` 会跟着受益；
  `MechrevoHw.cs:3819` 那句「读不到状态就不允许切换」的护栏要**有意放开**（否则降级永远进不去）。
- ⚠️ `SwitchAutoRefreshRate`（`GPU_DC_HZ`，插电/电池自动切刷新率）**无 Win32 等价物**，
  若要备路需**自行实现**（监听电源状态 + 切 Win32 刷新率）—— 工作量中等，**暂不做**。

### 待修 ③ —— 加"第三个修正时机"：打开设置页时主动修正一次
- **原因**：现有修正在**【GCU 上报】**与**【显示配置变化】**两个时机。
  ⚠️ 若内屏关闭期间两者都不触发，`hzList` 会停在**外接屏的档位**；重开内屏后若也没触发事件 ⇒
  **显示错误**（正是机主 2026-10-09 那个现象）。
- **改法**：用户打开设置页 / 切到"屏幕"区域时，**主动调一次**
  `MechrevoHw.RefreshRefreshRateFromActiveDisplay()`（`SettingsForm.cs:12200/12204` 附近已有同类调用，可参照）。
- **本机无法验证**（用户没有外接屏条件）⇒ ⚠️ **等有外接屏的用户报告再做**。

## 四、⏸ 为什么现在不修

- ⭐ 用户原话：**「没条件测试外接屏幕 先存档 有用户报告bug了再修吧」**
- 待修 ① ② 的**收益主要在"GCU 不可用的机型"**（星耀/无界14 2026/老机型）和**外接屏场景**；
  当前主流机型（GCU 正常）**不受影响**，因此**不是紧急项**。
- ⚠️ 待修 ② 会**有意放开一条既有护栏**（`读不到状态就不允许切换`），风险高于收益时不该盲改。
- ⚠️ 待修 ③ **本机无法验证** —— 没有外接屏就没有验收手段（与 C-1 老机型接口同理）。

## 五、触发条件（⭐ 什么时候捡起来）

1. 有用户报告：**外接屏切换后刷新率显示/切换不对** ⇒ 做 **③**（并可顺带验 ①）
