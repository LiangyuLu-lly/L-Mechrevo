生成时间：2026-10-05
背景：本机（翼龙15Pro，RTX 4060 = **40 系**）为了测试 30 系功能手动装过 30 系 GCU，
      期间**核显模式按钮消失**；切回 40 系 GCU 后恢复。
      用户要求：**寻找更可靠的判断方式**，并对比蛟龙16S / 极光Pro 的诊断数据。

## 二、现状：核显模式由哪些信号决定（②的问题）

`MechrevoLite.Hardware\MechrevoHw.cs`：

| 行 | 成员 | 来源 | 稳定性 |
|---|---|---|---|
| :411 | `SupportsIgpuOnly => Capabilities.IgpuOnly` | GCU 能力上报 | ⚠️ **会变** |
| :2796 | `IgpuOnlyStatusSupport` | GCU **状态回读**，候选字段名 `IGpuOnlyConnectionSwitch_Support` / `IGPUConnectionSwitch_Support` / `IGPU_ONLY_SUPPORT` | ⚠️ **会变**（且可为 null） |
| :378 | `IgpuOnlyStatusSupport`（`bool?`） | 同上 | 三态（null = 没读到） |
| :409 | `SupportsDgpuDirect => DgpuDirectStatusSupport ?? Capabilities.DgpuDirect` | 同上（优先状态回读） | ✅ 稳（三台都是 True） |
| :413 | `SupportsGpuHotSwap => Capabilities.GpuHotSwap` | GCU 能力上报 | ✅ 稳（三台都 False） |
| **:435** | `if (DgpuGeneration != Gen30 && (SupportsDgpuDirect \|\| SupportsIgpuOnly))` | **静态代际硬编码** | ❌ 一刀切 |
| :419 | `CanOfferIgpuOnly` | 组合上表 | 继承上面的不稳定 |
| — | `DisplayRouteMatrix.AllowsIgpuOnly(gen)` | **静态协议表**：Gen30 行明确载明 `IGPU_ONLY_*` 全载荷 0 命中 | ✅ 对 30 系**有据**，但仍是"按代际推断" |

**两个问题**：
1. **`:435` 的 `Gen30` 硬编码排除** —— 对**真 30 系机型**有证据支撑（官方 30 系载荷确无 `IGPU_ONLY_*`），
   但它是**按代际推断**，一旦遇到"30 系 GCU 装在 40 系机器"（本机这种测试场景），
   或"某 30 系机型其实支持"，就会**误判并隐藏按钮** ✅
2. **能力位与状态回读没有取并集** —— 两者都是"会变的观测"，任一为真就应视为支持；
   现在 `SupportsIgpuOnly` 只看能力位，`IgpuOnlyStatusSupport` 只在别处用，
   于是**任一信号短暂为假就把按钮藏掉**（本机 18:46 那次就是）✅

## 三、重新设计：多信号并集 + 正向锁存 + 溯源日志

### 3.1 判据（建议实现）

```
CanOfferIgpuOnly =
    ( 任一"支持"信号为真 )
    其中"支持"信号 = {
        S1  能力上报          Capabilities.IgpuOnly == true
        S2  状态回读          IgpuOnlyStatusSupport == true        （字段名三种候选）
        S3  硬件显示路由       NVRAM 显示字节表明存在 iGPU-only 通路（见 3.3）
        S4  协议词汇存在       当前 GCU 载荷/服务实际认识 IGPU_ONLY_CONNECT_RB_*
    }
    并且 ( 没有"明确不存在"的硬证据 )
    硬证据 = DisplayRouteMatrix 对该代际标了 ProvenAbsent 且 S1..S4 全无
```

要点：
- **去掉 `:435` 里"代际 != Gen30"的一票否决** ✅
  -> 把"代际"从**否决条件**降级为**证据之一**（`DisplayRouteMatrix` 已有的 `ProvenAbsent` 语义）✅
- **S1/S2 取并集** ✅（任一为真即支持）✅
- 30 系 GCU 因为 `IGPU_ONLY_*` 词汇确实不存在，S1/S2/S4 自然全假 -> 仍然得到"不支持"✅
  **结论不变，但依据从"猜代际"变成"实际观测"** ✅

### 3.2 正向锁存（解决"按钮忽隐忽现"）

```csharp
// 一旦见过"支持"就锁存，避免瞬时读空导致按钮消失
private static bool _igpuOnlyEverSupported;
...
if (S1 || S2 || S3 || S4) _igpuOnlyEverSupported = true;
CanOfferIgpuOnly = (_igpuOnlyEverSupported || S1||S2||S3||S4) && !hardAbsent;
```
同 `_telemetryRpmSeen` 的思路（本次刚在风扇转速那儿用过）✅
**用户可见效果**：核显模式按钮不再因为一次读空而消失 ✅

### 3.3 S3：NVRAM / EC 显示路由（最接近硬件真值）

本机日志里**已经有**这条线索：
```
GPU route at startup: panel=Discrete dgpu=Present route=Direct;
NVRAM display byte @0x62=1 (len=180, intel-decoded=IgpuOnly; offset unverified)
```
-> 已有现成的读取实现（"NVRAM display byte @0x62"），只是标注了 `offset unverified` ✅
**价值**：这是**不依赖 GCU 上报**的硬件级信号，最适合用来给 S1/S2 做**交叉验证** ✅
**待办**：把 offset 弄准（对比官方 40 系 OSD 工具或在不同 显卡模式下采几次 0x62 的值）✅

### 3.4 溯源日志（让下次能查）

把"是谁决定的"打出来（`DisplayRouteMatrix` 已有 `EvidenceMark` 的概念，沿用）：
```
IgpuOnlyDecision: supported=True by=S1+S3 gen=Gen40 gcuVariant=40
                  S1=True S2=null S3=True S4=True hardAbsent=False
IgpuOnlyDecision: supported=False by=hardAbsent gen=Gen30 gcuVariant=30
                  S1=False S2=False S3=? S4=False
```
并把**同样的字段**写进诊断包的 `[能力位]` 段（现在只输出一个 `IgpuOnly` 结论 ✅ ->
改成输出 S1..S4 + 判定来源），这样**下一份蛟龙16S/极光Pro 的诊断包就能直接对照** ✅
