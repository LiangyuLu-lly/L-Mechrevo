## 第 1 节：极光X（24极光X 128+4070）—— 双屏之后刷新率认错

**背景（一句话）**：单屏时一切正常；**只要两块屏同时开过一次**，之后 LM 里的刷新率档位就认错了（会把外接屏的高刷当成内屏上限，之后不自己纠正）。

**步骤（照做，别点刷新率按钮）**
1. 装上面的包，打开 LM → 「设置」→ 找到「日志级别」一行 → 选「**全部**」（立即生效，不用重启）。
2. **只留内屏**（拔掉外接屏），等 1 分钟 → 截图 **A**。
3. **接上外接屏**，按 `Win+P` 选「复制」，让两屏都亮 → 截图 **B**。
4. **两屏同开**：再按 `Win+P` 选「扩展」，等 1 分钟 → 截图 **C**。
5. **切回内屏**：拔掉外接屏，回到 LM，**点一下「屏幕」那一行**（点行本身，不是刷新率按钮）→ 截图 **D**。
6. 打开记事本 → 文件-打开 → 粘贴 `%APPDATA%\MechrevoLite\config.json` → `Ctrl+F` 搜 `screen_max`，记下这个数字。

**每一步要看什么**
- 刷新率那一行的档位是不是**内屏那一族（180 系，即 60 / 180）**；出现 300 / 240 就是错的。
- 当前档（带彩边那颗）是不是真的档位 —— 内屏应为 180。
- 同一页那行「屏幕: ???Hz」有没有**谎报 300**。
- 第 5、6 步：`config.json` 里的 `screen_max` 有没有回到 **180**。

**要回传什么**
- 四张截图（A / B / C / D，与上面四步一一对应）。
- 日志两类行：记事本打开 `%APPDATA%\MechrevoLite\log.txt`，`Ctrl+F` 分别搜 `Hz screen identify` 与 `screen metrics`，把这两类行（带时间戳）复制回传。
- `config.json` 里 `screen_max` 那一行的值。

**隐私提示**：截图前避开/涂掉用户名、机器名、序列号、桌面文件名；日志里出现机名/用户名的地方涂掉，只留时间与 Hz、`screen_max` 这些数字。

## 第 2 节：极光Pro23 —— GCU 连不上（已定性：GCU 后端没就绪）

**背景（一句话）**：已经查明**不是**变体装错、**不是** clientId 被占（我们试过三个白名单 id，全都是「连上了但订阅立刻被断」）⇒ 问题出在 **GCU 后端（GCUService / GCUBridge）**。

**步骤一：管理员 PowerShell 里粘这四条（只读，不改任何东西）**
```powershell
Get-Service GCUBridge,GCUService | Select Name,Status,StartType
Get-Process GCUBridge,GCUService -EA 0 | Select Name,Id,Path,StartTime
netstat -ano | findstr :13688
Get-Item "C:\Program Files\L-Mechrevo\GCUService.exe","C:\Program Files\L-Mechrevo\GCUBridge.exe" -EA 0 | Select Name,Length,LastWriteTime,VersionInfo
```
（第 4 条若整段没输出，说明这两个 exe 不在该目录 —— 实际安装位置通常是 `C:\Program Files\L-Mechrevo\GCU\AiStoneService\`，以脚本第 ⑤ 节读到的路径为准。）

**步骤二：跑升级版诊断脚本**（在仓库里：`D:\openLM\tools\诊断-GCU连不上.ps1`）
- 把脚本拷到本机，右键「使用 PowerShell 运行」；或
  `powershell -NoProfile -ExecutionPolicy Bypass -File "诊断-GCU连不上.ps1"`
- **默认只读**（不启停服务、不写注册表、不改文件）。它新增了「后端健康判定」一节。
- 跑完会在**桌面**生成 `GCU诊断-<时间>.txt`。
- **可选**：若脚本提示「后端未就绪 / 13688 被非 GCU 进程占」，**由机主自行决定**是否用管理员执行它给出的 `-Fix`（或手工 `Restart-Service GCUBridge,GCUService`）→ 复测 LM 是否连上 → 仍不行就重新导出 LM 诊断包。

**要看什么**
- 脚本「后端健康判定」那节的结论原话：后端是否就绪、13688 有没有被非 GCU 进程占。
- 四条命令里：两个服务的 Status/StartType、进程有没有、13688 有没有人在听、两个 exe 的大小与版本。

**要回传什么**：桌面那份 `GCU诊断-<时间>.txt` + 上面四条命令的输出 + （若重导了）新的 LM 诊断包。
**隐私提示**：txt 与命令输出里若含机名、用户名、路径中的真实姓名，自行打码后再发。

## 第 3 节：蛟龙15（Gen30）—— 30 系 GCU 实装验证

**背景（一句话）**：我们做了「30 系 GCU 载荷补全 + 安装器升级时可靠停服 + `-Variant 30` 参数修复」，这台要验证 30 系 GCU 是否真的装上了、能用。

**步骤**
1. **先关掉 LM**（托盘右键退出，确认任务管理器里没有 L-Mechrevo.exe）。
2. 装 `LM-0.291-beta22-setup.exe`（或当时给你的那个专供 30GCU 测试包）。
3. 装完**重启电脑**。
4. 开机后打开 LM，看顶部是否显示「**GCU 已连接**」。

**要看什么**
1. 服务 `GCUBridge` 是不是 **Running**（管理员 PowerShell：`Get-Service GCUBridge`）。
2. 安装目录 `C:\Program Files\L-Mechrevo\GCU\AiStoneService\MyControlCenter\` 里有没有 `GCUService.exe`（有文件、有大小才算数）。
3. 注册表 `HKLM\SOFTWARE\L-Mechrevo` 的 `GcuVariant` 是不是 **30**（`Get-ItemProperty HKLM:\SOFTWARE\L-Mechrevo | Select GcuVariant,GcuPayloadSha256`）。
4. LM 里 GCU 相关功能能不能用：风扇、灯效、性能模式。

**要回传什么**：上面 ①②③ 的结果 + LM 右下角「诊断」导出的诊断包。
**若装完 GCU 未连接**，请把这两个日志一起回传：`C:\Program Files\L-Mechrevo\install.log`、`C:\ProgramData\L-Mechrevo\logs\gcu-install-*.log`。
**隐私提示**：诊断包与安装日志里可能有机名/用户名/序列号，发之前自行打码。
