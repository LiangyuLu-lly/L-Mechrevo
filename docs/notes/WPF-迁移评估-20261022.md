# WinForms → WPF 迁移评估（主题背景透底需求驱动）

- 日期：2026-10-22
- 触发：机主希望在设置里自定义主题色与背景图，并让背景图「透进」主界面卡片/按钮、滚动时平滑不重绘。
- 当前状态：WinForms 稳定版保留「主题色」，**背景图定制先隐藏**（UI 不暴露，config `ui_show_background_customization=1` 可恢复）。本文评估是否/如何迁移到 WPF。

---

## 1. 需求本质

1. 背景图铺满主窗口（cover，无留边）；
2. 卡片/按钮/开关呈半透明，能看见底图；
3. 上下滚动时内容平滑平移，**不出现残影/闪烁/一顿一顿**；
4. 其余功能（EC/GCU/WMI/灯效/诊断/安装器）行为不变。

需求 1-3 本质是「GPU 合成式 UI」，与 WinForms 的 HWND + GDI 模型冲突。

---

## 2. 为什么 WinForms 做不到（本会话实测结论）

| 尝试 | 结果 |
|---|---|
| `Color.Transparent` 递归透底 | 静态可看，滚动出现残影/重影 |
| 容器自绘「底图切片 + 半透明底」 | 静态变成「半透明黑色地图」，滚动脏 |
| `WS_EX_COMPOSITED` 整窗合成 | 与自绘叠加导致**不动都在闪** |
| 滚动快照平移（`CopyFromScreen` + Blit） | 每次滚轮都重新拍图，卡顿、交互复杂，残影仍可见 |
| 关/开双缓冲、整窗 Refresh | 分别导致闪烁或卡顿 |

根因：

- WinForms 每个控件都是**独立 HWND**，透明是「父窗口重绘模拟」，不是 alpha 合成；
- 滚动 = 移动子窗口 → 暴露区域触发 `WM_PAINT` → 透明控件逐层请求父级重绘；
- 没有合成层，无法像 WPF/WinUI 那样把「内容」当成一个可平移的视觉层。

结论：**在现有 WinForms 控件树上继续打补丁无法根治**，只能牺牲其中一项（透明度 / 平滑 / 交互）。

## 3. 候选框架对比

| 维度 | 继续 WinForms | **WPF** | WinUI 3 |
|---|---|---|---|
| 真 alpha 半透明 | ❌ 模拟 | ✅ 视觉树合成 | ✅ 组合层（Composition） |
| 滚动不重绘 | ❌ 移动子窗口 | ✅ `ScrollViewer` 视觉树平移 | ✅ 合成层平移 |
| 背景图 + 半透明卡片 | ❌ 很难 | ✅ `Image` + 半透明 `SolidColorBrush` | ✅ 同上，另有 Acrylic/Mica |
| 亚克力/模糊 | ❌ | ⚠️ 需 DWM P/Invoke | ✅ 内置（Win11 最佳） |
| 发布方式 | exe+DLL（现状） | exe+DLL，**安装器可沿用** | Windows App SDK，MSIX/self-contained，较重 |
| 与 Win32 互操作（EC/WMI/悬浮窗） | 原生 | 成熟（P/Invoke 可复用） | 可用但封装更厚 |
| 学习/改造成本 | 0 | 中（XAML/样式/数据绑定） | 中高（新工具链+打包） |
| 生态/控件 | 现有自绘控件 | 成熟、第三方多 | 较新、部分控件缺失 |

**推荐：若迁移，选 WPF**（发布链不变、Win32 互操作成熟、透明与滚动原生支持）；WinUI 3 仅在「明确要 Fluent/亚克力、且接受 MSIX 发布」时考虑。

## 4. WPF 如何实现本需求（技术验证点）

```xml
<Window Background="Transparent">
  <Grid>
    <Image Source="bg.jpg" Stretch="UniformToFill"/>
    <ScrollViewer VerticalScrollBarVisibility="Auto">
      <StackPanel>
        <!-- 半透明卡片 -->
        <Border Background="#CC1E1E1E" CornerRadius="8" Margin="8">
          <Button Content="平衡"/>
        </Border>
      </StackPanel>
    </ScrollViewer>
  </Grid>
</Window>
```

- 半透明：`#AARRGGBB` 画刷原生 alpha；
- 滚动：`ScrollViewer` 平移视觉树，子元素不重绘（GPU 合成）；
- 背景图：`Image`/`ImageBrush` + `Stretch=UniformToFill` = cover；
- 窗口亚克力（可选）：`DwmEnableBlurBehindWindow` / `SetWindowCompositionAttribute` P/Invoke；
- 主题色：`ResourceDictionary` + `SolidColorBrush` 动态替换，绑定即可全局生效；
- 真实圆角：`CornerRadius` 原生，无需 `Region` 裁剪。

性能：WPF 默认 DirectX 渲染，滚动平移不触发内容重绘，可稳定 60fps。

## 5. 迁移范围与工作量

### 5.1 可原样复用的层（不改）

- `MechrevoLite.Hardware`：EC/ACPI/GCU MQTT/WMI/PawnIO/风扇/电池等；
- `MechrevoLite.Mode`、`MechrevoLite.Usage`、`MechrevoLite.Update`、`MechrevoLite.Gpu` 等纯逻辑库；
- 诊断包、日志、配置（AppConfig）、安装器（Inno Setup）脚本；
- 第三方驱动调用（inpoutx64 除外，许可证已单独处理）。

### 5.2 必须重写的层（UI）

| 窗体/控件 | 规模 | 说明 |
|---|---|---|
| `SettingsForm`（主界面） | 约 2 万行 | 最大工作量：卡片/开关/滑杆/下拉/仪表盘滚动 |
| `SettingsDialog`（设置对话框） | 数千行 | 分组、行、主题卡片 |
| `RgbForm`/`LightForm` | 数千行 | 灯效编辑、颜色/预设 |
| `CustomModeForm` | 数千行 | 自定义功耗表格、滑块、数字框 |
| `FanCurveForm`、`CpuTuningForm`、`DisplayEffectEditorForm` | 中等 | 曲线绘制、调参 |
| `FeedbackForm`/`FirstRunGuideForm`/`DonateForm`/`AboutLicensesForm`/`CalibrationStartupForm` | 小 | 弹窗类 |
| 自绘控件族（`RButton`/`RCheckBox`/`RSlider`/`RComboBox`/`RScrollBar`/`BufferedPanel`…） | 中 | 用 WPF `Style/ControlTemplate` 重写外观 |
| 悬浮窗 `HardwareOverlay` | 中 | WPF 透明窗口 + Win32 定位 |

粗略估算：

- 原型验证（P0：主界面静态布局 + 半透明滚动）：**1~2 周**；
- 完整迁移（P1-P3，所有窗体 + 交互 + DPI + 验收）：**6~10 周**（按工作日估算，视细节要求）；
- 期间需保留 WinForms 版本作为回滚。

### 5.3 分阶段建议

- **P0 原型**：新建 WPF 工程，只做「主界面一页」：背景图 + 半透明卡片 + 滚动 + 主题色；验证 DPI、字体、性能、与现有逻辑库引用；
- **P1 主界面完整**：性能模式/快捷开关/显卡/屏幕/电池/灯效/更多开关 + 全部交互；
- **P2 次级窗体**：设置对话框、灯效、自定义、风扇曲线；
- **P3 收尾**：悬浮窗、托盘、诊断、安装器、验收与文档。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 现有自绘控件像素级外观丢失 | P0 先做 3~5 个代表作对比截图，确认可接受再继续 |
| DPI/多屏缩放差异 | WPF 用 DIP 布局 + `PerMonitorV2`，P0 在 100/125/150/200% 下验证 |
| 悬浮窗 Win32 行为 | 继续用 HWND + WPF 透明窗口，必要时用 WinForms 宿主做过渡 |
| 托盘/单实例/安装器 | 逻辑复用；安装器只需替换主程序目录结构 |
| 迁移期双版本维护 | 分支隔离，主线不切；P0 验证通过再定 |
| 第三方库（PawnIO 等） | 已封装在 Hardware 层，UI 不直接依赖 |

---

## 7. 结论

1. 「背景图透进内容 + 平滑滚动」在 WinForms 内**无法稳定实现**，这是框架模型限制（本会话多轮实测已验证）；
2. 若未来要做 UI 现代化，**WPF 是性价比最高的迁移目标**：透明/滚动原生支持、发布链不变、Win32 互操作成熟；
3. WinUI 3 技术上同样可行（且亚克力更漂亮），但发布/工具链成本更高，建议作为备选；
4. 短期策略：WinForms 稳定版先收尾（主题色可用，背景图定制隐藏）；如决定迁移，先做 P0 原型（1~2 周）再评估是否继续。
