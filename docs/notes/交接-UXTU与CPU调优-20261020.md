## 1. 先厘清 UXTU 在这里的角色

- **UXTU** = `JamesCJ60/Universal-x86-Tuning-Utility`（**GPL-3.0**）。
- LM（本仓库）**没有**把 UXTU 当运行期依赖、也没有内嵌它；LM 只把它当作：
  1. SMU 命令语义的**参考来源之一**（与 g-helper、RyzenAdj、ZenStates-Core 互相印证）；
  2. 许可清单里的第三方致谢项。
- 具体到 LM 的 CPU 调优（负压 CO / 固定频率 / FMax / Intel 偏移），UXTU 提供的关键事实是：
  - `Socket_FT6_FP7_FP8` 表里的 `set-cogfx 0xB7`（iGPU CO，Mobile/Strix 家族）；
  - 每核 CO 的编码方式：`(core << 20) | margin`（与 g-helper 的 `SetCoPer` 同构）。
- **许可边界**：
  - LM 是 **GPL-3.0**；
  - 只「取命令语义」不算代码复制，已在 `ATTRIBUTION-CO-ADDENDUM.md` 记录致谢与逐条对照；
  - 如果 OpenRevo 插件**直接复用 UXTU 的代码/表文件**，那属于 GPL-3.0 波及范围，插件必须按 GPL-3.0 兼容方式发布（或仅以进程外调用方式使用，不改/不链接其代码）。

## 2. LM 已经实现的能力（可直接照这个抄语义，不要抄实现）

### 2.1 UI 层：`source\MechrevoLite\CpuTuningForm.cs`

| 功能 | 说明 |
|---|---|
| 负压 CO（AMD） | 全核 + **每核**（core 0..N）分别设置 margin（LM UI 范围 `-30..0`） |
| 固定频率（AMD） | `amd-clock`，1000..`MaximumClock(codeName)` MHz |
| FMax | 持久化保存/恢复（跨重启不丢） |
| Intel 偏移 | `intel-core` / `intel-cache`（mV 偏移）与 `intel-ratio`（倍频） |
| 自动应用 | `_autoApply` 开关（带二次确认），失败/异常关机时不自动应用 |
| 状态提示 | 守卫状态 `_guardStatus`（跳过自动应用的原因） |

### 2.2 业务层：`source\MechrevoLite.Hardware\RuntimeCpuTuning.cs`

- 入口：`Probe()` → 返回 `CpuTuningProbe`（能力/选项/当前值/是否可写）；
- 应用：`Apply(id, value)`；恢复：`Restore()`；
- 选项 id 固定为：**`amd-co` / `amd-clock` / `intel-core` / `intel-cache` / `intel-ratio`**；
- 依赖检查：
  - `PawnIOWrapper.Connect()` 结果 → `CpuTuneAdminRequired` / `CpuTuneDriverMissing`（需要管理员、需要 PawnIO 驱动）；
  - SMU 初始化失败 → 顶层给「不可用」原因；
  - 环境变量 `LMECHREVO_FORCE_CPU_TUNING=1`（调试用，强制显示入口）。
- FMax 持久化键：`FMaxSavedKey` / `FMaxBaselineKey`（存 `AppConfig`，登记进 `ModelScopedConfig.ExactMachineScopedKeys`，**按机型隔离**，不会把 A 机器的值带到 B 机器）。

### 2.3 SMU 命令层：`source\PawnIO\RyzenSmuService.cs`

可直接对照语义的方法表：

| 方法 | 作用 | 备注 |
|---|---|---|
| `SetAllLimits(stapmW, fastW, slowW)` / `SetStapmLimit` / `SetFastLimit` / `SetSlowLimit` | CPU 功耗墙三档 | 单位 W |
| `SetStapmTimeSeconds` / `SetSlowTimeSeconds` | 功耗墙时间窗 | 秒 |
| `SetCoAll(value)` | 全核 CO | 负值=降压 |
| `SetCoPerCore(coreIndex, margin)` | 每核 CO | 编码 `(core << 20) | margin` |
| `SetCoGfx(value)` | iGPU CO | Renoir 族 `MP1 0x64`；Mobile/StrixHalo `PSMU 0xB7`（**B7 来源即 UXTU 表**；RyzenAdj 明确 StrixHalo 不发 B7） |
| `SetOcClock(mhz)` | 固定频率 | |
| `SetThm(celsius)` / `SetTctlTemp(celsius)` | 温度墙/结温目标 | |
| `SetBoostLimitFrequencyAllCores(mhz)` | FMax | |

架构分派（CO 家族命令）：

```
Renoir / Cezanne / Lucienne   → MP1 0x54
Mobile / StrixHalo / Krackan  → MP1 0x4B
Raphael / GraniteRidge / ...  → PSMU 0x06
```

回调/校验：每个写操作返回 `SmuStatus`；LM 写入后尽量**回读校验**（部分机型不支持读 CO → 给 `CpuTuneNoReadCmd`，只提示、不假装成功）。

### 2.4 安全守卫：`source\MechrevoLite.Hardware\CpuCoAutoApplyGuard.cs`

- 三态：`clean` / `first_run` / `abnormal`；
- 键：`cpu_co_clean_exit`、`cpu_co_guard_armed`、`cpu_co_guard_boot`、`cpu_co_guard_verdict`；
- 规则：**异常关机/蓝屏后，下次开机不自动应用 CO**；只有正常退出才保留「自动应用」资格。
- 插件也必须实现同类守卫（至少做到“上次异常退出→本次不自动写”）。

## 3. 给 OpenRevo 插件的建议架构

OpenRevo（`faintonce/open-revo`）是**闭源**的（仓库无源码，只有 README/docs/发布二进制）。结论：

> ⛔ 不要尝试注入/改 OpenRevo 本体；✅ 做一个**独立的进程外 helper**，插件只负责调用它。

推荐形态：

```
OpenRevo 控制台（闭源）
   └─ 插件（JS/TS 或 C#，取决于其插件机制）
        └─ 调用 lm-cputune-helper.exe（我们提供，管理员权限）
             ├─ 只读探测：CPU 代号 / SMU 版本 / 支持命令 / 回读能力
             ├─ apply：只写补丁里非 null 的项 → 每项回读 → 失败回滚
             └─ 守卫：异常退出后拒绝自动应用
```

通信建议（任选其一，按 OpenRevo 插件能力定）：

1. **CLI + JSON**（最简单）：`helper probe --json` / `helper apply --json '<patch>'`；
2. **本地命名管道**（常驻，避免每次取管理员）；
3. **本地 HTTP（127.0.0.1 + token）**（仅当插件只能发 HTTP）。

### 3.1 建议的数据契约

```jsonc
// probe 返回
{
  "cpuCodeName": "Rembrandt",
  "vendor": "amd",              // amd | intel | unknown
  "smuVersion": "0x…",
  "features": {
    "coAll": true, "coPerCore": [true, true, …],
    "coReadback": true,
    "ocClock": true, "fmax": true,
    "stapmLimits": true, "tctl": true
  },
  "current": { "coAll": -20, "coPerCore": [-20, …], "fmaxMhz": 4300, "stapmW": 45 }
}

// apply 请求（只写非 null 的项；null/缺省 = 不动）
{
  "coAll": -25,
  "coPerCore": [-30, -25, null, …],
  "fmaxMhz": 4200,
  "stapmW": 45, "fastW": 65, "slowW": 55,
  "tctlC": 95
}
```

### 3.2 关键原则（从 LM 的实践抄）

1. **只有用户改过的项才写**（可空模型）——参考 `DOUZHUANZHE-Control` 的 `SmuOverrides` 思路；
2. **写后必回读**，读不到就如实提示「已写入但无法验证」，不要假装成功；
3. **失败回滚到写前值**；
4. **单写者**：与 GCU/官方控制台/其它调优工具同时写 SMU 会互相覆盖 → 插件启动时检查/提示；
5. **默认只读**：探测阶段不写任何东西；
6. **异常退出守卫**：开机不自动应用上一次的 CO；
7. 需要管理员 + PawnIO 驱动（或改用 RyzenAdj 自带驱动，注意其版本/架构支持表）。

## 4. 可复用的“命令语义表”（插件实现用）

> 只列语义，具体指令字节/寄存器以 PawnIO/RyzenAdj 当前版本为准。

| 功能 | AMD 通道 | Intel 通道 |
|---|---|---|
| 全核 CO | SMU CO 命令（家族分派 0x54/0x4B/0x06） | 不适用（用 core/cache 偏移 + ratio） |
| 每核 CO | `(core << 20) | margin`（margin 为负数补码） | 不适用 |
| iGPU CO | Renoir 0x64 / Mobile 0xB7（StrixHalo 不发） | 不适用 |
| 固定频率 | SMU OC clock | MSR 0x150 OC mailbox（PawnIO `IntelMSR.bin`） |
| 功耗墙 | STAPM/FAST/SLOW（W） | PL1/PL2（MSR，需机型/BIOS 支持） |
| 温度墙 | Tctl/Thm（℃） | TjMax offset（TCC，非所有机型可写） |
| FMax | Boost limit frequency（MHz） | ratio 上限 |

## 5. 已知坑（LM 踩过的，按重要性排序）

1. **架构差异**：0x54 / 0x4B / 0x06 用错 = 写入无效或蓝屏风险；必须按 CPU code name 选表。
2. **每核写编码**：写用 `core << 20`、读用裸核号（读写不一致，LM 注释里专门标过）。
3. **读回不一定支持**：部分型号 CO 能写不能读 ⇒ 必须允许“已验证/未验证”两种结果。
4. **PawnIO 权限**：无管理员或驱动未装 → 明确提示，不要静默失败。
5. **异常关机**：不加守卫直接开机自动应用，可能反复蓝屏 → 必须实现 `CpuCoAutoApplyGuard` 同款逻辑。
6. **值与机型绑定**：同一份 CO/FMax 不能跨机型复制（LM 用 `ModelScopedConfig` 按机型隔离）；插件也要按机器 ID 分组存。
7. **厂商软件抢占**：GCU/官方控制台/其它工具写同一个 SMU 寄存器会打架；插件应检测并提示用户关闭其它调优软件。
8. **Intel 与 AMD 完全不同通道**：别试图用一套命令兼容两边。

## 7. 给另一个会话的“一句话任务书”

> 用上面第 3 节的进程外 helper 架构，实现 OpenRevo 控制台的 CPU 调优插件：
> 先只读探测（CPU/SMU/能力/当前值），再支持「只写用户改过的项 + 写完回读 + 失败回滚 + 异常退出守卫」，
> 覆盖 AMD CO（全核/每核）/固定频率/FMax/温度墙 与 Intel core/cache 偏移/ratio；
> 与 LM 共用同一套命令语义，但不要复制 LM 或 UXTU 的源码（按许可边界处理）。

**验收清单**

- [ ] `probe` 在 AMD 与 Intel 机型上都能给出正确能力表（读不到时明确写「不可用原因」）；
- [ ] `apply` 只写非空项，逐项回读，失败回滚并如实返回；
- [ ] 异常关机后不再自动应用（守卫生效）；
- [ ] 与 GCU/官方控制台同时运行时有提示；
- [ ] 无管理员/无 PawnIO 时给明确可操作提示，不静默失败；
- [ ] 不跨机型复用保存的 CO/FMax 值。
