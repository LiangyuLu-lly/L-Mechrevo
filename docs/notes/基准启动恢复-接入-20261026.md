## 2. 启动恢复执行时序/安全

`StartupRecoveryService.Schedule()`：

1. 进程内只调度一次（`Interlocked`）。
2. 后台 `Task.Run` 轮询 `WpfBackend.Hw`，最多 **60s**，要求 `Hw != null && Hw.IsConnected`；超时日志跳过、不重试。
3. 依次执行（每项独立 `try/catch`，一项失败不阻塞下一项）：
   - `BatteryLimitRestore.RunOnce`
   - `RunDeferredFanStartupCleanup`
   - `RuntimeCpuTuning.ApplySavedOnStartup`
   - `WujieFanCurveAutoApply.Schedule`
4. 结束日志：`[startup-recovery] 启动恢复调度结束`。

说明：
- CPU/风扇/限充可能写硬件/EC/SMU，这是旧启动行为；本次构建**未执行**（见 §5）。
- 若后端 60s 未就绪（无硬件/PawnIO 未装/权限不足），只记日志，不改变 UI。

## 6. 风险

1. `startup` 隐藏窗口依赖 `SystemIdle` 时序；若 `OriginalStyleWindow` 在更晚的异步路径打开 wide/首启窗，可能短暂/持续出现，需要真机验收。
2. `RuntimeCpuTuning.ApplySavedOnStartup`/`RunDeferredFanStartupCleanup` 写硬件；与旧行为一致，但 WPF 后端连接时序如早于模式恢复，可能与 `RestorePerfModeOnStartupAsync` 竞争；两者内部各有门控/一次性，建议真机日志核对顺序。
3. 未接电源事件，唤醒自动切档仍缺失（task-22 P0）。
