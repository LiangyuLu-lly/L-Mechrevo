## 本版相对 `.5` 的实质改动

### ⭐ 一、探测判据与能力位解耦（`0d12bf3`）—— **本版最重要**

**根因**：`BaolongdaWmi.TryCreate()` 把「**功能号 22（CPU 温度）能读**」当成**唯一**活体证明。
30 系机型读不到功能号 22 ⇒ 判定"认不出宝龙达" ⇒ **整机退回 legacy** ⇒ 所有宝龙达功能失效。

诊断包实证（机主 `MRID6` · 6800H + 3070Ti）：
```
白名单判定 = ✅ 命中
宝龙达 WMI 探测：实例打开了但读不到 CPU 温度 ⇒ 判为不可用（⛔ 不接管）
Hardware backend: legacy MICommonInterface; built-in modes only.
```

**为什么 30 系读不到功能号 22**（两条独立证据）：
1. **30 系官方包的 `WMIMethodName` 只到 18**（无 `CPUThermometer=22`），
   官方读温度用的是它自带的 **LibreHardwareMonitorLib**
2. **真机读功能号 22 失败**

**改法**：

```
板号命中白名单（MRID6 / MRID6-*）+ 类存在  ⇒  必须接管（22 读不到只记 WriteError）
板号未命中                                ⇒  要求 ProbeLiveness() 非 null
类不存在（非宝龙达机型）                   ⇒  FindInstancePath() 静默返回 null（⛔ 不误认）
```

`ProbeLiveness()` **四级判据，每条都带语义校验**（防 `0xFF` 填充 / 假数据）：

| 判据 | 校验方式 |
|---|---|
| 功能号 **22** CPU温度 | 读数必须在 `1..254`（0 与 255 都判无效） |
| 功能号 **8** 性能模式 | `raw ≤ 3`；⚠️ 刻意用 `TryReadByte` 而**非** `TryReadOperatingMode` —— 后者遇未知 raw 会报"未知原始值"，那是**运行期**该报的错、探测期打会误导 |
| 功能号 **11/12** Fn锁/触摸板锁 | ⭐ **`OutData[3]` 回显校验**（回应必须回显我们请求的功能号 ⇒ 证明接口按我们的协议应答，**最强证据**） |
| 功能号 **13** 风扇转速 | 长度 ≥8 且两通道 RPM `< 20000`（排除 `0xFF` 填充出的 65535） |

新增如实字段：`CpuTempAvailable` / `CpuTempCelsius` / `LivenessEvidence` ⇒ 进日志与诊断包。
CPU 温度不可用时 `WriteError` 明确记录「由 LM 自带 **LHM 兜底**，⛔ 不会显示成 0℃」。

⭐ **LHM 是主路、功能号 22 是备路**（`HardwareControl.cs:16`「CPU 温度已切到 LHM」2026-10-16）⇒
功能号 22 读不到**不影响温度显示**，只是它不能再当"整机资格"的证明。

诊断包新增两行：`探测活体证据 = ...`、`CPU 温度（功能号 22）= ✅可读(xx℃) / ⚠️不可用`
⇒ **以后拿包一眼看出凭什么接管**。

**写进注释的设计原则**：
> 探测（要不要接管这个后端）与能力位（每项功能能不能用）是**两层**，
> ⛔ 绝不能用一个功能的可读性去决定整机是否接管。

### 二、宝龙达不再显示同方（GCU）独有 UI（`eb11b91`）

用户真机反馈：「性能模式变成三档加下拉了，应当还是四个按钮没有下拉；电池限充还在」。

**Bug 1**：`SupportsModeProfileConfig` 只看显卡代际
```csharp
if (DgpuGeneration == DgpuGenerationKind.Gen30) { return true; }   // ⚠️ 宝龙达 3070Ti 也是 Gen30
```
⇒ 判真 ⇒ 显示「配置 N」下拉 ＋ **隐藏「自定义」按钮**（只剩 3 档）。
**修法**：加 `if (UsesBaolongda) { return false; }`（挡在 Gen30 之前）。
下游全部自动受益（同读一个属性）：自定义按钮恢复、配置下拉隐藏并回落面板高度、`ResolveModeProfileIndex` 回落 0。

**Bug 2**：电池三档未隐藏。判据来自 `ApplyChargeLimitSliderGating`；
宝龙达有 EC 通道（`flag=true`）但**无任何限充通路**（EC 直写无 `UWACPIDriver`、GCU 三档无 GCU），
且机主残留了 `ec_charge_limit=1` 强制放行 ⇒ 三档可点、点了只弹「GCU 未连接」。
**修法**：新增 `ApplyChargeLimitTierVisibility(bool)` —— 三档按钮 + 宿主 `modePanel` 一起隐藏、
第 2 行行高收 0、幂等短路、⛔ **不删控件不删代码路径**（用户明令「注意不删三个按钮」）；
`panelBattery` 整块隐藏（依据「应该是整块不显示」）。
⚠️ 若要改回「只藏三档、保留卡片」⇒ 去掉表达式里的 `!baolongdaNoChargeLimit &&` 即可。

### 三、宝龙达彻底不显示「核显模式」UI（`d4075a6` ＋ `400f220`）

用户原话：「宝龙达没有核显模式，首次提示的核显模式只给同方开放，设置里面核显模式显示也只给同方开放」。

- `IgpuOnlyUiRowAvailable()` 加宝龙达排除 —— ⚠️ **必须显式排除**：原判据只排 `Gen30`/`NoDgpu`，
  而 `dgpu_generation` 未探出时是 `Unknown`（`Unknown != Gen30` ⇒ 仍判可用）。
  **判据优先于配置**：即使 `igpu_only_ui=show`（手动强制显示的后路）也不显示 —— 正是要"连后路都不给"。
- `FirstRunGuideForm` 首次引导**第 4 步整步不建**（`RowCount 5→4`、第 5 步行号回落）；
  `PersistIgpuOnlyChoice()` 直接 return ⇒ **`igpu_only_ui` 与 `igpu_only_asked` 都不写**
  （写了 `asked=1` 会让用户以后换同方机器永远不再问 = 隐性数据损坏）。
- `ShowFirstRunGuideIfNeeded()` 不调 `TryClaimIgpuOnlyGuide()`；`ShowIgpuOnlyGuideIfNeeded()` 加排除。
- ⭐ `OpenSettingsDialog()` 打开前按**当前**判据落一次 `Visible` —— 堵住两条漏出路径：
  `SettingsDialog.cs:276` 把传入面板**硬设 `Visible=true`**（而 `SyncIgpuOnlyUiChoice()` 只改 `Enabled`）；
  且 `EnsureSettingsDialogBuilt()` **幂等** ⇒ 预热时判据若为 true 行会被建进去，之后判据变 false 也不重建。

### 四、顺带查清一个"疑似 bug"（虚惊）

「**核显省电**」三态行判据走 **GCU 能力位** `IGpuOnlyConnectionSwitch_Support`，
宝龙达的 `ItemSupport` 里**没有这个键** ⇒ `Flag()` 返回 false ⇒ **天然正确隐藏**。

⭐ **由此得出一条规律**（值得写进以后的排查指南）：

| 判据来源 | 宝龙达下 |
|---|---|
| **GCU 能力位**（`Flag("XXX_Support")` 读 `ItemSupport` 注册表） | ✅ **天然正确**（无 GCU ⇒ 键缺失 ⇒ 全 false） |
| **自己按显卡代际判**（`GpuGenerationProvider.Current().Generation`） | ⚠️ **可能漏**（宝龙达常配 30 系显卡 ⇒ 撞上"同方 30 系"判据） |

⇒ **凡是"按显卡代际"的 UI 判据，在宝龙达机型上都要过一遍** —— 这是系统性风险点。
