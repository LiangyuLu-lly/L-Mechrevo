# 存档 —— 50 系 AMD 机型隐藏「纯核显模式」（⭐ 已查清，⭐ 暂不做）

> **状态**：⏸ **已调查清楚，⭐ 未动任何代码**。用户 2026-10-15 决定：「那就先查 不做」。
> 本文只记录**已查实的事实**与**待改的精确位置**，便于将来直接开工。

## 一、用户需求（⭐ 原话）

> **「还有对于50系的AMD CPU机型默认隐藏纯核显模式(它们可能硬件上不支持硬切换核显) 不要误伤核显省电功能」**

拆成两条：
1. **50 系 + AMD CPU 机型** ⇒ **默认隐藏「纯核显模式」**（硬件可能不支持硬切换核显）
2. ⚠️ **绝不能误伤「核显省电」** —— 那是**另一个功能**，该显示还是显示

---

## 二、⭐ 关键结论：两个功能**本来就是分开的**（误伤风险天然很低）

| | **纯核显模式**（用户截图那颗「核显模式」按钮） | **核显省电** |
|---|---|---|
| 语义 | **显示路由**切换（dGPU 断电/移出显示链路，需重启） | **软件层省电**（dGPU 低功耗，不切路由、不重启） |
| 命令 | `DGPU_DIRECT_CONNECT_TOGGLE_ON/_OFF/_IGPU`（+ `_RESTART`） | **`IGPU_ONLY_CONNECT_RB_ON/_OFF/_AUTO`** |
| 写路径 | NVRAM `OemDisplayMode`（+ WMI iGPU-only，视世代） | WMI `0x300000001` / `0x300000000` |
| 回读字段 | `CurrentGpuMode` / `GpuModeStatusVersion` | **独立字段** `IGpuOnlyConnectionSwitch_Status` ⇒ `MechrevoHw.IgpuOnlySaveMode` |
| **可见性判据** | **`MechrevoHw.CanOfferIgpuOnly`**（`MechrevoHw.cs:716`） | **`SettingsForm.IgpuSavingRowVisible`**（`SettingsForm.cs:11553`，**独立方法**） |
| UI 控件 | `buttonEco`（显卡模式行） | `_igpuSavingRow`（OFF/ON/AUTO 三颗，`SettingsForm.cs:6236`） |

> ⭐ 代码注释**明确写死了这个区分**（`IgpuOnlySaveModeDecision.cs:84-85`）：
> 「**显示路由**（`CurrentGpuMode`/`GpuModeStatusVersion`），而**核显省电有独立字段**
> （`IGpuOnlyConnectionSwitch_Status` ⇒ `MechrevoHw.IgpuOnlySaveMode`）」

⇒ ⭐⭐ **改 `CanOfferIgpuOnly` 不会碰到 `IgpuSavingRowVisible`** ⇒ **不会误伤核显省电** ✅

## 三、「纯核显模式」现在的显示判据（⭐ `MechrevoHw.cs:716-775`）

`CanOfferIgpuOnly` = **三态 UI 模式**（`IgpuOnlyUiMode`：`auto`/`show`/`hide`，用户三选）
                ＋ **硬件权威判据** `IgpuOnlyHardwareVerdict`（`bool?`：true/false/null 未知）

分支（按优先级，行号取自当前树）：
- `:729` **`DgpuGeneration == Gen30`** ⇒ **L1 硬屏蔽**（不显示）—— 注释：30 系点了确实没用
- `:745` **`DgpuGeneration == NoDgpu`**（无独显）⇒ 不显示
- `:748` **`IgpuOnlyHardwareVerdict` 有结论** ⇒ 以它为准（true 显示，含 40 系）
- `:771` 兜底：`IgpuOnlyAttempt.TrySucceeded`（用户**真试成功过**才显示）
- 其余按用户三态：`show` ⇒ 显示 · `hide` ⇒ 隐藏 · `auto` ⇒ 由上面各条决定

相关属性：
- `:692` `DgpuGeneration => GpuGenerationProvider.Current().Generation`
- `:624` `SupportsDgpuDirect => DgpuDirectStatusSupport ?? Capabilities.DgpuDirect`
- `:626` `SupportsIgpuOnly => Capabilities.IgpuOnly`
- `:688` **`SupportsGpuHotSwap => Capabilities.GpuHotSwap || (Gen50 && IgpuOnlyStatusSupport == true)`**
  ← ⭐ **热切换（免重启切核显）= 50 系专属**，就是本需求要限制的那个能力的上游
- `:807-809` `GpuRowHiddenByGcuReports => DgpuDirectStatusSupport == false`
  ← 已有机制：**GCU 上报"不支持独显直连"⇒ 整行隐藏**（⚠️ 注释明说它**只管整行、不参与 `CanOfferIgpuOnly`**）
- `:643` `HasReliableIgpuOnlyCapability => SupportsIgpuOnly && DgpuGeneration != Gen40`
- `:658` `IgpuOnlyUiIsGuess`：`Gen30` 或 `IgpuOnlyHardwareVerdict` 有值 ⇒ 都不算"猜"

已存在的**按世代**白名单：`MechrevoLite.Gpu\DisplayRouteMatrix.cs:86-91` `AllowsIgpuOnly(generation)`
- 它检查**该世代 console 协议里有没有 `IGPU_ONLY_CONNECT_RB_ON`/`_OFF`**
- 世代路由表（同文件 `:31/:32/:40/:48`）：**Gen30 = ProvenAbsent** · **Gen40 = 有** ·
  **40B = ProvenAbsent** · **Gen50 = 有**（且带 `_AUTO` + `GPU_HOTSWAP_ON/OFF`）

## 四、⭐ 缺口：**CPU 厂商判据在全树【不存在】**

- grep `IsAmd` / `IsIntel` / `AmdCpu` / `IntelCpu` / `CpuVendor` / `CpuBrand` / `IsRyzen` / `Win32_Processor`
  ⇒ **全部 0 命中**
- ⇒ ⭐ 「**50 系 + AMD CPU**」这条**现在没有判据可用**，要做就得**新建一个 CPU 厂商检测**

可选实现（按推荐排序）：
1. **注册表**（推荐）：`HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0` 的
   `VendorIdentifier` ⇒ `"AuthenticAMD"` / `"GenuineIntel"`
   ✅ **免 WMI** · ✅ **启动早期即可读** · ✅ 一行代码
2. **WMI**：`Win32_Processor.Manufacturer`（`"AuthenticAMD"` / `"GenuineIntel"`）
   ⚠️ 需 WMI 可用/有延迟（树里 WMI 用得多，非阻塞）
3. **CPUID 指令** 或 `IsProcessorFeaturePresent` ⚠️ 复杂、收益低
4. ⚠️ 用 `RyzenSmu`/`IntelMSR` 的可用性反推 ⇒ **不可靠**（那取决于驱动/机型，不是 CPU 身份）

## 五、⭐ 待改（⭐ 将来做时，两处 + 一个待定项）

### 改动 ①（必须）—— 新建 CPU 厂商判据
- 位置建议：`source\MechrevoLite.Hardware\`（与 `MechrevoHw` 同级，或作为 `MechrevoHw` 的静态属性）
- 建议实现：读注册表 `VendorIdentifier`，暴露 `IsAmdCpu` / `IsIntelCpu`（**带缓存**，别每次读）
- ⚠️ 读不到时**返回"未知"**，**不要**默认当 AMD（避免误伤 Intel 机型）

### 改动 ②（必须）—— 在 `CanOfferIgpuOnly` 里加一条
- **`Gen50 && IsAmdCpu` ⇒ `return false`**（隐藏「纯核显模式」）
- ⚠️⚠️ **位置待你确认**（我倾向）：**放在 `IgpuOnlyHardwareVerdict` 分支【之前】**
  - 理由：这是「**代际 + 平台**级」的"硬件可能不支持"判断，应优先于 GCU 上报的能力位
  - ⚠️ 反方观点：若某台 AMD 50 系机器**实测确实能切**，硬屏蔽会**剥夺一个可用功能**
- ⛔ **`SettingsForm.IgpuSavingRowVisible`（`:11553`）完全不动** ⇒ 核显省电不受影响 ✅

### 待定项（⚠️ 需你拍板）—— 用户手工 `show` 时要不要也隐藏？
- 方案 A：**隐藏优先**（`show` 也不生效）⇒ 但因为"可能无显示输出"级别的问题，不该让用户强开
  - ⚠️ 副作用：**用户三选行里的 `show` 选项形同虚设** ⇒ 应**连那行一起隐藏**（更一致）
- 方案 B：**尊重用户 `show`** ⇒ 用户可以强开（⚠️ 有风险，但保留自由度）
- ⚠️ 我倾向 **A + 连三选行一起隐藏**（保持 UI 一致，避免"选了没用"的困惑）

  没有实测证据 —— 硬屏蔽一个"可能其实能用"的功能，风险高于收益
