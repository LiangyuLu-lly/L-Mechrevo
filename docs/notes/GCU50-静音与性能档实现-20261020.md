# 50 系 GCU：静音 / 性能档位的实现（协议事实提炼）

> 来源：50 系 GCU 服务端反编译（1.2.0.0）。只记协议事实，不抄代码。

## 1. 档位模型

| 档位 | 动作（Fan/Control） | 配置号键（MainOption.json） | 配置集合 |
|---|---|---|---|
| 办公 / 静音 | `OPERATING_OFFICE_MODE` | `OfficeProfileIndex` | `M2T1`～`M2T3`（部分机型 5 个） |
| 游戏 / 平衡 | `OPERATING_GAMING_MODE` | `GamingProfileIndex` | `M1T1`～`M1T3` |
| 狂飙 / 性能 | `OPERATING_TURBO_MODE` | `TurboProfileIndex` | `M3T1`～`M3T3` |
| 自定义 | `OPERATING_CUSTOM_MODE` | `CustomProfileIndex` | `M4T1`～（自定义档） |

- 每个「档位」下有多个「配置」（T1/T2/T3…），官方每个模式默认 3 个，部分机型 5 个；
- 配置号持久化在 `UserPofiles\MainOption.json`；切换配置时服务端会回写该 JSON（`WriteMainOptionToJson("…ProfileIndex", n)`）。

## 2. 一套配置里到底存了什么

反编译里每套配置（如 `M1T1_CustomizeValues`）字段一致：

- **CPU**：`PL1` / `PL2` / `PL1_dc` / `PL2_dc`，各自带 `*_Enabled` 使能位；
- **AMD 平台**：`AmdSPL`（= PL1）/ `AmdSPPT`（= PL2）；
- **GPU**：`DynamicBoostSwitch`、`DynamicBoostTotalProcessingPowerTarget`（TGP）；
- **静音相关**：`WhisperModeSwitch`（NV Whisper Mode 开关）。

⇒ 「静音档性能低」不是单独写死，而是**静音档绑定的配置里 PL/TGP 更低 + 风扇表更保守 + WhisperMode 打开**。

## 3. 切档流程（Fan 管理器）

```
SetOperatingMode(mode)
  → 按 mode 取对应 ProfileIndex（Gaming/Office/Turbo/Custom）
  → RefreshCurrentProfile(mode)          // 把该配置的值拷进 currentProfile
       CPU.PL1/PL2(/dc/Enabled)、AmdSPL/SPPT、GPU.DB/TGP、WhisperModeSwitch
  → 套用该档的风扇表（UserFanTables\M*T*.json）
  → 写 EC / ACPI（风扇目标、功率墙等）
切换离开时：
  → RestoreCurrentProfile(mode)          // 还原上一档的值
```

## 4. Whisper Mode（静音性能）

- 能力位：`GetNVGpuWhisperMode2p0Support()`；
- 写接口：`SetNVGpuWhisperModeStatus(bool)`、`SetNVGpuWhisperModeSetting(int)`、`SetNVGpuWhisperModeMinFps(int)`（经 GPU 厂商 SDK，NV 系即 NVAPI 封装）；
- 触发：档位配置里的 `WhisperModeSwitch` 为真时，切档过程中一并设置。

## 5. 「静音狂暴 / 高能狂暴」子模式（狂飙档内部）

- `Fan/Control` 动作：
  - `SET_CPU_CORE_OFFSET_SILENT`  + `{ "SILENT": 1 }`
  - `SET_CPU_CORE_OFFSET_EXTREME` + `{ "EXTREME": 1 }`
- 通过 `FAN`/`CPU` 状态回读确认；属于狂飙档内部的 CPU 核心偏移预设，而不是独立档位。

## 6. 与 LM 的边界

- LM 只发：`Fan/Control { Action: OPERATING_* }` + 可选 `ProfileIndex`；自定义档参数走 `SET_OPERATING_MODE_DETAIL` 一类字段；
- 档位参数、风扇表、WhisperMode 的执行都在 GCU 服务端；
- 50 系（1.2.0.0）与 30/40 系（1.0.2.70）字段命名一致，差异在版本/机型能力位；
- LM 侧现在额外保存自己的档位参数并在启动时重放（30/40/50 自定义档与 30 系每配置），GCU 的 `UserPofiles` 不再作为唯一事实源。

## 7. 40 系对照（能不能做静音档）

可以，结构完全同 50 系。40 系 GCU 载荷（1.0.2.70）里：

- `UserPofiles\`：`Mode1_Profile1/2`（Gaming）、**`Mode2_Profile1/2`（Office/静音）**、`Mode3_Profile1/2`（Turbo）、`Mode4_Profile1..5`（Custom）；
- `MainOption.json`：`GamingProfileIndex` / `OfficeProfileIndex` / `TurboProfileIndex` / `CustomProfileIndex` + `WhisperModeSwitch` / `WhisperModeSetting` / `WhisperModeMinFps_*`；
- 风扇表：`UserFanTables\M1T1..M1T5`（Gaming）、`M2T1..M2T5`（Office/静音）、`M3T1..M3T5`（Turbo）、`M4T1..M4T5`（Custom），另有 `DefaultFanTable_Office/Gaming/Turbo.json`；
- 默认参数差异（同结构，静音=低功耗配置）：Office `PL1/PL2=35W`、`TGP=150W`；Turbo `PL1/PL2=95W`、`TGP=175W`、core offset 50。

⇒ 40 系“静音档”就是 `OPERATING_OFFICE_MODE` + `OfficeProfileIndex` 指向的配置（低 PL/TGP + 保守风扇表），与 50 系同一套协议；`WhisperModeSwitch` 字段也在（NV Whisper Mode 需显卡/驱动支持）。

差异：40 系服务端是 1.0.2.70，目前只有部分反编译；上述结论来自 40 系载荷 JSON 与 50 系同构字段，实际动作确认以 LM 抓包/回读为准。

## 8. 40 系能不能「静音狂暴」（silent-turbo 子模式）

**不能（厂商子模式层面）**。判据如下：

1. 50 系静音狂暴走 `Fan/Control` 的 `SET_CPU_CORE_OFFSET_SILENT` / `SET_CPU_CORE_OFFSET_EXTREME` + `{"SILENT":1}`/`{"EXTREME":1}`；
2. 该能力位来源：`WMIIsTurboSubModeSupport() == 0x55`（EC/WMI 返回 85 才支持），GCU 再通过 `HKLM\SOFTWARE\OEM\GamingCenter2\ItemSupport\IsTurboSubModeSupport` 上报给应用；
3. 40 系 GCU 1.0.2.70 反编译里**没有** `IsTurboSubModeSupport` 的导出，也**没有** `SET_CPU_CORE_OFFSET_SILENT/EXTREME` 动作实现（这些是 1.2.0.0/50 系新增）；
4. 40 系里名字相近的 `CPU_SILENT_MODE_STATUS_ON/OFF`、EC `SilentMode`、`OSD_SILENTON/OFF` 是**另一套**（CPU/风扇静音模式），不是静音狂暴子模式。

⇒ 40 系可做「静音档」（Office 配置 + M2T* 风扇表 + 低 PL/TGP + WhisperMode，见第 7 节），但不能发静音狂暴子模式；LM 单方面发 40 系服务端也不会执行。

替代方案（若 40 系用户需要「静音狂暴」效果）：用自定义档模拟——CPU PL1/PL2 略降、温度墙下调、风扇曲线更保守，GPU TGP 维持；这是 LM 自己的策略，不属于厂商子模式。

## 9. 决定记录：40 系不尝试「装 50 系 GCU 来换静音狂暴」

- 结论：**不做**（机主 2026-10-20 决定，先记录、不实施）。
- 原因：
  1. 静音狂暴能力位来自 EC/WMI `WMIIsTurboSubModeSupport == 0x55`，由硬件/BIOS 决定，换 GCU 版本不改变该返回值；
  2. `SET_CPU_CORE_OFFSET_SILENT/EXTREME` 最终写 EC 的 CPU core offset，40 系 EC 是否有对应语义未知；
  3. 50 载荷配套的 UWACPIDriver / NVControlSetting / UEFI_Firmware 与 40 系 BIOS 不保证兼容，可能影响风扇/电源/灯效；
  4. 混合安装会打乱 `GcuVariant` 判定、`UserPofiles` 兼容与官方控制台版本匹配。
- 若将来要验证，顺序固定为：先只读探测 `WMIIsTurboSubModeSupport`/`ItemSupport` 注册表 → 有 85 才考虑更换 → 更换前备份 `UserPofiles`/`UserFanTables` 与 `GcuVariant`，失败重装 40 载荷回滚。
