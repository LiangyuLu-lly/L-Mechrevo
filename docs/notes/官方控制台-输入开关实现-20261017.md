## ⭐⭐ 核心结论：四个开关走了**两种完全不同的通道**

| 开关 | 官方控件名 | 通道 | 具体实现 |
|---|---|---|---|
| **触摸板** | `TPLockButton` | **WMI 功能号 12 `TPLock`** | `SetValue(WMIMethodName.TPLock, ON/OFF)` |
| **Fn 键锁定** | `FnLock` | **WMI 功能号 11 `FnLock`** | `SetValue(WMIMethodName.FnLock, ON/OFF)` |
| **大小写** | `CapsLockToggleButton` | ⭐ **模拟按键** | `keybd_event(VK_CAPITAL=20, scan=69, …)` ＋ `GetKeyState(20)` |
| **数字小键盘** | `NumLockToggleButton` | ⭐ **模拟按键** | `keybd_event(VK_NUMLOCK=144, scan=69, …)` ＋ `GetKeyState(144)` |

⇒ ⭐ **CapsLock / NumLock 完全不碰 WMI、不碰 EC、不碰注册表、不需要驱动** —— 就是**模拟按一下键盘**。

## 一、大小写 / 数字小键盘：模拟按键（逐字证据，40 系）

```csharp
// MainWindow.xaml.cs:172-174
private const int VK_CAPITAL = 20;     // 0x14
private const int VK_NUMLOCK = 144;    // 0x90

// :273-277
[DllImport("user32.dll", CharSet = CharSet.Auto, ExactSpelling = true)]
public static extern short GetKeyState(int keyCode);
[DllImport("user32.dll")]
private static extern void keybd_event(byte bVk, byte bScan, uint dwFlags, UIntPtr dwExtraInfo);

// :279-291
public static bool SetCapsLock() {
    keybd_event(20, 69, 1u, (UIntPtr)0uL);    // 1 = KEYEVENTF_EXTENDEDKEY
    keybd_event(20, 69, 3u, (UIntPtr)0uL);    // 3 = KEYEVENTF_KEYUP | KEYEVENTF_EXTENDEDKEY
    return true;
}
public static bool SetNumLock() {
    keybd_event(144, 69, 1u, (UIntPtr)0uL);
    keybd_event(144, 69, 3u, (UIntPtr)0uL);
    return true;
}

// :293-301  状态读取
public static bool CapsLockStatus() => (GetKeyState(20)  & 0xFFFF) != 0;
public static bool NumLockStatus()  => (GetKeyState(144) & 0xFFFF) != 0;
```

### 几处值得照搬的细节

1. **`bScan = 69`（`0x45`）** —— CapsLock/NumLock 需要该扫描码；配 `KEYEVENTF_EXTENDEDKEY` 才生效
2. **`dwFlags`**：按下用 `1`、抬起用 `3`（`KEYEVENTF_KEYUP | KEYEVENTF_EXTENDEDKEY`）
3. **幂等**：`_Checked` 处理里先 `GetKeyState` 判断当前状态，**已到位就不发**（避免"点一次翻两次"）：
   ```csharp
   // :1846-1876  NumLock 为例
   if (!NumLockStatus()) { SetNumLock(); }   // 勾上时：若当前不是开 ⇒ 才切
   if (NumLockStatus())  { SetNumLock(); }   // 取消时：若当前是开 ⇒ 才切
   ```
4. **防回环**：`_Set` 标志（`NumLockToggleButton_Set` / `CapsLockToggleButton_Set`）——
   程序自己改 `IsChecked` 时会置位，事件处理看到它置位就只清标志、**不再反向触发**
5. ⚠️ 官方用的是**老的 `keybd_event`**，`SendInput` **0 命中**

## 二、触摸板 / Fn 锁：WMI（与我们完全一致）

```csharp
// MainWindow.xaml.cs:1098-1114
public void SetSP_TPMode(WMIResultState m)  => Task.Run(() => WMIMethodServices.SetValue(WMIMethodName.TPLock,  m));
public void SetSP_FNLock(WMIResultState m)  => Task.Run(() => WMIMethodServices.SetValue(WMIMethodName.FnLock, m));

// WMIMethodName.cs
FnLock = 11,
TPLock = 12,
```

### ⚠️ `TPLock` 的语义是「锁」，官方的勾选含义与**我们相反**

```csharp
// :830-841 初始化
WMIResultState TPLock = WMIMethodServices.GetValue<WMIResultState>(WMIMethodName.TPLock);
if (TPLock == WMIResultState.ON) { TPLockButton.IsChecked = true; }
else                             { TPLockButton.IsChecked = false; }
```

⇒ 官方 `TPLockButton` 勾上 = `TPLock = ON` = **触摸板被锁定（禁用）**。

⇒ 我们的 `touchpad` 开关 `true` = **可用**（与 GCU 侧 `TochpadEnable` 一致）⇒ **语义相反**
⇒ 我们已用 `BaolongdaToggleInverted(TPLock)` 取反处理（`ca035fb`）⇒ **内部映射正确**
⇒ ⚠️ 不要再把界面改成「TPLock 锁」语义 —— 「触摸板 / 打开即可用」对用户更直观

## 四、`BLDHotKeyService` / `BLDFnHotkeyUtility`

- `InstallService.bat`：
  ```bat
  InstallUtil.exe BLDHotKeyService.exe
  net start BLDHotKeyService
  ```
  ⇒ 用 `InstallUtil` **手动注册**成服务（安装器**不自动装** —— 与此前记录一致）
- 官方主程序里只**检查状态/启动**（`:811`、`:1509-1510` 的 `ServiceController("BLDHotKeyService")`）
- ⚠️ **四个开关都不经过它** —— 它更可能是 **Fn 热键（硬件热键→软件响应）** 的常驻宿主
- 30 系另有 `BLDFnHotkeyUtility-Test.exe`（951,296 B）—— 像是测试版工具

⇒ **本轮不依赖它**：四个开关的通道已经全部查清，没有任何一个需要这个服务。

## 五、`HID_EVENT20` 事件：**只用于同步 UI 状态，不参与控制**

```csharp
// :1389-1406
case WMIEventName.TouchPadState:
    if ((byte)eVENTvalue == 1) { TPLockButton_Set = true; TPLockButton.IsChecked = true; }
    else                       { TPLockButton_Set = true; TPLockButton.IsChecked = false; }
```

⇒ 收到硬件/其它途径改变的状态后**回写 UI 勾选**（并用 `_Set` 标志防回环）
⇒ 同类事件还有 `CapsLkState=9` / `NumLockState=13` / `FnState=7` / `AmbientlightState=10` / `SystemPerMode=15`

⚠️ 但 **CapsLock/NumLock 的状态官方并不靠这个事件**（它们用 `GetKeyState` 直读），事件那两项可能是给别处用的。

## 六、⭐ 我们能怎么接（两种开关，成本差异极大）

| | 触摸板 / Fn 锁 | 大小写 / 数字小键盘 |
|---|---|---|
| 现状 | ✅ **已接**（功能号 12/11） | ❌ 没接 |
| 需要什么 | — | **`GetKeyState` + `keybd_event`**（`user32.dll`，纯用户态） |
| 成本 | — | ⭐ **几乎为零**：不需要 EC、不需要驱动、不需要 GCU、不需要权限提升 |
| 风险 | — | 低（就是模拟按一下键盘；⚠️ 但会**真的改变键盘状态**，且 CapsLock 有程序会读它） |

### 若要接入，建议这么做
1. **读状态**：`(GetKeyState(VK) & 0xFFFF) != 0` —— 每次显示开关时直读，**不缓存**
2. **切换**：先判当前状态、已到位就不发；否则 `keybd_event(VK, 0x45, KEYEVENTF_EXTENDEDKEY)` ×2（按下+抬起）
3. **防回环**：沿用我们既有的 `_Set` 标志做法（`SyncBaolongdaQuickSwitch` 那套已经是这个模式）
4. **不要用 `WMIEventName.CapsLkState/NumLockState` 做状态源** —— 官方自己都没这么用；
   而 `GetKeyState` 是**唯一权威**
5. ⚠️ **`SendInput` 更现代**，但官方用 `keybd_event` 且实测有效 ⇒ 跟随官方即可（省一处风险）

### ⚠️ 但先想清楚"值不值得接"
- 这两个开关**本来就是键盘物理按键**（CapsLock 键 / NumLock 键）
- 官方提供的是"**在控制台里也能点**"的便利，不是新增能力
- 我们的界面若要加，属于**净增功能**（不是修 bug）
