# GCU 50 系 DB / TGP EC 寄存器研究存档（2026-10-20）

> 状态：50 系（含蛟龙16Pro 2025 5060）本次研究**只存档、不启用**；当前只对「40 系显卡 + 50 系 GCU」做 DB 联动。

## 1. GCU 50 源码里的寄存器定义（ECSpec.cs / GpuFeatures.cs）

| 常量 | 十进制 | 十六进制 | 含义 |
|---|---|---|---|
| `ADDR_ConfigurableTGP_DynamicBoost_CTRL_BYTE` | 1859 | `0x743` | 控制位域：bit0=DB 功能使能、bit1=DB 使能、bit2=ConfigurableTGP 功能使能 |
| `ADDR_ConfigurableTGP_VALUE` | 1860 | `0x744` | Configurable TGP 值 |
| `ADDR_DynamicBoost_TotalProcessingPowerTarget_VALUE` | 1861 | `0x745` | DB 总处理功耗目标 |
| `ADDR_DynamicBoost_MaximumTGP_VALUE` | 1862 | `0x746` | DB 最大 TGP |

写入函数全部**读-改-写、只改自己那一位**：

- `SetGpuConfigurableTgpFunCtrlEnable`：`x & 0xFB | 0x04`（置 bit2）
- `SetGpuDynamicBoostFunCtrlEnable`：`x & 0xFE | 0x01`（置 bit0）
- `SetGpuDynamicBoostEnable`：`x & 0xFD | 0x02`（置 bit1）
- `SetGpuDynamicBoostTotalProcessingPowerTarget` → `0x745`
- `SetGpuDynamicBoostMaximumTGP` → `0x746`

官方「狂暴/自定义」`UserSet_Mode4` 连续调用前三个 ⇒ `0x01 | 0x02 | 0x04 = 0x07`。

## 2. 已采集机型数据（只读）

| 地址 | GM5HG0A（4060，40系+50GCU） | 旷世 4090（50GCU） | 蛟龙16Pro 2025 5060（待补） |
|---|---|---|---|
| 驱动 Default / Max | 115 / 140 W | 150 / 175 W | 待采 |
| `0x743` | 0x00（关） | 0x00 | 待采 |
| `0x744` | 未关注 | 未关注 | 待采（ConfigurableTGP 值） |
| `0x745` | 0xFF | 0x00 | 待采（DB 总目标） |
| `0x746` | 0x19（25W） | 0x00 | 待采（DB 最大 TGP） |
| `0x7D4/0x7D5` | 0xFF / 0x19（第二份副本） | 0x00 / 0xFF（0x7D5 未使用） | **表里不存在** |

已验证（GM5HG0A）：写 `0x746=0x19`、`0x7D5=0x19`、`0x743=0x07` ⇒ enforced 140W；单写 `0x743=0x07` 会被固件收敛成 `0x03`（说明需同时给出 DB 最大额度）。

## 3. 当前实现（LM）

`source/MechrevoLite.Hardware/GpuDbControl.cs`：

- 仅 `GcuVariant=50` + `DgpuGeneration=Gen40` + GCU 已连接时生效；
- 狂暴（视觉档 1）→ DB 开；平衡/静音 → DB 关；
- 开：`0x746=0x19`；若 `0x7D5` 原值是合法编码（0x00/0x05/0x0F/0x19）则同步写 `0x19`，`0xFF` 视为未使用而跳过；再 `0x743` 读-改-写置 low3 位（`|0x07`）；
- 关：`0x743` 读-改-写清 bit1（`&0xFD`）；
- 写前记录三个地址原值，回读不符自动回滚；
- 切换模式、开机预热各同步一次。

## 5. 给后续的结论

1. 40 系 + 50 GCU：DB 联动的地址/编码已足够，可按 GM5 的已验证序列使用；
2. 50 系（含蛟龙16Pro 2025）：先用只读采集 `0x743–0x746` 在平衡/狂暴两态的值，确认编码后再写；
3. 任何机型写 DB 都必须先只读、再小步写、保留原值、失败回滚，不碰 ROMID/门控。
