# 宝龙达 30 系 · 灯光与探测 —— 关键事实与教训（2026-10-17）

> ⚠️ **这份文件是"防忘记、防反复"的**. 每次再碰宝龙达灯光/探测，先读它。
> 机型：**`MRID6`** · 6800H + RTX 3070Ti · 30 系（机主真机，`0.291.9.6` 诊断包实测）

## 一、⭐ 30 系宝龙达的协议边界（硬事实，别猜）

### 1. 功能号只有 **8~18**，没有 19~23

```
8  SystemPerMode          性能模式
9  GpuMode                GPU 模式（0=混合 · 1=独显直连）
10 RgbKeyboardStatus      键盘灯状态（⚠️ 恒 0，不可作判据）
11 FnLock                 Fn 锁
12 TPLock                 触摸板锁（1 = 锁定 = 禁用）
13 CpuGpuFanSpeed         风扇转速
15 AmbientLight           ⭐ LOGO 灯（屁股灯）—— **只有 0/1**
16 RgbKeyboardMode        键盘灯模式
17 RgbKeyboardColor       键盘灯颜色（写 3 字节 RGB）
18 RgbKeyboardBrightness  键盘灯亮度（0~3）
```

⛔ **没有**：`SystemAcType=19` · `MaxFanSpeedSwitch=20` · `MaxFanSpeed=21` · `CPUThermometer=22` · `CPUPower=23`

**证据**：
- 30 系官方控制台（v0.2.35）`WMIMethodName` 枚举**只到 18**
- 真机读功能号 22 **失败**（诊断包日志：`实例打开了但读不到 CPU 温度`）
- 官方 30 系读温度用的是**它自带的 `LibreHardwareMonitorLib`**，不走 WMI 功能号 22

⚠️ **后果**：
- **CPU 温度**：LM 由 **LHM 兜底**显示（`HardwareControl.cs:16`「CPU 温度已切到 LHM」）⇒ 功能号 22 读不到**不影响温度显示**
- **自定义档**：依赖功能号 23 ⇒ 30 系**不可用**（但 `BuildCapabilities()` 走运行时自检 ⇒ UI 自动不显示，✅ 不会"设了没反应"）

### 2. ⭐ 屁股灯 = 尾部灯带 = LOGO 灯 = 功能号 15

**用户原话**：
> 「30系蛟龙所谓屁股灯一个和logo灯是一路的」
> 「30系的"屁股灯"就是尾部多一个灯带和logo同亮的 当logo灯处理」

⇒ ⛔ **没有独立通道**，就是 `AmbientLight`(15)。
⇒ 所以「安静/狂暴模式屁股灯不亮」和「LOGO 灯」是**同一个问题**，⛔ 别当两个查。

### 3. ⭐ LOGO 灯**只有开/关** —— 没有颜色/效果/亮度/速度/帧率/角度

```csharp
// BaolongdaWmi.cs
internal bool TrySetLogoLight(bool on) => TryWriteByte(Function.AmbientLight, on ? (byte)1 : (byte)0);
internal bool TryReadLogoLight(out bool on) { on = raw == 1; }
```

**官方 UI 也印证**（截图）：灯光设置里只有「氛围灯」**开关** + 键盘灯亮度 + 键盘背光颜色，**没有氛围灯的颜色/效果选项**。

⭐ **而 LOGO 灯的颜色跟随性能模式 = EC/BIOS 自动调的**（协议里没有给我们发颜色的手段）
⇒ ⭐ **我们什么都不用做**，只要性能模式切对，颜色自动跟。

⚠️ **反过来这是个好用的验证信号**：
| 现象 | 说明 |
|---|---|
| 切模式后 LOGO 灯颜色变了 | ✅ EC **真的执行了**模式切换（哪怕我们判 `confirmed=False`）|
| 切模式后颜色不变 | ❌ 我们的功能号 8 写的 raw 值 EC 没认 |

### 4. 30 系宝龙达性能模式 = **3 档**（用户明确）

```
办公 / 游戏 / 狂飙（狂飙 = Turbo）
```

⭐ 用户原话：「**机械革命的宝龙达都是 3 档**」
⇒ `TurboMode = true` 是**对的**，⛔ 不需要按 `ModeCount` 加兜底。

⭐ 而「四个按钮」= **3 档硬件模式 + 1 个「自定义」软件按钮**（走功能号 23）
⇒ 宝龙达要有 4 个按钮、**没有**「配置 N」下拉（那是同方 30 系独有）。

## 二、⭐⭐ 键盘灯颜色写不进去的根因（已修，`62c82ea`）

### 现象（`0.291.9.6` 诊断包实证）

```
下发 rgb=#FFFFFF · 模式=2（固定色）· 亮度=3
回读：功能号 10=0 · 16 模式=2 ✅ · 17 颜色=0,0,0 ❌ · 18 亮度=3 ✅
```

**模式能写、亮度能写、只有颜色回读恒 `0,0,0`**（换任何效果模式都一样）。

### 根因：**写入顺序反了**

| | 顺序 |
|---|---|
| ❌ 我们（旧） | `颜色 17` → `模式 16` → `亮度 18` |
| ✅ 30 系官方 | `模式 2` → `颜色 17` |

**写模式会重置/覆盖颜色** ⇒ 我们后面那次写模式把颜色冲掉了。

**证据**（30 系官方 `SetSP_KeyboardColor`，v0.2.35）：
```csharp
SetValue(RGBKeyboardMode, Mode_RGBFixedMode);            // ① 先写模式 2
SetValue(RGBKeyboardColor, new byte[3]{red,green,blue}); // ② 再写颜色（30 系**无延迟**）
```
⚠️ 40 系官方在两者之间等 **500ms**；**30 系官方没有延迟** ⇒ 不加。

### 已修

`MechrevoHw.TrySetKeyboardLightingViaBackend` 顺序改为 **`模式 → 颜色 → 亮度`**（`:3291` `:3296` `:3299`）。

### ⚠️ 另一条教训：**官方从不读颜色** ⇒ 我们的"回读颜色一致"判据可能本身就是错的

30 系官方源码里 `GetValue` **只读模式**（`GetValue<WMIRGBKeyboardMode>(RGBKeyboardMode)`），**从不读颜色**。
⇒ 若修完顺序后颜色仍读回 `0,0,0`，那就是**固件只写不读**，此时**颜色不该参与回读判定**（写成功即视为已下发），与键盘灯"三层诚实"口径一致。

## 三、⭐⭐ 探测与能力位必须解耦（已修，`0d12bf3`）

### 踩过的坑

`BaolongdaWmi.TryCreate()` 原先把「**功能号 22（CPU 温度）能读**」当成**唯一**活体证明。
30 系读不到 22 ⇒ 判定"认不出宝龙达" ⇒ **整机退回 legacy** ⇒ 触摸板/键盘灯/性能模式/色彩增强**全部失效**。

诊断包铁证：
```
白名单判定 = ✅ 命中
宝龙达 WMI 探测：实例打开了但读不到 CPU 温度 ⇒ 判为不可用（⛔ 不接管）
Hardware backend: legacy MICommonInterface          ← ⛔ 退回 legacy
```

### 修法（分级）

```
板号命中白名单（MRID6 / MRID6-*）+ 类存在  ⇒  必须接管（22 读不到只记日志）
板号未命中                                ⇒  要求 ProbeLiveness() 非 null
类不存在（非宝龙达机型）                   ⇒  静默返回（⛔ 不误认）
```

`ProbeLiveness()` 四级判据，**每条带语义校验**（防 `0xFF` 假数据）：

| 判据 | 校验 |
|---|---|
| 22 CPU温度 | `1..254`（0 与 255 都无效） |
| 8 性能模式 | `raw ≤ 3` |
| **11/12 Fn锁/触摸板锁** | ⭐ **`OutData[3]` 回显校验**（最强证据） |
| 13 风扇转速 | 长度 ≥8 且 RPM `< 20000`（排除 `0xFF` 填充的 65535） |

### ⭐ 关键认识（写进注释了）

> **「不误伤同方」的真正保证是 `BaolongdaBackend.TryCreate()` 那道【机型白名单】硬闸门，不是活体判据。**
> 活体判据只负责"接口是否活着"。判据越宽，误判风险越高 ⇒ 白名单更不可少。

⇒ 真机验证：`0.291.9.6` 诊断包 `探测活体证据 = 功能号8(性能模式)=raw0` ⇒ ✅ 接管成功。

## 五、⚠️ 工具/环境坑（踩过的，别再踩）

### 1. PowerShell 函数名**不能撞内置别名**

```powershell
function RP(...) { ... }   # ⛔ RP = Remove-ItemProperty 的内置别名！
# 报错: A positional parameter cannot be found that accepts argument '0.291.9.7'
# ⇒ 版本号根本没改，打包白做
```
✅ 用 `ReplaceVer` / `Replace-KeepEol` 这类不会撞的名字。

### 2. **PS 5.1 按 GBK 读无 BOM 的 UTF-8**，中文会把后面的引号吃掉

⇒ 给机主的 `.ps1`/`.bat` **必须带 UTF-8 BOM**。
⚠️ 本会话已踩多次（包括自己写的"语法检查脚本"都因此报假错）。
验证方法：用**纯 ASCII 检查器 + BOM** 去 `Parser::ParseFile`。

### 3. `git commit -m "...\"fnkey\"..."` 在 PowerShell 里会被拆参数

⇒ 提交信息里有引号时，用 `Out-File` 写临时文件 + `git commit -F`。

### 4. 行尾（本会话踩三次）

- `Strings*.resx` **混合行尾**（CRLF=14 / LF=5343）⇒ ⛔ **绝不用 `edit` 工具**
- ⛔ **绝不用 `WriteAllLines`**（会把纯 LF 全文转 CRLF）
- ⛔ 别用 PowerShell `>` 读原版比对
- ✅ 改前看 HEAD、改后回验（`AssemblyInfo.cs` 纯 LF=19；`install_script.iss` CRLF=2641+裸LF8；`LightForm.cs` 是 CRLF；`SettingsForm.cs` 纯 LF）

### 5. subagent 反复创建失败

本会话多次出现 `subagent_fork` 返回 `started` 但之后 `send_message` 报
`active teammate not found`、`list_agents` 只剩 lead。
⚠️ **这种情况直接自己动手**，别反复重派。
