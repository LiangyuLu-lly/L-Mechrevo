## 1. 差异矩阵

| 项目 | 我们的旧 direct（现状） | fanctl table（参考） | 本实现 |
|---|---|---|---|
| 写入对象 | 25Hz 直写 `0x1804`/`0x1809`（0..200） | 写 `0x0F20`/`0x0F50` **前 8 字节**，置 `0x0727 bit6` 锁存，EC 长期保持 | **table 默认**；direct 保留为回退/对照 |
| 写入频率 | ~50 次/秒，永不停 | 仅目标变化时写（16 表字节 + 2 锁存 + 2 补写），稳态 0 次/秒 | 25Hz 定时器仍跑（采样/看门狗），**写只在目标变化/心跳漂移** |
| 防 EC 覆写 | 靠高频硬压 | 锁存后靠 EC 自身保持 + **10s 心跳**（读目标，漂移 >8 raw 才重锁） | 同；另检测“连续 5 次漂移”⇒ 疑似别的程序争用，重锁间隔放慢到 30s（⛔ 不跟着狂写） |
| 副扇独立 | 两路目标分别直写 | 表模式下必须置 `0x07C5 bit7`；主副目标**相同则清位** | 同：目标不同 → 绝对写 `isolate_base | 0x80`；相同 → `& ~0x80` |
| 锁存/隔离写法 | —（不涉及） | **绝对写**基线：`latch_base & ~0x40` → 50ms → `base | 0x40`；绝不做 read-modify-write（撕裂读会写出 0x07 垃圾） | 同；`latch_base`/`isolate_base` 在启动时读一次并掩位保存 |
| 低温交还 | <45℃ **暂停写入**，不解除锁存（本来也没有锁存） | <45℃ **释放表/交还 EC**；≥48℃ 重新接管（3℃ 回差） | table 模式同；direct 模式保持旧行为（仅暂停） |
| 释放 | 停止定时器即“交还”（EC 6~8s 接管） | 清锁存 + 清隔离，绝对写 + 回读校验（失败重试） | table `Stop`/低温交还都清锁存+隔离；direct 启动时**清理上次崩溃遗留**的锁存/隔离位 |
| 撕裂写防护 | 每次单字节调用都拿进程内锁 + 跨进程 `i2ec.lock` | 整组操作持 `RLock`；只写前 8 字节（避开 0x38/0x3A 地址低字节）；写后校验电源寄存器 | 新增 **`I2ecInpOut.TryWriteEcSequence`**：整组序列（含 50ms 脉冲）**一次持锁**；只写 8 字节；电源寄存器哨兵**本轮不实现**（见 §5） |
| 副扇堵转 | 12s 0 RPM 看门狗 ⇒ 停止交还 | 主/副独立时同样关注 | 两个后端都保留 12s 看门狗 |
| 默认策略 | direct 25Hz | table 默认 | **table 优先（I2EC 通道）**；显式 `wujie_fan_backend=direct|duty` 可强制 direct；table 初始化失败/连续 3 次写表失败自动回退 direct |
| 下限 | 20%（现有 `FanFloorPercent`） | 5%（表后端有 ~1745 RPM 地板，3%/0% 压不下去） | **保持 20% 不变**（避免未经真机验证的行为变化；作为真机验证项列出） |

## 2. 实现

### 2.1 `I2ecInpOut.cs`（串行化关键）

- 新增 `I2ecWriteStep(Address, Value, DelayAfterMs)` / `I2ecVerifyStep(Address, Expected)`；
- 新增 `TryWriteEcSequence(steps, verifySteps, out detail)`：
  - 一次拿进程内 `Gate` + **跨进程文件锁** `%ProgramData%\L-Mechrevo\i2ec.lock`，
  - 在锁内完成**全部**写（表 16 字节 → 隔离 → 清锁存 → 50ms → 置锁存 → 补写占空比）→ 可选回读校验，
  - 任何异常/回读不一致 ⇒ 返回 false + 具体地址/值；不会留下“半张表 + 已锁存”。
- 单字节 `TryReadEcByte/TryWriteEcByte` 行为不变（direct 路径、诊断继续使用）。

### 2.2 `WujieFanEc.cs`

新增常量（只取事实，⛔ 未复制 Python）：
`RegisterFanTableFan1=0x0F20`、`RegisterFanTableFan2=0x0F50`、`RegisterFanTableLatch=0x0727`、
`RegisterFanIsolate=0x07C5`、`FanTableActiveLength=8`、`TableHeartbeatMs=10000`、
`TableDriftToleranceRaw=8`、`TableLatchPulseMs=50`、`HandoffResumeTemperatureC=48`；
诊断文本补一句当前后端语义（table 默认/direct 回退），未改只读探测逻辑。

### 2.3 `WujieFanEcController.cs`

- `ControlBackend { Direct, Table }` + `SelectBackend(...)`：
  - 读 `wujie_fan_backend`：`direct`/`duty` ⇒ direct；其余（空/table/auto/未知）⇒ 尝试 table；
  - table 需要 I2EC 通道 + 能读 `0x0727`/`0x07C5`（采样基线）；读不到 ⇒ **自动回退 direct** 并写日志原因；
- `OnTickTable()`（25Hz 定时器里）：
  - 温度**每 500ms 读一次**（减少端口读压力）；连续 6 次失败（≈3s）⇒ Stop 交还；
  - 温度 ≥95℃ 交还；≥85℃ 目标 100%；目标计算/20% 下限沿用旧逻辑；
  - **目标变化** ⇒ `ApplyTable`（表+隔离+锁存脉冲+补写 0x1804/0x1809 跳斜坡）；
  - 目标不变 ⇒ 只做 **10s 心跳**：读 `0x1804/0x1809`，偏差 >8 raw 才重锁；连续 5 次 ⇒ 争用告警 + 重锁间隔 30s；
  - 低温 <45℃ ⇒ `ReleaseTable`（清锁存+隔离），`_lowTempHandoff=true`；≥48℃ 重新接管（3℃ 回差）；
  - 12s 副扇 0 RPM 看门狗保留，table 写表后 30s 软着陆宽限；
- `BuildTableWritePlan(...)`：纯函数生成写入计划（便于离线自检）；
- `ApplyTable(...)`：调用 `TryWriteEcSequence`；连续 3 次失败 ⇒ 清理旧表（`force`）并 `_backend=Direct` 自动回退；
- `ReleaseTable(reason, force=false)`：绝对写清锁存+隔离 + 回读校验，失败重试一次并如实记日志；
- `Stop(...)`：table 活跃时先 ReleaseTable 再交还；`ApplyTable` 在 `_running=false` 时拒绝重锁（避免 Stop 后又被锁上）；
- direct 启动时 `ClearStaleTableStateBestEffort()`：若检测到上次崩溃遗留的 `0x0727 bit6`/`0x07C5 bit7`，按基线绝对写清除（读不到就跳过，不猜）。
- `Start(...)` 签名不变（`WujieFanCurveAutoApply` / WPF `FanCurveWindow` 无需改）。

## 3. 默认策略（可解释）

1. 无界 + I2EC 可用 + 能读到 `0x0727/0x07C5` ⇒ **table**（稳态零写、撕裂写窗口最小）。
2. 配置 `wujie_fan_backend=direct` 或 `=duty` ⇒ 强制旧 25Hz direct（对照/回退/排障）。
3. table 初始化失败（通道不是 I2EC / 读不到基线）⇒ **自动 direct**，日志写明原因。
4. table 运行中连续 3 次写表失败 ⇒ 清旧表（尽力）并**自动回退 direct**；direct 仍受原看门狗保护。
5. ACPI-EC 实验通道（没有 inpoutx64 时）⇒ direct（table 批量写只实现于 I2EC）。

## 5. 真机验证步骤 / 未验证项

验证步骤（无界 + inpoutx64 环境）：

1. 启动后日志应出现 `[fan] 无界 EC：选择 table 后端优先 … · 计划自检=True…`；
   若看到 `回退 direct`，按日志原因处理（驱动/权限/寄存器读不到）。
2. 应用曲线：目标变化时出现 `[fan] 无界 table：已写表+锁存…`，风扇转速应跟随；
   稳态 10s 内除心跳读外**不应有写**（日志无 target 变化/重锁行）。
3. 观察心跳：若反复出现 `心跳发现偏离…重锁`，检查是否有其它程序（官方控制台/FanCtl）在抢 EC。
4. 低温交还：让 CPU <45℃ 保持一段时间 ⇒ `释放表并交还 EC`；升温 ≥48℃ ⇒ `重新接管`。
5. 副扇独立：主副目标不同 ⇒ 日志 `隔离=置`，两扇应各按各的；目标相同 ⇒ `隔离=清`。
6. 停止/关闭曲线 ⇒ `已清锁存+隔离并交还 EC`；随后 EC 应恢复自动控速。
7. 掉电/稳定性：table 写窗口只有 `0x0F20..0x0F27 / 0x0F50..0x0F57 / 0x07C5 / 0x0727`，
   已避开 `0x083A/0x0522/0x0520` 地址低字节；但仍需观察无异常断电/电池读数异常。

未验证/已知差异：

## 6. 风险清单（审计结论）

1. **端口锁/串行化**：旧实现每字节都获取跨进程锁，表写入的 16+ 字节可能与其他进程（ACPI 电池驱动/另一实例）交错 ⇒ **已新增整组序列锁**修复；但仍非原子硬件操作，文件锁只覆盖本机 LM 进程与其他遵守同一锁的进程（ACPI 驱动不遵守） ⇒ 只能缩小窗口，不能消除。
2. **撕裂写**：只写 8 字节后地址低字节仅 0x20~0x27 / 0x50~0x57，避开最危险的 0x38/0x3A；锁存/隔离用绝对写（不 read-modify-write）；未实现电源寄存器写回（见 §5）。
3. **释放风险**：Stop/低温/失败回退都会清锁存+隔离；但**进程被强杀**不可能执行释放 ⇒ direct/table 下次启动都会检查并清理遗留位（table 启动不主动清，因为会立即重写表+锁存；direct 启动调用 `ClearStaleTableStateBestEffort`）。
4. **副扇堵转**：保留 12s 0 RPM 看门狗；table 地板较高，正常不应触发；目标变化后的软着陆期仍计入 12s 窗口（延用旧行为，未加 grace）。
5. **低温交还**：<45/≥48 回差；温度读失败沿用上次值最多约 3s；≤0/异常值不接管。
6. **硬件差异**：fanctl 的寄存器地址/表语义来自特定 14XA EC，若其它无界批次不同，可能表现为“写表后转速不跟随/EC 不稳定” ⇒ 需真机对照；发现异常可设 `wujie_fan_backend=direct` 立即回到旧路径。
7. **默认策略风险**：默认切 table 是行为变化（尽管默认值可配置）；若真机异常，回退开关明确、无需改代码。
