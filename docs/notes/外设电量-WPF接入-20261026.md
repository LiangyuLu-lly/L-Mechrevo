# 外设电量接入说明（WPF 设置页 · 2026-10-26）

## 1. 背景与基准对照

基准清单（`docs/notes/基准功能清单-20261026.md` §7）指出：**旧版 `SettingsForm.RefreshPeripheralsBattery` / `PeripheralsProvider` 的外设电量读取在 WPF 0 命中**。本次补齐。

### 1.1 旧版真实实现（先只读核对，`6faf99b^` = 删除 WinForms UI 前最后一次提交）

- 入口：`source/MechrevoLite/SettingsForm.cs:12217` `RefreshPeripheralsBattery()` → 仅一行：
  `PeripheralsProvider.RefreshBatteryForAllDevices(force: true);`
- 刷新时机：设置页 `VisibleChanged` 里 `Task.Delay(2500)` 后后台调用一次（`SettingsForm.cs:12197-12211`），失败只写日志、不弹窗；
- UI：`SettingsForm.cs:16363-16430` 的 `panelPeripherals`（3 个 `buttonPeripheral1/2/3`，"Mouse 1/2/3" 卡槽，3 列各 25%），**`Visible=false` 默认隐藏**；
- 启动期：`Program.cs:1211-1212` 调 `PeripheralsProvider.DetectAllAsusMice()` / `RegisterForDeviceEvents()`；
- **关键核对结论：直接查 `6faf99b^`、`archive/versions/0.291.8.1/`、`archive/refs/L-Mechrevo-18.6-source/`、`archive/unpacks/beta21/decomp/`、`archive/checkpoints/*` 的所有 `PeripheralsProvider.cs`，全部是空实现**（`RefreshBatteryForAllDevices`/`RegisterForDeviceEvents`/`UnregisterForDeviceEvents`/`DetectAllAsusMice` 方法体为空）⇒ 旧版"外设电量"在源码基线里只有**入口/卡槽骨架、没有数据源**，UI 永远隐藏。
- 因此：WPF 不能"复用旧业务类"（旧类在 Core 中已随 WinForms UI 删除，且即便保留也是空实现）；Core 里也没有等价中性类（`grep Peripherals/外设电量` 无业务实现）。⇒ **新建中性 `PeripheralsService` + WPF 设置页卡片，行为对齐旧入口（延迟一次、失败隐藏），数据源按基准意图（HID/蓝牙）真正实现。**

## 2. 新数据源

新增 `tools/dev/wpf-p0/Services/PeripheralsService.cs`（WPF 内中性服务，不引用任何 WinForms UI）：

| 来源 | 原理 | 覆盖 |
|---|---|---|
| **蓝牙（BLE）** | WinRT `Windows.Devices.Enumeration` 枚举已连接 BLE 设备 → `BluetoothLEDevice.GetGattServicesAsync` 找 Battery Service `0x180F` → Characteristic `0x2A19` 读 1 字节百分比（Windows 10/11 设置页同源） | BLE 蓝牙鼠标/键盘/耳机等 |
| **HID** | 复用 Core `MechrevoLite.Hardware.HidDeviceWin.Enumerate()` 枚举 HID 设备 → 对每个设备用 `hid.dll` 读 Feature Report 的 **Battery Strength**（HID Usage Page `0x06` / Usage `0x20`）：`HidD_GetPreparsedData` → `HidP_GetValueCaps(HIDP_FEATURE)` 找 usage caps → `HidD_GetFeature` 读值；名称用 `HidD_GetProductString` | 走标准 HID 电量上报的键鼠（含部分蓝牙经典 HID） |

实现约定：
- **不新增高频轮询**：只在设置页打开后延迟 2.5s 扫描一次；`PeripheralsService` 内部 **60s 缓存**（同一次程序内重复打开设置页不重复扫）；无定时器、无设备事件订阅（旧版 `RegisterForDeviceEvents` 亦为空实现）；
- **失败/能力隐藏**：无蓝牙适配器、无已连接设备、无 HID 电量上报、超时（蓝牙 5s / HID 5s）、异常、结构校验失败 ⇒ 一律返回空列表；设置页卡片保持 `Collapsed`，不弹错；
- **安全优先**：HID `HIDP_VALUE_CAPS` 结构在运行时校验 `Marshal.SizeOf == 72`（与 x64 原生一致）否则整条 HID 路径放弃；读取值必须落在 caps 逻辑范围内，防错误解析出离谱电量；
- 去重：同一设备同时被 BLE+HID 读到（蓝牙鼠标常见）按名称去重，保留 BLE 结果；结果按“蓝牙优先、名称”排序，UI 最多显示 3 个（对齐旧版 3 卡槽）。

### 5.3 未验证 / 未确认点
1. **本机没有带电池的蓝牙/HID 键鼠**，所以“有设备时卡片显示、百分比正确”只能由代码路径/单元反射验证，尚未真机看到数值；建议机主用罗技/微软等标准 BLE 或 HID 电量鼠标实测。
2. HID 位域解析按“feature report 内单值、字节对齐”简化（已用逻辑范围校验兜底）；若某设备把电池值放在多值/非对齐报告中可能读不到（会走隐藏分支，不会显示错值）。
3. 蓝牙**经典 HID**（非 BLE）若设备不暴露标准 HID Battery Strength usage，则不会出现在列表（不猜测厂商私有协议）。
4. 卡片文案尚未接 `WpfStrings` 本地化（资源文件超出本任务写作用域）。
5. 未接入设备插拔实时刷新（按“不增加高频轮询”约束，仅设置页打开时扫描一次；如需可后续用 `WM_DEVICECHANGE` 节流刷新）。
