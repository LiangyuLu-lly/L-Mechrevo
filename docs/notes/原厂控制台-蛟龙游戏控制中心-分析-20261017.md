## 三、⭐ 关灯方式：原厂印证「亮度 = 0」

```csharp
public enum WMIRGBKeyboardMode : byte {          // 蛟龙游戏控制中心.dll :216
    Mode_Off = 0, Mode_RGBAutoCyclic = 1, Mode_RGBFixedMode = 2, Mode_CustomColors = 3, Unknow = 255
}
```
**`Mode_Off` 在两个原厂程序集里都只出现在枚举定义处 —— 零调用点。**
（与蛟龙第三方控制台 `JiaolongControl` 完全一致。）

而原厂有**专门的"把亮度设为 0"状态机**与写入方法：
```csharp
private int SetKeyboardLightBrightnessToZeroStep;                       // :784
private void KeyboardLightBrightness_ValueChanged(...) { ... }          // :2520 附近
private void LightBrightness_ValueChanged2(...) { ... }                 // :2534 附近

public void SetSP_KeyboardLightBrightness(byte keyboardLightBrightnessValue) {   // :2016
    LogHelper.WriteLog("SetSP_KeyboardColor", "Level: " + keyboardLightBrightnessValue);
    Task.Run(() => WMIMethodServices.SetValue(WMIMethodName.RGBKeyboardBrightness, keyboardLightBrightnessValue));
}
// UI 滑块事件（:2883）
private void KeyboardLightBrightness_MouseLeftButtonUp(object sender, MouseButtonEventArgs e) {
    int num = (int)Math.Round(KeyboardLightBrightness.Value);
    KeyboardLightBrightness.Value = num;

```
⇒ ✅ **"关灯 = 写功能号 18（亮度）= 0" 是原厂口径**。
⇒ ⛔ 我们 `078f959` 的关灯路线 A（写模式 0）**确实错了**。
⇒ ⚠️ 保留我们的回读确认（原厂**不做回读确认**：`SetValue` 只返回 `InvokeMethod` 是否成功）。

## 五、⭐ 灯效到底几种（修正"官方只有单色"）

原厂**枚举定义四种**，但写入点只有两个：
```
Mode_RGBAutoCyclic = 1  ｜ :2032（SetSP_KeyboardColorDefault）、:3885（调试）
Mode_RGBFixedMode  = 2  ｜ :2040（SetSP_KeyboardColor）、     :3890（调试）
Mode_Off           = 0  ｜ 仅枚举定义 —— 零调用点
Mode_CustomColors  = 3  ｜ 仅枚举定义 —— 零调用点
```
⚠️ **原厂自己的命名很混乱**：调试输出把 `Mode_RGBAutoCyclic` 打印成 **"Single mode"**、
把 `Mode_RGBFixedMode` 打印成 **"RGB"**。

⭐ 而主程序的 **WMI 事件处理**给出了模式的确切语义：
```csharp
case WMIEventName.RGBKeyboardMode:
    if ((byte)eVENTvalue == 1) { KeyboardRGBColor.IsEnabled = false; Opacity = 0.4; }  // 模式 1：禁用颜色选择器
    else if ((byte)eVENTvalue == 2) { KeyboardRGBColor.IsEnabled = true; Opacity = 1.0; } // 模式 2：启用颜色选择器
```
⇒ **`Mode_RGBAutoCyclic=1` = 用出厂固定色/循环（不能选颜色）**；
⇒ **`Mode_RGBFixedMode=2` = 可自定义颜色**。
⇒ 所以机主说的"只有单色"可能正是**模式 1 下颜色选择器被禁用** + 命名混乱所致。
⇒ **原厂实际提供两种模式**，且**不支持"关灯"作为模式**（关灯靠亮度 0）。

## 七、⭐⭐⭐ 状态推送走 WMI 事件 `HID_EVENT20`（重要修正）

```csharp
// 两个原厂程序集完全一致
string query = "SELECT * FROM HID_EVENT20";
_watcher = new ManagementEventWatcher("root\\WMI", query);
_watcher.EventArrived += Watcher_EventArrived;
_watcher.Start();
```
事件数据解析（`Watcher_EventArrived`）：
```csharp
WMIEventType wMIEventType = (WMIEventType)array[0];    // 1 = HotKey
WMIEventName wMIEventName = (WMIEventName)array[1];    // 4..21+
object obj = (wMIEventName != CPUFanSpeed && != GPUFanSpeed) ? (object)array[2]
                                                             : (object)((array[2] << 8) + array[3]);
```

### 这修正了我们诊断段 ④ 的结论
我们此前写的是：「参考实现有一张 `EventName` HID 事件表（4~33）……**但我们收不到这类事件**，
因为我们的 HID 封装 `HidDeviceWin` 只有 `HidD_SetFeature`/`WriteFile`/`CreateFile`、
**没有 `ReadFile`** ⇒ 本版用周期性 WMI Get 回读做保底」

⇒ ⭐ **原厂根本不走 HID —— 它用 WMI 事件订阅**（`ManagementEventWatcher` on `root\WMI`）。
⇒ ⭐⭐ **所以这条路我们也能走**：加一个 `ManagementEventWatcher("root\\WMI", "SELECT * FROM HID_EVENT20")`
即可，**不需要 HID `ReadFile`**。
⇒ 收益：用**推送事件**替代 3 秒轮询；能拿到 Fn 热键（亮度增减、模式切换、触摸板、飞行模式、
性能档、Caps/Num/Scroll）等**设备主动上报**的状态变化。

### ⚠️ 本机验证结果
```
本机 root\WMI 精确查：
  [无] HID_EVENT20     [无] HID_EVENT     [无] MICommonInterface
  [有] AcpiTest_MULong
```
⇒ **`HID_EVENT20` 与 `MICommonInterface` 一样都是宝龙达 BIOS 提供的 WMI 类**（本机是同方 ⇒ 都没有）
⇒ **必须在蛟龙真机上验证**该事件类是否存在、能否订阅。

（⚠️ 这张表在**蛟龙第三方控制台**里也有，我们此前叫它"HID 事件表" —— 现在确认它是 **WMI 事件号**。）

## 九、⭐ 原厂不碰 EC、也不装内核驱动

| 检查项 | 结果 |
|---|---|
| `DeviceIoControl` / `CreateFile` / `WriteIoPort` / `ReadIoPort` / `inpout` / `WinRing` / `IOCTL` / `0x4E` / `0x2E` / `0x62` / `0x66` / `EC_RAM` / `SuperIO` / `0x2000` / `0x1060` | **0 命中**（先前几处是 `System.Windows.Controls` 里 "ols" 的假命中） |

- `user32.dll` ×若干（热键/OSD）
- `ServiceController("BLDHotKeyService")`（检查热键服务状态）

## 十、⭐ 原厂没有限充 / 充电阈值（又一次独立确认）
