## 1. 启动恢复（性能/CPU/风扇/充电）

### 已有
- WPF 连接后端后执行：
  - `RestorePerfModeOnStartupAsync()`：`PerfModeService.ReconcileForStartupAsync` + `ReplayLocalProfileOnStartupAsync` + `ApplyApuAntiDegradeOnStartup`（`OriginalStyleWindow.xaml.cs:1993-2019`）。
  - 灯光启动恢复：`RestoreLightingOnStartupAsync`（`OriginalStyleWindow.xaml.cs:4719`；调用点 `:3005/:3425/:4666`）。
- 旧实现对应：`Program.cs:3831-3843`（Perf 启动协调/重放/APU）、`:2305+`（灯光启动恢复）。

### 缺失
- **CPU 自动应用**：旧 `Program.cs:3478 RuntimeCpuTuning.ApplySavedOnStartup()` / `ScheduleCpuCoAutoApply()`；WPF 当前无 `RuntimeCpuTuning.ApplySavedOnStartup` 调用点。
- **风扇启动清理**：旧 `Program.cs:3779 warmHw.RunDeferredFanStartupCleanup()`；WPF 无调用点。
- **宝龙达限充正常启动核对**：旧 `Program.ScheduleIdleBackendWarmup`（`Program.cs:3495`）会走 `BatteryLimitRestore`；WPF 只在 `charge` 任务/电池页触发；正常 UI 启动未调用 `BatteryLimitRestore.RunOnce`。
- **UJ 风扇曲线自动应用**：旧 `WujieFanCurveAutoApply.Schedule()`（`Program.cs` 启动 deferred 段）；WPF 无调用点。

> 结论：性能/灯光启动恢复已有等价；CPU/风扇/限充/无界曲线属于**缺失**，需后续在“backend ready”回调中补（不宜在 App 里做，需 hw 实例）。

## 2. 唤醒自动切档 / 电源计划跟随

### 已有
- WPF `PowerBroadcastHook` 捕获 `WM_POWERBROADCAST` 的 `PBT_APMRESUMEAUTOMATIC`，1.5s 后恢复灯光（`OriginalStyleWindow.xaml.cs:1207-1218`）。
- 睡眠前/唤醒键盘灯恢复逻辑存在（`RestoreKeyboardLightAfterWakeAsync`、`_sleepKeyboardLightWasOn`，约 `:1220+`；旧 `Program.cs` 的 `ScheduleKeyboardLightingRestoreAfterResume` 等价）。

### 缺失
- 旧 `SystemEvents.PowerModeChanged`（`Program.cs:3601`）：
  - `Suspend` 时记录键盘灯、`gpuControl.StandardModeFix()`、`InputDispatcher.ShutdownStatusLed()`；
  - `Resume` 时 `MarkResumeShowSuppression` + 键盘灯恢复；
  - 每次电源模式变化 `SchedulePowerCheck()`。
- 旧 `OnPowerSettled`（`Program.cs:3589`）：电源来源变化时 `currentSource` 更新 → `SetAutoModes(powerChanged: true)` + `ReconcileLightingPowerAsync()`。

- 旧 `SystemEvents.SessionEnding`：`CpuCoAutoApplyGuard/GpuOcShutdownGuard.MarkCleanExit`、`BatteryControl.AutoBattery`、`InputDispatcher.ShutdownStatusLed`。

> WPF 仅覆盖“自动唤醒灯光恢复”；**电源来源变化自动切档/电源计划跟随/会话切换/干净退出标记均未移植**。

## 3. 充电计划任务 / 开机恢复

### 注册（已有）
- 旧 `Startup.Schedule()`：`ScheduleUserTaskOnly()` + `ScheduleCharge()`（`source/Startup.cs:661-671`）。
- WPF 设置页开机自启开关：`Startup.Schedule()` / `Startup.UnSchedule()`（`SettingsWindow.xaml.cs:422`）。
- `ScheduleCharge()` 注册 SYSTEM `BootTrigger` + Kernel-Boot EventID 27，动作参数 `charge`（`source/Startup.cs:543-590`）。

### 执行（本任务刚补齐）
- 旧 `Program.Main`：`if (text == "charge") ApplyBatteryLimitAtBootAsync()`（`6faf99b^:Program.cs:872-878`；实现 `:4052-4105`）。
- WPF 之前 `App.OnStartup` **完全不解析 `e.Args`**，所以计划任务以 `charge` 启动 WPF 时会打开正常 UI，充电上限不会恢复。
- **本任务已实施**：
  - 新增 `Services/HeadlessStartupService.cs`：
    - `RunChargeTask()`：宝龙达先 `BatteryLimitRestore.RunOnce("charge-task")`；非宝龙达/EC 路径按旧 `ApplyBatteryLimitAtBootAsync` 逐条：`BatteryControl.ReestablishArmed()` 门控 → `charge_limit` 范围/通道检查 → `EcChargeLimit.TrySet` → Flush/退出码。
    - `RunRegisterAutostart()`：仅管理员执行 `Startup.ScheduleUserTaskOnly()`，返回 0/5/1。
  - `App.xaml.cs` 在**单实例互斥体之前**处理 `charge` / `--register-autostart`：设置 `Environment.ExitCode` 后 `Shutdown()`，⛔ 不创建窗口。
  - 正常启动时后台 `global::Startup.StartupCheck()`（修复/补建启动/充电计划任务；失败只记日志）。

### 仍缺
- 正常 UI 启动未调用 `BatteryLimitRestore.RunOnce`（旧 `ScheduleIdleBackendWarmup` 路径）；`charge` 任务已覆盖开机场景，但用户手动启动/重启 WPF 时不会核对限充。
- 旧 `Startup.StartupCheck` 的 `ScheduleCharge` 修复需要管理员；WPF 进程通常按管理员清单运行，行为同旧。

## 4. 单实例 / 开机自启 / 计划任务

### 已有等价
- WPF 单实例：`App.xaml.cs:12-42` `Local\L-Mechrevo.WpfP0` mutex + `ShowMainEvent`；第二实例 `existing.Set()` 后退出；主实例 `ShowMainFromExternal()`（`OriginalStyleWindow` 实现）。
- 旧：`Global\L-Mechrevo-SingleInstance` + ACL + `ShowMain`（`6faf99b^:Program.cs:727-790`）。
- 差异：作用域 `Local` vs `Global`；WPF 是新进程名/任务指向新 exe，因此不会与旧进程互斥（旧 UI 已删除，运行期无双进程）。
- 开机自启：WPF 设置页 `Startup.IsScheduled/Schedule/UnSchedule`（`SettingsWindow.xaml.cs:155/422`）；任务名/计划与旧 `Startup.cs` 同一套。
- 本任务补 `--register-autostart` 无 UI 分支，修掉“提权注册时打开正常 UI、注册可能不生效”的缺口。
- 本任务补正常启动 `Startup.StartupCheck`（旧 `Program` 的 `Task.Run(Startup.StartupCheck)`）。

### 仍缺
- `startup` 参数：旧 `Program.IsStartupLaunch("startup")` ⇒ `startMinimized=true`，延迟初始化、不显示主界面（`Program.cs:804/1219/1251`）；WPF App 仍按 `last_window_mode` 正常显示窗口。⇒ **启动任务会显示 UI，而不是静默驻留托盘**。
- WPF 单实例是 `Local`，如果同一用户会话已有进程，计划任务 `startup` 以第二实例进入会被挡掉并发 ShowMain；这符合“已有实例则唤起”，但对“开机静默启动”不是旧语义。
