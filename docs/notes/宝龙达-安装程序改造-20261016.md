# 宝龙达机型「不安装 GCU」安装程序改造（2026-10-16）

> ⭐ 任务来源（用户原话）：
> 「⭐ 安装程序也派一路改 我们是不是知道宝龙达的主板号了 对于蛟龙16Pro **30系 40系 不安装GCU 走宝龙达路**」
>
> ⭐ 本文件由**安装程序改造**这一路（子 agent）编写。⛔ 不涉及 `source\` 里的宝龙达后端代码
> （那条线由另一路 agent 负责），两路**判据必须一致**、见第 3 节。

---

## 1. 改造前的 GCU 安装流程（现状梳理）

⭐ 关键落点全部在 `installer-src\install_script.iss`（172 KB，Inno Setup 6.7.1）。

| 步骤 | 位置 | 做什么 |
|---|---|---|
| ⭐ ① 变体判定 | `files\GCU\Select-GcuPayload.ps1` | 按 **型号串 / 显卡代际** 选 5 个载荷变体之一：`1020` / `30` / `40` / `50` / `WJXY` |
| ⭐ ② 载荷暂存 | `[Files]` 212~217（`Flags: dontcopy`） | 5 个 `.7z` + `7za.exe` **不进安装文件集**，只在 setup 存活期用 |
| ⭐ ③ 载荷解压 | `[Code] ExtractGcuStagingTemporaries` | `PrepareToInstall` 里把它们解到 `{tmp}`；⚠️ **解不出任何一件 ⇒ 返回非空 ⇒ 中止安装** |
| ⭐ ④ 脚本落盘 | `[Files]` 111~113 | 三个 ps1（`Select-` / `Install-` / `Uninstall-Gcu.ps1`）→ `{app}\GCU\` |
| ⭐ ⑤ 装机本体 | `[Run]` 296 | 跑 `Install-Gcu.ps1`（`-StagingRoot {tmp}` `-TargetDir {app}\GCU`）⇒ 解压落 `{app}\GCU\AiStoneService`、注册 GCUBridge 服务、入驱动库 |
| ⭐ ⑥ 驱动 | `[Files]` 156~158 | `UWACPIDriver` 三件 → `{app}\UWACPIDriver`（应用**根目录**） |
| ⭐ ⑦ 附带件 | `[Files]` 229~230 / 249~250 | `logo\Language\*.json` → `{app}\GCU\logo\Language`；`README.txt` / `NOTICE.txt` → `{app}\GCU\` |
| ⭐ ⑧ 卸载 | `[UninstallRun]` 347 | 跑 `Uninstall-Gcu.ps1 -PurgeVendor` ✅ **本次刻意不动** |

⭐ 装完后 `{app}\GCU\` 下只应有：`AiStoneService\` · `logo\Language\` · `README.txt` · `NOTICE.txt` · 3 个 ps1
（⛔ 无 `payload\`、⛔ 无 `7za.exe`、⛔ 无没用到的变体）。

⚠️ **为什么必须做到"不装 GCU"**（⭐ 不是可选项）：
程序侧后端候选顺序是「**GCU（若服务已装）** → 宝龙达 → 老同方 → GCU 兜底」。
⇒ ⭐ 若宝龙达机型上**装了** GCU，则 `IsGcuServiceInstalled` 为真 ⇒ **GCU 被优先试**
⇒ ⭐ 而该机**根本没有 GCU 通道** ⇒ **永远连不上** ⇒ ⭐ **宝龙达后端永远轮不到** ⇒ ⭐ **程序不可用** ❌
⇒ ⭐ 所以"不装 GCU"是这条线**能工作的前提** ✅

## 2. 本次改了什么（只动 `install_script.iss` 一个文件）

### 2.1 新增 `[Code]` 判据（两个函数）

| 函数 | 作用 |
|---|---|
| ⭐ `IsBaolongdaMold(): Boolean` | 读注册表判"是不是宝龙达模具" |
| ⭐ `ShouldInstallGcu(): Boolean` | `Check:` 用；= `not IsBaolongdaMold()` |

⚠️⚠️ **踩到的坑（⭐ 已修，⭐ 记下来免得再犯）**：
`Check:` 函数的原型**必须无参** ⇒ 写成 `function ShouldInstallGcu(Param: String): Boolean`
会被 ISCC 直接拒绝：`Invalid prototype for 'ShouldInstallGcu'` ⇒ **编译中止** ❌
（⭐ 带 `Param: String` 的原型只适用于 `{code:Name}` 常量展开，⛔ 不适用于 `Check:` ✅）

### 2.2 给 14 个条目加 `Check: ShouldInstallGcu` 闸

| 行 | 条目 | 效果 |
|---|---|---|
| ⭐ 296 | `[Run]` `Install-Gcu.ps1` | ⭐ **GCU 本体不装**（核心 ✅） |
| ⭐ 212~217 | `[Files]` 5 个 7z + `7za.exe`（dontcopy） | ⭐ 载荷不再准备 |
| ⭐ 156~158 | `[Files]` `UWACPIDriver` 三件 | ⭐ 蛟龙用不上该驱动 ⇒ 不铺 |
| ⭐ 229~230 | `[Files]` `logo\Language\*.json` | ⭐ GCU 附带件不铺 |
| ⭐ 249~250 | `[Files]` `README.txt` / `NOTICE.txt` | ⭐ 同上 |

### 2.3 `ExtractGcuStagingTemporaries` 加**提前退出**（⭐ 关键，⛔ 不能漏）

```
⚠️ 这是本次最容易踩的坑：
   [Files] 的 6 件载荷被 Check 挡掉后，若还去 ExtractTemporaryFile
   ⇒ 六件全失败 ⇒ Failed 非空 ⇒ 返回非空 ⇒ PrepareToInstall 会 Exit
   ⇒ ⭐ 整个安装被中止 ❌❌
⇒ 所以函数开头加了：
   if IsBaolongdaMold() then begin Log(...); Result := ''; Exit; end;
   ⇒ ⭐ 宝龙达机型直接跳过解压、且【不中止安装】✅
```

### 2.4 ⭐ 刻意**没有**改的东西

| 项 | 为什么不动 |
|---|---|
| ⭐ `[Files]` 111~113（3 个 ps1） | ⭐ **保持无条件安装** —— `[UninstallRun]` 347 要用 `Uninstall-Gcu.ps1` 做真卸载 ✅ |
| ⭐ `[UninstallRun]` 347 | ⭐ 卸载流程**必须逐位不变** ✅ |
| ⭐ `Select-GcuPayload.ps1` 的变体判定 | ⭐ 非宝龙达机型仍需要它 ✅（且宝龙达机型已跳过整个 GCU 段，用不到 ✅） |
| ⭐ 三个变体 iss（`NoGCU` / `30GCU` / `LMEXP`） | ⭐ 既有约定：不动、不同步版本号 ✅ |
| ⭐ 版本号 | ⭐ 保持 `0.291.9 / beta22.9`，⛔ 未改 ✅ |

## 3. ⭐⭐ 判据（⭐ 与后端**逐条一致**，⭐ 这是硬要求）

### 3.1 判据本体

```
⭐ 读（⭐ 只读）：HKLM\HARDWARE\DESCRIPTION\System\BIOS
   ⭐   BaseBoardProduct
⭐ ① 精确命中 'MRID6-23'            ⇒ 宝龙达 ⇒ 不装 GCU ✅
⭐ ② 前缀 'MRID6-'（前 6 字符）      ⇒ 宝龙达 ⇒ 不装 GCU ✅（⚠️ 待真机确认，见 4.2）
⭐ ③ 其余一切                       ⇒ 照旧装 GCU ✅
⭐ ④ 读不到 / 空值 / 任何异常        ⇒ 照旧装 GCU ✅（⭐ 失败方向 = 保守 ✅）
```

⭐ 后端 `BaolongdaBackend` 用的是**同一套**（`MRID6-23` 精确 ＋ `MRID6-` 前缀 ＋ 其余不认 ＋
读不到按不是宝龙达）⇒ ⭐ **两路结论永远一致**（⭐ 要么都走宝龙达、⭐ 要么都装 GCU ✅）。

### 3.2 ⛔ 被**明确否决**的判据（⭐ 写在这里，⭐ 免得以后有人再想用）

| ❌ 判据 | ⚠️ 为什么不能用 |
|---|---|
| 型号串含 `Jiaolong` | ⚠️ **50 系蛟龙也含它**，⭐ 而那些是**同方模具**、⭐ 要装 GCU ⇒ **会误伤** ❌ |
| "蛟龙 ＋ 30/40 系" | ⭐ 用户原话：「⭐ **GM5 系的 30 40 蛟龙也是同方** 所以说白名单是对的」⇒ ⚠️ **有 30/40 系蛟龙是同方**（如 `GM5HG0A`）⇒ **会误伤** ❌ |
| 有 `MICommonInterface` | ⚠️ **同方机型也有这个 WMI 类** ⇒ ⛔ 不能作主判据 ❌ |
| 显卡代际（4060/4070） | ⚠️ 同方机型也有 40 系 ⇒ ⛔ 不能单独当判据 ❌ |

### 3.3 ⭐ 白名单安全性：**已被真机数据验证** ✅

⭐ 用户确认 + 28 个诊断包扫出来的「机型 ↔ 板号」对照：

| 模具 | 板号实例 |
|---|---|
| ⭐ **宝龙达** | ⭐ `MRID6-23` ✅ |
| ⭐ **同方** | ⭐ `GM5HG0A` · `GM6IX8B` · `KUANGSHI-JIGUANG Series-X6AR55xW`（RTX 5070）· `YAOSHI Series-X6AR55y`（RTX 5070）· `Standard`（板号读不到） |

⇒ ⭐ ⭐ **同方机型【没有一个】用 `MRID6-` 前缀** ⇒ ⭐ **白名单不会误伤同方** ✅

### 3.4 ⭐ 为什么用**注册表**而不是 WMI

```
⭐ ① Inno Pascal 读注册表是一行 RegQueryStringValue，⛔ 无需 COM/WMI 依赖 ✅
⭐ ② 这两项与 WMI 的 Win32_BaseBoard.Product / Win32_ComputerSystemProduct.Name
      ⭐ **同源**（⭐ 同一份 SMBIOS 数据 ✅）
⭐ ③ 真机抓包实证过这两项的值：BaseBoardProduct = MRID6-23 ✅ · SystemProductName = Jiaolong Series MRID6 ✅
```
