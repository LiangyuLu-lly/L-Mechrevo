旧 WinForms 水冷区（`archive/refs/L-Mechrevo-18.6-source/source/MechrevoLite/SettingsForm.cs`，只读参考）：

- 控制路由不是「一律 BLE」：`GetLiquidCoolingRoute()` 决定 `DirectBle` / `Gcu` / `BluetoothObserved`（例如 `:1887`、`:1941`、`:2499`）；
- 泵/风扇：`DirectBle` 走 `ble.ApplyPumpProfileAsync/ApplyFanProfileAsync`；`Gcu` 走 `Program.service.SwitchLcPump/SwitchLcFan/SwitchLcFanAuto`（`:1949-1970`、`:2046-2066`）；
- 灯光：旧 UI 有「水冷灯光」按钮 + `LiquidCoolingLightMenu`（`:2112-2175`），菜单项为
  青色常亮/青色呼吸/七彩/七彩呼吸/自定义常亮/自定义呼吸/风扇旋转/风扇彩虹/关闭（`:2135-2147`）；
- 下发：`DirectBle` ⇒ `ble.ApplyLightProfileAsync`；`Gcu` ⇒ `Program.service.LcApplyLightProfile(profile, color, persist:true, requireReadback:true)`（`:2523-2537`）；
- GCU 灯效确认/恢复：`Program.hw.LcLightingStatusSeen` 用于「已确认/已发送」文案（`:2552`）；`RestoreSavedGcuLightingAsync()` 按 `lc_light_profile`/`lc_light_color` 恢复（`:2839-2875`）；
- 风扇灯支持：`SupportsLiquidCoolingFanLighting(route)`：BLE 看 `ble.SupportsFanLed`，GCU 看 `Program.hw.LcFanLightingSupported`（`:2894-2907`）。

### 1.2 为什么 WPF 不搬 BLE UI

- WPF 项目当前没有 BLE 宿主：旧 `WaterCoolerBle` 依赖 WinRT `Windows.Devices.Bluetooth*`，而 WPF 的 `BackendProbe` 只创建 `MechrevoHw`/`MechrevoService`（GCU/EC 后端）；WPF 工程没有 `Program.ble` 等价物，也没有 BLE 连接管理界面；
- 目标机是 GCU 水冷（WPF 水冷卡由 `_backendProbe.Hw.SupportsLiquidCooling` / `Capabilities.LiquidCooling` 驱动），硬加 BLE 会得到**不可用的连接按钮/扫描 UI**；
- 因此本次 **不新增 BLE 设备发现/连接 UI**；若以后有 BLE 机型，应作为独立 `LiquidCoolingBleService` + 路由层接入，而不是在当前 GCU 卡里塞假按钮。

## 三、本次新增入口

### 3.1 能力判定（不硬编码机型）

新增 `tools/dev/wpf-p0/Services/LiquidCoolingLightService.cs`（纯逻辑，不碰 UI/硬件连接）：

```csharp
SupportsColor(hw) =
    hw.SupportsLiquidCooling &&
    (hw.LcLightingStatusSeen || hw.LcHeadLightMode >= 0 || hw.LcFanLightMode >= 0
     || (hw.LcLedRed >= 0 && hw.LcLedGreen >= 0 && hw.LcLedBlue >= 0));
```

- `LcLightingStatusSeen` / `LcHeadLightMode` / `LcFanLightMode` / `LcLedRed/Green/Blue` 均来自 GCU `BT_LC/Status` 解析（`MechrevoHw.cs:9041-9050`），不是按机型名写死；
- 风扇灯特效另按 `hw.LcFanLightingSupported`（`MechrevoHw.cs:1570-1579`）；
- 无灯光能力位 ⇒ 灯光行 `Visibility=Collapsed`，不会出现一条点了没反应的入口。

### 3.2 下发 API

现有 `MechrevoService` 已有能力（未改 source）：

- `LcSetLightColor(Color)`（`MechrevoService.cs:3763-3766`）→ `BT_LC/Control` `{Action:"LEDControl", LCLED_R/G/B:"…"}`（`:3768-3785`）；
- `LcApplyLightProfile(profile, color, persist, requireReadback)`（`:3668-3721`）→ 按 profile 下发灯头/风扇灯效果，必要时回读确认；支持
  `cyan_static` / `cyan_breath` / `colorful` / `colorful_breath` / `custom_static` / `custom_breath` / `fan_rotate` / `fan_rainbow` / `off`。

WPF 封装（`LiquidCoolingLightService.ApplyAsync`）：

```csharp
service.LcApplyLightProfile(profile, color, persist: true, requireReadback: true)
```

颜色持久化沿用旧键 `lc_light_color`、效果持久化沿用 `lc_light_profile`，与 WinForms 基准兼容。

### 3.3 UI 行为

- `MainWindow` 水冷卡新增「灯光」行：效果下拉（关闭/青色常亮/青色呼吸/七彩/七彩呼吸/自定义常亮/自定义呼吸；有 `LcFanLightingSupported` 时追加风扇旋转/风扇彩虹）+「颜色」按钮（打开现有 `ColorPickerWindow`）；
- `OriginalStyleWindow` 用代码动态把同一行追加到 `LiquidSection`（不改 XAML，遵守写作用域），逻辑与宽屏一致；
- 效果改变 ⇒ 调 `LcApplyLightProfile`；颜色选择 ⇒ 保存 `lc_light_color` 后按 `custom_static`（若当前不是自定义）下发一次；均用 `StatusText` 显示结果；
- 「颜色」按钮的色块取自 `LcLightingStatusSeen`/LED 状态读回（`LcLed*`）或已保存值，没有能力位时整行隐藏；
- 没有新增任何 BLE 扫描/连接控件。

## 六、验收要点

1. **无 BLE 机型/无 GCU 灯光能力**：水冷卡只显示原有泵/风扇；灯光行不出现（`SupportsColor==false`）；无 BLE 扫描/连接按钮；
2. **GCU 有水冷灯光能力**：水冷卡出现「灯光」行；效果下拉与旧版菜单语义一致（常量/呼吸/七彩/自定义/关；风扇灯仅在 `LcFanLightingSupported` 时出现）；
3. **颜色**：点「颜色」→ `ColorPickerWindow` → 保存 `lc_light_color` → 下发 `custom_static`（或保持当前自定义 profile）；状态提示成功/失败；
4. **持久化**：重启后下拉选中 `lc_light_profile`、色块为 `lc_light_color`；
5. **范围**：其余灯光编辑器、BackendProbe、App、source 均无改动。

> 说明：当前没有目标机 GCU 水冷硬件可在此会话实测「灯色实际变化」；能力位/UI 显隐与下发路径已按 `MechrevoService.LcApplyLightProfile/LcSetLightColor` 实现，构建和启动验证通过。管理员真机运行时的最终灯色确认需机主/测试执行。
