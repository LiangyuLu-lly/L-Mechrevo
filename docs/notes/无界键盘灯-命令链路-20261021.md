# 无界 WUJIE14XA 键盘灯：命令链路、50 GCU 协议与最小修复方案

日期：2026-10-21（只读分析，未修改 `source/`）
机型：MECHREVO WUJIE14XA / 主板 WUJIE14-GX4HRXL / AMD Ryzen 7 8745HS（无独显）/ GCU 1.2.0.0
结论先行：**硬件/GCU 通道可用；LM 当前失败有两层原因：**
1. **P0（已由 Lead 定位并修）：`KeyboardCtrlPublishSwitch.Enabled` 在启动早期把 `false` 缓存成永久 OFF**，无界的「自动启用全字段链路」永远没生效，整进程一条 `Keyboard/Ctrl` 都不发；
2. **协议/顺序层：** 即使开关打开，仍有两个高概率失败点：
   - 亮度发的是 `function:"SetLightingLevel"`，50 GCU 的键盘亮度入口是 `RGBKeyboard_SetEffectLight`（`light` 字段），组件里**没有** `SetLightingLevel` 入口；
   - 键盘电源 `SetPower` 与效果 `SetEffectALL` 是两条独立路径，而 50 GCU 单分区 EC 的 `RunEffct()` **只在 GCU 内部 `_PowerStatus == On` 时才写 EC**（`SingleZone.cs:894-902`）⇒ 先发效果、后开电源（或电源未确认）时，效果被静默丢弃，表现就是「灯不亮/不生效」。

### 3.3 50 单分区解析器实际读取的字段

`SingleZone.SetEffect`（`SingleZone.cs:230-586`）只读取：

- `effect`（`:246`）
- `MonochromeIndex`（`:292`）
- `ManualIndex1..6`（`:318`..`:448`）
- `ManualInterval`（`:474`）
- `BreathingIndex`（`:500`）
- `color`（`:525-551`，转为 `UserDefineColor`）

⇒ **它不读 `light`、`speed`、`direction`、`nv_save`、`powerstatus`、`solution`、`level`、`type`。**
因此：
- 效果/颜色只能靠 `SetEffectALL`；
- 亮度必须走另一条入口（见 §3.4），不能指望 `SetEffectALL.light` 在 50 单分区上生效；
- `powerstatus` 在 `SetEffectALL` 里没有作用，开/关必须走 `SetPower`（或官方控制台那样先确保电源 On）。

### 3.4 亮度与电源的 50 GCU 入口

50 GCU 中 `RGBKeyboard` 可见的键盘亮度/电源相关处理：

- **亮度**：`GCUService/MyRGBKeyboard/RGBKeyboard.cs:995-1105`（`RGBKeyboard_SetEffectLight(dynamic data)`）
  读取 `mode` 和 `light`，调用 `m_hidkeyboad.SetBrightness(num)`（`:1092-1103`）。
  另有 `RGBKeyboard_SetEffectLight_ACDC`（`:861-990`）读取 `ACBrightness`/`DCBrightness`。
  50 GCU 组件里**没有 `SetLightingLevel` 这个方法/入口**（全源码检索只有 `LM_Manager.LM_SetLightingLevel` 内部方法）。
- **电源**：`SetPower` 的 MQTT 分发在 `OnMqttMessage` 状态机里（该文件未能完整还原出 async 方法体），但 LM 现有 `{"function":"SetPower","powerstatus":0|1}` 与 GCU 的 `SetPowerStatus` 语义一致：`SingleZone.SetPowerStatus`（`:597-627`）→ `SetPowerDisable_EC`（`:631-639`）。
  ⇒ **建议保留 SetPower，但开灯后必须补发效果帧**（见 §4 P2/P3）。

### 3.5 EC 寄存器（50 单分区 = EC 背光）

| EC 地址 | 十进制 | 用途 | 位/取值 |
|---|---|---|---|
| `0x78C` | 1932 | 键盘背光使能 + 亮度 | bit1：`1`=关闭/禁用，`0`=开启（`SetPowerDisable_EC` `:631-639`，`bitArray[1] = enable`，Off 调 true）；bit4..7：亮度档位（`SetBrightness_EC` `:643-696`） |
| `0x767` | 1895 | 颜色模式/彩虹 | bit5：单色 `SetRGBLevel` 置 true（`:1233-1246`）；bit7：彩虹 `StartRainbowMode=true` / `StopRainbowMode=false`（`:1250-1277`） |
| `0x769/0x76A/0x76B` | 1897/1898/1899 | 单色 R/G/B 等级 1..50 | `SetRGBLevel` 依次写三色（`:1233-1237`） |
| `0x7C5` | 1989 | 呼吸色 | 低 3 位：`BreathingIndex` 0..4（`StartBreathingMode` `:1406-1427`） |

亮度位模式（`SetBrightness_EC`）：

| level | bit4 | bit5 | bit6 | bit7 |
|---|---|---|---|---|
| 1 | 1 | 1 | 0 | 0 |
| 2 | 1 | 0 | 1 | 0 |
| 3 | 1 | 1 | 1 | 0 |
| 4 | 1 | 0 | 0 | 1 |
| 其它/0 | 1 | 0 | 0 | 0 |

### 4.3 失败点排序

1. **P0（已定位，Lead 已修）**：开关缓存 `false`，整进程 OFF，无任何帧。诊断包直接证据见 §1.3。
2. **P1（高）**：亮度 function 名不对：LM `SetLightingLevel` vs 50 GCU `RGBKeyboard_SetEffectLight`。证据：`RGBKeyboard.cs:995`、`:1092-1103`；50 组件无 `SetLightingLevel` 入口。
3. **P2（高）**：效果/电源顺序。`SingleZone.RunEffct` 的 `_PowerStatus == On` 门（`:894-902`）+ `SetPowerStatus` 的 `save_effect != 0` 门（`:614-619`）⇒ 冷启动 `powerStatus:Off` 时效果帧不落 EC；LM `SetKeyboardPower(true)` 只发 `SetPower`，不补效果。
4. **P3（中）**：`SetEffectALL` 的 `powerstatus=1` 与官方 `0` 不一致；`ManualInterval=6` 与官方 `10` 不一致；低风险但建议对齐。
5. **P4（中）**：首次/重置后 `DefaultData`/GCU `_EcEffectData` 为空，开灯后若没有全字段效果帧，颜色/效果不恢复。
6. **P5（低）**：`MonochromeIndex=33` 时若 `ColorBuffer` 第一段缺失/默认红，单色会变成红色；LM 新链路在非 Single 效果可能传 `singleColor=null`，`BuildColor` 会填默认红（`KeyboardCtrlPayload.cs:55-79`、`:218-231`）。

- 保留自动启用日志：`[kbd] 无界键盘：自动启用 Keyboard/Ctrl 全字段链路（默认 OFF 只对非无界机型）`。

验收：无界诊断包不应再出现 `Keyboard/Ctrl 下发开关 = OFF … 不发任何 Keyboard/Ctrl 帧`；应出现 `[kbd] Keyboard/Ctrl SetEffectALL …`。

### 5.2 P2：开灯后补一次全字段效果（推荐最小改法）

`source/MechrevoLite.Hardware/MechrevoService.cs`，`PublishKeyboardCtrlPowerAsync(bool on)`（`:5314-5332`）：

- `on == true` 时：先发 `SetPower(powerstatus=1)` → 等待 150~250ms → 调用 `PublishKeyboardCtrlEffectAsync(savedEffect, savedLight, savedSpeed, savedColor)`（全字段 `SetEffectALL`）；
- `on == false`：保持 `SetPower(powerstatus=0)`；
- 保存值从 `LightingSettingsStore.Load("Keyboard/Ctrl", "Single")` 读，颜色按 `ResolveKeyboardColor`/`EffectiveColorArgb`，不要新造换算；
- 若 `SetEffectALL` 返回 false，日志如实记录，不静默。

这样可同时覆盖 `_PowerStatus Off` 门（效果晚于电源）和 `save_effect==0`（冷启动无内部保存）两种情况。

### 5.3 P1：亮度 function 改为 50 GCU 可识别的入口

`source/MechrevoLite.Hardware/MechrevoService.cs`，`PublishKeyboardCtrlBrightnessAsync`（`:5335-5381`）：

- 把 payload 的 `function` 从 `"SetLightingLevel"` 改为 **`"SetEffectLight"`**，保留 `mode:"Lighting"` 和 `light`（字符串），可只发 `{function, mode, light}`（`RGBKeyboard_SetEffectLight` 只读这两个字段，`:1092-1103`）；
- 若要兼容其它机型，可保留原 `SetLightingLevel` 作为 fallback（按机型分支：无界/50 EC 用 `SetEffectLight`，其它保持原样），避免扩大影响；
- 亮度值仍用现有 `MapSoftwareBrightnessToHardwareLevel` / `Light` 映射，不新造换算。

### 5.4 P3：`SetEffectALL` 对齐官方值

`source/MechrevoLite.Hardware/MechrevoService.cs:5291-5301` 与 `KeyboardCtrlPayload.cs:89-138`：

- `powerstatus` 默认改为 `0`（与官方 SetEffectALL 一致；`SetPower` 单独管电源）；
- 非 Manual 的 `ManualInterval` 用 `"10"`（与官方一致），Manual 时保留实际节奏；
- `MonochromeIndex`/`ColorBuffer`：自定义色固定 33 且 `ColorBuffer[0]` 必为用户色；预设色用 1..29；
- 无界 `effect` 仅允许 `Single`/`Breathing`/`Rainbow`/`Manual`（UI 表已由 `KeyboardFirmwareEffects.SingleZone` 提供）。

### 5.5 日志与可验证判据

建议在 `PublishKeyboardCtrl*` 已有日志基础上补：

- 发送前：`[kbd] Keyboard/Ctrl 发送：function=… effect=… light=… mono=… color=… blocks=7`（现有日志已含大部分）；
- 发送后：读取 `Keyboard/Status`，校验 `powerStatus` 是否为 `On`、`brightNess` 是否等于目标档位；
- 失败判定：`GCU` 未回 `Keyboard/Status.powerStatus=On` ⇒ 电源未生效；`SetEffectLight` 后 `brightNess` 不变 ⇒ 亮度入口不对；`SetEffectALL` 后 `Keyboard/Status.effect`/`DefaultData.save_effect` 不变 ⇒ 效果未接收；
- 可选 EC 只读核对（管理员）：`tools/dev/ec-kbd-sniff.ps1 -Start 0x78C -End 0x78C` 观察 bit1/bit4..7 变化；`0x767` 观察彩虹/单色位。

### 5.6 真机验收步骤

1. 使用包含 P0 + P2/P1 修复的构建（不打包也可直接跑 exe）；
2. 打开键盘灯设置，检查日志：`[kbd] 无界键盘：自动启用…`、`Keyboard/Ctrl SetPower`、`Keyboard/Ctrl SetEffectALL`；
3. 选择 Single / Breathing / Rainbow / Manual，确认灯变化；
4. 拖亮度滑块，确认 `SetEffectLight` 发送且实际亮度变化；
5. 关闭再打开键盘灯，确认颜色/效果恢复（P2 补帧）；
6. 同时用 `tools/dev/gcu_kbd_capture.py` 抓 `Keyboard/Ctrl`，确认字段与 §3.2 一致；用 `ec-kbd-sniff.ps1` 只读核对 0x78C/0x767 写入。
