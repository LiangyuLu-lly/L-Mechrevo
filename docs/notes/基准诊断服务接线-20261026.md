## 2. 接线位置与时序

### 2.1 `--ui-probe` 优先无界面（App.xaml.cs `OnStartup` 第一段）

```csharp
protected override void OnStartup(StartupEventArgs e)
{
    // task-24：--ui-probe 优先无界面（等价旧 Program.cs:340-343；必须在单实例互斥体之前）
    if (L_Mechrevo.WpfP0.Services.UiProbeRunnerService.TryHandleHeadless(e.Args, out int uiProbeExitCode))
    {
        Environment.ExitCode = uiProbeExitCode;
        Shutdown();
        return;
    }
    bool startupLaunch = false;               // 原 task-23 逻辑
    ...
    HeadlessStartupService.TryHandle(...)     // 原 task-22 无界面参数
    _instanceMutex = new Mutex(...)           // 单实例
```

- `list`/`?`/空参数 → 打印帮助、`ExitCode=0`、立即退出（不建窗口、不拿互斥体、不连硬件）。
- 未知能力档/窗体 → `ExitCode=2`、退出。
- 合法 `<profile>:<form>` → 返回 false，继续正常启动（由 §2.3 的 `TryApplyPreview` 应用合成能力位）。
- 时序理由：与旧 `Program.Main` 一致（参数分支先于单实例判定），保证“预览/帮助”永远不会被已有 UI 实例挡掉。

### 2.2 正常启动：单实例/语言之后、创建窗口之前

插入位置：`OnStartup` 里 **取得单实例互斥体且设置 UICulture 之后**、`ApplyFont()` 之前：

```csharp
// ① 旧 Program.cs:920-954 启动诊断顺序（只读；每项内部 try/catch，失败不影响启动）
StartupDiagnosticsService.Run();          // UiQa/Force30Perf/LightCompat/KeyboardCtrl*/MachineCodeProbe
ModelScopeDiagnosticsService.LogStatus(); // 只读 marker 日志（基线 0 调用迁移，不迁移）
_ = UiQaShowAll.Enabled;                  // UiQa 初始化/缓存
UiQaShowAll.LogStartupState();            // 默认 OFF 也打一行（task-20 服务内部有一次性缓存，重复调用安全）

// ② 合法 --ui-probe 预览（无参数时无操作）
UiProbeRunnerService.TryApplyPreview(e.Args);

// ③ 息屏生命周期（等价旧 Program.cs:979 / SettingsForm PBT_APMSUSPEND/APMRESUMEAUTOMATIC）
VirtualDisplayBlankService.InitializeStartupCleanup();  // Task.Run 清 usbmmidd 虚拟屏残留（不阻塞启动）
VirtualDisplayBlankService.AttachPowerEvents();         // Suspend→AbortOnSuspend / Resume→RestoreImmediate

ApplyFont();                              // 原逻辑
```

- 为什么放在单实例之后：旧 Program 的“后一半”日志（LightCompat/KeyboardCtrl/MachineCode）也在单实例判定之后 ⇒ 第二个实例不会再打一遍。
- 为什么放在窗口创建之前：`OriginalStyleWindow` 构造/后端连接需要读能力位；`--ui-probe` 合成能力位必须先挂上。
- 外层再包一层 `try/catch` 记 `[diag] ... 失败（不影响启动）`，单点异常不会阻塞启动。

## 5. 风险 / 未确认

1. **测试实例处理**：见 §4.2。提权测试实例已自行正常退出（无 crash/error），未残留；本轮无需要人工清理的进程。
2. **`VirtualDisplayBlank` 真机未回归**：`Start()` 依赖安装包分发的 `usbmmidd_v2` 驱动；若组件缺失，点击会返回失败原因（已记日志，磁贴回弹），不会崩。需真机验证：点息屏→屏灭、移鼠标恢复、外接屏拓扑保持、睡眠/唤醒不重复熄屏、崩溃后重启清残留。
3. **`--ui-probe` 预览能力位会被真实 BackendHost 连接替换**：预览仅用于样式检查，不代表真机能力（与旧版同一定位）。
4. **并行构建竞争**：同一工作区多人构建 `WpfP0.csproj` 会争 `obj`/输出锁；本轮已遇到并规避，建议串行构建或各自 `-o` 输出（但共享 obj 仍可能被锁）。
5. **日志级别**：默认“仅错误”下 `[qa]/[model-scope]/[machine-code]` 等 Info 行不落盘（与基线一致）；需要验收这些行时用 `LMECHREVO_LOG_LEVEL=all` 启动（用户日志目录），或用诊断包里的机型码节。
