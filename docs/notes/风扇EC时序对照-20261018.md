# 风扇 EC 时序对照（2026-10-18 · 机主「EC 全 0 / 写失败」后的根因分析）

> 目的：把开源蛟龙（JiaolongControl，MIT）的 `EC_RAM_READ` / `EC_RAM_WRITE` 与我们的 `EcLpcIo` **逐行对照**，
> 说明机主实测「0xC83C/0xC83D/0xB20/0x2000/0x1060/0xC411 **全 0**」到底错在哪一步。
> 只记录**协议事实**（端口/命令/顺序），未复制任何第三方代码。

## 1. 参考实现的完整时序（事实）

出处：`D:\openLM-baolongda\_refs\JiaolongControl\JiaoLongControl\Server\Core\Drivers\Blding64.cs`（187 行）

```
ECMemoryTable: EC_ADDR_PORT = 0x4E, EC_DATA_PORT = 0x4F
               Fan1_RPM_SET = 0xC83C, Fan2_RPM_SET = 0xC83D
EC_init():
    id = EC_RAM_READ(0x2000)
    if (id == 0x55) { v = EC_RAM_READ(0x1060); EC_RAM_WRITE(0x1060, v | 0x80); }   // 解锁

EC_RAM_READ(iIndex):
    high = iIndex >> 8;  low = iIndex & 0xFF;
    WritePort(0x4E, 0x2E); WritePort(0x4F, 0x11);   // 索引 = 0x11（地址高）
    WritePort(0x4E, 0x2F); WritePort(0x4F, high);   // 数据 = high
    WritePort(0x4E, 0x2E); WritePort(0x4F, 0x10);   // 索引 = 0x10（地址低）
    WritePort(0x4E, 0x2F); WritePort(0x4F, low);    // 数据 = low
    WritePort(0x4E, 0x2E); WritePort(0x4F, 0x12);   // 索引 = 0x12（数据）
    WritePort(0x4E, 0x2F);                          // 访问数据命令
    ReadPort(0x4F);                                 // ⇒ 该地址的值

EC_RAM_WRITE(iIndex, data):  // 同上三步寻址，最后
    WritePort(0x4E, 0x2E); WritePort(0x4F, 0x12);
    WritePort(0x4E, 0x2F); WritePort(0x4F, data);

CpuFanSetSpeed(speed): EC_RAM_WRITE(0xC83C, speed); mask = EC_RAM_READ(0xB20) | 0x02; EC_RAM_WRITE(0xB20, mask);
GpuFanSetSpeed(speed): EC_RAM_WRITE(0xC83D, speed); mask = EC_RAM_READ(0xB20) | 0x08; EC_RAM_WRITE(0xB20, mask);
RemoveFanSpeed():      CpuFanSetSpeed(0); GpuFanSetSpeed(0); EC_RAM_WRITE(0xB20, 0x00);
```

**关键：0x4E/0x4F 不是「标准 SuperIO index/data」**，而是 **ITE EC-RAM 命令口/数据口**：

| 端口 | 角色 |
|---|---|
| `0x4E` | **命令口**：写 `0x2E` =「下一个字节是索引寄存器号」；写 `0x2F` =「下一个字节/读回是数据」 |
| `0x4F` | **数据口**：命令 `0x2E` 后写索引寄存器号；命令 `0x2F` 后写数据 / 读数据 |

⇒ 访问一个索引寄存器 = **4 个端口写**（命令 0x2E + 索引号，命令 0x2F + 数据）；读 = 3 写 + 1 读。

## 2. 我们原来的时序（错误）

`EcLpcIo.ReadByteCore` / `WriteByteCore`（改前）走 PawnIO `ioctl_superio_outb/inb`，
即**标准 SuperIO index/data**：`outb(0x4E, 寄存器号); outb(0x4F, 值)`。

| 步骤 | 蛟龙（正确） | 我们（改前） | 结果 |
|---|---|---|---|
| 选地址高 | `0x4E←0x2E; 0x4F←0x11; 0x4E←0x2F; 0x4F←high` | `0x4E←0x11; 0x4F←high` | ❌ 0x4E 收到命令 `0x11`（非 0x2E/0x2F），EC 不进入 XRAM 访问态 |
| 选地址低 | `0x4E←0x2E; 0x4F←0x10; 0x4E←0x2F; 0x4F←low` | `0x4E←0x10; 0x4F←low` | ❌ 同上 |
| 读数据 | `0x4E←0x2E; 0x4F←0x12; 0x4E←0x2F; 读 0x4F` | `0x4E←0x12; 读 0x4F` | ❌ 读到一个与 XRAM 无关的值 |
| 写数据 | `0x4E←0x2E; 0x4F←0x12; 0x4E←0x2F; 0x4F←data` | `0x4E←0x12; 0x4F←data` | ❌ EC 不认，写失败 |

**结论：错在“把 0x4E/0x4F 当成标准 SuperIO 索引/数据对”。**
机主实测全 `0x00`（含 `0x2000` 芯片 ID 应为 `0x55` 却是 `0x00`、`0xC411` 版本 `0x00`）正好说明：
我们读到的不是 XRAM，而是错误命令路径下的 0/填充值。

## 3. 修正（本次提交）

- `EcLpcIo` 改用 **PawnIO LpcIO 的原始端口 I/O**（`ioctl_pio_outb` / `ioctl_pio_inb`，模块只放行所选槽位 +0/+1）；
- 按蛟龙时序实现 `EcWriteIndex(reg,val)` / `EcReadIndex(reg)`：
  ```
  命令 0x2E → 索引号；命令 0x2F → 数据(写) / 读回(读)
  ```
- 地址映射不变：索引 `0x11`=地址高、`0x10`=地址低、`0x12`=数据；
- 槽位 1（0x4E/0x4F）仍默认；slot 0（0x2E/0x2F）保留对照能力；
- `EC_init` 的解锁（`0x1060 |= 0x80`）：**2026-10-18 机主批准并已实现**（见 §4/§5）；
  只允许 `当前值 | 0x80`（读-改-写、保留其它位），只在 `0x2000 == 0x55` 时执行，写后回读 bit7=1；
  `--fan-ec-test` 的 finally 会把 `0x1060` 写回测试前读到的原值。

## 4. 判据修正（机主实测确认后的最终版）

旧判据「0xC83C/0xC83D/0xB20 三个地址都读得到」→ **不够**（全 0 也“读得到”）。
中间版又加了「三地址非全 0」→ **假否决**：机主报告 `0xC83C/0xC83D` 在**固件自动控制时本来就是 0**，
而 `0xC834/0xC835=0x14`（2000 RPM）与 WMI 13 完全吻合 ⇒ EC 已经可访问。

最终判据（`EcLpcIo.TryReadEcIdentity`，只读）：
- `0x2000` 芯片 ID **必须 == `0x55`**；
- **且** `0xC411` EC 版本 **非 `0x00`/`0xFF`**；
- 不满足 ⇒ **EC 不可访问** ⇒ `FanCurveVerified` 保持 false、UI 继续隐藏、**不写任何 EC 字节**；
- ⛔ 不再把“目标寄存器为 0”当成不可访问（目标为 0 是固件自动控制下的正常值）。

## 5. 下一步（2026-10-18 机主实测结果）

机主已确认：`0x2000=0x55 ✅` · `0xC411=0x23 ✅` · `0xC834/0xC835=0x14`（≈2000 RPM，与 WMI 13 吻合）
⇒ EC 只读通路已修好 ✅；`0x1060=0x00` ⇒ **未解锁**，按批准先执行 `0x1060 |= 0x80` 再写风扇。

`--fan-ec-test` 新流程：身份 → 解锁（回读 bit7）→ 读基线（0xC834/0xC835 + WMI 13）→
写 Fan1 目标 +5 + `0xB20 bit1` → 等 2 s → 读回（RPM 涨 ≥200 判可用）→ finally
（目标 0、清 `0x02|0x08`、`0x1060` 写回原值），报告含解锁前后 `0x1060` 与写入/回读细节。

## 6. 2026-10-18 第二轮实测：读成功、写失败 ⇒ 仪表化 + 双通道对照

机主报告：身份 `0x2000=0x55 / 0xC411=0x23` ✅，但**写 `0x1060` 失败**（0x00 → 回读 0x00）。
⇒ 读通路正确，**写通路被拒**（ioctl 失败 or EC 不认序列）。本轮只做排查，不改产品逻辑：

- `PawnIOWrapper`：新增 `LastError`（最近一次 ioctl 的 Win32 错误码），`Execute` 失败时记录；
- `EcLpcIo`：新增写操作**仪表化**——
  · `LastWriteTrace`：最近一次写操作的**完整端口序列**（`pio_outb(0x4E,0x2E) · ioctl_rc=…` 逐行），
    报告里可与 `Blding64.EC_RAM_WRITE` 逐条并列；
  · `LastIoctlOk` / `LastIoctlError`：最后一条 ioctl 结果 / Win32 错误码；
- `EcChannelCompare`（新）：**ACPI EC 只读对照** —— 用 `EcPortIo.TryReadByte`（XRAM mailbox 0x92）
  读 `0x2000/0x1060/0xC411/0xC83C/0xC83D/0xB20/0xC834/0xC835`；
  若 ACPI EC 也能读到 `0x2000=0x55` ⇒ 说明两条通道都能读，**写可能应走 ACPI EC**（下一轮验证）；
- `--fan-probe` / `--fan-ec-test` 报告都已加入上述只读对照；`--fan-ec-test` 还会打印每次写的端口序列；
- ⛔ 本轮**不改任何产品风扇逻辑**，⛔ 不写 ACPI EC（只读）；仍保持“未验证 ⇒ 不开放”。
