## 5. 星耀真机未验证项 / 风险

> 开发机不是星耀 AMD，以下均**未实测**，需真机（P916F AMD + PawnIO + 无 NVIDIA）验证：

1. **平台判据命中**：`XingyaoPmc2.IsXingyaoPlatform()` 依赖 `GcuIdentity.Variant=="WJXY"` 或机型串含`星耀/XINGYAO/P916F`；`WujieSmuGate.Evaluate()` 需正确得到 AMD + 无 NVIDIA。若两处口径不一致（例如星耀也命中 `WJXY` 但机型名含「无界」）会走无界路径——需确认 `!IsWujie` 分支真机成立。
2. **SMU 就绪**：需 PawnIO 安装 + AMD SMU 可读；`XingyaoAmdSmuApu` 含 `SmuAvailability.IsReady`，未就绪时星耀退回既有 GCU/固件路径（是否可接受需机主确认）。
3. **SMU 写读语义**：本次沿用无界口径（PL1→STAPM、PL2→fast/fPPT、slow 独立、fast≥slow 自动抬升、UXTU 式不强制回读）；星耀固件是否同样接受这些命令、PM 表是否可读、PL 范围 15–90W / Tcc 60–105℃ / STAPM 时间范围（BaolongdaProfile 常量）是否真实适配——全部未实测。
4. **UI（WPF）仍有四处直接 `WujieSmuApu`**（写作用域外，本次未改）：
   - `CustomModeWindow:171` 路由提示仍是默认/宝龙达提示（非「本机应用」）；
   - `:528` 无 SMU 标签回退（PL1/PL2 显示通用标签而非 SMU 标签，即使字段行可见）；
   - `:593-600` 滑杆 Min/Max 仍取默认 `hw.Pl1Minimum/Maximum`，不是 WujieSmuGate 15–90W（Core 写入会二次夹取，UI 范围与下发范围可能不一致）。
   - SMU 行可见性经 `UsesSmuForCustomPower` 间接生效（行可见，无需改 WPF）；如需标签/滑杆也一致，需另派 WPF 任务把上述 4 处改为 `SmuCustomApu`（本次严格未越界）。
5. **`apuOrNoDgpu` 门控**（WPF `:405`）：`WujieSmuApu || DgpuGeneration==NoDgpu`；星耀 AMD 通常无 NVIDIA → NoDgpu=true → 强冷/风扇卡隐藏（符合不打开无界风扇）；若机型上报的 DgpuGeneration 不是 NoDgpu，风扇卡可能仍显示——需真机确认；Core 侧无界风扇 EC/曲线路径仍只认 `WujieSmuApu`，不会实际写 EC。
6. **`EnsureWujieHighPowerModeAsync` 未扩展**：无界「目标功耗 ≥60W 先切狂暴」预步骤，星耀是否需要未知；如需，另行评估。
7. **日志文案**：`PerfModeService:723/747/762/805`、`MechrevoService` UXTU/slow 等部分日志仍写「无界 APU/Wujie」；星耀下会打印该字样（仅文案，不影响能力）；可按需后续统一。
8. **性能/探测副作用**：`PerfModeCapabilities.UsesSmuForCustomPower` 现在会在非 Wujie/非宝龙达时探测一次星耀判据（缓存；WPF 旧调用点在同一次 UI 刷新中可能首次触发）；`XingyaoAmdSmuApu` getter 每次调用会做一次去重日志判断，已用 `Logger.TryMarkChanged` 限制输出但仍有一次判据开销。
9. **无界回归**：未在无界真机上复测；按代码 diff 条件扩展为包含式，逻辑不变，但建议真机点一次自定义档应用/启动恢复确认。
10. **未执行**：真实星耀 SMU 写 PL/温度墙/STAPM、插拔电源/重启恢复、UI 逐项可见性；本轮仅有 Core/WPF 构建与静态审计。
