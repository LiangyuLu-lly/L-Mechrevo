# 耀世 · 灯效回归：需要机主做什么

给机主的一份**照做说明**。这次要办两件事：

1. 定位「**beta18 正常 / beta22（0.291 线）不正常**」这个回归；
2. 查清另一件更要紧的事 —— **你点开【性能模式·自定义】窗口时，LM 进程会被结束 / 崩溃**（你的原话：**「我点开自定义软件就被KILL了」**）。

**一句话背景**：有机主反馈说，**同一台耀世**上 **beta18 正常、beta22（0.291 线）不正常**。要定位是哪一条改动引起的，我们需要在**这台耀世上**拿到一份**新旧对照数据** —— 所以下面几件事都请在**同一台机器**上做。

建议顺序：**先做第零件事**（崩溃那件，最要紧）→ **再做第一件事**（回答问题，2 分钟）→ **第二件事**（导两份包）→ 第三件事有空再做。

---

## ⚠️ 动手之前，先记住这两条（我们在你那份诊断包里看到的问题）

1. **日志级别必须先改成「全部」** —— 打开 LM → **设置** → 「**日志级别**」→ 选「**全部**」→ 然后**退出 LM 再打开一次**。
   你上次那份包里日志级别是「**关闭**」，结果 `日志\log.txt` **不存在**：灯效命令、原始 JSON（`LB-RAW`）、去重记录**一条都没有**。**不改这一项，后面所有材料都不够用。**
   ⚠️ **更正一句（我们之前说错了）**：`crash.txt` **和日志级别没关系** —— 它不是「日志」，而是**崩溃现场**：只要程序里接住了异常，**哪怕日志级别是「关闭」也一定会写出 `crash.txt`**。
   ⇒ 所以「**没有 `crash.txt`**」不是「日志没开」的意思，而是一条**有用的正向证据**：说明**没发生程序能接住的异常**（很可能是被系统/驱动**硬杀**，或原生崩溃/栈溢出——这些只能去**事件查看器**看）。**别把它当成"日志级别不对"而忽略掉。**
2. **导出诊断包要「趁热」** —— 复现完（尤其是崩溃后）**立刻**导，别隔太久、别重启 LM 之后再导。崩溃现场只在崩溃那一刻落盘。

## ⭐ 第零件事（最要紧）：关于「我点开自定义软件就被KILL了」

> ### ⚠️ 先说最要紧的一条：在问题查清前，**请不要点开【性能模式·自定义】窗口**
>
> 不是让你「别点应用、别改数值」那种谨慎，而是**这个窗口本身**：已经查明，**点开它 = 自动触发一次「全量硬件下发」**（把功耗 PL1/PL2/PL4、风扇、超频等一整批设置重新写一遍），而**他的崩溃正是发生在这批下发的中途 —— 进程被瞬间终止**。
>
> ⚠️ **下发做到一半被打断，有可能把 EC / 固件留在"不一致的中间状态"**（比如某几项写进去了、后几项还没写）。他说的「**重启之后灯光就好了**」很可能就是这类中间态被开机流程纠正过来的表现。
>
> 所以：**要碰自定义窗口，等我们这边的针对性修复版本**。这一条优先于下面所有步骤。

**你说的是**：打开【性能模式·自定义】那个窗口时，LM 会被结束 / 崩溃。

**为什么要这些材料**：这类「被 KILL」有两种情况，需要的证据不一样 ——
- 一种是程序里能接住的异常：崩溃瞬间会写 `crash.txt`（就在 `%APPDATA%\MechrevoLite\crash.txt`）；
- 另一种是**被系统/驱动硬杀**（没来得及写任何文件）：这时**只有 Windows 事件查看器**里留下堆栈。

所以下面两条路都要取一遍。

> ⭐ **我们这次又挖了一遍你之前给的两份包，挖到一件很具体的事**（所以上面那条警告不是空话）：
> 你那份包里的日志显示 —— 打开自定义窗口后，LM 会一批一批往下写设置：`GpuDynamicBoostSwitch=1` → `OverClockingSwitch=1`（这一步报了 `GPU OC direct write was rejected and no elevated helper is available.`——**没提权就直接写显卡超频，被驱动拒了**）→ `FanSwitchSpeedEnabled=1` → **`PL1=200`**，然后……**日志就断在这里了**，进程被瞬间终止（下一条日志已经是 7 秒后**新进程**的 `App launched:`）。**也就是说：崩的那一刻，它正写到一半。**

### ① 要做什么（照顺序做；命令可整段复制）

1. **先确认你装的确切版本号**（很重要，不同版本结论不一样）：
   - 看 LM 里 **设置 / 关于** 处显示的版本号（抄下来或截图）；
   - 或打开 `%APPDATA%\MechrevoLite\log.txt`，看最前面形如 `App launched: 0.291.0.0zh-CN.` 的那一行。
   - ⚠️ 我们手上那份包里是 **0.291（beta22）**，**不是 0.291.1**。如果你现在已经升到 0.291.1，请**用你现在这一版**复现，并把版本号告诉我们。
2. **把日志级别改成「全部」**：LM → 设置 → 日志级别 → 「全部」→ **退出 LM，再打开一次**。
3. **复现一次崩溃**：点开【性能模式·自定义】窗口，等它崩 / 窗口消失。
   ⚠️⚠️ **停一下** —— 这一步 **只在我们明确说"可以了"之后再执行**（原因见本节开头那条红框警告：**打开这个窗口本身就会触发一次全量下发，中途被打断可能把 EC/固件留在中间状态**）。如果只是想配合我们拿材料，**先做第 5 步的事件查看器**（那一步不需要你再崩一次），并把**已经崩过那几次**的信息发我们。
4. **崩溃后立刻**用 LM 底部那排按钮里的【**诊断**】导出诊断包（保存到自己找得到的位置，比如桌面）。
5. **再取一份 Windows 事件查看器的记录**（这条最关键，硬杀类崩溃只能靠它）：
   - 按 `Win + R` → 输入 `eventvwr.msc` → 回车；
   - 左边展开「**Windows 日志**」→ 点「**应用程序**」；
   - 右边点「**筛选当前日志…**」→ 勾上「**错误**」（顺便勾「警告」）→ 时间选「**最近 1 小时**」（或你刚崩溃的那段时间）→ 确定；
   - 在列表里找**来源**是 `Application Error`、`.NET Runtime`、`Application Hang`、`Windows Error Reporting` 的行，**事件 ID 常见为 1000 / 1002 / 1026**，描述里会出现 `L-Mechrevo.exe`；
   - 找到后**右键那一行 → 「复制」→「复制详细信息」**，粘到记事本里发我们；**顺手截一张图**（能看到时间、来源、事件 ID，以及下面那段异常文本）。
   - 如果筛选后什么都没有：**不要筛选**，直接在「应用程序」里按时间翻到崩溃那一刻，找**红色的错误**。
6. **同时告诉我们崩溃前的动作**：崩之前你有没有点过「**应用**」、有没有**改过数值**、有没有**切过模式 / 插拔电源 / 开过别的窗口**。
7. **⚠️ 补两问（这次新加的，很关键）**：
   - ☐ **崩溃前，你有没有点过【以管理员身份重启】**（就是弹过 **UAC** 那个"是否允许此应用对你的设备进行更改"的小窗）？点过 / 没点过 / 记不清？—— **这条能一刀切开两种完全不同的死法**（自己重启退出 vs 被系统硬杀）。
   - ☐ **事件查看器**（就是下面第 5 步那个界面）里，请**明确按下面三条来找**：
     - 筛选「**错误**」；
     - **来源**找这三个：**`Application Error`**、**`.NET Runtime`**、**`Application Hang`**；
     - **事件 ID**找这三个：**`1000`** / **`1002`** / **`1026`**；描述里必须有 **「出错应用程序名称: L-Mechrevo.exe」**。
     - 找到后，**务必抄下两样**：**「异常代码」** 和 **「出错模块名称」**（照抄原文，别改写成中文）。
     - 对照表（方便你判断，也方便我们）：

       | 异常代码 | 含义 | 对我们的意义 |
       |---|---|---|
       | `0xc0000005` | 访问冲突（读/写非法内存） | 原生崩溃，最常见 |
       | `0xc00000fd` | 栈溢出（递归太深） | 原生崩溃 |
       | `0xc0000409` | FailFast（进程主动自杀） | 原生崩溃 |
       | `0xe0434352` | **托管异常**（.NET 异常） | ⚠️ **出现这个，那时就应该有 `crash.txt`** ⇒ 请一并把 `crash.txt` 发来 |

### ② 看什么（这些是我们拿到材料后会看的）

- `日志\crash.txt`（**崩溃现场：只要程序接住了异常就一定有，和日志级别无关**；没有它 ⇒ 说明是"没接住的死法"——硬杀 / 原生崩溃，这时**只能看事件查看器**）；
- `日志\log.txt` 里**崩溃前最后几十行**，以及有没有 `PerfModes`、`CustomMode`、`edit custom` 之类的行（上次那份包只有 29 秒的窗口，全是启动向内容，**一条都没有**）；
- 事件查看器里那一刻的**完整异常文本 + 堆栈**；
- 版本号（`App launched:` 那行 / 关于页）。

### ③ 回传什么

- ☐ **诊断包**（崩溃后**立刻**导出的那一份）；
- ☐ 如果有，**直接把 `%APPDATA%\MechrevoLite\crash.txt` 这个文件本身**发来；
- ☐ 事件查看器里那条错误的「**复制详细信息**」文本 + 截图；
- ☐ **版本号**；
- ☐ 第 ① 条第 6 步的动作说明（崩之前点过什么、改过什么）。

### ④ 注意（务必看一眼）

- ⚠️ **崩溃后不要反复重试太多次**：复现 1~2 次、导出**一次**就够了。反复崩可能让现场丢失。
- ⚠️ **在问题查清前，请先不要在自定义窗口里点「应用」，也不要改数值** —— 别让机器状态跟着变。
- ⚠️ 事件查看器**只看、只复制**：不要点「清除日志」。

你说过「**设双 210**」，但我们从你那份诊断包的配置副本里看到落盘的是 **`perf_custom1_pl1=200`、`perf_custom1_pl2=85`** —— PL2 是 85，和 210 对不上。所以请补充：

## ⭐ 第三件事（可选，但很有用）：用「开关」现场 bisect，不用换版本

**思路**：新版里那两条灯效改动 —— 下面叫 **A =「补 ID」**、**B =「灯带去重」** —— 已经做成了**环境变量开关**，默认**开启**（= 新版行为）。所以可以在**不换版本**的前提下，一条一条关掉，看哪条一关就好了。

> ### ⚠️ 变量名以你装的那一版为准
>
> 下面表格里的变量名来自**我们当前的源码**（`source\MechrevoLite.Hardware\LightCompatibilitySwitches.cs`）。**变量名以当前版本为准**：设置后请看日志里那条 `[light]` 行 —— **如果日志里 `[light]` 行显示的名称与下表不同，以日志为准**（把那行发我们，说明你那版用的是别的名字）。
>
> | | 关掉的东西 | 环境变量名 | 默认值 | 关掉（= 回到 18.6） |
> |---|---|---|---|---|
> | **A** | 补 ID（给灯带 / Logo 的 `ColorBuffer` 每项补 ID） | `LMECHREVO_LIGHTBAR_IDFIX` | **开启**（源码常量 `EnableLightbarIdFix = true`） | 设 `0` |
> | **B** | 灯带去重（灯带行与 Logo 行指纹同值时只下发一次） | `LMECHREVO_LIGHTBAR_DEDUP` | **开启**（源码常量 `EnableLightbarDedup = true`） | 设 `0` |
>
> **取值表**（判定**大小写不敏感**，首尾空格忽略）：
>
> | 你设的值 | 结果 |
> |---|---|
> | 不设 / 空 | **开**（默认，= 新版行为） |
> | `1` / `true` / `on` / `yes` | **开** |
> | `0` / `false` / `off` / `no` | **关**（= 逐字回到 18.6 的老行为） |
> | 其它任何值（如 `abc`、`2`） | **保持开**（写错不会出事），但日志里会记下你写的原值 |
>
> **读取顺序**：进程级 → 用户级（**不读机器级**，也**绝不写**你的环境变量）。
> **生效方式**：设好之后**退出托盘里的 LM，再重新启动**；**删掉变量即恢复默认（开）**。
>
> **启动日志**（把日志级别设成「全部」才看得到；每次启动一条、不去重）：
>
> ```
> [light] 灯带修复开关: lightbarIdFix=on dedup=on (来源: idFix=默认(未设 LMECHREVO_LIGHTBAR_IDFIX); dedup=默认(未设 LMECHREVO_LIGHTBAR_DEDUP)) | LMECHREVO_LIGHTBAR_IDFIX / LMECHREVO_LIGHTBAR_DEDUP 取值 1/true/on/yes=开, 0/false/off/no=关; 改完重启 LM 生效; 删掉变量即恢复默认(on)
> ```
>
> ⚠️ **如果日志里根本找不到 `[light]` 这一行**（且日志级别确实是「全部」），说明你装的这一版**还没带这两个开关** —— 那第三件事现在做不了：**跳过它**，告诉我们一声，我们把带开关的版本发你。
>
> ⭐ **你这一台请优先试 A 和 B 这两个开关**：我们已经从你的诊断包里确认，你这台是 **`solution=ITE`、`KeyboardType=0`** —— 那条「**50 系单分区键盘**」修复**对你无效**（它只对键盘类型上报为 1/2 的机型生效）。所以**别把希望放在 50 系那条上**，重点就是 A / B 两个开关哪个一关就正常。

**怎么用**：`setx` 设的是**用户级**环境变量，不需要管理员，也不用重启电脑。设完**退出 LM 再打开**即可（LM 只在启动时读一次环境变量）。

关掉 A（补 ID）：

```bat
setx LMECHREVO_LIGHTBAR_IDFIX 0
```

关掉 B（灯带去重）：

```bat
setx LMECHREVO_LIGHTBAR_DEDUP 0
```

恢复默认（两个都恢复）：

```bat
setx LMECHREVO_LIGHTBAR_IDFIX 1
setx LMECHREVO_LIGHTBAR_DEDUP 1
```

或者彻底删掉（回到「从没设过」的状态）：

```bat
reg delete HKCU\Environment /F /V LMECHREVO_LIGHTBAR_IDFIX
reg delete HKCU\Environment /F /V LMECHREVO_LIGHTBAR_DEDUP
```

不想用 `reg` 的话，PowerShell 等价写法（同样只删用户级）：

```powershell
[Environment]::SetEnvironmentVariable('LMECHREVO_LIGHTBAR_IDFIX',$null,'User')
[Environment]::SetEnvironmentVariable('LMECHREVO_LIGHTBAR_DEDUP',$null,'User')
```
