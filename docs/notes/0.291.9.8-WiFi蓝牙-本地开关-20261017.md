# WiFi / 蓝牙「本地开关」（不依赖 GCU）（2026-10-17）

> 起因：机主问「WiFi 蓝牙麦克风摄像头等开关能不能做到不依赖 GCU」；
> 后追问「蓝牙开关不能做成开关状态吗」，并给了 **40 系 GCU 反编译** 作参考。
> 答案：**能**，而且厂商自己就是这么做的。

---

## 一、证据链

1. **40 系 GCU 反编译**（`D:\Downloads\decompiled.7z`）里：
   `GCUService\GCService5\DeviceSwitchItem.cs` 与 `BLE.cs` 都 `using Windows.Devices.Radios;`，
   异步状态机里出现 `RadioAccessStatus` / `TaskAwaiter<Radio>` / `DeviceInformationCollection`
   ⇒ 厂商用 **Windows Radio API** 切 WiFi/蓝牙，⛔ 不是"禁用设备"那种重手段。
2. **本机只读探针**（`tools\dev\radio-probe`，目标框架同主程序）：
   ```
   RequestAccessAsync ⇒ Allowed
   Radio 设备数 = 2
     Kind=WiFi · State=On · Name=WLAN
     Kind=Bluetooth · State=On · Name=蓝牙
   ```
   ⇒ `net10.0-windows10.0.19041.0` · 未打包 · 管理员 下 API **可用** ✅

## 二、实现

新增 `source\MechrevoLite.Helpers\RadioSwitch.cs`：

| 能力 | 说明 |
|---|---|
| 后台轮询 | 启动后 50 ms 首扫、之后 **3 s** 一次；缓存快照（UI 侧同步读，⛔ 不阻塞） |
| 读状态 | `DeviceInformation.FindAllAsync(Radio.GetDeviceSelector())` → `Radio.FromIdAsync` → `radio.State` |
| 写状态 | `radio.SetStateAsync(On/Off)` ⇒ **等 400 ms 再回读**确认（⛔ 不"调用成功就报成功"） |
| 不可用判定 | 访问被拒 / 找不到该 Radio / `State` 既非 On 也非 Off（被禁用、硬件开关、飞行模式）⇒ `Available=false` |

接线（**只在宝龙达**，GCU 机型逐位不变）：

| 位置 | 改动 |
|---|---|
| `MechrevoHw.SupportsQuickSwitch` | `wifi` / `bt` 改为 `WifiSeen \|\| (UsesBaolongda && RadioSwitch.Available(...))` ⇒ 开关**显示且可点** |
| `MechrevoService.SwitchQuick` | 宝龙达下 `wifi`/`bt` 分派给 `RadioSwitch.SetAsync`（写后回读），⛔ 不再走注定失败的 MQTT |
| `MechrevoHw.RefreshBaolongdaSwitchStates` | 每 3 s 把 Radio **真实状态**同步进 `QuickSwitches["wifi"/"bt"]`（日志注明来源是 Windows Radio，不谎称"硬件"） |
| `MechrevoHw.ApplyBaolongdaBackendAsync` | `RadioSwitch.Start()` ＋ 可用性变化回调（首次探测到 Radio 时让界面重新评估显示） |

## 三、边界（UI 必须如实）

- 访问被拒（组策略等）⇒ **不显示**这两个开关（⭐ 能点的必须有反应）
- 机身物理开关 / 飞行模式下 `State=Disabled` ⇒ 点"打开"会**如实失败**并说明原因
- 关 WiFi 会断网（功能本身）；恢复后网络可能需几秒
- 摄像头**不**走 Radio（它不是无线电）⇒ 下一步单独做「系统隐私开关」

## 四、验证（40 系真机）

1. 打开 LM → 快捷开关里应出现 **WiFi / 蓝牙**（状态与任务栏一致）；
2. 点蓝牙关：任务栏蓝牙图标同步变灰；再点开：恢复；
3. 点 WiFi 关：断网；再点开：恢复；
4. 开飞行模式后再点"打开蓝牙"：应**失败**并给出原因（不谎报成功）；
5. 日志关键字：`SwitchQuick(bt,...) ⭐ 走本地 Radio` / `宝龙达状态回读：⭐ bt ⇒ …（来源：Windows Radio）`。

⚠️ 真机验证时**用有线键鼠/外接屏**，避免关蓝牙把无线鼠标键盘也关掉。

## 附：摄像头「系统隐私开关」（同日追加）

摄像头**不是无线电**（不能走 `Windows.Devices.Radios`）⇒ 用 Windows 的摄像头隐私授权：

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\webcam
  Value        = Allow / Deny     ← 打包应用
  NonPackaged\Value = Allow / Deny ← 桌面应用（本开关以它为准，写入时两项都写）
```

实现：`source\MechrevoLite.Helpers\CameraPrivacy.cs`
- `Available`：能打开该键且可写（LM 是 requireAdministrator ✅）
- `TryGetDenied`：**桌面应用那一项优先**（读不到退父键）
- `TrySetDenied`：两项都写 → **回读确认**（只认 NonPackaged）

接线（仅宝龙达）：`SupportsQuickSwitch("webcam")` · `SwitchQuick` 分派 · `RefreshBaolongdaSwitchStates` 状态同步。

### ⚠️ 语义边界（UI 文案必须写清）

- 等价于 **设置 → 隐私和安全性 → 摄像头 →「让应用使用摄像头 / 让桌面应用使用摄像头」**，**立即生效**（无需重启）
- ⛔ **不是** EC/固件级断电：个别绕过系统相机栈的旧程序**可能**不受影响
- 所以文案用「**摄像头隐私**」而不是「摄像头开关」，避免用户以为断了电

### 验证（40 系）

1. LM 里关「摄像头隐私」⇒ 打开 Windows 相机应用应被拒；再开 ⇒ 恢复；
2. 同时打开 Windows 设置里的摄像头隐私页，确认**两边状态一致**（我们同步的就是它）；
3. 日志：`SwitchQuick(webcam,False) ⭐ 走系统摄像头隐私（ConsentStore）⇒ 确认=True（已写 Deny 并回读确认…）`
