## 0. 为什么需要这份文档

D-1 落地后，界面上只会多一句提示（「本机可能不支持，可试一次」），并在用户**真点过一次**之后，
于**下次开机**回读**实际显示路由**来记住结论。这条链路里有两件事**只有真机能证明**：

1. **LM 自己发的切换指令在这台机器上到底切不切得动**（D-1 原本的「选项 1」问题）；
2. **「试过就记住」的落盘与界面反应**是否符合设计（成功 → 一直显示；失败 → 收起按钮）。

第 1 件只能用「真切一次 + 重启」来证明；第 2 件的**失败分支**可以在**完全不动显示路由**的前提下验证（见 §4 B 组）。

## 1. 需要什么样的机器（硬性要求）

| 项 | 要求 |
|---|---|
| 机型 | **40 系机械革命**、且属于「没有可靠自动判据」的那一类（界面上会出现「核显模式」按钮，并带 D-1 提示） |
| 机主意愿 | **必须**机主同意「真的切一次核显模式」并接受一次重启 |
| 权限 | 管理员账户（LM 需要写 NVRAM / 发 GCU 指令） |
| 重启次数 | A 组 1~2 次整机重启；B 组 1 次整机重启 |
| 逃生手段 | **必须有**：能进 BIOS 手动切回显示模式（或外接显示器 + 另一台设备查阅本文档） |
| 明确不要用的机器 | 本工作机翼龙15Pro（用户硬要求：不切核显、不写 NVRAM） |

> 风险提示（LM 自己的功能自检里也这么写）：**切换失败可能导致无显示输出**。
> 所以这是一次「受控」实验：事前记好原始状态、事后有回滚路径，才动手。

## 3. A 组：真实验（证明「LM 能不能切核显」+ 成功分支）

> 目标：走完整链路「点一次 → 重启 → 回读」，看 D-1 是否记住并保留按钮。

1. 确认 LM 界面「系统」页有「核显模式」按钮，并且显卡行右侧显示提示「**本机可能不支持，可试一次**」。
2. **点「核显模式」** → 弹窗问是否立即重启 → 选**「是（立即重启）」**。
   - 日志会先出现一行 `[igpu-d1] iGPU-only attempt marked pending; ...`（说明这次尝试被记下了）。
3. 重启后（LM 会自动启动），等 30 秒，然后看三处：
   - **日志**：
     ```
     GPU route verify: target=0 actual=<路由> (... ) verdict=<Applied|NotApplied>
     [igpu-d1] iGPU-only attempt verdict=... -> igpu_route_verified=<1|0> (...)
     ```
   - **配置**：`igpu_route_verified` 变成 `1` 或 `0`，且 `igpu_attempt_pending` 回到 `0`。
   - **界面**：按钮还在（成功）还是被收起（失败）；提示那句**都应该消失**（因为已经试过了）。
4. 判定表：

   | 观察结果 | 含义 | 期望的 D-1 行为 |
   |---|---|---|
   | 路由变成核显（`route=IgpuOnly`）+ 设备管理器里 NVIDIA 被屏蔽 | **LM 真能切** ✅ | `igpu_route_verified=1`；按钮**保留**，提示消失；设置里开关仍为开 |
   | 路由没变（回到 `Direct`/`Hybrid`） | **LM 切不动** ❌ | `igpu_route_verified=0`；按钮**被收起**，提示消失；设置里开关显示为关（可手动重新打开 = 你的明确表态） |
   | 路由读不到（`Unknown`） | 数据不足 | **不写结论**（`igpu_route_verified` 保持不变），下次再试 |

5. **回滚**（无论成功失败）：
   - 界面上切回「直连」或「混合」；或命令行（仓库工具）：
     ```
     py -3 tools\gcu_send_mode.py dgpu      :: 回独显直连
     py -3 tools\gcu_send_mode.py dgpuoff   :: 回混合
     py -3 tools\gcu_send_mode.py recover   :: 救援
     ```
     （需要重启生效；万一界面/命令都不行，进 BIOS 手动切回。）

## 4. B 组：零硬件风险的「失败分支」验证（可选，够用就够）

> 目标：**不动任何显示路由**，只验证「试过一次且没成功 → 收起按钮」这条落盘/界面链路。
> 做法是给 LM 一个「上次点了核显模式、重启后待回读」的现场，然后**只重启操作系统**（不切显卡）。

1. 关闭 LM，备份 `%APPDATA%\MechrevoLite\config.json`。
2. 在 config.json 里加/改这 4 个键（**只写配置文件，不碰硬件**）：
   ```json
   {
     "gpu_restart_pending": 1,
     "gpu_restart_tick": 0,
     "gpu_restart_target": 0,
     "igpu_attempt_pending": 1
   }
   ```
   - `gpu_restart_tick=0` 是「上上次开机」的时间戳，LM 由此判断**这中间重启过**。
   - 副作用（正常现象）：重启前 LM 会显示「重启以应用」的棕色高亮与一条提示。
3. **只重启操作系统**（不要点任何显卡模式按钮）。
4. 开机后看：日志应出现
   `[igpu-d1] iGPU-only attempt verdict=NotApplied -> igpu_route_verified=0`（因为实际路由仍不是核显），
   并且界面上的「核显模式」按钮**被收起**、设置里「显示核显模式」开关变成**关**。
5. 收尾：把备份的 config.json 复原（或在设置里重新打开开关 = 明确表态）。

> 说明：这条路径证明的是「试过没用 → 不再猜」；「试过有用 → 一直显示」只能在 A 组证明。
