### P1（必须修）

**P1-1 宽屏刷新率按钮“错档”：点 120 Hz 实际下发 180 Hz**
- 位置：宽屏刷新按钮生成 `tools/dev/wpf-p0/MainWindow.xaml.cs:928-940`（`{60, max(120, maxHz/2), max(60,maxHz)}`），点击→`:939` `_owner?.WideSetRefresh(target)`；`tools/dev/wpf-p0/OriginalStyleWindow.xaml.cs:324-327` 的实现只认“≤60→低按钮，否则高按钮”，而低/高按钮的 Tag 只在 `SyncRefreshRateState()` 里被改成**实际 min/max**（`:1788-1812`，`Refresh180Button.Tag = max`）；下发时 `RefreshRate_Click` 用按钮 Tag 作为目标（`:2151-2166`）。
- 后果：180/165/240 Hz 屏上，宽屏显示 3 个按钮（如 60/120/180），点 **120 Hz** 会走“高按钮”=180 Hz；界面高亮还会被 `RefreshRate_Click` 纠正回 180 Hz（`requested >= _refreshHighHz` 判定），用户看到“点了 120 却变 180”。
- 证据（静态链路）：`MainWindow.xaml.cs:928`（三档来源）→ `OriginalStyleWindow.xaml.cs:324`（两档映射）→ `:2151`（按 Tag 下发）→ `:1788`（Tag=max）。
- 复现：宽屏首页 → 点 `120 Hz` → 观察刷新率变为 180 Hz（可在显示信息文本 `WideDisplay()` 的 `CurrentHz`/设备设置中确认）。
- **运行时未验证**（原因见 §6：用户实例已结束且不得再启动新实例）。

**P1-2 运行中重复启动/桌面快捷方式“打开主界面”不按 `last_window_mode`，宽屏模式下表现为“双击没反应”**
- 位置：单实例唤起处理 `tools/dev/wpf-p0/App.xaml.cs:41-56`——收到唤起事件后直接 `MainWindow.Show()`；而 `MainWindow` 属性在启动时指向**小窗**（`App.xaml.cs:61-62` `MainWindow = window;`，`window` 是 `OriginalStyleWindow`）。宽屏模式下小窗被置于屏幕外且透明（`OriginalStyleWindow.xaml.cs:5228-5240` `Opacity=0; ShowInTaskbar=false; Hide()`；启动时 `App.xaml.cs:61-74` `Left/Top=-20000`），因此 `Show()` 后仍然**不可见**。
- 对照：托盘双击路径是正确的（`TrayIconService.cs:77-78 DoubleClick → ShowRequested`；`OriginalStyleWindow.xaml.cs:818-826 ShowFromTray` 按 `last_window_mode` 分派 wide/mini），只有“第二实例唤起”路径绕过了这个分派。
- 后果：宽屏关闭驻留托盘后，用户双击桌面图标/再次启动程序 → 没有任何窗口出现（看起来像程序没反应）；需从托盘双击才恢复。
- 证据：`App.xaml.cs:46-52` 无 `last_window_mode` 判断；`OriginalStyleWindow.xaml.cs:818-826` 有正确实现但未被第二实例路径调用。
- **运行时未验证**（本机提权启动第二实例失败，见 §6；代码级链路确定）。

### P2（应修/建议修）

1. **能力位与后端连接时序：未连接/连接瞬间卡片不过滤，且部分区域只构建一次不重建**
   - `ApplyHomeCapabilities()`（`MainWindow.xaml.cs:1397-1428`）在 `_probe?.Capabilities == null` 时直接 `return`（无过滤）；宽屏在启动直开 wide 时可能先于后端就绪创建（`App.xaml.cs:61-74` + `OriginalStyleWindow.xaml.cs:270-274` 的调度顺序）。
   - 灯光卡片只在构造时构建一次（`:1429-1466`），缺少/未知后端时 `hw?.SupportsKeyboard ?? true` 等默认全支持，连接成功后不会重建。
   - 更多开关磁贴只在 `MoreSwitchGrid.Children.Count == 0` 时重建（`:1340-1341`），连接前用硬编码回退分组（`OriginalStyleWindow.xaml.cs:535-598`）构建后不再按连接后的 `_services.QuickSwitches.Groups` 刷新。
   - 影响：不支持机型上可能显示无效控件；连接后“更多开关/灯光”内容与旧 UI 不一致（重启宽屏窗口才刷新）。
2. **屏幕页“色彩增强”卡片无能力位**：`ScreenEffectCard.Visibility` 在全工程从未被赋值（仅 XAML 默认 Visible）；`ApplyHomeCapabilities` 只门控了 `ScreenCalibrationCard`（`MainWindow.xaml.cs:1422`），`NavScreen` 仍因 `displaySupported`（含 `DisplayRefresh`）可见（`:1416-1424`），可能出现“页面在、效果下发无反应”的假接入。旧 UI 对色彩增强有独立能力判定，需按 `MechrevoDeviceCapabilities` 补齐。
3. **电池卡“无极限充（实验性）/关闭 EC 直写”两行无条件下发**：`BuildHomeExtras` 中 `if (_owner.WideChargeLimitVisible)` 只包住“限制充电/区间/保存”那一组（`MainWindow.xaml.cs:801-824`），而 `_chargeExperiment`/`_ecDirect`/滑杆在条件外无条件创建并添加（`:825-863`）；非支持板上会显示无效控件（点击后 mini 侧处理器可能只弹状态、不改硬件）。
4. **灯光页缺少“编辑”入口**：`LightEditorWindow` 仅在 mini 路径使用（`OriginalStyleWindow.xaml.cs:833`），宽屏灯光页只生成内联卡片（`MainWindow.xaml.cs:1429-1466`），与交接说明 §7“灯光编辑按钮还未接编辑器”一致（未接）。
5. **灯光滑杆无防抖**：每通道亮度/速度滑杆 `ValueChanged` 直接 `ApplyLightCardAsync`（`MainWindow.xaml.cs:1688/1700`），拖动过程会连续下发后端命令（旧 UI 有节流/合并策略），存在命令风暴/状态回跳风险。
6. **托盘菜单能力位不全**：WPF 托盘“狂暴”恒显示（`TrayIconService.cs:147`），旧 UI 用 `TrayShow(caps.TurboMode || 宝龙达 || GCU…)` 门控（`source/MechrevoLite/SettingsForm.cs:12427`）；无 Turbo 能力机型上会显示不可用项。
7. **托盘菜单自定义“全不选”失效**：`TrayMenuConfig.Load()` 对空串按“默认全选”处理（`TrayIconService.cs:42-50`），而设置页允许全部取消并 `Save()` 空串（`SettingsWindow.xaml.cs:217-246`）⇒ 用户无法隐藏全部菜单项（会恢复成全选）。
8. **自定义模式/风扇曲线窗口未设 Owner**：`new CustomModeWindow(...).ShowDialog()`（`MainWindow.xaml.cs:1869/1890`）、`new FanCurveWindow(...).ShowDialog()`（`:1904/1917`）无 `Owner`，可能出现在宽屏窗口之后/不居中；同类窗口（设置/校色/灯光编辑器）都设置了 Owner。

## 5. 建议（按优先级）
1. **P1-1 刷新率**：宽屏只生成 mini 实际支持的两档（min/max），或让 `WideSetRefresh` 支持任意 Hz（直接 `SwitchRefreshRateAsync(hz)`，不绕 mini 按钮）；同时修正高亮判定。
2. **P1-2 第二实例唤起**：`App.ShowMainEvent` 处理器改为“按 `last_window_mode` 分派”，直接复用 `ShowFromTray()` 逻辑（或转发到 owner 的公开方法），不要 `MainWindow.Show()`。
3. **P2-1 能力位/重建**：`ApplyHomeCapabilities` 在 caps 为空时不隐藏但需在连接后重跑；灯光卡片/更多开关按“后端就绪”重建（给 `OriginalStyleWindow` 加 BackendReady 事件）；`ScreenEffectCard` 按能力位隐藏。
4. P2-3 电池实验行按 `WideChargeLimitVisible`/能力位收进条件块；P2-4 补灯光编辑入口或明确移除；P2-5 滑杆加 100-150ms 防抖；P2-6/7 补托盘能力位与空集语义；P2-8 补 Owner。
5. P3 清理：overlay XAML 默认值对齐、删死事件、统一默认磁贴集；WIP 合并后重跑本清单 §3 的“更多开关/快捷开关”。
