## 1. ⭐⭐ WMI 接口（**权威**，来自官方控制台逆向）

出处：`BellatorFanControl\README.md`（⭐ 原话：「原厂控制台通过 WMI 调用厂商 ACPI 接口，**不是直接写 EC 端口**」）

```
⭐ 命名空间 : root\WMI
⭐ 类       : **MICommonInterface**
⭐ 实例名   : ⭐⭐ **ACPI\PNP0C14\MIFS_0**
              （调用写法：`MICommonInterface.InstanceName='ACPI\PNP0C14\MIFS_0'`）
⭐ 方法     : **MiInterface**（入参 `InData` byte[32] ⇒ 出参 `OutData` byte[]）
```

### 1.1 请求布局

```
InData[1] = ⭐ 250(Get) / ⭐ 251(Set)
InData[3] = ⭐ **功能号**（见下表）
InData[4] = ⭐ 第一参数（Set 时的值；⭐ 风扇是 FanType）
InData[5] = ⭐ 第二参数（⭐ 风扇的转速值）
```

### 1.2 ⭐ 功能号表（**官方控制台里确认的**）

| 功能号 | 名称 | 说明 |
|---|---|---|
| ⭐ **8** | `SystemPerMode` | ⭐ **性能模式**（读/写单字节） |
| ⭐ **13** | `CPUGPUSYSFanSpeed` | ⭐ **读三个风扇转速**（见 1.3） |
| ⭐ **20** | `MaxFanSpeedSwitch` | ⭐ **风扇手动上限 开关**（`[4]=FanType`、`[5]=0/1`） |
| ⭐ **21** | `MaxFanSpeed` | ⭐ **风扇手动上限 转速**（`[4]=FanType`、`[5]=` **x100 RPM**） |
| ⭐ **22** | `CPUThermometer` | ⭐ **CPU 温度** |
| 9 | `GPUMode` | 显卡模式（⭐ 来自 DOUZHANZHE 那份） |
| 11 / 12 | `FnLock` / `TPLock` | Fn 锁 / 触摸板锁（⭐ 来自 DOUZHANZHE 那份） |

### 1.3 ⭐ 风扇转速读取（功能号 13）的字节布局

```
OutData[4..5]   = ⭐ 大风扇 1  RPM
OutData[6..7]   = ⭐ 大风扇 2  RPM
OutData[10..11] = ⭐ 小风扇    RPM
```

⭐ 风扇通道（`FanType`）：⭐ **0 = 大风扇通道** · ⭐ **1 = 小风扇通道** ✅

### 1.4 ⭐⭐ 性能模式编号（**与我们的口径不同！**）

```
⭐ 官方口径：
   ⭐ **0 = 平衡模式**（BalanceMode）
   ⭐ **1 = 增强模式**（PerformanceMode）
   ⭐ **2 = 静音模式**（QuietMode）
   ⭐ **3 = 疯狂模式**（原厂斗战模式 / FullspeedMode）
⚠️⚠️ 对照我们的 `LegacyMifsWmi`：⭐ 我们内部 0/1/2 ⇄ MIFS **2/0/1**
   ⇒ ⭐ **映射不一样** ⚠️（我们把"静音"当 0、"平衡"当 1、"狂暴"当 2）
   ⇒ ⭐⭐ **这是接宝龙达时第一个必须真机核对的地方** ✅
```

## 3. ⭐ EC 直写层（备选路径，⚠️ 风险高）

出处：`DOUZHANZHE-Control\server\hal\DriverBridge.cs`

```
⭐ 通道   : **inpoutx64.dll**（配套 **WinRing0x64.sys** 内核驱动）
⭐ EC 基址: ⭐ **0xFE800400**（映射长度 **0xFF**）
⭐ 方法   : `MapPhysToLin(EC_BASE, EC_SIZE, out ptr)` 后按偏移读写
⭐ 另有 IO 端口路径 : `0x62 / 0x66`（⭐ 用于 CPU 温度回退）
⭐ 用到的寄存器 : ⭐ **0x5E / 0x5A**（风扇转速直写，日志前缀 `[FanEC]`）·
                  ⭐ **0x1C**（CPU 温度，IO 端口协议，⭐ 有 `<128` 上界校验）⚠️
⚠️⚠️ 注意：⭐ **官方控制台走的是 WMI，不是 EC 直写**（⭐ README 原话 ✅）
   ⇒ ⭐ 我们也**优先走 WMI**，⭐ EC 直写只在 WMI 覆盖不到的能力上才考虑 ✅
⚠️ 而 EC 直写需要**随包带内核驱动**（⭐ 签名/安装/卸载都麻烦 ⚠️）
   ⇒ ⭐ 我们现有 `PawnIO`（⭐ 已在用 ✅）**可能是更合适的通道** ⇒ ⭐ 优先评估它 ✅
```

## 4. ⭐⭐ 与我们现有实现的关系（**重要判断**）

我们**已经有**一个同族实现：`source\MechrevoLite.Hardware\LegacyMifsWmi.cs`（老机型 MICommonInterface）。

```
⭐⭐ **协议完全一致的部分**（⭐ 逐字对得上）：
   ⭐ `InData[1] = 250/251`   ⭐ 一致 ✅
   ⭐ `InData[3] = **8**`     ⭐ **SystemPerMode 一致** ✅
   ⭐ `InData[4] = 值`        ⭐ 一致 ✅
   ⭐ 32 字节缓冲              ⭐ 一致 ✅
   ⭐ `OutData[4]` 读回        ⭐ 一致 ✅
⭐⭐ **差别一：怎么找到那个实例**
   ⭐ 我们  ：⭐ 类级 `new ManagementClass("root\\WMI:MICommonInterface")`
               ＋ ⭐ **GUID 校验** `B60BFB48-3E5B-49E4-A0E9-8CFFE1B3434B` ＋ `GetInstances()`
   ⭐ 宝龙达：⭐ 直接指名 ⭐ **`InstanceName='ACPI\PNP0C14\MIFS_0'`** ✅
   ⚠️ **真实风险**：⭐ 我们硬编码了 GUID ⇒
      ⭐ 若宝龙达那台的 `MICommonInterface` **GUID 不同**（或没有 GUID 限定符）⇒ ⭐ 我们会**探不到** ❌
      ⭐ ⇒ ⭐ **这是第一个要验证的点** ✅
⭐⭐ **差别二：性能模式编号语义**（⭐ 见 1.4）⭐ 官方 0=平衡/1=增强/2=静音/3=疯狂，
   而我们内部 0/1/2 ⇄ MIFS 2/0/1 ⇒ ⭐ **必须真机核对**，⛔ 不要想当然 ⚠️
```

```
⭐⭐ ① **先试我们现有的 LegacyMifsWmi** —— ⭐ 很可能直接就能用 ✅

      ⭐ 注意 `PNP0C14` 是 ACPI 的 WMI 通用设备 ID，⭐ `MIFS_0` 才是厂商实例名 ——
      ⭐ **不同机型的实例名后缀可能不同**（⭐ `MIFS_0` / `MIFS_1` / 别的前缀 ✅）
      ⇒ ⭐ 这正是**抓包工具第 02 节要收集的东西** ✅

      ⭐ 该仓库的曲线做法：⭐ 定时（⭐ 5 秒）读温度 ⇒ ⭐ 按曲线写**风扇上限** ⇒ ⭐ 带 3℃ 降档回差 ✅
      ⭐ 退出/关闭自定义时 ⭐ **恢复固件控制**（⭐ 这条我们要照做 ✅）
⭐ ④ **CPU 温度**：⭐ 功能号 22（`CPUThermometer`）⭐ 官方通道 ✅
      ⭐ 备选：⭐ LHM → ⭐ EC IO 端口 0x62/0x66 → ⭐ EC 物理映射 ⚠️
⭐ ⑤ **EC 直写**（⭐ 若真需要）：⭐ 基址 `0xFE800400`；⚠️⚠️ **这条路我们要慎重**（⭐ 见第 3 节）✅
```
