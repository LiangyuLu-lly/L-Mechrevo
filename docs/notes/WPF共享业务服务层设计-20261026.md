# WPF 共享业务服务层设计（2026-10-26）

> 任务：task-5「设计并搭建 WPF 共享业务服务层骨架」。
> 写作用域：`tools/dev/wpf-p0/Services/` + 本文件。⛔ 未修改任何现有 UI 文件、未改 csproj、未打包。

## 1. 要解决的问题

当前 WPF P0 里「宽屏窗口」(`OriginalStyleWindow`) 与「迷你窗 / MainWindow」之间靠**窗口方法**互相调用：

- 迷你窗需要调 `OriginalStyleWindow.WideSetMode()` / `WideSetGpuMode()` / `WideToggleQuickAsync()`
  等 `Wide*` 方法（`OriginalStyleWindow.xaml.cs:302-735` 一带），等于**把一个窗口当服务单例**；
- 这些方法内部又同时做四件事：读 `_backendProbe`、调 MechrevoLite、写 `AppConfig`、改本窗控件/`StatusText`；
- 同一份业务（例如 `WideSensors()` 的 14 项传感器、`WideMoreSwitches()` 的分组表）在第二处复用时
  只能复制或穿透窗口，**状态口径与文案会漂移**。

目标：**UI 只调用服务接口；服务持有 `BackendProbe` 与 MechrevoLite 能力，不依赖窗口；宽屏与迷你窗共用同一服务实例。**

## 2. 分层

```
OriginalStyleWindow / MainWindow / 迷你窗 / 托盘 / 设置窗
        │  （只依赖接口 + 事件）
        ▼
AppServices（组合根，Services/AppServices.cs）
        │
        ├─ IBackendStatusService  连接/能力位/一行诊断
        ├─ ISensorService         传感器快照（原始数值）
        ├─ IPerformanceService    性能模式 + 风扇强冷 + 模式目录
        ├─ IGpuService            显卡模式/pending/核显省电（只读能力位）
        ├─ IQuickSwitchService    「更多开关」目录/能力/状态/下发
        ├─ IDisplayService        刷新率/亮度/校色/色彩增强
        ├─ IBatteryService        电量/健康/三档电池保护
        ├─ IChargeLimitService    充电阈值（EC 写入仍走既有 Writer/Restore）
        ├─ ILightingService       灯光通道持久化/自动关灯/灯效下发
        └─ ITrayMenuService       托盘菜单配置目录/读写
        │
        ▼
BackendAccessor（唯一可变槽位：同一个 BackendProbe）
        │
        ▼
tools/dev/wpf-p0/BackendProbe.cs → MechrevoLite（MechrevoHw/Service/Mode/Display/Battery/Hardware…）
```

**所有权**：`BackendProbe` 的 `ConnectAsync` / `Dispose` 仍归窗口/App；服务层只 `Attach/Detach` 同一个实例，
⛔ 不建连、⛔ 不 Dispose（避免双窗口双重释放）。

设计约束：

- **服务不引用任何 WPF 控件 / Window / Dispatcher / 事件处理器**；
- 结果统一 `ServiceResult(Ok, Detail)`：成功/失败 + 人话原因，窗口只负责显示（⛔ 不再各自拼同一句话）；
- 快照统一 `record`：服务返回**原始数值**，单位/占位符由 View 格式化（原窗口 `WideSensors` 里的 `" ℃"/" RPM"` 拼接不再进服务）；
- 需要“组合动作”的方法（如校色的自定义 ICC 分支、强冷的本机通道）保留完整语义，但仍只调 MechrevoLite/BackendProbe，不碰窗口。

## 4. 关键设计决策

1. **共享槽位而不是每服务一个探针**：`BackendAccessor` 只存一个 `BackendProbe?`，窗口连接成功后 `Attach`；
   服务在未连接时全部安全降级（返回 `Empty`/`Fail("后端未连接")`），不抛异常。
2. **目录数据上移**：`QuickSwitchService.Groups`、`DisplayService.CalibrationOptions/DisplayEffectModes`、
   `LightingService.LightIdleOptions`、`PerformanceModeLabel`、`TrayMenuService.Catalog` 都从窗口搬到服务层，
   两个窗口渲染同一份数据。⚠️ 文案目前仍是中文硬编码（与 P0 一致），后续迁 resx/ViewModel。
3. **UI 决策不搬**：GPU 重启确认框、核显省电占用确认、MiniLED/FHD/HDR 切换后的整页刷新、
   充电滑块关闭后的“写回满充”、托盘的 `ContextMenuStrip` —— 全部留在窗口；服务只提供原语与只读状态，
   避免“服务里弹窗”的反模式。
4. **行为补丁收敛在服务层**：`BackendProbe.SupportsQuick("fanboost")` 只认 GCU 能力位、且 `QuickState`
   读 GCU `FanBoost` 字段（宝龙达恒 false）。服务层按 WinForms 侧 2026-10-19 的修复口径补
   `UsesBaolongda` / `MechrevoHw.FanBoostActive`（`PerformanceService`、`QuickSwitchService`），
   ⛔ 未修改 `BackendProbe`（不在本任务写作用域）。
5. **零 csproj 改动**：`WpfP0.csproj` 未关闭默认编译项，`Services/*.cs` 由 SDK 自动包含。

## 6. 首批接入步骤（不改 XAML / 不改 csproj）

1. 在 `OriginalStyleWindow` 增加字段：`private readonly AppServices _services = new();`
2. `ConnectBackendAsync` 成功后：`_services.AttachBackend(_backendProbe);`；窗口关闭时 `DetachBackend()`（⛔ 不 Dispose 探针）。
3. 把 5.1 的 `Wide*` 方法体**逐个**改成“服务调用 + 原样拼 `StatusText`”，签名不变 ⇒ 调用方零改动、行为可逐项回归。
4. 迷你窗/托盘改为 `Program.Services`（或构造函数注入同一个 `AppServices`）后，`Wide*` 才能删除；
   删除前禁止让第二处继续新增对 `Wide*` 的调用（否则又形成窗口依赖）。

## 7. 风险与边界

1. **`BackendProbe` 本身仍是窗口层助手**（内部持 `_hw/_service` 并摸 `Program.acpi`）。它先保持原样；
   下一步应把它移到 `Services/Backend/` 并让服务构造它，否则“服务不依赖窗口”只是单向成立。
2. **`internal` + IVT**：服务用到 `LightingSettingsStore`、`BatteryLimitWriter/Restore`、`ScreenNative`、
   `KeyboardFirmwareEffects`、`PerfModeStore`、`SettingsForm.LightingCloseTimerOptions` 等 internal 成员，
   依赖 `source/Properties/AssemblyInfo.cs` 的 `InternalsVisibleTo("L-Mechrevo.WpfP0")`。
   若服务层将来拆成独立程序集，需要补 IVT 或把这些 API 提升为 public（会扩大生产程序集表面）。
3. **Windows-only 依赖**：`System.Windows.Forms.Screen/PowerStatus`（分辨率、供电状态）仍在服务里；
   P0 只跑 Windows，可接受；若要跨平台需换成各自平台封装。
4. **文案未本地化**：服务层目录/标签仍中文硬编码（与 P0 现状一致）；迁 resx 时以服务目录为唯一源。
5. **两处行为补丁**：`fanboost` 的宝龙达能力/状态在服务层补，`BackendProbe` 未改。
   窗口完成切换前，**以原窗口行为为准**；切换后需要真机回归强冷（无 GCU 机型）。
6. **未消除 `Wide*`**：本任务只搭骨架 + 迁移清单；现有窗口仍然可用，⛔ 无任何既有行为改动
   （本次仅新增 `Services/` 文件与本文档）。
7. **线程**：服务无锁、无状态；`BackendAccessor` 用 `Volatile`。硬件写入的线程语义沿用原窗口调用点
   （UI 线程触发、异步方法内部 `ConfigureAwait(false)`），未引入新的后台写硬件路径。
