# LM 核显模式判断与解释

> 适用范围：L-Mechrevo 群友版（对齐作者 beta21 后）——核显模式（iGPU Only）、混合模式、独显直连、核显省电的**判断逻辑**与**显示/切换行为**。
> 证据来源：`D:\openLM\source\` 当前源码（行号以 2026-10-04 状态为准）。每个判断都标注了代码位置，可逐条核验。

---

## 0. 概念速览

| 模式 | 含义 | LM 里对应 |
|---|---|---|
| 核显模式（iGPU Only） | 只用核显输出内屏，独显被 MUX 断开/待机 | GpuMode=0 |
| 混合模式 | 核显+独显都在，内屏可切换输出 | GpuMode=1 |
| 独显直连（DGPU Direct） | 独显直接输出内屏 | GpuMode=2 |
| 核显省电（IgpuOnly Save Mode） | 混合模式下让核显接管显示的省电开关 | IgpuOnlySaveMode（0/1/3） |

一句话判断链：

```
GCU 上报字段（iGPUModeOnlySupport / IGpuOnlyConnectionSwitch_Support …）
  → Capabilities 静态能力位（IgpuOnly / DgpuDirect / GpuHotSwap）
  → Supports* / CanOffer* 属性（叠加 GCU 动态 *_Support 回读 + 代际动作表）
  → UI 按钮/托盘/省电开关显示 & 切换命令路由
```

## 1. GCU 上报字段 → 能力位（第一层）

解析入口：`MechrevoDeviceCapabilities.cs:271 / 292 / 312`（`FromValues`）。

### 1.1 核显模式能力 `IgpuOnly`

```csharp
bool igpuOnly = Flag(new string[4] { "iGPUModeOnlySupport",
                                     "IGpuOnlyModeSupport",
                                     "IntegratedGpuOnlySupport",
                                     "IGpuOnlyConnectionSwitch_Support" });
// 代码注释（原样）：50 系 GCU（ConnectionSwitch 系列）用 IGpuOnlyConnectionSwitch_Support=Enable
// 表达核显能力；40 系 GCU 用 iGPUModeOnlySupport。两者均认。
```

- 命中任意一个字段且数值 > 0 → `IgpuOnly = true`
- **40 系 GCU 报 `iGPUModeOnlySupport`；50 系 GCU 报 `IGpuOnlyConnectionSwitch_Support=Enable`，两个都认**——这是"蛟龙16s=0 / 翼龙15Pro=1 / 双显三模=1"的来源

### 1.2 独显直连能力 `DgpuDirect`

```csharp
DgpuDirect = Flag(new string[3] { "DGpuDirectConnectionSupport",
                                  "DiscreteGpuDirectConnectionSupport",
                                  "MuxSwitchSupport" }),
```

### 1.3 热切换能力 `GpuHotSwap`（50 系专属）

```csharp
// 2026-10-03（更正）：热切换（免重启切集显）是 50 系专属能力，与核显省电同一命令
// （IGPU_ONLY_CONNECT_RB_ON/OFF），判断只认 50 系 GCU 上报的 IGpuOnlyConnectionSwitch_Support=Enable；
// 40 系三模（iGPUModeOnlySupport）为冷切换（重启生效），不计入热切换
GpuHotSwap = Flag(new string[1] { "IGpuOnlyConnectionSwitch_Support" }),
```

- **只认一个字段**：`IGpuOnlyConnectionSwitch_Support`
- **40 系三模即使有核显模式（iGPUModeOnlySupport=1），也不计入热切换**——40 系切核显是冷切换，必须重启

## 2. 动态回读与能力属性（第二层）

解析入口：`MechrevoHw.cs:2792-2818`（GCU 实时状态）；属性定义 `MechrevoHw.cs:376-447`。

### 2.1 动态 `*_Support`（GCU 实时回读，bool?）

```csharp
// MechrevoHw.cs:2795-2796 字段别名（兼容大小写/新旧命名）
DgpuDirectStatusSupport = FirstOptionalBool(o, "DiscreteGpuDirectConnectionSwitch_Support",
                                           "DGpuDirectConnectionSwitch_Support", "DGPU_DIRECT_SUPPORT") ?? …;
IgpuOnlyStatusSupport   = FirstOptionalBool(o, "IGpuOnlyConnectionSwitch_Support",
                                           "IGPUOnlyConnectionSwitch_Support", "IGPU_ONLY_SUPPORT") ?? …;
```

**乐观回填**（MechrevoHw.cs:2797-2818）：如果 GCU 上报了可识别的**状态值**（`IGPU_ONLY_STATUS` 等）但 **Support 字段缺失**，自动把对应 Support 回填为 true——防止"有能力但不报 Support"的机型被误判为不支持。

### 2.2 四个核心属性

```csharp
// MechrevoHw.cs:409-413
public bool SupportsDgpuDirect => DgpuDirectStatusSupport ?? Capabilities.DgpuDirect;  // 动态优先，静态兜底
public bool SupportsIgpuOnly   => Capabilities.IgpuOnly;                              // 纯静态能力位
public bool SupportsGpuHotSwap => Capabilities.GpuHotSwap;                            // 纯静态能力位
```

### 2.3 两个"可提供"属性（能力 + 代际动作表双重校验）

```csharp
// MechrevoHw.cs:419-429
public bool CanOfferIgpuOnly
{
    get
    {
        if (SupportsIgpuOnly)
            return IsGpuActionAllowedByGeneration("IGPU_ONLY_CONNECT_RB_ON");  // 动作表里有 IGPU_ONLY_CONNECT_RB_ON
        return false;
    }
}

// MechrevoHw.cs:431-445
public bool CanOfferGpuModeSwitch
{
    get
    {
        if (DgpuGeneration != DgpuGenerationKind.Gen30 && (SupportsDgpuDirect || SupportsIgpuOnly))
        {
            if (!IsGpuActionAllowedByGeneration("DGPU_DIRECT_CONNECT_TOGGLE_ON")
                && !IsGpuActionAllowedByGeneration("DGPU_DIRECT_CONNECT_TOGGLE_OFF"))
                return IsGpuActionAllowedByGeneration("DGPU_DIRECT_CONNECT_RESTART");
            return true;
        }
        return false;
    }
}
```

要点：
- `CanOfferIgpuOnly` = 有核显能力 **且** 当前代际动作表里有 `IGPU_ONLY_CONNECT_RB_ON`
- `CanOfferGpuModeSwitch` = **非 30 系** +（有直连或核显能力）+（TOGGLE_ON/OFF 或 RESTART 允许）——**30 系直接 false**（动作表只有 TOGGLE_ON/OFF 的 30 系不提供模式切换）

## 3. 代际矩阵（30 / 40 / 50 的动作词汇表）

定义：`MechrevoLite.Gpu\DisplayRouteMatrix.cs:29-49`（`GenerationRouteFacts` 行表，含反编译证据等级）。

| 代际 | 动作词汇 | 核显模式？ | 热切换？ | 结论 |
|---|---|---|---|---|
| **Gen30** | 仅 `DGPU_DIRECT_CONNECT_TOGGLE_ON/_OFF` | ❌ IGPU_ONLY_* 全载荷 0 命中（ProvenAbsent） | ❌ HOTSWAP 0 命中（ProvenAbsent） | **不提供显卡模式切换**（CanOfferGpuModeSwitch=false） |
| **Gen40 三模**（双显三模档） | TOGGLE_ON/OFF/IGPU、IGPU_ONLY_CONNECT_RB_ON/OFF、DGPU_DIRECT_CONNECT_RESTART | ✅ 有 | ❌ GPU_HOTSWAP_* 0 命中（Unknown→无） | **冷切换**：发 IGPU_ONLY_CONNECT_RB_ON 后必须重启 |
| **Gen40 双模**（不带三模档） | TOGGLE_ON/OFF/IGPU、RESTART（无 IGPU_ONLY_*） | ❌ | ❌ | 无核显模式，只有直连切换 |
| **Gen50** | TOGGLE_ON/OFF/IGPU、IGPU_ONLY_CONNECT_RB_ON/OFF/AUTO、RESTART、GPU_HOTSWAP_ON/OFF | ✅ 有 | ⚠️ GPU_HOTSWAP 枚举存在但处理器是 log-only no-op（wire 用法未证） | 核显模式走 RB_ON/OFF；**热切换实际由 IGpuOnlyConnectionSwitch_Support 表达**（见 §6） |

路由校验：`DisplayRoutePolicy.cs:21-32`——`AllowsAction(代际, 动作, 三模)`：查该代际（+三模档）行表的 ConsoleActions 是否包含该动作。

## 4. 代际探测（怎么知道机器是 30/40/50 系）

定义：`MechrevoLite.Gpu\DgpuGenerationProbe.cs` + `GpuGenerationProvider.cs`。

1. 枚举注册表中的 NVIDIA 显卡适配器（`GpuAdapterReader.ReadFromRegistry`）
2. 优先按 MarketingName 正则匹配 `\bRTX\s*(\d{4})\b`，取前两位 → 30/40/50（`FromMarketingName`）
3. 匹配不到再按 DeviceId（PCI `DEV_xxxx`，30 系 0x20-0x25 / 40 系 0x26-0x28 / 50 系 0x2B-0x30）（`FromDeviceId`）
4. 结果缓存到 AppConfig（`dgpu_generation` + 适配器指纹），指纹不变不再重解析
5. 无 NVIDIA 独显 → `NoDgpu`；枚举不可用 → `Unknown`

> 注意：代际只影响"动作表允许什么"，**不影响**核显能力位本身（§1）。30 系即使 Capabilities 有值，动作表也没有 IGPU_ONLY_*，所以不提供核显模式。

## 6. 核显省电 = 热切换（重要结论）

历史演进结论（多轮讨论后用户拍板）：
- **核显省电和热切换是同一套命令**：`IGPU_ONLY_CONNECT_RB_ON/OFF`
- **50 系 GCU 的 `IGpuOnlyConnectionSwitch_Support=Enable` 同时表达"核显模式能力"和"热切换能力"**（§1.1/§1.3 都认这个字段）
- **40 系三模只有核显模式（iGPUModeOnlySupport），没有热切换**——切换后必须重启才生效（冷切换），用户原话："40系三模是冷切换核显,不存在免重启的"
- beta21 引入的 `GPU_HOTSWAP_ON/OFF` 动作在官方 50 系控制台里处理器是 log-only no-op（wire 用法未证，`DisplayRouteMatrix.cs:48`），**不作为判断依据**；实际判断只认 `IGpuOnlyConnectionSwitch_Support`
- LM 侧热切换执行已于 2026-10-03 停用（`MechrevoHw.cs:3362-3363` 注释："热切换执行已删除（与核显省电功能重叠）"）——**热切换能力只用于显示核显省电开关**，切换本身走核显省电命令或重启路由

## 7. 切换执行细节（命令路由）

入口：`MechrevoHw.cs:3360+`（`SetGpuMode`）：

```csharp
bool useMuxTarget = mode == 0 && SupportsDgpuDirect && !SupportsIgpuOnly;
GpuRouteCommand gpuRouteCommand = GpuRouteCommandLayer.BuildSwitchCommand(mode, SupportsDgpuDirect, SupportsIgpuOnly, DgpuGeneration);
```

- 目标 mode=0（核显）且"支持直连但不支持核显"→ 走 MUX 目标（老式切换）

## 9. 常见问题 FAQ

**Q1：蛟龙 16s 为什么以前会显示核显模式按钮？**
旧代码 `flag || flag2`（GPUModeControl.cs:38-43）把"支持独显直连"也当成"显示核显按钮"的依据。2026-10-04 修正为核显按钮**只用 `CanOfferIgpuOnly`**（能力 + 动作表），"支持直连但不支持核显"的机型不再误显示。

**Q2：`IgpuOnlyStatusSupport` 到底判断什么？**
它是 GCU 实时上报的 `IGpuOnlyConnectionSwitch_Support` 动态回读（bool?），**50 系对核显省电/热切换能力的判断**（乐观回填 true）。它不是"核显模式能力"的判断——核显模式能力是静态 `Capabilities.IgpuOnly`（认 4 个字段）。

**Q3：核显省电按钮为什么在混合模式下才显示？**
`SettingsForm.cs:7214`：`SupportsGpuHotSwap && GpuMode == 1 && !HasPendingGpuRestart()`——核显省电只在混合模式有意义；核显模式/直连模式本身就不需要它；有待重启的切换时不显示避免冲突。

**Q4：40 系有核显模式，为什么没有免重启热切换？**
40 系三模的 `iGPUModeOnlySupport` 只表达"支持核显模式"（冷切换，发命令后重启生效）；`GpuHotSwap` 只认 50 系 GCU 的 `IGpuOnlyConnectionSwitch_Support`（§1.3）。官方 40 系控制台动作表也无 GPU_HOTSWAP_*（§3）。

**Q5：托盘菜单里的核显/混合/直连入口用什么判断？**
`SettingsForm.cs:5754-5755`：`CanOfferIgpuOnly`（核显）、`SupportsDgpuDirect ?? Capabilities.DgpuDirect`（直连）、`CanOfferGpuModeSwitch`（整行开关）。

**Q6：30 系机器为什么没有显卡模式切换？**
`CanOfferGpuModeSwitch` 对 Gen30 直接 false（`MechrevoHw.cs:435`），且 30 系动作表只有 TOGGLE_ON/OFF（§3，反编译 ProvenAbsent：IGPU_ONLY_*/RESTART/HOTSWAP 全 0 命中）。

**Q7：判断"是否支持核显模式"用哪个属性最干净？**
- 只问能力：`Capabilities.IgpuOnly`（静态，认 4 字段，40/50 系 GCU 都兼容）
- 问能否提供核显模式按钮/切换：`CanOfferIgpuOnly`（能力 + 当前代际动作表）
- 问核显省电/热切换：`SupportsGpuHotSwap`（50 系 ConnectionSwitch 专属）
