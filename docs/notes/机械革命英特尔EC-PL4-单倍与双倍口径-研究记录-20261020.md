# 机械革命 英特尔机型 EC PL4 单倍/双倍口径研究记录（2026-10-20）

> ⚠️ 适用范围（重要）：下文「`0x0727` bit7 = 单位选择位」只对**已核对的这 5 份固件**成立。
> 不同机型/不同 EC 固件的双倍门控**可能不同**（地址不同、位不同，甚至不是同一个机制），
> 未核对过的机型不能直接套用本记录，必须先用判据逐个固件核对后再操作。

## 一句话本质

EC RAM `0x0727` 的 **bit7** 是 PL4 的「单位选择位」：

- bit7 = 1 ⇒ 主机写进 `0x785` 的 PL4 值按 **2W/LSB** 解释，EC 内部乘 **16**；
- bit7 = 0 ⇒ 按 **1W/LSB** 解释，EC 内部乘 **8**。

PL1/PL2 没有这个选择位，恒乘 8（恒定 1W/LSB）。这就是只有 PL4 会出现「折半」现象的原因。

## 联动表

| 联动项 | bit7 = 1（2W/LSB） | bit7 = 0（1W/LSB） | 代码位置（ec146 / ec128） |
|---|---|---|---|
| PL4 写入乘数 | × 16（`75 F0 10`） | × 8（`75 F0 08`） | 0xF18D / 0xE17F |
| XRAM `0x0889` 初值 | 50 → 折半 25 | 50 → 不折半 | 0x1A741 / 0x1A393 |
| XRAM `0x088D` 时间窗 | 0x05 | 0x0B | 0x1A7E9 / 0x1A43B |

## 数据流

```
控制台 / BIOS            PL4 = 290W
        │ 按 2W 口径写入 145
        ▼
EC RAM 0x785 = 145      （ecutil 读的就是这里，是输入不是结果）
        ▼
XRAM 0x08C3 / 0x08C6    镜像
        ▼
XRAM 0x088B             PL4 工作副本
        ▼
XRAM 0x086E             与其它候选择优后的最终值
        ▼
EC RAM 0x046A–0x046F    对外发布影子块
        ▼
EC RAM 0x0727 bit7 ── =1 ── MUL ×16 → XRAM 0x9040
        │           └─ =0 ── MUL ×8  → XRAM 0x9040
        ▼
BIOS 写 MSR 0x614
```

## 判据（字节模式）

| 层级 | 字节模式 | 判读 |
|---|---|---|
| 主判据 | `90 07 27 E0 44 80` | 1 处 = 启用；0 处 = 未启用 |
| 反证 | `90 07 27 E0 54 7F` | 存在则说明有主动清 bit7 的代码 |
| 辅助 1 | `54 80 60 06` + `75 F0 10` / `75 F0 08` | 双分支是否完整（机制前提） |
| 辅助 2 | `90 08 89 E0 C3 13 F0` | 折半站点是否存在 |
| 辅助 3 | `90 08 8D` + `74 05` / `74 0B` | 时间窗二选一；硬编码 0x05 说明当唯一模式编译 |
| 陷阱 | 不要只搜 `90 07 27 E0 44` | 会命中 `44 10`(bit4)/`44 08`(bit3) 假阳性 |

## 三个要点

1. **bit7 是编译期决定的，运行期恒定**。五份固件里 `0x0727` 的 bit7 只在开机初始化末尾写一次，此后全片没有 `ANL A,#0x7F` 之类的清除代码 —— 不是随温度/负载切换的模式，是出厂定死的口径。
2. **两套数据并存不矛盾**。ec128 / ec_jgx146 / ec_backup256 的功耗表里同时存 `8C A5 FA`(250) 与 `8C A5 91`(145)：前者是 1W 口径的 PL4，后者是 2W 口径下同一个 290W；标定时两套都算好，只差 bit7 没置。
3. **真正没定死的是 host 侧下发口径**。置了 bit7 后如果 BIOS 仍按 1W 发 250，EC 会理解成 500W。每个补丁刷入后必须先设低值（如 100W）看 MSR 0x614 是否翻倍，再决定保留或回滚。

## 补充说明

1. `0x785` 不是结果而是输入。EC 全片没有 ÷2 运算（无 `74 02 84` DIV、无 ÷2 查表、无 `RRC` 落在 PL4 链上）；145 是 host 按 2W 口径写进来的原始 LSB，EC 原样搬到 `0x9040` 再乘 16。
2. 只有 PL1/PL2 是恒定 1W。setter（`0x0F2F1` / `0x0E164`）里直接 `MOV 0xF0,#0x08`，不读 `0x0727`；所以置 bit7 后 PL1=140W 在 EC 里仍是 140×8，不会变 280W。实机可用 HWiNFO 同读 MSR 0x610 与 0x614 验证。
3. 补丁只有两种通用形态：
   - **启用**：init 末尾 `RET` 前插 5 条指令（`MOV DPTR,#0x0727 / MOVX A,@DPTR / ORL A,#0x80 / MOVX @DPTR,A / RET`）；空间不够用 `LJMP` 到 FF 空洞再补，共 17 字节；
   - **关闭**：把已有的 `44 80`（`ORL A,#0x80`）改成 `54 7F`（`ANL A,#0x7F`），只改 2 字节。
4. 折中方案：（待验证）保留原 1W 口径、只改时间窗 `0x088D`；或按需在 2W 口径下把 host 下发值同步减半。此类折中补丁未实测，刷入前同样先低值验证。

## 待办

- 逐机型核对双倍门控：每份新固件都要先跑判据（主判据 + 反证 + 三个辅助），确认门控地址/位与乘数分支，再决定是否打补丁；不同机型的门控地址/位可能不同，本记录不可跨机型套用。

- 把判据做成可双击运行的 exe（拖入 EC 文件即报「启用/未启用」+ 命中的字节位置）。
- 对 ec146 做「保留原口径、只改时间窗」折中补丁（如需）。
- 实机验证：置 bit7 后 PL1/PL2 是否确实不受影响（MSR 0x610 vs 0x614）。
