# WPF 宽屏内存优化：后续想法（2026-10-26）

## 已完成

- 悬浮窗按需创建，不再开机预加载。
- 背景图按需解码，未启用时不加载。
- 宽屏五页已拆成独立 UserControl，首次进入页面时才创建。
- 后台隐藏/最小化且悬浮窗关闭、托盘传感器提示关闭时回收工作集。

## 当前实测（本机，175% DPI）

```text
旧 WinForms：WS ≈ 162 MB / Private ≈ 47 MB
WPF 迷你：  WS ≈ 176 MB / Private ≈ 96 MB
WPF 宽屏：  WS ≈ 360 MB / Private ≈ 430 MB
```

宽屏空内容（`Content=null`）也有约：

```text
WS ≈ 322 MB / Private ≈ 254 MB
```

说明 WPF 窗口/渲染层本身有较高固定成本，页面拆分无法把可见宽屏压到 250 MB 以下。

## 后续可尝试

1. **离开页面后销毁页面视图**
   - 切页时 `ContentControl.Content = null`、清空字段、解绑事件、清空页面集合。
   - 只保留当前页，任何时刻最多一个页面视图。
   - 需要处理：页面状态恢复、重复初始化、事件重复绑定、滚动位置。

2. **页面内部再延迟**
   - 即使页面已创建，也可延迟 `BuildSensorBlocks`、`BuildQuickTiles`、`BuildLightingCards`、`BuildCustomModeList` 到页面真正可见后。
   - 页面首次显示前只保留 XAML 空壳。

3. **共享页面状态与重建**
   - 页面销毁前保存滚动位置、选中项、滑杆值。
   - 重建时从配置/后端回填，避免用户状态丢失。

4. **诊断 WPF 渲染层固定占用**
   - 已实测软件渲染测试：Private 可降到约 228 MB，但 Working Set/交互不占优，暂不启用。
   - 若要继续，需评估 WPF `RenderOptions`、字体缓存、窗口合成层。

5. **低内存模式（可选）**
   - 仅在用户显式开启时降低视觉质量/切换渲染模式，不作为默认。
   - 需先做性能与交互回归。

## 不建议

- 不再通过隐藏页面卸载视觉树来省内存：实测基本不降，且会引入状态丢失。
- 不为省内存强行切换软件渲染：工作集收益不稳定，交互可能变慢。
