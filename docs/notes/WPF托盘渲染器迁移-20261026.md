# WPF 托盘菜单渲染器迁移（P0-5）· 2026-10-26

## 背景与目标

审计 P0-5：WPF 托盘（`tools/dev/wpf-p0/TrayIconService.cs`）此前把菜单渲染器直接挂到旧 WinForms UI 的
`MechrevoLite.UI.CustomMenuRenderer` 上。旧 UI（`source/MechrevoLite.UI`）最终要删除，托盘菜单不能跟着
一起失效，所以把渲染器**等价迁入 WPF 项目内**（中性 UI 归属），并保持主题色 / 字体 / hover / 选中 /
禁用项等观感不变。

- 迁移前：`_menu.Renderer = new MechrevoLite.UI.CustomMenuRenderer();`
- 迁移后：`_menu.Renderer = new TrayMenuRenderer();`（`tools/dev/wpf-p0/TrayMenuRenderer.cs`）
- 菜单字体：`MechrevoLite.UI.UiVisualStyle.Font(9f)` → `TrayMenuRenderer.MenuFont(9f)`（内嵌字体加载逻辑一并迁入）

## 改动文件

| 文件 | 变更 |
| --- | --- |
| `tools/dev/wpf-p0/TrayMenuRenderer.cs` | **新建**：从旧 `CustomMenuRenderer` 等价迁移的渲染器（`ToolStripProfessionalRenderer`），并自带菜单字体/DPI 画笔辅助 |
| `tools/dev/wpf-p0/TrayIconService.cs` | 构造与 `SetTheme` 改用 `TrayMenuRenderer`；`SetTheme` 字体改用 `TrayMenuRenderer.MenuFont(9f)`；主题色值未变 |
| `docs/notes/WPF托盘渲染器迁移-20261026.md` | **新建**：本说明 |

其它窗口（`MainWindow` / `OriginalStyleWindow` / `SettingsWindow` 等）**未改动**；旧 UI 源码
（`source/MechrevoLite.UI`）**未改动**。

## 旧实现回顾（source/MechrevoLite.UI/CustomMenuRenderer.cs，81 行）

- 继承 `ToolStripProfessionalRenderer`（基类使用空 `ProfessionalColorTable()`）。
- 依赖两个旧 UI 工具：
  - `UiVisualStyle.Font(9f)` —— 内嵌 HarmonyOS Sans SC，回退 Microsoft YaHei UI，按 (字号,字重,单位) 缓存；
  - `UiVisualStyle.OutlinePen(Graphics, color, 1f, 1f, inset:false)` —— 按绘制 DC 的 DPI 把逻辑线宽换成
    设备像素（`max(minPx, round(logical*dpi/96))`，AwayFromZero），`inset` 控制 `PenAlignment.Inset`。
- 观感要点：菜单底色/前景色由 `TrayIconService.SetTheme` 写到 ContextMenuStrip 上，渲染器只读取；
  hover/选中 = `SystemColors.Highlight` 整行矩形；打勾 = 手绘 `✓`；禁用项 = 前景色 130/255 透明；
  分隔线 = 50/255 前景色、1 逻辑像素、DPI 感知；背景/图像边距 = 菜单底色；**不画边框**；
  ⚠️ **没有圆角**（逐行整块矩形填充，平角）。

## 迁移映射（旧 → 新）

| 旧 | 新 | 说明 |
| --- | --- | --- |
| `MechrevoLite.UI.CustomMenuRenderer` | `L_Mechrevo.WpfP0.TrayMenuRenderer` | 同名七处重写方法逐项搬入，逻辑等价 |
| `UiVisualStyle.Font(9f)` | `TrayMenuRenderer.MenuFont(9f)` | 内嵌 `Fonts/HarmonyOS_Sans_SC_Regular.ttf` + `_Bold.ttf`，族名包含匹配；失败回退已安装字体 → `Microsoft YaHei UI` |
| `UiVisualStyle.OutlinePen(g, color, 1f, 1f, inset:false)` | `TrayMenuRenderer.CreateOutlinePen(...)` | 迁移为项目内私有静态方法，DPI 换算与取整规则与旧实现相同 |
| `MechrevoLite.UI.UiVisualStyle`（命名空间） | ❌ 不再引用 | 托盘路径对旧 UI 零命名空间依赖 |

## 已知差异 / 未覆盖视觉点（明确记录）

1. **审计 DPI 覆盖未迁移**：旧工具链 `UiDpi.AuditDpi`（UI 审计截图专用的 DPI 覆盖）仅影响审计渲染路径；
   托盘菜单不跑审计截图，`CreateOutlinePen` 直接取 `Graphics.DpiX`（≥96）。正常用户路径像素等价。
2. **字体族解析顺序**：新实现优先 `PrivateFontCollection`（与旧 `UiVisualStyle` 相同的内嵌文件方式）；
   若文件缺失，先尝试系统已安装的 "HarmonyOS Sans SC"，再回退 `Microsoft YaHei UI`——旧实现是
   "内嵌失败直接 Microsoft YaHei UI"，此差异只影响"字体文件缺失但系统装了同名字体"的边缘情况。
3. **仍是 WinForms 菜单载体**：本次迁移只把渲染器归属迁入 WPF 项目；托盘图标与菜单仍沿用
   `NotifyIcon + ContextMenuStrip`（WPF 项目 `UseWindowsForms=true`）。若后续要把托盘菜单改为 WPF 原生
   `Popup`/`ContextMenu`，属于新的视觉/架构任务，不在 P0-5 范围。
4. **圆角菜单**：迁移前托盘菜单为平角；本次不引入圆角，保持逐像素观感一致。若设计希望圆角，需要与
   `ContextMenuStrip` 圆角窗口（Region/阴影）一起另立任务。
5. **`CustomMenuRenderer` 其它使用点不受影响**：`source/MechrevoLite/SettingsForm.cs`、
   `source/MechrevoLite.Helpers/DonateControl.cs` 仍在旧 WinForms 应用内使用旧渲染器，这次只解 WPF 托盘路径。

## 回退方式

若托盘菜单出现渲染回归：把 `TrayIconService.cs` 中两处 `new TrayMenuRenderer()` 换回
`new MechrevoLite.UI.CustomMenuRenderer()`、`TrayMenuRenderer.MenuFont(9f)` 换回
`MechrevoLite.UI.UiVisualStyle.Font(9f)`（旧类型仍在旧 UI 项目中，未删除），或 `git revert` 本次提交。

## 后续建议

- 托盘菜单若要做 WPF 原生菜单（圆角/动画/主题资源联动），需要同时替换 `NotifyIcon` 交互路径，建议单独立项。
- 旧 UI 删除前，清理 `CustomMenuRenderer` 在旧 WinForms 应用内的剩余使用点（`SettingsForm` / `DonateControl`）。
