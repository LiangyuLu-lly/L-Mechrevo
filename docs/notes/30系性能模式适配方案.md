## 二、官方 30 系的模型（抓包 + 真机文件双重确认）

### 2.1 协议：切模式与"配置"在同一条消息里

官方控制台 `GamingCenter3_Cross`（UWP，`ControlCenter3 4.17.47.13`）切模式时发：

```
topic: Fan/Control
{"Action":"OPERATING_OFFICE_MODE","ProfileIndex":"3"}    // 办公模式 + 配置 4
{"Action":"OPERATING_GAMING_MODE","ProfileIndex":"2"}    // 游戏模式 + 配置 3
{"Action":"OPERATING_TURBO_MODE","ProfileIndex":"2"}     // 狂飙模式 + 配置 3
{"Action":"FAN_BOOST_ON"}                                 // 风暴唤醒 开
{"Action":"FAN_BOOST_OFF"}                                // 风暴唤醒 关
```

**模式 = `Action`；配置 = `ProfileIndex`（字符串数字，0 起）；两者一条消息同时下发。**

### 2.2 真机配置：每个模式各记一个配置号

`C:\Program Files\OEM\机械革命电竞控制台\UniwillService\MyControlCenter\UserPofiles\MainOption.json`：

```json
"GamingProfileIndex": 2,    // 游戏模式用 配置 3
"OfficeProfileIndex": 3,    // 办公模式用 配置 4
"TurboProfileIndex":  2,    // 狂飙模式用 配置 3
"FanBoostEnable": 0,        // 风暴唤醒
"OperatingMode": 0
```

**与抓包逐条吻合**：办公发 `"3"` ✅、游戏发 `"2"` ✅、狂飙发 `"2"` ✅
（抓包里更早的 `GAMING 3` / `TURBO 0` 是用户改动**之前**的旧值）

### 2.3 配置数量：每个模式 5 个

同目录下：

```
MainOption.json
Mode1_Profile1.json … Mode1_Profile5.json     // 游戏
Mode2_Profile1.json … Mode2_Profile5.json     // 办公
Mode3_Profile1.json … Mode3_Profile5.json     // 狂飙
```

→ **3 模式 × 5 配置**。`ProfileIndex` 0..4 ↔ 界面显示「配置 1..5」
（截图里的"配置 1 / 配置 4"就是这个）

`ProfileIndexFor(kind, root)` 里 LM 自己的映射：

| LM `PerfModeKind` | 官方 Mode 号 | 官方名 | 官方键 | 官方风扇表名 |
|---|---|---|---|---|
| `Silent` | Mode2 | **办公模式** | `OfficeProfileIndex` | `DefaultFanTable_Office` |
| `Balanced` | Mode1 | **游戏模式** | `GamingProfileIndex` | `DefaultFanTable_Gaming` |
| `Turbo` / `SilentTurbo` | Mode3 | **狂飙模式** | `TurboProfileIndex` | `DefaultFanTable_Turbo` |

**LM 的三个模式 = 官方的三个模式，只是叫法不同（静音/平衡/狂暴 vs 办公/游戏/狂飙）。**

## 六、需要拍板的问题

### Q1：怎么判断"这台机器支持多配置"？

你这台是 **Gen40 显卡 + 30 系 GCU**，所以不能用 `DgpuGeneration == Gen30` 当判据。候选：

| 判据 | 评价 |
|---|---|
| `DgpuGeneration == Gen30` | ❌ 你这台是 Gen40，不成立 |
| **官方 `UserPofiles\Mode*_Profile*.json` 存在且每个模式 > 1 个** | ✅ **推荐**：直接反映"这台机器的官方控制台支持多配置" |
| GCU 上报某字段 | ❓ 未知，需再抓一次 GETSTATUS 找 |

→ 建议用第二种：`DataRoot()` 已经能定位目录，数一下文件即可。

### Q2：配置数量取几？

官方是 **5**（Profile1..5）。但 LM 现有两处钳位不一致：

- `VendorModeDefaults.ProfileIndexFor`：0..1
- `MechrevoService.cs:361` / `MechrevoHw.cs:3295`：`Math.Clamp(CustomProfileIndex, 0, 3)`
- `FirmwareSlotPlanner.DefaultSlotCount = 5`

→ 建议统一为**按实际配置文件数量**（本机 = 5）。

### Q3：40/50 系要不要跟着改？

你说 40/50 系没有这个模型（只有 50 系"两种狂暴"的分支）。那就靠 Q1 的判据自然分流：
官方没有多配置文件的机型 → 不下发、不显示下拉，行为完全不变。

### Q4：`OperatingMode` 的取值语义要再确认一次

官方 `MainOption.json` 里 `OperatingMode: 0`，而抓包最后一条是 `OPERATING_OFFICE_MODE`。
LM 的映射是 `0=游戏 / 1=狂飙 / 2=办公 / 3=自定义`（`MechrevoService.cs:350-354`）。

两者对不上，需要确认 `MainOption.json` 的 `OperatingMode` 是**同一个语义**还是官方 UI 的另一套编号。
→ 不影响第 1 步（`Action` 名与 `ProfileIndex` 已确认），但要动"回读"时得先弄清。
