> **时间**：探索与实测 2026-10-06（19:30 前后）；存档整理 2026-10-06 20:10。
> **一句话**：我们试着像厂商官方控制台那样，**从厂商服务器按机型下载屏幕校色的 ICC 配置文件**；
> 用**本次这套地址与取法**什么都没取到（全部 404）。**但这套方法不是 40 系机型的方法，所以下面的结论都只能算"待验证"。**

## 零、先看保留意见（这一节比后面所有内容都重要）

1. **本次实测用的"取法 / 服务器地址"并不是 40 系机型的方法。**
   - 你的原话与观察：「**40 系貌似只有第一个地址**」—— 也就是说，40 系机型（我们手上这台翼龙15Pro）可能只走**第一个地址**，
     而这次我们是把**三个地址**凑在一起试的（组合来自别的机型与旧资料）。
   - 取法（用序列号还是用有线网卡 MAC、后缀多长、大小写）也可能**不是** 40 系的那一套。
   - 另外还有一句**没有验证过**的说法：「第一个地址与第三个地址的**指令（拼法/参数）不一样**」。
2. **因此，"厂商服务器上没有本机档案"这个结论不能算数。**
   - 它最多只能说明：**按我们试的那组"地址 + 取法"，服务器回了 404**。
   - **不能**据此认定"厂商没给这台机器做校色档案"，更**不能**认定"厂商不支持这件事"。
3. **要真正确认，前提是先拿到 40 系机型正确的方法 / 地址。** 可能的来源（都还没做）：
   - 官方**控制台安装包**里负责校色/ICC 的那部分程序（看它实际拼 URL 的代码或配置）；
   - 它的 **PowerShell 脚本 / 配置文件**（官方安装器与 GCU 里有一批 ps1 / json，本次没找到 ICC 拉取那一条）；
   - 或者一位**能连通该服务的同机型（40 系）机主**帮忙实测一次。
   > 在这三件事之一完成之前：**本存档里的"结论"一律视为未定。**

## 一、这是什么（白话）

- LM（L-Mechrevo）的「屏幕校色」用的是 **ICC 色彩配置文件**（一个描述"这块屏幕显示出来的颜色长什么样"的文件）。
- LM 现在只有**本地**这一条路：把 `.icc` 文件放进程序目录的 `customICC\`，再在校色弹窗里选「自定义」。
- 我们探索的是**另一条路**：能不能像**官方控制台**那样，**联网**按"本机机型 + 面板/序列号"从**厂商服务器**上把官方校色档案拉下来，
  省得用户自己去找文件。
- 探索用的是一个只读脚本（见第四节）：它**只下载、只解压，不安装**，也不改任何系统设置。

## 二、已知事实（来自脚本、官方安装包内的实例、以及本次实测）

### 2.1 三个 ICC 服务器地址

| # | 地址 | 端口情况 |
|---|---|---|
| ① | `http://iccprofile.uniwill.com.tw/api/iccprofile/` | 80 通 |
| ② | `http://iccprofile.aistoneglobal.com:8001/api/iccprofile/` | 只有 8001 通（80 不监听） |
| ③ | `http://iccprofile1.aistoneglobal.com:3081/api/iccprofile/` | 只有 3081 通（80 不监听） |

- ⚠️ **拼写更正**：aistone 那个域名的真名是 **`aistoneglobal`（中间有 e）**；
  早先资料/脚本里出现的 **`aistonglobal`（少一个 e）是错拼** —— 本次实测该错拼域名**三个都 DNS 解析失败**。
- 你的观察（关键）：**40 系机型"貌似只有第一个地址"** —— 也就是 ②③ 很可能压根不是 40 系该用的地址。

### 2.2 两种取法（URL 的拼法）

1. **取法一（序列号）**：`<显示器PnP ID>_<序列号>.zip`
2. **取法二（有线网卡 MAC）**：`<显示器PnP ID>_<有线网卡MAC>.zip`

- 命名形态的旁证来自官方安装包内 `ICCProfile\` 目录里的**真实实例文件名**：
  - `BOE0D55_B025AA7FCFA5.zip` → 后缀是 **12 位 MAC**（`B025AA7FCFA5`）
  - `BOE0D55_425032C32531090339.zip` → 后缀是 **20 位序列号**（`425032C32531090339`）
  - 另有 `XMI27B3_*.zip` 等 —— 一律**大写、无分隔符**，PnP ID 形如 `BOE0D55` / `XMI27B3`。

## 三、本次实测矩阵与结果（只对"本节这套取法 + 地址"成立）

- **矩阵**：**3 个地址 × 2 种取法 = 6 格**（真实 PnP `BOE0CBE` + 真实序列号）。
- **结果**：**6 格全部 HTTP 404**，响应体是固定的 **9 字节**自定义纯文本 `Not found`（220–980 ms），不返回 zip。
- **旁证（这是本次唯一的"强证据"，但它也只对本次所试的地址/取法成立）**：
  - 随机路径（`/totally/nonexistent`）与 `/api/zzz/<名字>.zip` 返回的是 **1552 字节的 Laravel 默认 HTML 404 页**；
  - 而 `/api/iccprofile/<名字>.zip` 返回的是上面那 **9 字节自定义 404**；
  - → 说明**这条路由（`/api/iccprofile/{name}.zip`）在服务端是真实存在的**，我们遇到的**不是**"路由不存在 / 路径写错"。
  - → 但它只能证明"**路由存在、我们查的这条档案在这台服务器上不存在**"，
    **不能**证明"厂商没做支持"（原因见第零节）。
- 顺带排除的写法：分隔符改成 `-`、PnP 改小写、只给 `<PnP>.zip`、路径大小写变体（`/ICCProfile/`）—— 全都落回 404。
- 网络侧：三个端口 TCP 探活都通（43–174 ms）；**首轮** 8001 / 3081 曾连续 10 次 10 秒超时，约 2 分钟后复测恢复正常（原因未定性）。
- 本次**没有安装任何 ICC 文件**，也**没有改动系统颜色管理关联**。

## 四、工具：`tools\Get-IccProfile-fixed.ps1`

- **用途**：把上面那套"三地址 × 两取法"的探测与下载做成一个只读脚本，用来回答"服务器上到底有没有本机这条档案"。
- **特点**：
  - 三地址 × 两取法（`<PnP>_<序列号>.zip` / `<PnP>_<有线网卡MAC>.zip`）自动跑一遍；
  - 每个请求默认 **10 秒超时**；
  - 诊断输出里**序列号与 MAC 做遮蔽**（只显示前后 2 位），PnP ID（面板型号）不遮蔽；
  - **只下载 + 只解压**，**绝不安装**、不写系统颜色管理设置；
  - 命中后做**真 ZIP 校验**（先看 `PK` 幻数，再用 .NET 真正打开、要求条目数 > 0），
    防止"HTTP 200 + HTML 错误页"被当成成功。
- **先看不联网的示例（`-Dry` 只打印将要请求的 URL 矩阵，不联网）**：

  ```
  powershell -ExecutionPolicy Bypass -File .\tools\Get-IccProfile-fixed.ps1 -Dry
  ```

- 真跑（会联网；仍然只下载不安装）：

  ```
  powershell -ExecutionPolicy Bypass -File .\tools\Get-IccProfile-fixed.ps1
  ```

- ⚠️ 该脚本文件必须是 **UTF-8 带 BOM**：Windows PowerShell 5.1 对无 BOM 的 `.ps1` 按 ANSI(GBK) 读中文，
  会直接解析失败（本次踩过这个坑）。

## 八、2026-10-30 实测更新（已确认，替换上面"未验证"部分）

> 本节为**实机确认**结果，前述"没取到 / 待验证"的结论已被本节覆盖。

### 8.1 两套命名规则（都已实测命中）

| 代际 | 服务器 | 命名 | 实测样本 | 返回 |
|---|---|---|---|---|
| **40 系** | `iccprofile.uniwill.com.tw` | `<pnp>_<MAC>` | `BOE0CBE_B025AA781188` | 单文件 `.icm`，20,340 B，`acsp` |
| **50 系** | `iccprofile.aistoneglobal.com:8001` | `<pnp>_<BIOS序列号>` + `.zip` | `BOE0D55_425052C32559370299.zip` | ZIP，42,504 B |

- `pnp` = `WmiMonitorID.ManufacturerName` + `ProductCodeID`（如 `BOE` + `0CBE` = `BOE0CBE`，`BOE` + `0D55` = `BOE0D55`）
- `sn` = `Win32_BIOS.SerialNumber`（面板 `SerialNumberID` 实测常返回 `"0"`，不可用）
- `MAC` 来自 `Get-NetAdapter -Physical`（去掉 `-`/`:` 后大写）
- 每套命名都试三种后缀：`''` → `.zip` → `.icm`（50 系实际是 `.zip` 命中）
- 40 系机器访问 aistone 服务器全部 404（服务器按代际分家）；50 系反之亦然

### 8.2 50 系 ZIP 内部结构（BOE0D55，2025-05-24 文件日期）

```
BOE0D55_425052C32559370299.zip   42,504 B   SHA256 5E468769FBB8D90F26C205602CA54B0205CE310210B6B33CCDA835EF08950AFF
├─ sRGB.icm           35,884 B   acsp / dataSpace=RGB / pcs=XYZ
├─ Default.icm         9,628 B   acsp / dataSpace=RGB / pcs=XYZ
└─ PanelInfo.xml         211 B
```

`PanelInfo.xml` 内容：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE PanelInfo>
<PanelInfo version="2">
    <HDR>true</HDR>
    <ColorSpace>sRGB</ColorSpace>
    <Gamma>2.2</Gamma>
    <Profiles>sRGB,Default</Profiles>
</PanelInfo>
```

**结论：ZIP 必须原样保留，不能解包只取一个。** 广色域机型一个包里会有多个 ICM（`sRGB` / `Default`，未来可能还有 `P3` 等），
`PanelInfo.xml` 还给出了 HDR/色域/Gamma 元数据，是选择安装哪一个的依据。

### 8.3 脚本行为（`D:\openLM\tools\icc-fetch\Get-CloudIcc.ps1`）

- 服务器返回 ZIP → **原样保存 `<候选名>.zip`**，不解包；只读取中央目录列出包内 `.icm/.icc` 清单
- 服务器返回 ICC → 保存 `<候选名>.icm`
- 落盘名统一取候选名本体，不再出现 `xxx.zip.icm` 双后缀（2026-10-30 修）
- 支持 `-Method 1|2|3|auto`：1=序列号（50 系）/ 2=MAC（40 系）/ 3=两个都试 / auto=1 失败再 2，仍失败兜底
- 自提权（UAC）+ `-KeepOpen` 双击入口 `双击运行-获取云端ICC.cmd`

### 8.4 对 ICC 插件（openrevo-plugin-icc）的设计含义

1. 用宿主 `fetch_url_bytes` 拉 ZIP（0.9.5 已具备该命令）
2. 前端解析 ZIP 中央目录，列出所有 `.icm`（不必依赖第三方库，ZIP 中央目录格式简单）
3. 解析 `PanelInfo.xml` → 显示 HDR / ColorSpace / Gamma / Profiles
4. 让用户选择要安装的 ICM（或按 `PanelInfo.Profiles` 顺序推荐第一个）
5. 调宿主 `import_custom_color_profile` 安装，必要时 `apply_color_profile` 激活
