## 4. ⭐⭐ 本次新增的关键结论（这几条最值钱）

### 4.1 灯光（详见 `第三方JiaoLong7.3-灯光指令-20261017.md`）

> **事实（顺序 + 时序）**：先写功能号 16 = 2（固定色）⇒ **等 500 ms** ⇒ 再写功能号 17 = 3 字节 RGB。
> 第三方 7.3 与官方 40 系都有这个 500 ms；官方 30 系没有。⛔ 不贴代码（见 §7.7）。


| 枚举 | 值 |
|---|---|
| `WMIRGBKeyboardMode` | Off=0 / AutoCyclic=1 / FixedMode=2 / CustomColors=3 |
| `WMIRGBKeyboardBrightnessLevel` | **Level_0..Level_4（0~4 五档）** |
| `WMIResultState`（LOGO 灯） | OFF=0 / ON=1 |

### ⚠️⚠️ 两个参考源在【亮度档位】上不一致（别绕回去）

| 来源 | 值域 |
|---|---|
| `JiaolongControl`（MIT · 蛟龙16Pro · `SysEnums.cs:67-72`） | **`Level_0..Level_3`（0~3）** |
| 第三方 `JiaoLong7.3`（40 系改版） | **`Level_0..Level_4`（0~4）** |
| 官方 30 系 / 40 系 | 未逐字核对 |

⭐ 当前代码取的口径：**Gen40/Gen50 ⇒ 0~4**（信第三方 7.3）、**30 系 ⇒ 0~3**（信 JiaolongControl）。
⚠️ 这仍是**推测**，需 40 系真机确认「传 4 是否有效」；无效就整体回退 0~3。


- ⭐ **LOGO 灯只有 0/1**，没有颜色/效果/亮度 ⇒ 灯条搜索**零命中** ⇒ 宝龙达**没有独立灯条**
- ⭐ **颜色只写不读**（三方都不读 RGB）⇒ 回读 `0,0,0` 是固件不回读，**不是写失败** ⇒ `confirmed` 不该含颜色
- ⭐ `WinKeyLock=33` **只在事件表**、功能表里没有 ⇒ 我们隐藏 win 键锁是对的

### 4.2 温度（CPU）

三档兜底顺序：**厂商值（功能号 22 / GCU）→ LHM → ACPI 热区**

- 30 系功能号 22 **返回 0**（无效）；40 系可读（65℃）
- LHM 读核心温度需 **PawnIO**（读 MSR）⇒ 没装就只剩 ACPI 热区
- ⭐ **两个断点都修了**：`_cpuInfoReceivedAt` 没人写（`5ab92fc`）+ ACPI 热区兜底（`93db9b2`）
- ⭐ 官方 30 系控制台**也用 LHM、也没带任何 `.sys`** ⇒ 它靠 LHM 的降级路由

### 4.3 GPU 温度（4070 那条）

- LHM 的 GPU 支路**被我们主动关掉**（防 NVML 原生崩溃 `0xc0000005`）⇒ 温度只能来自 `NvmlHelper`
- ⭐ 真机日志里**既无"取到"也无"没取到"** ⇒ 走了那条**静默的"厂商值"分支**（`hw.GpuTemp > 0 && !facadeIsOurs`），而宝龙达**没有厂商 GPU 温度**
- 已改：宝龙达**强制走 LHM→NVML**，并加了「GPU 温度探路（宝龙达）」限流日志 ⇒ 下次诊断包能直接看出卡在哪一环

### 4.4 风扇曲线（本次新接）

- ⭐ 宝龙达**没有固件曲线表** ⇒ 只能**软件闭环**：读温度 → 查曲线 → 写功能号 21
- 通道归属（owner 已确认）：**`FanType 0` = 大扇/GPU** · **`FanType 1` = 小扇/CPU**
- `FanChannelMappingConfirmed = true`（⚠️ 唯一开关点，回滚就改它）
- ⭐ 原来 `ApplyBaolongdaFanCurveStep()` **只在保存时调一次** ⇒ 已挂到 3s 定时器
- UI 复用 `FanCurveForm`（本来就是双通道），只做 RPM ↔ % 换算

## 7. ⚠️ 踩过的坑（**别再踩**）

### 7.1 行尾（本会话踩了 **5 次**）

- `Strings*.resx` **混合行尾**（CRLF=14 / LF=5343）⇒ ⛔ **绝不用 `edit` 工具**
- ⛔ 绝不用 `WriteAllLines`（会把纯 LF 全文转 CRLF）
- ⛔ 别用 PowerShell `>` 重定向
- ⭐ **改前先查基线**（各文件行尾不同：`AssemblyInfo.cs` 纯 LF / `install_script.iss` CRLF+8 裸 LF / `FanCurveForm.cs` 纯 CRLF / `SettingsForm.cs` 纯 LF）
- ⭐ Python 脚本改文件时：先 `replace('\r\n','\n')` 归一，最后再 `replace('\n','\r\n')` 写回
- ⭐ PowerShell here-string 的换行是 `\n` ⇒ **对 CRLF 文件不匹配**，要用 `\r\n` 显式拼

### 7.2 PowerShell 坑

- ⛔ **函数名不能撞内置别名**：`function RP(...)` = `Remove-ItemProperty` ⇒ 版本号没改、打包白做
- ⛔ **中文引号 `"..."` 会搞崩解析** ⇒ 用 `「」`
- ⛔ `git commit -m "...\"x\"..."` 会被拆参数 ⇒ 用 `-F 文件`

### 7.3 PS 5.1 编码

- ⛔ 无 BOM 的 UTF-8 会被按 GBK 读 ⇒ 中文吃掉后面引号 ⇒ 脚本跑不起来
- ✅ 给机主的 `.ps1`/`.bat` **必须带 UTF-8 BOM**

### 7.4 Inno Setup

- `[Run]` 的 `Flags` **没有 `ignoreerrors`**（那是 `[Files]` 的）⇒ 用 `-Command "...; exit 0"` 兜住返回码
- `waituntilterminated` / `runhidden` 是合法的

`SettingsForm` 的 duty 判据同步（GCU 分支一字未改）；诊断包把功能号 21 改标为「手动转速设定值」。

⚠️ **30 系未套用**旧版 30 系控制台（v0.2.35）的 `rpm / 35f`（⇒ 3500）—— 那是另一套年代／

### 9.8 显卡功耗 / DB（动态加速）调研

机主问「宝龙达原版或开源项目有没有显卡功耗调节」「NVAPI 能不能读 DB」→ 结论：

- ✅ **`JiaolongControl`（MIT）有显卡功耗上限**：NVML `GetPowerManagementLimitConstraints` → 钳制 →
  `SetPowerManagementLimit`（毫瓦）；另有 `SetGpuLockedClocks` 频率锁。**不依赖 GCU**
- ✅ 斗战者（GPL · 只取事实）也有：NVAPI `SetPowerLimit`（W→mW），并按模式保存/恢复
- ❌ 原厂 40 系 / 7.3：**两者都没有** GPU 功耗调节（7.3 只有锁频）
- ❌ **DB 读不到**：NVAPI/NVML/控制面板/`nvidia-smi` 都没有 DB 字段；DB = PPAB，由驱动 + OEM EC 协同
  ⇒ 只有厂商固件字段（GCU 的 `GpuDynamicBoostSwitch` / `GpuDynamicBoost`）才有档位语义；
  宝龙达 WMI 功能号表里**没有**这一项
- 决策：**做显卡功耗上限**（NVML `min~max` + 回读；不支持就不显示滑块）；**DB 数值不做**；
  将来要 DB 档位必须先有宝龙达 EC 文档/只读抓包证据

明细：`docs\notes\显卡功耗与DB-调研-20261017.md`
