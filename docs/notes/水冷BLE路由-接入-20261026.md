## 二、新增路由服务

`tools/dev/wpf-p0/Services/WaterCoolerRoutingService.cs`：

- 构造参数：`MechrevoHw?`、`MechrevoService?`（来自 `BackendProbe`，不改 BackendProbe）；
- **GCU 优先**：`hw.SupportsLiquidCooling == true` ⇒ `Route=Gcu`，**不创建/不探测 BLE**（保持现有 GCU 行为）；
- GCU 不可用才创建 `WaterCoolerBle`：
  1. `ProbeSystemConnectionAsync`（只读，不扫描）检查 Windows 已连接 BLE；
  2. 已连接 ⇒ `DirectBle`；
  3. `HasSavedDevice` ⇒ 标记 `BluetoothObserved` + 后台 `AutoConnectAsync()`（只对已保存设备，内部才会扫描）；
  4. 仅系统观察到已连接蓝牙 ⇒ `BluetoothObserved`；
  5. 否则 `None`；**不调用 `StartScan`，不连接未知设备**；
  6. 对象/探测异常全部捕获 ⇒ `None`，不影响启动。
- 路由操作：
  - `SetPumpAsync/SetFanAsync`：GCU 用原有 `SwitchLcPump/SwitchLcFan/SwitchLcFanAuto`；BLE 用 `ApplyPumpProfileAsync/ApplyFanProfileAsync`；
  - `ApplyLightAsync`：GCU 复用 `LiquidCoolingLightService.ApplyAsync`（task-21）；BLE 用 `ApplyLightProfileAsync(profile,color)`；
  - `SupportsLight/LightOptions/LightColor/LightProfile`：GCU 沿用 task-21 能力位；BLE 在已连接时开放，风扇灯按 `SupportsFanLed`；
  - `RefreshAsync`：GCU 刷新 GCU 状态；BLE 只读探测/状态刷新；\n  - `Disconnect`：BLE 已连接时按旧行为断开（状态按钮在 BLE 路由下触发；GCU 路由仍只刷新状态）；
  - `Dispose`：窗口关闭时 `WaterCoolerBle.Dispose()`（停 watcher/释放 GATT），对应旧 Program 的 `ble.Dispose()`。

## 三、UI 接口（宽屏/迷你水冷卡）

`OriginalStyleWindow.xaml.cs`：

- 新增 `_waterCoolerRouting` + `EnsureWaterCoolerRouting()`（懒创建，`RouteChanged` 回 UI 线程刷新）；
- `WideLiquidVisible/Supported/Connected/Pump/Fan` 改由路由提供；
- `WideSetLiquidPumpAsync/FanAsync`、`WideRefreshLiquidAsync` 改走路由；
- 灯色 `WideLiquidLight*`/`WideApplyLiquidLightAsync` 改走路由（GCU 仍用 task-21 实现，BLE 用旧 BLE profile）；
- `RefreshLiquidCoolingUi` 按路由显示：
  - GCU：与 task-21 之前一致（泵/风扇/灯色能力位，文案「水冷已连接/未连接」）；
  - BLE 已连接：显示泵/风扇/灯色，文案「蓝牙水冷已连接」；
  - 仅观察到蓝牙：显示卡片与状态「检测到蓝牙水冷（未连接）」，控件禁用；
  - `None`：不显示（除非 `force_liquid_cooling_menu`）；
- `Closed` 时释放路由服务/BLE。

`MainWindow.xaml.cs`：现有宽屏水冷卡通过 `_owner.WideLiquid*` 读取路由后的状态/档位/灯色能力，无需独立 BLE UI；状态按钮文案也改为路由状态。
