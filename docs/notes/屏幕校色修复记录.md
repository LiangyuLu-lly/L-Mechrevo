## 〇、校色功能架构速览

LM 屏幕校色有两条链路：

| 链路 | 走 GCU | 档位 | 记忆来源 | 关键文件 |
|---|---|---|---|---|
| **GCU 四档校色** | 是（MQTT `Setting/Control` 发 `COLOR_CALIBRATION_ON_*`） | 默认=1 / sRGB=2 / P3=3 / AdobeRGB=4 | 40 系无回读→依赖 LM 自身记忆（AppConfig calib_mode）；50 系有回读 | `MechrevoService.cs`、`MechrevoHw.cs`、`SettingsForm.cs` |
| **自定义 ICC** | 否（直写 Windows 颜色管理 HKCU 槽位） | value=999（仅 calib_custom_on 开启时追加） | AppConfig calib_mode=999 + calib_custom_icc | `IccHelper.cs`、`CalibrationStartupForm.cs`、`SettingsForm.cs` |

- 入口可见性：`SettingsForm.cs:4890` `Show(caps.ColorCalibration || hw.SupportsColorCalibration)`（能力位来自 GCU `Customize/Info` 的 SupportColorCalibration>0，FailClosed）。
- 档位下拉：`SettingsForm.cs:10697 RebuildCalibrationItems`——默认/sRGB/P3/AdobeRGB 由 GCU 上报档位决定，「自定义」仅在 `calib_custom_on` 为真时追加 value=999。
- 开机自动应用：`Program.cs:909-930`（calib_apply_on_startup=1 且 calib_mode>0；999 走 ApplyIcc，其余走 GCU）。
- 回读同步按能力区分：`SettingsForm.cs:2633` 定时器，`_lastCalibUi` 后 3s 才允许同步，且仅 `CalibrationReadbackSupported()`（50 系 + GCU 上报过档位）为真时同步；40 系一律不回读（`:10691` ResolveColorCalibrationMode 走 LM 自身记忆）。

## 一、抓包阶段（2026-09-27 ~ 09-30）

### 1.1 初探：40 系 GCU 校色回读缺失（09-27/09-29）
- `ColorCalibrationResultCode`：40A 恒为 1，**无法区分开/关**。
- 40A `Setting/Status` **无 ColorCalibrationSwitch/_Status 字段**——40 系 GCU 不回读校色状态。
- 校色文件在系统 ICC 目录 `%SystemRoot%\System32\spool\drivers\color`（本机 sRGB 面板两档：`BOE0CBE_B025AA78094A.icm` / `BOE0CBE_B025AA781188.icm`）。

### 1.2 档位数量跟随 GCU 上报（09-30，GCU_capture_20260930_191721 / 205804）
- **档位字段**：`Customize/Info` 的 `SupportColorCalibration`（与 `Customize/SupportInfo` 的 `ColorCalibrationSupport` 数值一致）。
- 三台机型实测：
  - 极光（IDK，无灯带）`SupportColorCalibration=2` → 官方 2 档（默认/sRGB）
  - 低配耀世（IDY，无灯带）`=2` → 2 档
  - 高配耀世（IDY，有灯带+多彩呼吸）`=4` → 4 档（默认/sRGB/P3/AdobeRGB）
- **结论（用户拍板）**：官方档位数量完全由 `SupportColorCalibration` 决定（1/2/4）；LM 0.289.5.3 按上报档位显示：
  - 1 档 = 关闭 + 默认
  - 2 档 = 关闭 + 默认 + sRGB
  - 4 档 = 关闭 + 默认 + sRGB + P3 + AdobeRGB
- **广色域有两种形态**：极光只上报默认/sRGB（2 档），耀世/苍龙上报四档——同为广色域屏上报档位数不同，**一律以上报值为准**；「不是 50 系报 4，得根据实际来」。
- 档位数量轮询来源存疑：注册表获取不一定准确，**以 GCU 实际上报为准**。

## 三、40 系无记忆修复（2026-10-02/03，beta21.2 = 0.290.2）

- **问题**：40 系 GCU 无档位回读，关闭校色后重启 LM 开关回跳"打开"。
- **修复**：初始化/轮询状态 `ResolveColorCalibrationMode`——40 系 GCU 无档位回读时，**优先读 LM 自身记忆**（AppConfig calib_mode，设置校色时已写入）；从未用 LM 设置过才回退读官方控制台注册表。
- **效果**：在 LM 内关闭校色后重启 LM，开关保持"关闭"，不再回跳"打开"。
- 相关：40 系 3s 校色状态刷新曾导致开关一直"打开"——为 40 系 GCU 关闭 3s 刷新（判断挂在 3s 刷新定时器内，40 系跳过）。

## 四、自定义 ICC 修复闭环（2026-10-04，0.290.3 beta21.3 归属）

### 4.1 自定义 ICC 功能背景
设置弹窗「自定义开关 + ICC 下拉 + 导入按钮」、主界面校色下拉「自定义」档 value=999，经 Windows 颜色管理关联（不经 GCU）。

### 4.2 第一轮收尾修复
1. **设置页不显示配置文件**（颜色管理"找不到配置文件"）：
   - 根因：WCS `WcsAssociateColorProfileWithDevice` 把 HKCU 槽 ICMProfile 写成逐字符数组（`B||O||E||0||...`），破坏格式。
   - 修复：**弃用 WCS Associate API**，`ApplyIcc` 直接写 HKCU 显示器类槽（0000-0008）`ICMProfile = MultiString{完整文件名}`；另写用户颜色目录副本 `%LOCALAPPDATA%\Microsoft\Windows\Color\` + `HKCU ICM\RegisteredProfiles\<文件名>` 注册标记。页面显示 NE153QDM + (Current SDR profile)。spool 文件已存在则跳过复制（避免 IOException）。
2. **关闭/切离不清理**：清理判断改为 `(calib_mode==999) || calib_custom_on`；下拉切到非自定义档、总开关关闭时自动调用 `ClearAllIcc`（直清 HKCU 槽 ICMProfile + 删注册标记）。
3. **总开关关闭连带关闭自定义开关**：删除 `calib_custom_on=0` 写入，总开关只清理 ICC，自定义开关保持用户设置。
4. **自定义档位记忆**：关闭时当前档位存 `calib_mode_saved`，calib_mode 归 0；重开总开关消费 saved 恢复档位；下拉手动切档清空 saved。

### 4.3 追加修复（关键）
1. **校色档位与开关状态分离**：
   - 根因：关闭总开关成功后把 calib_mode 覆盖为 0 → 重启后回显"默认"、档位记忆丢失。
   - 修复：`calib_mode` 恒存用户档位选择（999=自定义 / 1-4=官方档），关闭只写新增 `calib_enabled`（0/1），不再覆盖 calib_mode；下拉切档隐含置 calib_enabled=1；初始化优先读 calib_enabled，无键回退 calib_mode>0。
2. **重新打开自定义档走 ApplyIcc**（不再经 GCU）：根因是恢复 saved=999 时走了 `SetColorCalibration(999)`（GCU 无效模式）→ 失败 → 开关回弹。修复：开关打开且档位==999 时直接 `IccHelper.ApplyIcc`。
3. **ClearAllIcc 去遍历 + 不误伤外屏**：不再遍历 customICC 目录，只清理 `calib_custom_icc` 记录的当前应用文件；关联槽不再 `DeleteSubKeyTree`（误伤外屏），改为按文件名精确匹配删除对应槽 ICMProfile（仅遍历 8 个槽）。
4. **关闭校色不连带关闭自定义开关**：清理 ICC 不再写 `calib_custom_on=0`，开关独立记忆。

### 4.4 收尾修复（同日三连）
1. **ICC 文件缺失导致校色总开关打不开**（[10-04 19:05]）：重装 LM 后 {app}\customICC 被清，AppConfig 仍记忆 calib_mode=999/calib_custom_icc → ApplyIcc 失败 → 开关弹回。修复：SettingsForm.cs 两处 value==999 分支加**文件存在性判断**——文件缺失回退默认档（value=1 + 下拉同步 + SetColorCalibration(1)）。
2. **安装器升级备份 customICC**（[10-04 19:20]）：`BackupAndUpgrade` 增加 {app}\customICC 备份到 {tmp}\lm-upgrade-backup\customICC（失败不中止升级）；ssPostInstall 恢复。卸载逻辑不变（卸载清 {app}，不备份）。
3. **开机自动应用支持自定义档**（[10-04 19:25]）：Program.cs 在 calib_apply_on_startup 且 calib_mode==999 时改经 ApplyIcc（文件存在才应用），普通档保持 SetColorCalibration（此前 999 被范围校验直接拒绝）。
4. **删除「屏幕校色」弹层与 ✕ 重复的「取消」按钮**（[10-06 20:40]）：closeBtn 与 ✕ 同为 `Close()`，无回滚语义（设置全部即时落盘），安全删除；ClientSize 580×380 → 580×300。

## 五、50 系校色专项（2026-10-06 ~ 10-07）

### 5.1 50 系机主反馈"校色用不了"排查（[10-06 22:10]，诊断包 0.290.7）
- 机型：耀世（ARL/IDY，RTX 5060，Gen50），GCU 1.2.0.0，能力位校色=是/档位数 4。
- 链路读全：入口/能力/GCU 全部满足；config 为 calib_mode=2(sRGB)、calib_apply_on_startup=1、**calib_custom_on=0**、calib_custom_icc="sRGB (2).icm"（重复导入副本名，非厂商 ICC）。
- **结论**："用不了"最可能是**自定义 ICC 这条路没走通**（开关未开/下拉空/导入选不到厂商 zip/应用后屏幕无感），而非 GCU 四档校色坏了。日志级别 Off 导致零证据。
- 缺口（未改代码，仅建议）：A. ApplyIcc 失败与 ICC 缺失回退两条路径**静默失败**，建议给可见提示 + Error 级日志；B. 数据源太窄且**导入挡 .zip**（厂商 ICC 是 `…\MyControlCenter\ICCProfile\BOE0D55_<PnP>_<序列号>.zip`）。

### 5.2 校色档位无法应用/自动跳回 sRGB（[10-07 17:30] 排查 → [10-07 18:20] 返工定版）
- 现象：选 sRGB 屏幕依旧默认校色；切 P3 无变化；一会儿后跳回 sRGB（50 系机主）。
- ⚠️ **17:30 那版"GCU 动作词汇错、四档需折叠为两档"的根因已作废（18:20 返工）**：当时只扫了 GCUService.exe 的 **UTF-16** 字符串，而该 exe 的 **UTF-8/ASCII** 命令名表里四档是齐的——
  `ICCPROFILESETING / COLOR_CALIBRATION_ON / COLOR_CALIBRATION_ON_DEFAULT / COLOR_CALIBRATION_ON_SRGB / COLOR_CALIBRATION_ON_P3 / COLOR_CALIBRATION_ON_ADOBERGB / COLOR_CALIBRATION_OFF / OSDTP_COLOR_CALIBRATION_OFF`（`installer-src\files\GCU\payload\50\AiStoneService\MyControlCenter\GCUService.exe` 偏移 ≈10,123,309，与官方 GCU 反编译 `Define\ServCMD.cs` 同构）。
  → **"静态字符串扫不到 ≠ 不存在"**：动作词表在 Costura 打包/运行时拼接场景下不可靠，折叠依据不成立，**已撤销折叠**。
- **真实档位口径（用户原话）**：「50系的P3色域屏幕是有4档位的 还有一个广色域屏幕是2档位(default和srgb) 像我这个40系srgb屏幕在40系GCU下只有校准和不校准(LM做成开关形式了其实40系GCU不支持回读但是50系支持回读开关)」：
  - 40 系 + sRGB 屏 = **二分（校准 / 不校准）**，UI 用**开关**，40 系**不做回读**；动作只有裸 `COLOR_CALIBRATION_ON` / `COLOR_CALIBRATION_OFF`（`payload\40`、`payload\30` 命令名表实测只有这两个）。
  - 50 系 + P3 屏 = **4 档下拉**（默认/sRGB/P3/AdobeRGB），50 系**做回读**。
  - 50 系 + 广色域屏 = **2 档下拉**（default/sRGB），50 系**做回读**。
- 18:20 实现（0 错误，**未部署**）：`ColorCalibrationSwitchPolicy.ResolveLevel/IsBinaryDevice/SupportsReadback`（档位数口径 + 二分判定 + 回读能力）；`SettingsForm.CalibrationLevel/CalibrationBinaryOnly/CalibrationReadbackSupported`，二分设备隐藏档位下拉（`CalibComboNeeded`），`MapCalibrationMode` 只做"不超过上报档位数"的截断；`MechrevoService.ColorCalibrationAction(mode, binaryDevice)` 二分→裸 ON，多档→四档 1:1；`ConfirmColorCalibrationAsync` 的档位比较对二分设备只看开关。
- 上一轮保留项：`_calibSetInFlight`/`_calibSyncHoldUntil` 闸门（操作中 + 成功后 8s 不覆盖用户选择）与失败提示 `ToastForm.ShowFailure(Strings.ColorCalibrationFailed)`（新增键 en/zh-CN）。
- 备份：`D:\openLM\backup\snapshots\2026-10\20261007_1820_pre_calibrework\`（本次返工改前快照）。

## 六、校色 ICC 联网拉取探索（2026-10-06，已存档非待办）

- 用户原话："对于校色的探索…40系貌似只有第一个地址 目前我用这个脚本是不行的"。
- 三地址 × 两取法实测（`<PnP>_<序列号>.zip` 与 `<PnP>_<有线网卡MAC>.zip`）：
  - `iccprofile.uniwill.com.tw:80` / `iccprofile.aistoneglobal.com:8001` / `iccprofile1.aistoneglobal.com:3081` **全部 HTTP 404**（自定义 9 字节 "Not found"）。
  - 路由存在性验证：`/api/iccprofile/<name>.zip` 返回自定义 404、`/api/zzz/...` 返回 Laravel 默认 HTML 404 → **该路由真实存在**，只是服务端没有本机档案。
  - **aistonglobal（无 e）是错拼**，真名带 e；错拼域名 DNS 全失败。
  - 命名规则旁证（安装包 GCU\payload\50\AiStoneService\MyControlCenter\ICCProfile\）：BOE0D55_00155DB30100.zip（MAC）、BOE0D55_425032C32531090339.zip（20 位序列号），一律大写无分隔符。
- **结论**：不是网络/脚本问题，是服务端确实没有本机（BOE0CBE + 本机序列号）的 ICC 档案。脚本侧"用不了"另有独立原因（UTF-8 无 BOM → PS 5.1 按 ANSI 解析失败），已修（Get-IccProfile-fixed.ps1，15,735B，UTF-8 带 BOM）。
- **决策**：LM 不改代码、不做联网拉取（对本机无收益 + 隐私面扩大），改为纯研究存档《校色ICC-探索存档.md》；待办 H-1 已移除。
- ⚠️ 该探索的取法/地址**不是 40 系机型的方法**（用户观察"40 系貌似只有第一个地址"），"服务器上没有本机档案"结论不能算数。
