# 核显模式（iGPU 档位）判据 —— 存档与结论

存档时间：2026-10-05
适用机型：**翼龙15Pro（GM5HG0A，RTX 4060 = 40 系）+ GCUService 1.0.2.70（`payload\40`）**

> ⚠️ 本文**取代**《核显模式判据设计与三方对照.md》的结论部分：
> 那篇里「能力位不可靠」「应把 Gen30 从否决条件降级」等推断**均已作废**（见 §5）。

---

## 1. 结论（一句话）

> **非核显模式下，GCU 不暴露「有 iGPU 档位」** ❌
> 唯一可靠的常驻信号是「**支持显示路由切换**」+「**支持独显直连**」，
> 因此核显模式按钮应按这条**代理规则**显示，而**不能**依赖 GCU 的 IgpuOnly 能力位。

---

## 2. 实测字段全貌

### 2.1 独显直连下 `Setting/Status` 里所有与 iGPU 相关的字段

```json
"DiscreteGpuDirectConnectionSwitch_Status": "DGPU_DIRECT_CONNECT_TOGGLE_ON",
"DiscreteGpuDirectConnectionSwitch_Support": "Support",
"IGpuOnlyConnectionSwitch_Status": "IGPU_ONLY_CONNECT_RB_OFF",
"IGpuOnlyConnectionSwitch_Support": "NotSupport",
"IGpuAutoSupportSwitch": "IGPU_ONLY_CHECK_IGPU_AUTO_DETECT_OFF"
```

| 字段 | 独显直连 | 混合 | **核显** | 能否当判据 |
|---|---|---|---|---|
| `DiscreteGpuDirectConnectionSwitch_Status` | `..._TOGGLE_ON` | `..._TOGGLE_OFF` | **`..._TOGGLE_IGPU`** | 只能判断**当前**是否核显 ❌ 不能判断"支不支持" |
| `DiscreteGpuDirectConnectionSwitch_Support` | `Support` | `Support` | `Support` | ✅ **常驻**，= 支持路由切换 |
| `IGpuOnlyConnectionSwitch_Status` | `..._RB_OFF` | 同 | 同 | ❌ **永远是 OFF** |
| `IGpuOnlyConnectionSwitch_Support` | `NotSupport` | 同 | 同 | ❌ **永远说不支持** |
| `IGpuAutoSupportSwitch` | `..._DETECT_OFF` | 同 | 同 | ❌ 恒为 OFF |

**关键**：后三个字段的**字段名里有 `IGPU_ONLY`**，但**取值恒为 OFF/NotSupport** ⚠️
—— 固件是固定 schema，**"字段存在"不能当支持证据** ❌

### 2.2 其它 topic

- `Customize/Info`：只有 `AppType/APPTarget/BatteryCalibration/PluginPath/DebugMode` —— **与显卡无关** ❌
  （`MechrevoDeviceCapabilities.FromValues` 吃的是这一路，所以 `iGPUModeOnlySupport` 在这里也取不到）
- `GPUDevice/Status`：`currentHZ` / `currentHZList` / `AutoEnable` 等 —— **与显卡模式无关** ❌

## 3. 判据的两种写法与历史

| 时期 | 判据 | 翼龙15Pro 结果 | 出处 |
|---|---|---|---|
| 早期 | `CanOfferGpuModeSwitch && SupportsDgpuDirect` | ✅ **True** | **更新日志 0.289.1.0**：「官方 GCU 在 40 系三模机型**不上报 IgpuOnly 支持字段**，改为按『支持切换 && 支持独显直连』显示集显模式」 |
| 后来 | `SupportsIgpuOnly`（+ 代际动作校验） | ❌ False | 被代际判据取代 |
| **现在（2026-10-05 恢复）** | 二者**并存**：`SupportsIgpuOnly` 优先，否则回退到早期规则 | ✅ **True** | `MechrevoHw.cs:419 CanOfferIgpuOnly` |

**「之前显示支持、现在反复」的真正原因 = 判据换代** ✅
不是硬件在变 ✅（10-02 诊断包 `集显模式: 是` 正是早期规则给出的 ✅）

## 4. 当前实现（生效中）

```csharp
// MechrevoHw.cs:419
public bool CanOfferIgpuOnly
{
    get
    {
        if (SupportsIgpuOnly)
        {
            return IsGpuActionAllowedByGeneration("IGPU_ONLY_CONNECT_RB_ON");   // 原逻辑保留
        }
        // 2026-10-05 恢复更早的逻辑（0.289.1.0）：支持切换 && 支持独显直连
        return CanOfferGpuModeSwitch && SupportsDgpuDirect;
    }
}
```

- ✅ **不依赖当前模式** → 切到独显/混合后按钮**仍在**（这是上一版失效的根因）
- ✅ **30 系屏蔽自动保留**：`CanOfferGpuModeSwitch` 内部已有
  `:441 if (DgpuGeneration != DgpuGenerationKind.Gen30 && ...)` → Gen30 时回退分支必为 False
- ⚠️ **不要动 `ThreeModeCapability`（:415）**：它被 `CanOfferGpuModeSwitch` 经 `:1378`
  间接使用 → 反过来依赖会**无限递归** ❌
- ⚠️ **切换路径无需改**：`CreateGpuSwitchPayload(mode=0, supDgpu=true, supIgpu=false)`
  条件为假 → 正好返回 `DGPU_DIRECT_CONNECT_TOGGLE_IGPU`（**实测有效**那条）

## 5. 已作废的推断（重要，避免以后重走弯路）

| 曾经的推断 | 实际 |
|---|---|
| 「能力位不可靠」（《核显模式判据设计与三方对照.md》§二） | ❌ 位是**可信**的：它报 `NotSupport` 是真的；问题是**判据换代**了 |
| 「应把 Gen30 从否决条件降级」 | ❌ **作废**。用户明确：「30 系没有支持核显模式的机器，30 系可以全部屏蔽的」→ `:441` 保留 |
| 「两条路不通（Customize/Info vs Setting/Status）」 | ✅ 这条**成立**（`FromValues` 吃 Customize/Info） |
| 「在 `MechrevoHw` 解析 text24 时置位即可」 | ❌ 无效。真因是**子串写错**：真实 token 是 `DGPU_DIRECT_CONNECT` + `_TOGGLE_` + `IGPU`，`Contains("DIRECT_CONNECT_IGPU")` 匹配不上 |
| 「切走之后仍要显示 → 靠 GCU 上报 + 锁存」 | ❌ 锁存作用域=LM 运行，切模式伴随重启 → 清零 → 又消失。**已回退** |

> **教训**：三次修改无效后加了诊断日志才拿到真值 ✅
> —— 正是本项目 §9.2 的既有教训：**先打真值日志，别猜** ✅

```
用户第一次按「核显模式」
```

## 8. 附：NVRAM 显示模式字节（顺带修好的一个 bug）

```
AMD   : Direct=1  Hybrid=0  Igpu=2      ← 本机
Intel : Direct=2  Hybrid=4  Igpu=1

日志：NVRAM display byte @0x62=0 (len=180, amd-decoded=Hybrid; offset unverified)
```
- 原先 `UefiDisplayModeDiagnostics.cs` 把平台**写死成 Intel** → AMD 机器上
  `@0x62=1` 被误标成 `IgpuOnly`（实际是 Direct）、`0` 被标成 `unrecognized`
- 已修：`Describe(bool isAmd)` + 两个调用点传 `Program.hw?.IsAmdPlatformForLimits` ✅
- ⚠️ `offset unverified` 仍在：`0x62` 这个偏移**未经交叉验证**，但**与路由读回一致** ✅

# ⚠️ 重要更正（2026-10-05 11:30）

本文 §7 与 §4 里「实测：`on` 有效 —— NVRAM `@0x62` 变为 2、NVIDIA 被屏蔽」的结论 **作废** ❌

**用户澄清**：那次核显模式是**他进 BIOS 手动切的** ✅，不是我发的 `IGPU_ONLY_CONNECT_RB_ON` 生效 ✅

## 更正后的结论

1. **`IGpuOnlyConnectionSwitch_Support = NotSupport` 说的是真话** ✅
   → 本机这个 40 系 GCU（GCUService 1.0.2.70）**确实不支持运行时切核显** ✅
2. `IGpuOnlyConnectionSwitch_Status = IGPU_ONLY_CONNECT_RB_OFF` 也是**真实的** ✅（不是"死字段"）
3. **手动发 `IGPU_ONLY_CONNECT_RB_ON` 是失败的** ✅（与用户最初判断一致）
4. ⚠️ **本文 §4「当前实现」的回退分支前提不再成立**：
   `CanOfferIgpuOnly => CanOfferGpuModeSwitch && SupportsDgpuDirect`
   会显示一个**按了可能没用**的按钮 ⚠️（比藏起来更差）
5. ⚠️ **尚未确认**：LM 自己发的 `DGPU_DIRECT_CONNECT_TOGGLE_IGPU` 是否真能切？
   `confirmed=True` 只是**状态字段回读** ✅，而当时机器**已经**因 BIOS 处于核显模式 ✅
   → 无法区分"真切了"还是"读到了 BIOS 已切的状态"

## 唯一可靠的判定法（不动 BIOS 的受控实验）

```
① 读 NVRAM @0x62         （应 = 1 = Direct）
② 在 LM 里点「核显模式」
③ 重启
④ 再读 NVRAM @0x62：
     变 2(IgpuOnly) + NVIDIA 被屏蔽  => LM 真能切 ✅
     仍为 1(Direct)                  => LM 也不能切 ❌
```

NVRAM 值看 `%APPDATA%\MechrevoLite\log.txt` 的 `GPU route at startup: ... NVRAM display byte @0x62=`
（或重启 LM 让它重新读一次）
