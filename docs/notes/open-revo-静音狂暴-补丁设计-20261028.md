# open-revo 增加“静音狂暴”模式：补丁设计文档

日期：2026-10-28  
目标：在不破坏 open-revo 现有 4 档性能模式架构的前提下，增加 50 系 GCU 的“静音狂暴 / 高能狂暴”子模式。  
参考来源：GCU 50 反编译 `MyFanManager_RamFan1p5.cs`、`WMIEC.cs`；open-revo `src-tauri/crates/openrevo-core` 与 `src/`。

---

## 1. 结论

不建议把“静音狂暴”做成第 5 个 `PowerMode`。

推荐做成：

```text
PowerMode 3（狂暴）的子模式
  turbo_submode:
    false = 高能/极限狂暴
    true  = 静音狂暴
```

原因：

```text
1. 原厂语义就是狂暴档内部子模式，不是独立 OperatingMode
2. open-revo 的 PowerMode 只定义了 1..4
3. 5 号模式会牵动配置、AC/DC 策略、热键、托盘、插件 API、数组索引
4. 官方只改 EC 1832 bit0 + WMI BIOS RAM，不新增模式
```

---

## 2. 原厂硬件协议

### 2.1 能力探测

```text
WMIEC.WMIIsTurboSubModeSupport()
  → GetSetULong Data = 5497558138888 (0x50000000008)
  → 返回低字节
  → 0x55 (85) = 支持
```

### 2.2 EC 位

```text
EC 1832（0x728）bit0
  0 = 高能/极限狂暴
  1 = 静音狂暴
```

### 2.3 WMI BIOS RAM

```text
静音：
  GetSetULong Data = 5497558138889 (0x50000000009)

高能：
  GetSetULong Data = 5497558138890 (0x5000000000A)
```

### 2.4 原厂执行顺序

静音：

```text
1. currentProfile.Extreme = 0
2. currentProfile.Silent = 1
3. read 1832
4. write 1832 = value | 0x01
5. WMIWriteSilentSubModeForBiosRAM()
6. 写注册表 SilentPerformanceModeSwitch = 0
```

高能：

```text
1. currentProfile.Silent = 0
2. currentProfile.Extreme = 1
3. read 1832
4. write 1832 = value & ~0x01
5. WMIWriteExtremeSubModeForBiosRAM()
6. 写注册表 SilentPerformanceModeSwitch = 1
```

注意：

```text
1832 bit0 只是子模式选择位
PL / 风扇 / GPU OC 仍由狂暴档 Profile 决定
```

```text
前端
  PowerMode 仍为 1/2/3/4
```

## 4. 后端补丁点

### 4.1 常量

新增文件或加到 `driver/wmi_ec.rs`：

```rust
// EC 子模式选择位
pub const ADDR_TURBO_SUBMODE: u16 = 1832; // 0x728
pub const TURBO_SUBMODE_BIT: u8 = 0x01;

// WMI GetSetULong 命令
pub const CMD_TURBO_SUBMODE_SUPPORT: u64 = 0x50000000008;
pub const CMD_TURBO_SUBMODE_SILENT: u64 = 0x50000000009;
pub const CMD_TURBO_SUBMODE_EXTREME: u64 = 0x5000000000A;
```

注意：

```text
0x50000000008 对应十进制 5497558138888
0x50000000009 对应十进制 5497558138889
0x5000000000A 对应十进制 5497558138890
```

### 4.2 能力探测

open-revo 已有：

```rust
crate::driver::wmi_mulong::mulong_query_raw(...)
```

建议新增：

```rust
pub fn is_turbo_submode_supported() -> bool {
    static CACHE: OnceLock<bool> = OnceLock::new();
    *CACHE.get_or_init(|| {
        match crate::driver::wmi_mulong::mulong_query_raw(CMD_TURBO_SUBMODE_SUPPORT) {
            Some(v) => (v & 0xFF) as u8 == 0x55,
            None => false,
        }
    })
}
```

禁止：

```text
仅凭机型名/50 系判断
必须在实机查询 0x55 后再显示 UI
```

### 4.3 读取当前子模式

```rust
pub fn get_turbo_submode_silent() -> Option<bool> {
    if !is_turbo_submode_supported() {
        return None;
    }
    crate::driver::wmi_ec::wmi_read_ec(ADDR_TURBO_SUBMODE)
        .map(|v| (v & TURBO_SUBMODE_BIT) != 0)
}
```

优先读 EC，因为 EC 是当前硬件真值。

### 4.4 设置子模式

建议放在 `system/power/ec_mode.rs` 或新文件 `system/power/turbo_submode.rs`：

```rust
pub fn set_turbo_submode_silent(silent: bool) -> Result<(), String> {
    if !is_turbo_submode_supported() {
        return Err("当前 BIOS/WMI 不支持狂暴子模式".into());
    }

    // 只能作用于狂暴档
    let cfg = crate::system::config::load_config();
    if cfg.power_mode != 3 {
        return Err("静音狂暴只能在狂暴模式下切换".into());
    }

    // 1. EC 1832 bit0
    let current = crate::driver::wmi_ec::wmi_read_ec(ADDR_TURBO_SUBMODE)
        .ok_or_else(|| "读取 EC 1832 失败".to_string())?;
    let next = if silent {
        current | TURBO_SUBMODE_BIT
    } else {
        current & !TURBO_SUBMODE_BIT
    };
    if !crate::driver::wmi_ec::wmi_write_ec(ADDR_TURBO_SUBMODE, next) {
        return Err("写 EC 1832 失败".into());
    }

    // 2. WMI BIOS RAM
    let cmd = if silent {
        CMD_TURBO_SUBMODE_SILENT
    } else {
        CMD_TURBO_SUBMODE_EXTREME
    };
    if !crate::driver::wmi_mulong::mulong_exec_raw(cmd) {
        return Err("WMI 写 BIOS RAM 子模式失败".into());
    }

    // 3. 回读
    let readback = crate::driver::wmi_ec::wmi_read_ec(ADDR_TURBO_SUBMODE)
        .map(|v| (v & TURBO_SUBMODE_BIT) != 0);
    if readback != Some(silent) {
        return Err(format!("子模式回读不一致: {:?}", readback));
    }

    // 4. 持久化
    let mut cfg = crate::system::config::load_config();
    cfg.turbo_silent = silent;
    crate::system::config::save_config(&cfg);

    crate::event::emit_global("turbo-submode-changed", serde_json::json!(silent));
    Ok(())
}
```

### 4.5 切狂暴档时自动恢复子模式

修改 `commands/power_cmd.rs::set_power_mode` 或 `system/power/ec_mode.rs`：

```text
mode == 3：
  先正常应用狂暴档
  再读取 cfg.turbo_silent
  如果硬件支持，调用 set_turbo_submode_silent(cfg.turbo_silent)
```

注意顺序：

```text
先切 OperatingMode=3
再写 1832 bit0
再写 WMI BIOS RAM
```

否则可能出现：

```text
子模式写了，但模式还没到狂暴
```

建议不要把子模式写进普通 `apply_full_power_mode` 最前面，而是放在狂暴档应用完成之后。

### 4.6 硬件状态

`commands/system_cmd.rs::HardwareState` 增加：

```rust
pub turbo_submode_supported: bool,
pub turbo_silent: bool,
```

填充：

```rust
turbo_submode_supported: crate::driver::wmi_ec::is_turbo_submode_supported(),
turbo_silent: crate::driver::wmi_ec::get_turbo_submode_silent().unwrap_or(false),
```

### 4.7 配置

`system/config.rs` 的 `AppConfig` 增加：

```rust
#[serde(default)]
pub turbo_silent: bool,
```

默认 `false`，即高能狂暴。

恢复策略：

```text
优先读 EC 1832 bit0 作为真值
读不到再用 cfg.turbo_silent
```

### 4.8 Tauri command

`commands/power_cmd.rs` 增加：

```rust
#[tauri::command]
pub fn set_turbo_submode(
    silent: bool,
    app: AppHandle,
    ec_state: State<'_, SharedEcBridge>,
) -> Result<(), String> {
    crate::system::power::turbo_submode::set_turbo_submode_silent(silent)?;
    let mut cfg = crate::system::config::load_config();
    cfg.turbo_silent = silent;
    crate::system::config::save_config(&cfg);
    let _ = app.emit("turbo-submode-changed", silent);
    Ok(())
}
```

注册到 `lib.rs` 的 `invoke_handler`。

## 5. 前端补丁点

### 5.1 类型

`src/types/hardware.ts`：

```ts
export interface HardwareState {
  // ...
  turbo_submode_supported?: boolean;
  turbo_silent?: boolean;
}

export interface HardwareCapabilities {
  // ...
  turbo_submode_supported?: boolean;
}
```

`PowerMode` 保持：

```ts
export type PowerMode = 1 | 2 | 3 | 4;
```

### 5.2 狂暴按钮旁开关

`src/components/drawer/DrawerPowerModeCard.tsx`：

```tsx
const turboSubmodeSupported =
  capabilities?.turbo_submode_supported === true;

const onToggleTurboSubmode = async () => {
  const next = !status.turbo_silent;
  await invoke('set_turbo_submode', { silent: next });
  setHardware((prev) => ({ ...prev, turbo_silent: next }));
};
```

UI 建议：

```text
狂暴按钮本身：切换 PowerMode 3
狂暴按钮下方/旁边：一个小 Toggle
  静音狂暴  [开/关]
```

只在：

```text
status.power_mode === 3
&& capability.turbo_submode_supported
```

显示。

也可以做成：

```text
狂暴按钮长按/右键 → 弹出“静音/高能”
```

但初次实现建议显式 Toggle，避免隐藏交互。

### 5.3 显示名称

`src/components/FullDashboard.tsx` / `OverviewView.tsx`：

```ts
const turboName = status.power_mode === 3
  ? (status.turbo_silent ? '静音狂暴' : '高能狂暴')
  : modeName;
```

不要改 `POWER_MODES` 数组，避免破坏索引。

### 5.4 插件 API

`src/plugins/plugin_manifest.tsx` 和插件 API：

```ts
power_modes?: string[];
```

可增加：

```ts
turbo_submode?: boolean;
```

但插件兼容性应保持：

```text
旧插件只认 office/balance/turbo/custom
新字段忽略即可
```

## 6. 模型清单

### 6.1 能力字段

`src-tauri/crates/openrevo-core/src/hal/declarative/model_manifest.rs`：

```rust
pub struct ModelCapabilities {
    // ...
    #[serde(default)]
    pub turbo_submode: bool,
}
```

50 系对应机型的 manifest：

```json
"capabilities": {
  "turbo_submode": true
}
```

### 6.2 不要只靠 manifest

manifest 只声明“可能有”：

```text
真实是否支持仍要 WMI 查询 0x55
```

否则 40 系/不同 BIOS 会误显示。

建议逻辑：

```text
manifest.capabilities.turbo_submode == true
且 is_turbo_submode_supported() == true
才显示
```

## 7. 状态机

```text
当前 PowerMode = 3
  ├─ 高能狂暴
  │    EC 1832 bit0 = 0
  │    WMI 0x5000000000A
  │    cfg.turbo_silent = false
  │
  └─ 静音狂暴
       EC 1832 bit0 = 1
       WMI 0x50000000009
       cfg.turbo_silent = true
```

切到其他模式：

```text
1/2/4
  → 不显示子模式 Toggle
  → 不清除 1832 bit0（原厂通常保留，下次进狂暴按 cfg/EC 恢复）
  → 下一次切回 3 时重新应用
```

建议切回 3 时：

```text
读取 cfg.turbo_silent
写 1832 bit0
写 WMI
```

而不是什么都不做。

## 8. 电池/供电限制

静音狂暴仍是狂暴档，必须沿用：

```text
非 thin & light
且非 DC 圆口
且 unlock_battery_power_limit == false
  → 不允许切到 3
```

也就是说：

```text
静音狂暴不能绕过狂暴档的供电限制
```

## 9. 验证清单

### 能力

```text
[ ] 50 系 BIOS 返回 0x55
[ ] 40 系返回非 0x55，UI 不显示
[ ] 无 WMI 时返回 false，不崩溃
```

### EC

```text
[ ] 静音：1832 bit0=1
[ ] 高能：1832 bit0=0
[ ] 回读一致
[ ] 重启后状态保持
```

### WMI

```text
[ ] 静音：GetSetULong 0x50000000009 成功
[ ] 高能：GetSetULong 0x5000000000A 成功
[ ] 失败时回滚 UI，不假装成功
```

### 模式切换

```text
[ ] 办公 → 狂暴（默认高能）
[ ] 狂暴 → 静音狂暴
[ ] 静音狂暴 → 高能狂暴
[ ] 狂暴 → 均衡 → 狂暴（子模式恢复）
[ ] 电池下切狂暴被拒绝
```

### UI

```text
[ ] 只有狂暴档显示 Toggle
[ ] 切到其他档 Toggle 隐藏
[ ] 状态与 EC 一致
[ ] 托盘/迷你窗不显示错误模式名
```

## 10. 不建议方案：新增 PowerMode 5

如果坚持新增：

```ts
export type PowerMode = 1 | 2 | 3 | 4 | 5;
```

需要改：

```text
HardwarePowerMode enum
AppConfig power_mode/power_mode_ac/power_mode_battery
PowerMode 数组/索引
狂暴/自定义限制逻辑
热键循环
托盘菜单
插件 API
所有 status.power_mode === 3 判断
```

而且原厂语义并不是独立模式，后续维护成本高。

结论：

```text
不推荐
```
