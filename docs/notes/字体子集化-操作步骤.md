# 字体子集化 · 操作步骤（路线 B：机主本机生成）

> **目标**：把两个原始 ttf（合计 **15.7 MB**）子集化为约 **4.99 MB**，安装包减小约 **10.7 MB**。
> **做法**：你（机主）在本机跑两条命令 + 一个验证脚本。**不编译、不打包、不装额外软件**（只装一个 Python 包）。
> **材料**：`installer-src\字体子集\` 目录。

---

## 0. 前置：装 fontTools（只需一次）

```powershell
py -3 -m pip install fonttools
```

- 只装 **fonttools**（纯 Python，无二进制依赖）。**不要**装 `brotli`/`zopfli`，本流程用不到。
- 验证：`py -3 -c "import fontTools; print(fontTools.version)"` 有版本号即可。
- ⚠️ 若公司网络装不动，可加国内镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple`

---

## 1. 备份两个原始 ttf（15.7 MB）

**别跳过这步** —— 这是唯一可靠的回滚手段。

```powershell
cd D:\openLM\installer-src\files\fonts
New-Item -ItemType Directory -Force -Path ..\..\字体子集\备份 | Out-Null
Copy-Item HarmonyOS_Sans_SC_Regular.ttf ..\..\字体子集\备份\ -Force
```

> 备份放在 `installer-src\字体子集\备份\`，**在 `files\` 之外，不会被打包**，也不会被压缩进安装包。

## 2. 跑两条 `pyftsubset` 命令

在 **`D:\openLM\installer-src\字体子集\`** 目录下执行（输出也落在这里，先不覆盖原件）：

```powershell
cd D:\openLM\installer-src\字体子集

py -3 -m fontTools.subset "..\files\fonts\HarmonyOS_Sans_SC_Regular.ttf" `
  --text-file="SUBSET-KEEP.txt" `
  --output-file="HarmonyOS_Sans_SC_Regular.subset.ttf" `
  --layout-features="*" `
  --glyph-names --symbol-cmap --legacy-cmap `
  --notdef-glyph --notdef-outline --recommended-glyphs `
  --name-IDs="*" --name-legacy --name-languages="*"

py -3 -m fontTools.subset "..\files\fonts\HarmonyOS_Sans_SC_Bold.ttf" `
  --text-file="SUBSET-KEEP.txt" `
  --output-file="HarmonyOS_Sans_SC_Bold.subset.ttf" `
  --layout-features="*" `
  --glyph-names --symbol-cmap --legacy-cmap `
  --notdef-glyph --notdef-outline --recommended-glyphs `
  --name-IDs="*" --name-legacy --name-languages="*"
```

跑完看大小：

```powershell
Get-ChildItem *.subset.ttf | Select-Object Name,Length
```

预期：单个约 **2.4–2.6 MB**，两个合计约 **4.99 MB**。

### 参数逐条说明

| 参数 | 是否必需 | 说明 |
| --- | --- | --- |
| `--text-file="SUBSET-KEEP.txt"` | **必需** | 保留集来源。文件是 **UTF-8 无 BOM**，含 9728 个码位。`pyftsubset` 按 UTF-8 解析。 |
| `--output-file=...` | **必需** | 输出路径。**注意用 `.subset.ttf` 后缀**，不要直接覆盖原件。 |
| `--layout-features="*"` | **必需** | 保留全部 OpenType 特性（`kern` 字距、`liga`、`vert` 等）。**GDI+ 依赖 `kern`/`GPOS` 做字距**；不保留会让中英混排变难看，且可能改变文本度量。子集化本身会裁掉用不到的 feature 内容，所以给 `*` 不吃亏。 |
| `--glyph-names` | **建议必需** | 保留 `post` 表的字形名。GDI+ 在 `PrivateFontCollection` 下做字体匹配/回退时会读字形名。**去掉有风险**，保留成本很小。 |
| `--symbol-cmap` | **必需** | 保留 `cmap` 的 **(3,0) 符号子表**。GDI+ 在部分场景只认符号 cmap；**去掉可能导致字体加载后取不到字**。 |
| `--legacy-cmap` | **必需** | 保留 `cmap` 的 **(1,0) Mac Roman 子表**。**老 API / GDI+ 会走这个表**，去掉是常见的"字体装了但显示方框"的坑。 |
| `--notdef-glyph` + `--notdef-outline` | **必需** | 保留 `.notdef` 字形及其轮廓。缺了它，缺字符时可能**整段文字不渲染或渲染出空白**。 |
| `--recommended-glyphs` | **必需** | 强制保留 `space` 等推荐字形。缺 `space` 会导致**空格宽度为 0**，排版全乱。 |
| `--name-IDs="*"` | **必需** | 保留 **`name` 表全部条目**。⚠️ **关键**：`UiVisualStyle.cs:87` 用 `f.Name.Contains("HarmonyOS Sans SC")` 找族名 —— 族名来自 `name` 表 **ID 1 / ID 16**。若无此参数，`pyftsubset` 默认只保留少量 name ID，**字体族名会丢**，程序就回退到 `Microsoft YaHei UI`，外观全变。 |
| `--name-legacy` | **必需** | 保留 `name` 表里的 **Unicode 平台 (3,1) 之外的老编码条目**（Mac (1,0) 等）。GDI+ 在枚举 `PrivateFontCollection.Families` 时**会读老编码的族名**。缺了可能枚举不到族名。 |
| `--name-languages="*"` | **必需** | 保留 `name` 表所有语言版本（含 `zh-CN` 条目）。缺了在中文系统上族名可能取到英文条目或被裁掉，影响匹配稳定性。 |

> ⚠️ **这三个 `name` 参数是本次任务的重点** —— 它们直接决定 `UiVisualStyle.cs:87` 能否找到 `HarmonyOS Sans SC`。

### 不用的参数（刻意不加）

| 参数 | 为什么不用 |
| --- | --- |
| `--drop-tables=...` | ⚠️ **不要加**。裁掉 `GSUB`/`GPOS`/`post`/`DSIG` 等"看起来没用"的表，很容易让 **GDI+ 加载失败或字重失效**。本方案靠**只删未被引用的字形**来减小体积，收益已经足够（15.7 → 4.99 MB）。**收益小、风险大，跳过。** |
| `--flavor=woff2` | 输出 WOFF2，**GDI+ 不认**。不用。 |
| `--desubroutinize` / `--no-hinting` | 这是 CFF/TrueType 提示相关。⚠️ **不确定**：`--no-hinting` 理论上能再小一点，但**可能改变小字号下的渲染观感**（GDI+ 部分走 hinting）。**建议保持默认（保留 hinting）**；如确要试，**先小范围试并肉眼对比小字号**。 |
| `--prune-unicode-ranges` | 会重算 `OS/2` 的 Unicode 范围位。**不确定**是否有益，**保持默认**。 |

### ⚠️ 我不确定的地方（明确标出）

1. **`--no-hinting` / `--desubroutinize` 的取舍**：不确定对 GDI+ 小字号渲染的影响。**建议先不加**。
2. **`--name-languages="*"` 是否真的必需**：从"最保险"角度建议加。若你想试更激进的做法，可以去掉后**跑验证脚本**，只要族名检查仍 `[OK]` 就说明没坏 —— 但**不省多少体积**，不划算。
3. **`--layout-features="*"` 是否只保留 `kern`/`liga` 更好**：不确定。给 `*` 更安全，体积差异可忽略。

## 3. 跑验证脚本（**必须 0 缺字**）

```powershell
cd D:\openLM
py -3 installer-src\字体子集\验证-子集缺字.py --regular installer-src\字体子集\HarmonyOS_Sans_SC_Regular.subset.ttf --bold installer-src\字体子集\HarmonyOS_Sans_SC_Bold.subset.ttf
```

脚本会自动**重新扫一遍 `source\` 的 374 个 `.cs` + 4 个 `.resx`**（自包含，不依赖任何历史结论），
抽出 UI 字符后与子集 ttf 的 `cmap` 求差集。

**期望输出**（关键三行）：

```
  UI 字符 = 1118 个（汉字 964 + 非汉字 154）
  覆盖 1118/1118 字符，缺 0 个
  [OK] 缺字 = 0
  [OK] 字重正确
  总判定：PASS ✅ 全部通过
```

**判定标准**：
- ✅ `缺 Z 个` 里 **Z 必须 = 0**；
- ✅ Regular 的 `usWeightClass` **必须 = 400**，Bold **必须 = 700**；
- ✅ 两个文件的族名都必须含 `HarmonyOS Sans SC`。

**任何一项 FAIL 就不要覆盖原件**，回到第 2 步调整参数重跑。

> 想顺便留一份 UI 字符清单：加 `--export-ui`，会写出 `installer-src\字体子集\UI-CHARS.txt`。

## 5. ⚠️ 真机验证（唯一能验 GDI+ 真加载的办法）

**子集化最容易翻车的地方不是"缺字"，而是"GDI+ 加载了但渲染不对"。** 验证脚本只能证明 `cmap` 有字，**证明不了 GDI+ 能正常出图**。所以必须**装一次 LM，肉眼过一遍界面**。

### 重点看的界面

1. **主界面** —— 所有卡片标题、选中态按钮（**Bold 用得多**）、数值读数片
2. **设置窗口** —— 文字最多，各种符号最密集
3. **风扇曲线** —— 坐标轴数字、`°C` 里的 `°`
4. **关于 / 致谢**
5. **首次引导**（新装机才有，可能要先卸干净）
6. **捐赠窗**
7. **反馈窗**
8. **校色窗**
9. **托盘菜单** —— `SettingsForm.cs:9889` 注释说托盘菜单继承 UI 字体族，**特别注意**

### 要留意的符号（逐个确认不是方框 / 不是别的字体）

```
✅ ✓ ✗ ❌ ⚠ ⛔ ❤ ⭐ ① ② ③ ④ ⑤ ▲ ▸ ▼ ▾ ● ★
← → ↔ ⇒      （箭头）
─ │          （制表线）
、 。 「 」 『 』 【 】   （中文标点）
— – “ ” …    （通用标点）
° · × ！ （ ） ， ： ； ＝ ？ ［ ］ ／  （全角/单位）
```

### 特别要盯的

- **English / 数字**：全角半角混排、等宽对齐有没有变。
- **选中按钮的 Bold**：如果 Bold 丢了，选中态会变成"和普通一样粗"，看起来像没选中。
- **中文换行位置**：字宽若有变化，换行点会移动，可能出现截断。

## 7. ⚠️ 风险与边界

1. **生僻字会落系统字体（已接受）**
   保留集外的汉字不在子集里，GDI+ 会走字体回退链（`Microsoft YaHei UI` 等）出图。
   - **不会显示成方框**（回退链能兜住）；
   - **但字宽可能跳变** —— 该字由系统字体渲染，度量与 HarmonyOS 不同，可能出现**一个字宽窄不一**、换行点轻微移动。
   - 影响面：仅限 GB2312 一二级（6763 字）之外的**生僻字**。本轮实测**界面文案 964 个汉字 100% 在 GB2312 内**，所以**正常情况下看不到这种字**。

2. **英文版 Windows 不受影响**
   拉丁字母、数字、ASCII 标点全在保留集内。回退族 `Microsoft YaHei UI` 在英文版 Windows 上同样存在（`UiVisualStyle.cs:97`）。

3. **子集字体只给 LM 内嵌用**
   `UiVisualStyle.cs` 用 `PrivateFontCollection.AddFontFile` 加载，**不装进系统字体目录**，所以**不会影响系统其他程序的字体**，也不会因子集化干扰用户已装的 HarmonyOS 字体。

4. **`FontStyle.Bold` 依赖 Bold 文件**
   `UiVisualStyle.cs:78` 同时加载 Regular 与 Bold 两个文件，GDI+ 按 `OS/2.usWeightClass`（400/700）配对。
   若 Bold 的 `usWeightClass` 被子集化改坏，**`FontStyle.Bold` 会失效**（界面大量用 Bold）。
   第 3 步脚本会**显式校验 700**，这是必过项。

5. **尚未验证的部分**
   ⚠️ 本轮**没有**实际生成子集字体，也**没有**在真机上装过。
   `pyftsubset` 的参数语义是基于 fontTools 文档 + GDI+ 已知行为推断的，
   **必须靠第 5 步真机验证兜底**。
