# 无界（WUJIE14XA）电池充电电压修复 · 实测存档（2026-10-21）

## 结论（实测可用）

- 无界 14XA 电池为 4S LiHV（设计 17,600mV = 4.4V/节）；EC（ITE IT5571）内部「辅助老化降额」异常触发 `17,600 − 4×250 = 16,600mV`，主机按 16.6V 报 100%，实际只到 ~4.08V/节。
- 修复方式：覆盖 EC 的 `desired/queued voltage` 与充电电流、解除最终停充门，使目标回到 17,600mV / 2,816mA。
- **2026-10-21 实测：LM 内置版（inpoutx64 P/Invoke）可用，不需要 Python / JG_BAT 脚本。**

## 内置实现（LM 0.293.4 beta23.4 起）

- 类：`source/MechrevoLite.Hardware/I2ecInpOut.cs`；
- 通道：I2EC 端口 `0x681`（地址高）/ `0x682`（地址低）/ `0x683`（数据），经本机已安装的 **inpoutx64** 驱动（`Inp32/Out32` P/Invoke）；
- 寄存器（与参考 JG_BAT/batteryctl 同口径）：
  - `0x200D` I2EC 模式位（bit0/1 需为 1）；
  - `0x0454` EC 身份（比较时忽略 bit1，降额态会变 0x8E）；
  - `0x030E` 基础目标电压（必须 =17600 才允许覆盖）；
  - `0x0522` desired 电压 / `0x0836` queued 电压 → 写 17600；
  - `0x0520` desired 电流 / `0x0834` queued 电流 → 写 2816；
  - `0x083A` queued input 电流：仅当原值为 2304（原装 100W 适配器）时映射为 2816；
  - `0x0574` 最终停充门 → 写 0；
  - 只读：`0x0491` cells（0xC0=4S）、`0x04AB` SOC、`0x0438` pack 电压、`0x050A` 电池电流。
- 行为：校验 4S + base=17600 后启动后台循环（每 2s 保持上述值）；启动时记录原值，关闭开关 / 退出 LM / 进程退出时恢复原值。
- 回退：inpoutx64 不可用时回退外部 JG_BAT + Python（`batteryctl.py hold-full`）。
- 入口：电池页「电池充电电压修复（无界）」开关（仅 `WujieSmuApu` 机型可见）。

## 与 PawnIO 的关系

- PawnIO `LpcIO` 模块拒绝 `0x681` 端口写（Win32=21），`LpcACPIEC` 只放行 `0x62/0x66` ⇒ 现有签名模块无法覆盖 I2EC。
- 因此内置实现只使用机器上**已安装的 inpoutx64**，LM 不打包、不分发该驱动/DLL。

## 依赖与法律风险（重要）

- `inpoutx64` 为 Highresolution Enterprises 第三方驱动：个人/非商业免费，商业分发需授权，不允许随意再分发。
- 早期分发包里的 `inpoutx64.dll`（101.9KB，v1.4.0.0）取自 GCU 1020 payload（`UniwillService\MyControlCenter\inpoutx64.dll`），**公开分发有版权风险**；`inpoutx64.sys` 未随包提供，需目标机器自行安装。
- 结论：公开产物不打包 dll/sys，只做「检测本机已有驱动 + 缺失时给安装指引」。
- 另有硬件责任风险：覆盖 OEM 老化降额属越过厂商保护策略，电池寿命/安全由使用者自担；功能默认关闭、带风险提示、可随时恢复。

## 2026-10-22 收尾：暂时屏蔽（决定）

### 为什么屏蔽

- 真机表现为：修复开启后，AIDA64 电池电流**一会有一会没有**（+1.2A ↔ -1.3A 交替，pack 16.2V → 15.3V），无法稳定把 16.6V 目标维持在 17.6V 充电。
- 排查结论：
  1. 字节序修正后（`0x030E` 大端、desired/queued/current 小端），写入不再造成 49.2V 过压/黑屏；
  2. 但旧实现每 **2 秒**才重写一次，EC 在间隔内回写/中断充电；参考脚本 `batteryctl.py` 是 **每 2ms** 重写一遍（`time.sleep(0.002)`）；
  3. 改成 2ms 后仍偶发电流断续；同时 500Hz 会与无界风扇曲线 25Hz 抢 I2EC（已加让路 + 锁轮询 1ms，但稳定性仍未完成真机验收）；
  4. 输入限流原值 2176mA（非 2304）时脚本不覆盖，系统负载高时电池会被抽电，也可能被误判为“修复没效果”；
  5. 高 SOC（85%~88%）强制 2816mA + 每轮清停充门，可能与 EC taper/保护打架。
- 机主决定：**先存档、暂时屏蔽该实验性功能**，不再让用户误以为“开了就能修好”。

### 屏蔽方式（代码）

- `BatteryVoltageFix.FeatureEnabled = false`（`source/MechrevoLite.Hardware/BatteryVoltageFix.cs`）：
  - 设置页 / 电池页开关**不显示**（`IsUiVisible` / `IsWujieBatteryFixSupported`）；
  - 开机 `RunOnStartupIfEnabled`：停掉可能残留的覆盖、清掉旧启用态，不再启动；
  - `Run("hold-full")` 直接返回“已暂时屏蔽”，不写任何 EC 寄存器；
  - `Run("status")` 与诊断包只读状态段保留，方便后续排查。
- 旧的 SYSTEM 计划任务若仍在，需管理员删除：
  ```bat
  schtasks /Delete /TN JG_BatteryOverride /F
  ```

### 已确认的 EC 事实（供后续重启项目）

- 4S LiHV，基础目标 `0x030E = 17600mV`（4×4.4V），实际 desired/queued 被降额到 **16600mV**（4×4.15V，正好 4×250mV），不是 60%/80% 限充：`0x7B9=0x00`、`BatteryProtection=0`、电池在 87% 仍显示充电。
- 参考脚本的电流：desired/queued 固定 **2816mA**；输入限流只在原值 2304 时映射 2816，其它值不覆盖；实测 3200mA 间歇保护、3584/4096/4992 更差。
- 写序：`0x200D` 模式位 → 校验 4S + base 17600 → 记录原值（version=3）→ 2ms 循环写 `0x0522/0x0836/0x0520/0x0834/0x0574` → 停止时恢复原值。
- 若将来重启项目，最低验收标准：
  1. 连续 10 分钟 AIDA64/诊断波形无正负交替；
  2. 与风扇曲线同时运行，风扇 25Hz 不掉写；
  3. 充满到 100% 后不高 SOC 抖动，且断电/重启能恢复原值；
  4. 不依赖外部 `batteryctl.py`，不与其他 I2EC 工具并发。

## 2026-10-23 更新：恢复启用（默认关 + 限充互斥）

- 机主真机确认可用：电池显示 `17.358V / 91% / 充电率 49574mW（约 50W）`，磨损 0%，设计 79171mWh / 最大 80080mWh；说明 2ms 保持节奏 + 17.6V 目标已稳定进入约 50W 充电。
- 代码状态：
  - `BatteryVoltageFix.FeatureEnabled = true`，UI 重新显示「无界电池电压修复(实验性)」；
  - **默认关**：`battery_voltage_fix` 缺省 0；升级后通过一次性键 `battery_voltage_fix_default_off_reset` 清掉旧测试启用态；
  - **限充互斥**：只有「不限充/长效模式」才允许开启/保持：
    - `BatteryControl.LockEnabled()`（EC 限充开关）必须为关；
    - `charge_limit_slider` 若启用，`charge_limit` 必须 =100；
    - `BatteryControl.ResolveDisplayLimitPercent()` 必须为 100（或 -1 未设置）；
    - `Program.hw.BatteryProtection` 必须为 0（GCU 长效模式；80/60 = 平衡/工作站均拒绝）；
  - 启用时冲突 ⇒ 拒绝并回弹开关；运行中被改成非 100% ⇒ 1 秒内检测到，停止覆盖并恢复 EC 原值。
- 仍保留：2ms 重写、固定 2816mA、输入限流仅 2304→2816、60s 复查、风扇让路（每 8 轮 +2ms、锁轮询 1ms）、诊断波形/状态段。
- 注意：诊断包里的 `[无界电池电压修复状态]` 仍只读；关闭开关/退出会恢复原值（version=3 原值文件）。
