# NUC / UMI 性能键接管计划

日期：2026-10-28
范围：Intel NUC X15（LAPKC71F 一类）与 UMI 30 系同模具机型
方案：方案 1，LM 监听性能键事件并接管三档切换；不新增厂商后端

## 1. 目标

实现和原厂控制台一致的三档键控体验：

```text
按一次性能键
  → LM 收到事件
  → 切换静音 / 平衡 / 狂暴
  → LM 显示对应状态
  → 按厂商习惯更新键盘指示灯
    全灭 / 亮 1 个 / 全亮
```

约束：

- 不新增独立的 UniwillService / WCF 厂商后端
- 不接管 NUC 控制台的整套风扇、灯光、电池功能
- 不改现有 Keyboard/Ctrl 单键 RGB 下发链
- 不碰已确认正常的键盘灯、灯带、水冷通道
- 只在 NUC / UMI 机型启用，不影响 40/50 系与宝龙达

## 2. 现状

### LM 当前模式路径

```text
WPF 模式按钮
  → DashboardCommands.SetPerformanceModeResultAsync
  → MechrevoService.SwitchMode
  → GCU Fan/Control
     OPERATING_OFFICE_MODE / OPERATING_GAMING_MODE / OPERATING_TURBO_MODE
     + ProfileIndex
  → LCHWOC/Control
     IsNormalRun 0/1/2
```

### NUC 原厂性能键路径

```text
EC/WMI OSD 事件
  → UniwillService.UWOSD
  → UWPerformance.SwitchNextProfileIndex()
  → ProfileIndex
     Performance / Balanced / BatterySaver
  → OsdType.PerformanceMode
  → 键盘指示灯变化
```

关键差异：

```text
LM 的档位：静音 / 平衡 / 狂暴
原厂按键档位：Performance / Balanced / BatterySaver
```

需要映射，不能直接把 `ProfileIndex` 数值当 LM 视觉档。

## 3. 总体架构

```text
IPerformanceKeySource
  ├─ WmiPerformanceKeySource
  │    ManagementEventWatcher
  │    监听 EC OSD 事件
  │
  └─ AcpiPerformanceKeySource（备用）
       ACPIDriver 读取/订阅事件寄存器

        ↓ 统一事件
PerformanceKeyRouter
  ├─ 防抖 / 去重
  ├─ osd_code → 按键类型
  ├─ 三档循环状态机
  ├─ 调用现有 MechrevoService.SwitchMode
  └─ 通知 UI / OSD / 指示灯

        ↓
PerformanceKeyPresenter
  ├─ LM OSD 显示三档
  └─ 键盘指示灯 0 / 1 / 全亮
```

新增代码只在 Core/WPF 内，不新增厂商服务，不依赖 WCF。

## 4. 事件源探测（先只读）

### 4.1 WMI

原厂控制台使用 `System.Management` 的 `ManagementEventWatcher` 监听 EC OSD 事件。

需要确认：

```text
WMI Namespace
WQL 查询语句
事件属性名（如 osd_code）
性能键对应的 osd_code
```

探测步骤：

1. 枚举常见厂商 WMI 命名空间
2. 建立只读 EventWatcher
3. 按键，记录事件原文
4. 重复按三次，确认三个 code 与档位/灯效的对应关系

### 4.2 ACPI 备用

如果 WMI 事件不可用：

```text
\\.\ACPIDriver
读取 OSD/EC 事件寄存器
```

原厂服务内部存在：

```text
ACPICtrl.Read(1870, ...)
```

可先作为只读探针，确认按键时该寄存器是否变化，再决定是否轮询。

### 4.3 验收

M0 只做探测，不写任何模式：

```text
按一次键 → 抓到事件 → 记录 code
连续三次 → 记录三个 code
同时记录键盘 LED：全灭 / 1 个 / 全亮
```

## 5. 三档映射

### 5.1 默认候选

```text
全灭   → 静音 / BatterySaver
亮 1 个 → 平衡 / Balanced
全亮   → 狂暴 / Performance
```

这只是候选，必须用 M0 抓到的原厂行为确认后再定稿。

### 5.2 LM 侧状态

统一使用：

```text
ModeProfileConfig 的 visual + profileIndex
```

不直接依赖 `PerfModeService` 的固件槽路由。

切档动作统一走：

```text
MechrevoService.SwitchMode(visual)
```

保持现有 GCU 执行链不变。

### 5.3 状态循环

```text
当前档位 → 下一档
静音 → 平衡 → 狂暴 → 静音
```

或者按原厂实测顺序；顺序必须由 M0 确认，不能猜。

## 6. 键盘指示灯

原厂用键盘 LED 数量表示档位：

```text
全灭
亮 1 个
全亮
```

LM 实现原则：

1. 只使用现有键盘灯通道
   - GCU 单键/单分区通道
   - 现有 HID 键盘通道
2. 不改造 `Keyboard/Ctrl` 单键 RGB 主链
3. 指示灯逻辑做成独立可选层，失败不影响模式切换
4. 白色背光键盘不适用“亮 1 个”，降级为开关/亮度提示

### 6.1 实现顺序

```text
P1：只做 OSD 状态显示，不碰键盘灯
P2：验证单键 RGB 能否只点亮指定键
P3：接入全灭 / 1 个 / 全亮
```

如果 P2 发现会干扰现有单键 RGB 行为，则停止 LED 指示，只保留 OSD。

## 7. 冲突处理

这是必须解决的问题。

### 7.1 原厂服务也在监听

如果安装了 NUC Software Studio / UniwillService：

```text
LM 和原厂服务可能同时收到同一个 EC OSD 事件
```

结果：

```text
两边都切档
LM 切完原厂又切回去
键盘灯被两边同时改
```

### 7.2 处理策略

优先级：

1. **检测原厂服务是否运行**
2. 如果运行：
   - 默认让原厂按键继续工作，LM 只读状态并显示
   - 或明确提示用户关闭原厂性能键接管
3. 如果未运行：
   - LM 接管事件和档位

不允许：

```text
LM 和原厂服务同时写性能模式
```

### 7.3 LM 内部冲突

需要关闭/绕过：

```text
PerfModeService 对 30 系内置档的固件槽重放
```

否则 LM 按键切档后又被启动重放改写。

## 8. 生命周期

```text
后端连接成功
  → 检测机型 NUC/UMI
  → 检测原厂服务
  → 订阅性能键事件
  → 同步当前档位
  → 启动 OSD

退出 / 断开
  → 取消订阅
  → 释放 WMI watcher / ACPI 句柄
```

睡眠恢复：

```text
恢复后重新订阅
重新读取当前档位
不重放旧档位覆盖用户按键结果
```

## 9. 失败与回退

| 情况 | 行为 |
|---|---|
| WMI 事件不可用 | 尝试 ACPI 备用源 |
| 两个事件源都不可用 | 隐藏按键接管，保留 UI 三档 |
| 原厂服务运行 | 不抢事件，只显示状态 |
| 键盘灯指示失败 | 只显示 OSD，不影响切档 |
| 切档失败 | OSD 提示失败，保留当前档 |
| 快速连按 | 300~500ms 防抖，只处理最后一次 |

## 11. 分阶段计划

### M0：事件探测（只读）

- 确认 WMI/ACPI 事件源
- 抓三个 osd_code
- 记录原厂按键后的档位与 LED 行为
- 输出探测报告

验收：不改任何档位，只拿到可复现的按键事件。

### M1：接管切档

- `PerformanceKeyRouter`
- 三档映射与防抖
- 直接调用 `MechrevoService.SwitchMode`
- LM OSD 显示三档

验收：按键可以稳定切三档，日志能说明每次动作。

### M2：状态回读

- 启动/恢复时同步当前档位
- 避免 `PerfModeService` 固件槽重放覆盖
- 原厂服务运行时的只读模式

验收：重启、睡眠恢复后状态不跳。

### M3：键盘指示灯

- 全灭 / 1 个 / 全亮
- 单键 RGB 兼容验证
- 白色背光键盘降级

验收：按键后指示灯与档位一致，且不影响现有键盘灯功能。

### M4：UMI 兼容

- 同模具复用
- 差异点单独探测
- UMI 原厂控制台存在时按冲突策略处理

验收：NUC 与 UMI 行为一致，且不影响其它机型。
