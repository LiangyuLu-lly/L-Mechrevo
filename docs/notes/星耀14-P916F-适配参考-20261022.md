# 星耀 14（P916F-STX）适配参考整理（2026-10-22）

- 参考来源：<https://github.com/YMGPwcca/Mechrevo-Xingyao-14>（文档型技术参考，CC BY 4.0；仅整理要点，未复制其内容）
- 适用基线：**P916F-STX / BIOS 1.15 / EC 1.15 / ITE IT5571 / AMD Ryzen AI 9 365（Strix Point）**
- 说明：该仓库是**文档**，不含驱动/工具；其中很多结论有证据分级（live-confirmed / static / inference）。本文只采纳与 LM 适配相关的部分，并标注未验证边界。

## 1. 与我们现有平台的差异（先认清）

| 维度 | 星耀 14（P916F-STX） | LM 现有 |
|---|---|---|
| EC | **ITE IT5571**（rev 0x07） | 无界：ACPIDriver EC H2RAM；宝龙达：MIFS/EC；GCU 机型：GCU MQTT |
| 充电限充 | **ITE PMC2 I/O 0x68/0x6C 的命令族** | GCU `BatteryProtection` / EC 直写 |
| 性能模式/风扇 | **ACPI WMI `WMAA`（PNP0C14 / _UID=HWMI）** + EC 字段 | GCU MQTT / EC 补位 |
| 键盘背光 | EC 字段 `KBBL`(0x33)/`KBST`(0x35)，WMI `GKBT/SKBT` | GCU Keyboard/Ctrl 或 EC 直写 |
| 不能套用的东西 | — | ⛔ 不能拿 Uniwill/Tongfang 的 `0x07B9/0x07D0`、GCU MQTT、现有 EC 地址表硬套 |

⚠️ 该仓库明确写了：**不要因为 EC 家族相似就把通用 Uniwill/Tongfang 偏移搬到这台机器**；P916F 的充电控制是独立的 PMC2 命令子系统。

## 2. 充电限充（最有价值、可直接落地）

### 2.1 主机接口

```text
PMC2 DATA           = I/O 0x68
PMC2 COMMAND/STATUS = I/O 0x6C
status bit0 OBF = 输出缓冲满（EC 有回包）
status bit1 IBF = 输入缓冲满（主机需等待）
```

读命令流程：等 IBF=0 → 写命令字节到 0x6C → 等 IBF=0 → 写数据/子命令字节到 0x68 → 等 OBF=1 → 读 0x68。

### 2.2 命令族（live 已验证的 5 条 + 1 条 static）

| 操作 | 写 0x6C | 写 0x68 | 验证状态 |
|---|---:|---:|---|
| 使能限充 | `0xF1` | `0x11` | live-confirmed |
| 读状态/使能位 | `0xF1` | `0x12` | live-confirmed |
| 读 T1 | `0xF1` | `0x13` | live-confirmed |
| 读 T2 | `0xF1` | `0x14` | live-confirmed |
| 写 T1 | `0xF2` | 0..100（0x00..0x64） | live-confirmed（80/85） |
| 写 T2 | `0xF3` | 0..100 | live-confirmed（100/90） |
| 关闭/复位 | `0xF1` | `0x10` | **static only（未 live 验证）** |

### 2.3 语义（关键，和“80% 上限”不一样）

```text
关闭限充 -> 平台默认充电策略
开启限充:
  SOC <  T1        -> 允许充电
  T1 <= SOC <= T2  -> HOLD（Not charging，电量保持）
  SOC >  T2        -> 电池主动放电（AC 仍在线，实测数 W 级）
```

- **T1 = 下限（充/停边界）**，**T2 = 上限（主动放电触发）**；
- 旧配置 `T1=80, T2=100` 看起来像“80% 上限”，是因为 `SOC>100` 不可达；
- 实测 `85/90` 三区都验证过；T1==T2、T1>T2 未验证，不可作为推荐配置；
- 持久化：正常重启保留；Linux→Windows 切换保留；**电池耗尽掉电后回到 0/0/0**；
- 因此 LM 启动时应读取状态，必要时做幂等恢复（set T1 → set T2 → 校验 → enable → 再校验），且状态已匹配时避免重复写。

### 2.4 对 LM 的适配建议

- 新增独立后端（如 `XingyaoPmc2Backend`），**不要**并进 GCU/宝龙达通道；
- UI 需要表达双阈值：建议预设「健康(T1=85,T2=100) / 平衡(T1=85,T2=90，含主动放电) / 自定义 T1/T2」——⚠️ 主动放电（T2 生效）可能在电池健康上不友好，默认给 T2=100 的“纯上限”语义；
- 驱动通道：Windows 下访问 I/O 0x68/0x6C 需要端口权限。LM 现有可用方案（ACPIDriver/PawnIO/inpoutx64）要单独评估：inpoutx64 有分发许可问题，**不能随 LM 分发**；需要确认 PawnIO 或自有驱动能否申请 I/O 端口访问；
- 风险控制：先做**只读 getter**（F1 12/13/14）实机确认，再谈写入；每次写后必须回读确认。

## 3. 性能模式 / 风扇（先只读）

### 3.1 WMI 设备

```text
ACPI 设备: WMI1，_HID=PNP0C14，_UID="HWMI"
方法 event GUID（_WDG 记录）:
  ABBC0F5B-8EA1-11D1-A000-C90629100000
  ABBC0F5C-8EA1-11D1-A000-C90629100000
BMOF GUID: 05901221-D566-11D1-B2F0-00A0C9062910
```

`WMAA` 是 3 参数 Serialized 方法，请求缓冲 byte0=MFID、byte1=SFID，返回 **两元素 package**（4 字节 buffer + 256 字节 buffer）；结果缓冲 byte0 是状态（0=成功）。

### 3.2 可用 dispatch（节选）

| MFID/SFID | 目标 | 说明 |
|---|---|---|
| 0x02/0x01 | GFNS | 风扇转速 raw word（selector 0/1 → FNS0/FNS1） |
| 0x03/0x09 | GPFM | 读当前性能档 `FTVL` |
| 0x03/0x0A | SPFM | 请求性能档（1/2 → THMM + ECMD 0x94/0x95，九月源） |
| 0x03/0x01..0x08 | GWLS/SWLS/GFLS/SFLS/GCLS/SCLS/GTPS/STPS | Win 键锁/Fn 锁/Copilot 锁/触控板 等状态位 |
| 0x03/0x0B..0x0C | GKBT/SKBT | 键盘背光状态字 `KBST` 读写 |
| 0x01/0x01 | GVER | 接口版本（0x00020004） |

事件：`_Q16` FTVL=1/2 → `0x41/0x42`（Balance/Performance）；`_Q11` KBBL=0/1/2 → `0x20/0x21/0x22`；`_Q17` KBFN → `0x50/0x51`。

### 3.3 EC 字段（H2RAM 窗口）

H2RAM：host physical `0xFEEC2300..0xFEEC23FF` ↔ EC XRAM `0x0300..0x03FF`，对应字段：

| 字段 | 窗口偏移 | 说明 |
|---|---:|---|
| FNS0/FNS1 | 0x3B/0x3D | 风扇转速 raw（16-bit，未证明单位=RPM） |
| FTVL | 0x3F | 当前性能档 |
| KBBL | 0x33 | 键盘背光档位（0/1/2 有事件） |
| KBST | 0x35 | 键盘状态字（GKBT/SKBT） |
| KBFN/TPST | 0x32 bits | Fn 锁/触控板 |
| WINS/CPLS | 0x34 bits | Win 键锁 / Copilot 锁 |
| ACIN/ACLW/LIDS | 0x30/0x31 bits | AC/lid 状态 |

### 3.4 对 LM 的适配建议

- **先只读**：GFNS（风扇 raw）、GPFM（当前档位）、GVER、GKBT；
- ⚠️ **SPFM/THMM 写入未被 live 验证**，且 SPFM 先调 THMM 再分支 ⇒ 失败状态不能证明没有副作用；不要直接做“性能模式切换”下发；
- 风扇 raw 不是 RPM，不要在 UI 当转速/温度阈值用；
- EC 字段读取建议走 ACPI EC（0x62/0x66）而不是直接 MMIO 写。

---

### 3.5 风扇控制：现实结论（2026-10-22 记录）

- **参考仓库没有可直接用的风扇控制**：只有 `GFNS`（风扇 raw word，未标定 RPM）和 `GPFM`（当前性能档 `FTVL`）可读；
- `SPFM`（请求性能档）**未 live 验证**，且先调 THMM 再发 EC 0x94/0x95，失败状态不能证明无副作用 ⇒ ⛔ 不做写入；
- **手动 PWM / 风扇曲线 / 目标 RPM 表均未恢复**，参考明确写了「没有建立直接 PWM 或风扇标志写流程」；
- EC 侧 `FNS0/FNS1/FTVL` 位于 H2RAM 系统内存窗口（host `0xFEEC2300`），读它需要内存映射驱动，不是 ACPI EC 0x62/0x66 能读的；
- **LM 现有风扇控制走 GCU**（风扇表/Fan Control/自定义曲线），WJXY（星耀）载荷已有「固件回读曲线不可靠」的既有处理 ⇒ 星耀风扇优先用 GCU 路径，前提是 GCU 上报风扇能力；
- 若要做星耀风扇**只读**遥测：只能走 WMI `WMAA` 的 `GFNS/GPFM`（用户态可用，不需要内核驱动），需先实现 WMAA 调用与运行时类/方法确认；**写入不做**。

## 4. 键盘背光

- 读取：`GKBT` → `KBST`（16-bit）；EC 字段 `KBBL`(0x33) 反映 0/1/2 档并有 `_Q11` 事件；
- 写入：`SKBT` 写 `KBST`（仓库只验证了字段/layout，**没有验证用户体验/范围**）；
- 对 LM：星耀键盘背光可以和现有 GCU/EC 键盘灯逻辑并列成第三套后端；先只读 `KBBL/KBST` 用于诊断/UI 初始值，写入仍需实机确认。

## 5. 电池阈值相关旁证（避免踩坑）

- 官方 Control Center 的 BatteryProtection 前端 ID：`HighCapacity=0 / Balanced=1 / Healthy=2` —— **是档位 ID，不是百分比**，不能直接当 80% 映射；
- 该 GX 包是多机型包，**不能证明**里面的 GCU 服务适用于星耀；星耀验证过的充电路径是 PMC2；
- `_BTP`（BTPL/BTPH）只是 ACPI 电池 trip-point 通知，不是限充；
- 通用 sysfs `charge_control_*` 在这台机器上不存在；Huawei WMI 阈值 GET `0x1103` 返回失败，不要尝试其 SET。

## 6. 建议的接入顺序（LM）

1. **平台识别**：按声明式架构新增 `P916F-STX` 规则（Board/BIOS/EC 证据），单独后端；
2. **只读探测**（低风险）：PMC2 `F1 12/13/14`、WMI `GVER/GPFM/GFNS/GKBT`、EC `KBBL/KBST/FTVL/FNS0/FNS1` → 进诊断包；
3. **充电限充**（中风险）：只读确认后，再按 owner 批准做 set/enable（含持久化与掉电后恢复）；
4. **键盘背光**（中风险）：只读先用，写入等实机验证；
5. **性能模式/风扇控制**（高风险）：SPFM/THMM 未验证，暂只展示 GPFM/GFNS，不做写入；
6. 驱动通道评估：PMC2 需要 I/O 端口访问，先确认 PawnIO/ACPIDriver 能力，inpoutx64 不可分发。

---

## 7. 边界与安全（摘自参考仓库，适用于我们）

- 不要往 `0xFEEC2300` H2RAM 写未知值；
- 不要暴力枚举 PMC2 命令；
- 不要把通用 Uniwill/Tongfang 偏移套到 P916F；
- 不要把 getter 成功当成 setter 已被验证；
- 不要把 BQ25700A/BQ25710 的寄存器兼容性当成充电器型号结论；
- T1/T2 任意组合、T1==T2、T1>T2 都未验证，不要作为默认策略。
