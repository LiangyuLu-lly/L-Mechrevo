## 2. 关键机制（已确认的代码事实）

### 2.1 EC `0x7C7`(1991) bit1 = 水冷已连接

`LiquidCooling.SetECSupport(bool)` 读-改-写这一位：连接置 1、断开清 0。

### 2.2 WMI 通知 `WMILC_Condition(bool)`

通过 `root\WMI` → `AcpiTest_MULong`（实例 `ACPI\PNP0C14\1_1`）`GetSetULong` 通知固件；脚本里读 `Data=(0x0100<<32)|0xD6BF` 返回 0（待确认写常量）。

### 2.3 连接后的 HWOC 流程（`LiquidHWOC.SetEnableFlow()`）

1. `FanTable.SetFanTable("IsLCConnect")`——切水冷风扇表；
2. `SetCustomModetoEC(true)`——EC 自定义模式位置位；
3. `SetHWOCSetCoreMem(coreOffset, memOffset)`——GPU 核心/显存偏移；
4. 配置项：`HWOCEnable / NormalRun / CustomRun`。

### 2.4 能力判定

`IsSupportLiquidCoolingHWOC()` / `IsSupportLC_HWOC_ADL()` 读 EC（非 0xFF 才支持）；`IsSupportLCFanTable()` 读 bit5。

## 3. 本机实测（GM5HG0A / 4060 / 50 GCU）

| 动作 | 结果 |
|---|---|
| 只读 `0x7C7` | `0x0C`（bit1=0，未接水冷） |
| 邻近快照 | `0x7C3=0x07 0x7C4=0x38 0x7C5=0x60 0x7C6=0x04 0x7C7=0x0C 0x7C8=0x40 0x7CA=0x01 0x7CC=0x01` |
| 写 bit1=1 | 回读 `0x0E`，固件随后自动改 `0x16`（bit1 保持 1） |
| 写后（空闲 20s） | `enforced=140W` 不变、功耗 8~9W、温度 44~45℃ ⇒ 没有负载看不出上限变化 |
| `-Restore` | 写回 `0x0C`，回读一致 ✅ |
| WMI `mailbox[0xD6BF]` | 读 0 |

## 5. 完整流程模拟：能做到哪一步

| 步骤 | 可行性 |
|---|---|
| ① EC `0x7C7` bit1=1 | ✅ 已实测 |
| ② `WMILC_Condition(true)` | ⚠️ 可调但写常量待确认 |
| ③ 切水冷风扇表 `IsLCConnect` | ✅ 可通过 GCU `UserFanTables` 指定/放入该表 |
| ④ `SetCustomModetoEC(true)`（EC 自定义位） | ⚠️ EC 地址待从 GCU 常量确认 |
| ⑤ `SetHWOCSetCoreMem` 核心/显存偏移 | ✅ LM 已有 GCU 自定义档偏移通道 |
| 官方 BLE 水冷机握手 | ❌ 需逆向 BLE 协议 + 硬件造假（ESP32 假外设），工作量大、成功率不保证 |

## 6. 风险

- 无真实水冷时放开 HWOC/偏移 = 直接过热；负载测试必须盯温度；
- 切 LC 风扇表可能让风扇策略异常（LC 表是给水冷泵/风扇的）；
- ④ 的 EC 位写错可能影响性能模式判定；
- `0x7C7` 易失，重启/断电自动回原值（脚本仍保留 `-Restore`）。
