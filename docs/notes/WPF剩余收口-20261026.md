## 1. 灯光滑杆防抖（核对结论：已有覆盖，另补 1 处安全收口）

**核对**：宽屏灯光卡早就使用 **150 ms 合并计时器** `lightApplyTimer`：

| 连续输入 | 行为 | 位置（本次提交后行号） |
|---|---|---|
| 亮度滑杆 `ValueChanged` | `Stop(); Start();`（合并拖动，只发最后值） | `MainWindow.xaml.cs:2263-2270`（speed）、`:2276-2282`（brightness） |
| 速度滑杆 `ValueChanged` | 同上 | 同上 |
| 程序化回填 `updateEffectUi` | `lightUiSyncing` 门控，不触发下发 | `updateEffectUi` 内 |
| 离散控件（效果按钮/电源/颜色/预设/七色混色/呼吸色） | 直接 `ApplyLightCardAsync`（点一次=一次下发，不需要合并） | :2070/2116/2147/2176/2205 等 |

⇒ 任务描述的"每次 ValueChanged 直接下发"在当前树**不成立**（计时器已存在），语义与旧 UI 的节流一致。

**本次补的收口**（不改变 150 ms 语义）：

- `BuildLightingCards()` 重建前统一 `Stop()` + `Clear()`（`:1958-1962`），避免后端就绪重刷/页面重建后，**旧卡 pending 的 slider 值再补发一次**（也顺手避免旧卡闭包常驻）。

## 2. 屏幕效果/校色：后端未连接门控

实现（`MainWindow.xaml.cs`）：
- `IsWideBackendConnected`（`:1502`）= `_probe?.Connected == true || _owner?.CurrentBackend?.Connected == true`（BackendProbe 或迷你窗当前后端任一在线）；
- `UpdateScreenBackendGating()`（`:1511`）——**只在连接状态变化时改 UI**（`_screenBackendConnected` 缓存，避免 2 s tick 抖动）：
  - 禁用：`ScreenEffectEditButton`（编辑参数）、`ScreenEffectToggle`（启用色彩增强）、`ScreenCalibrationToggle`（启用校色）、`ScreenEffectOptionsPanel`、`ScreenCalibrationOptionsPanel`、`ScreenFeaturesPanel`（显示特性）；
  - 同时设置 tooltip `后端未连接：需要 GCU/厂商服务在线后才可编辑`，并 **折叠** `ScreenEffectEditorPanel`；
  - ⚠️ `ScreenCalibrationSettingsButton`（高级设置）**保持可用**：里面是**本地 ICC**（导入/选中/开机应用，与 GCU 无关）⇒ 只加提示 tooltip `后端未连接：校色开关/档位需连接后生效；本地 ICC 设置仍可用`，不清空能力；
  - 日志（去重）：`[wide-screen] 后端未连接 ⇒ 禁用…（本地 ICC 设置保留）` / `[wide-screen] 后端已连接 ⇒ 启用…`。
- 调用点：`BuildScreenControls()`（屏幕页按需创建时，`:1240`）、`OnBackendReady()`（`:449`）、`ApplyPage("screen")`（切页即校正，`:607`）、`RefreshSensors()` 每 2 s tick（覆盖运行中掉线/重连，`:163`）。
- 事件兜底（即使状态竞争也**不静默下发**）：`ScreenEffectEditButton_Click`、`ScreenEffectReset_Click` 未连接直接提示并返回；两个开关在未连接时回退 UI 勾选并提示；`ScreenCalibrationSettingsButton_Click` 打开本地 ICC 面板并提示需后端的部分。

## 3. HID / 白色背光入口：能力位日志 + 无设备不崩（不伪造能力）

- `WideIsHidKeyboard` / `WideIsWhiteBacklightKeyboard` 内部 `try/catch`：能力读取异常 ⇒ 返回 false（**按不支持处理**，不崩、不伪造）；判定外层再整体 `try/catch`（`BuildLightingCards`）；
- 新增 `LogKeyboardCapabilityDecision()`（`:2524`，`WriteLineIfChanged` 去重）——**无论 hid/white 是否为真都记一行**，真机/验收可从日志确认"入口为什么出现/不出现"：
  ```
  [wide-light] 键盘能力判定：hid=False white=False hw=ok connected=True KeyboardType=1 solution=EC
               firmwareVisible=4 rgb=null 原因=IsGcuZoneKeyboardPath=true（固件/HID 回退路径）
  [wide-light] 键盘能力判定：hid=False white=False hw=null connected=False KeyboardType=-1 … 原因=hw=null（后端尚未就绪）
  ```
- `BuildLightingCards` 对 `_owner.WideKeyboardEffects()` 也加 try/catch：失败 ⇒ **本次不建键盘卡**（不伪造效果表）；
- `OpenWideHidKeyboardEditor`：**无设备/后端未连接 ⇒ 只提示、不打开编辑器**（`StatusText="后端未连接：HID 键盘编辑器暂不可用"` + 去重日志 `[wide-light] HID 编辑入口：无设备或后端未连接…`）；有设备时仍走原有 try/catch（HidKeyboardWindow 构造失败也提示不崩）。
- 白色背光编辑器入口保持 task-17 能力门控（`WideIsWhiteBacklightKeyboard`），无设备时该入口本身不会出现。

## 4. UiQaShowAll 显隐钩子（核对结论：已有覆盖，本次未新增）

旧 WinForms `UiQaShowAll` 的**唯一语义**是"把被能力位挡住的 UI 元素显示出来看样式"，旧基线只挂了 **2 处**（`6faf99b^`）：
1. 「静音狂暴」按钮（性能模式行）；
2. 「核显省电」行。

WPF 等价覆盖（task-22/task-25 已接，证据：`docs/notes/基准电源唤醒会话-接入-20261026.md §4`）：
- 迷你窗核显省电行：`OriginalStyleWindow.xaml.cs:2400`（`… || UiQaShowAll.Enabled`）；
- 宽屏核显省电面板（构建 + 刷新）：`MainWindow.xaml.cs:1072/1080`（本次未改）；
- 托盘「静音狂暴」项：`OriginalStyleWindow.xaml.cs:1229`（`SilentTurboVisible = … || UiQaShowAll.Enabled`）；
- 宽屏**没有**独立的「静音狂暴」行（与迷你窗一致）⇒ 托盘项即等价入口，**没有可补的宽屏控件**。
- 说明：QA 开关只影响显示、不参与能力/取数/下发；不得为凑覆盖率把其它被能力位隐藏的元素硬显示（会变成"伪造能力"）。本次**未新增 hook**，结论 = 已有覆盖。
