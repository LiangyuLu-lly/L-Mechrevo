# 开源项目的自定义档（功耗墙/温度墙）方案调研

调研日期：2026-10-16 · 分支 `baolongda` · 纯静态分析（未碰硬件、未写 EC、未发 MQTT、未改代码）

起因：用户质疑「自定义干嘛自己探索官方的 **开源的都有方案的不是吗**」。
目的：查清开源项目里有没有可以直接采用的**默认值/推荐值**。

---

## 一、结论摘要

| 项目 | 功耗墙通道 | 默认值情况 |
|---|---|---|
| **蛟龙开源** `JiaolongControl`（**MIT**） | **WMI 功能号 23** `[2,值]/[3,值]/[4,值]` —— **与我们一致** ✅ | ⚠️ **两套自相矛盾，不能直接采用** |
| **斗战者** `DOUZHANZHE-Control`（**GPL-3.0**） | ⚠️ **RyzenAdj（SMU）**，不是 WMI | ⭐ **根本不预设默认值** |

⇒ **开源里没有一个可直接照抄的"默认值"**。但斗战者给出一个更好的思路（见第四节）。

## 二、斗战者（`DOUZHANZHE-Control`）

### 它的功耗墙走 SMU，不走 WMI
`README.md:34`：
> **性能调优** — CPU 功耗墙/温度墙/核心数/睿频 (**SMU via RyzenAdj**)、
> GPU 功耗/超频偏移/锁频 (NVAPI + nvidia-smi)、**四档模式预设**一键切换（安静/均衡/野兽/斗战）

`server\hal\CpuPowerController.cs`（275 行）**全部走 Windows `powercfg.exe`**
（头行注释：`底层: powercfg.exe (无需管理员权限，无需驱动)`），只做频率限制/睿频/核心数，
**里面没有 PL1/PL2、没有温度墙**。

⇒ **通道不同，实现方式不能照搬。**

### ⭐ 但它的"不预设默认值"思路值得采纳
```csharp
public class SmuOverrides {
    public int? StapmLimitW; public int? ShortPowerLimitW; public int? TempLimitC; public int? CoAll;
}
```
全是**可空**（默认 `null` = 不覆盖）。写入时按模式**只保存用户改过的项**：
`SavePerfOverrides(o => o.Smu.ShortPowerLimitW = req.ValueM, mode)`

⇒ **没改过的保持机器原样，绝不猜一个默认值。**

### 它的四档模式映射（`src\services\uxtuAdapter.js`）
```javascript
const thermalModeMap = { silent: 2, office: 0, gaming: 3, beast: 1 };
```
### ⚠️ 它的风扇数值**不可用于蛟龙**
```javascript
beast: { largeMin: 3200, largeMax: 3800, smallMin: 6400, smallMax: 7200 }
均衡默认: { fanLargeRpmTarget: 2900, fanSmallRpmTarget: 5200 }
beast:   { fanLargeRpmTarget: 3500, fanSmallRpmTarget: 6900 }
```
⇒ 它 README 自述"**专为联想 Legion N176 2025 (宝龙达 OEM) 打造**" ⇒ 那是 **N176** 的值，与蛟龙无关。

## 三、蛟龙开源（`JiaolongControl`，MIT）

### 通道与我们完全一致 ✅
`Server\Core\Controllers\CpuController.cs`：
```csharp
SetCpuShortPower(sp) → SetValue(CPUPower, new byte[2] { (byte)CPUPower.ShortPower, sp })
SetCpuLongPower(lp)  → SetValue(CPUPower, new byte[2] { (byte)CPUPower.LongPower, lp })
SetCPUTempWall(tw)   → SetValue(CPUPower, new byte[2] { (byte)CPUPower.CpuTempWallState, tw })
SetCustomMode(open)  → SetValue(CPUPower, CPUPower.OpenState / CloseState)
GetCustomMode()      → GetValue<CPUPower>(MethodName.CPUPower)
```

### ⚠️ 默认值两处不一致（同一项目自己就对不上）

**Server 端**（`Server\Core\Models\JiaoLongConfig.cs`）：
```csharp
Default     : CpuLongPower = 45, CpuShortPower = 65, CpuTempWall = 90, CpuMaxFrequency = 4400
Performance : CpuLongPower = 65, CpuShortPower = 90, CpuTempWall = 95, CpuMaxFrequency = 4700
Saving      : CpuLongPower = 30, CpuShortPower = 45, CpuTempWall = 85, CpuMaxFrequency = 3800
Custom      : new()          // 空 ⇒ 用字段默认
// 字段默认与范围：
CpuLongPower    = 45   [ConfigRange(5, 120)]
CpuShortPower   = 55   [ConfigRange(5, 150)]
CpuTempWall     = 95   [ConfigRange(60, 105)]
CpuMaxFrequency = 4800 [2000, 6000]
```

**Client 端**（`Client\src\constants\index.ts`）：
```javascript
// 注释自称"与 Server system_info._default_config 保持一致" —— ⚠️ 实际不一致
Default     : 45 / 60 / 85 / 5150
Performance : 54 / 75 / 90 / 5150
Saving      : 30 / 45 / 75 / 3200
Custom      : 45 / 60 / 85 / 5150
```

**差异**：PL2 差 5~15W、温度墙差 5~10℃、频率差 750~1950 MHz。

### 滑块范围也不一致
`Client\src\pages\CPU.vue`：
```javascript
<a-slider v-model="activeProfile.CpuLongPower"  :min="30" :max="255" />
<a-slider v-model="activeProfile.CpuShortPower" :min="30" :max="255" />
<a-slider v-model="activeProfile.CpuTempWall"   :min="60" :max="105" />
```
⇒ UI 给到 `255`（`byte` 上限），而 Server 的 `ConfigRange` 是 `(5,120)`/`(5,150)`。
⚠️ **写 255 到 PL1 有风险。**

### ⭐ 应用顺序（`CPU.vue:81-105`）
```
PL1（SetCpuLongPower） → PL2（SetCpuShortPower） → 温度墙（SetCPUTempWall）
→ 最大频率（SetCPUMaxFrequency） → 睿频（EnableTurbo/DisableTurbo）
```
**全程没有调用 `SetCustomMode`** —— 虽然 `bridge.ts:359` 导出了它，但**没有任何页面调用**。

## 四、⭐ 悬案解决：功耗墙**不需要显式 enable**

| 来源 | 是否 enable |
|---|---|
| 官方控制台 | **没有** enable 步骤，直接写 `[2,值]/[3,值]/[4,值]` |
| 蛟龙 UI | **没有** `SetCustomMode` 调用（API 存在但无人调用） |

⇒ **两处独立印证：直接写值即可。**

⚠️ 澄清一处旧混淆：**限充**要发的 `0x0D`（启用原生阈值）是**充电阈值**的子命令，
与**功耗墙**（子命令 `2/3/4`）是两回事，不能混为一谈。

## 五、对照我方 `bf00637` 的实现

| 项 | 我们 | 蛟龙开源 | 结论 |
|---|---|---|---|
| 通道 | 功能号 23 `[2/3/4, 值]` | 同 | ✅ **一致，无需改** |
| 顺序 | 先设三个值、**最后 enable** | PL1→PL2→温度墙→频率，**不 enable** | ⚠️ **"最后 enable"该去掉** |
| 默认值 | **45 / 65 / 95** | Server `Default` 45/65/90；字段默认 45/55/95；Client 45/60/85 | ❌ **我们的值是拼出来的，无单一来源** |
| PL1/PL2 范围 | 5–200 | Server 5–120 / 5–150 | ⚠️ **上限过宽，建议收窄** |
| 温度墙范围 | 60–105 | 60–105 | ✅ 一致 |

### 我们那个 `45/65/95` 的来历（逐项追溯）
- **PL1 = 45** —— 蛟龙两套都是 45 ✅ 有依据
- **PL2 = 65** —— 取自 Server 的 **`Default` 档位**（而字段默认是 55、Client 是 60）
- **温度墙 = 95** —— 取自**字段默认**（而 Server `Default` 档是 90、Client 是 85）

⇒ **从两个不同层级各取一个数拼出来的，没有任何一处完整支持 `45/65/95`。**

## 六、建议（等拍板，本轮未改代码）

1. ⭐ **去掉"最后 enable"那一步**（官方 + 蛟龙 UI 双印证不需要）
2. ⭐ **默认值不再自己编**。三选一：
   - **A（推荐）**：学斗战者 —— **未设置时显示「未设置」**，用户设过才显示其值。
     既符合"读不到就显示未知"铁律，也不编数字
   - **B**：用**原厂包**里的官方默认值（分析 `蛟龙游戏控制中心Setup.exe` 的那一路可能有权威值）
   - **C**：若必须有初值，采用蛟龙 **`Default` 档位**那一套（45/65/90），
     并**在界面标明"参考蛟龙开源 Default 档"**，**不要拼**
3. **收窄范围**：PL1 到 120、PL2 到 150（照蛟龙 Server 的 `ConfigRange`），别用 200；
   温度墙保持 60–105
4. ⛔ **不要**采用斗战者的风扇数值（那是 **Lenovo Legion N176** 的，与蛟龙无关）

## 八、方法论提醒（本会话踩过，勿重犯）

- PowerShell `-shl` 对 `[byte]` 会**截断**（`[byte]0x81 -shl 8` = `0`）⇒ 用 `* 256`
- 大文件（BIOS 镜像）别用逐字节循环；建 Latin1/UTF-16 视图 + `String.IndexOf`，UTF-16 要试**两个偏移**
- **负结论必须配对照测试**（否则是假否定）
- ⚠️ **同一项目内部也会自相矛盾**（本例：蛟龙 Server vs Client 的默认值），
  **采用任何数值前先确认它有几个出处、是否一致**
